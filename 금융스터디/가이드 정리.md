# 카드사 결제/정산 시스템

| 항목        | 내용                                              |
| ----------- | ------------------------------------------------- |
| 기간        | 총 8주 · 격주 1회 · 회당 30분                     |
| 팀 구성     | 6 팀 · 팀당 4명 · 총 24명                         |
| 주차별 역할 | 발표자 / 서기 / 질문자 — 매주 로테이션            |
| 발표 분량   | 팀당 10분 (슬라이드보다 문서 A4 2~3장 우선)       |
| 질의응답    | 다른 팀 반드시 질문 1개씩 — 미리 준비해서 옴      |
| 아카이브    | Notion 에 매주 발표 문서 누적 저장 — 팀 공동 편집 |

| 8주  | 면접 대비   | 면접 예상 질문 롤플레이, 취약 개념 총정리, 스터디 회고         | 면접 Q&A 모음      |

## 발표 가이드

| 번호 | 항목         | 기준 / 가이드                                                             |
| ---- | ------------ | ------------------------------------------------------------------------- |
| 1    | 개념 정의    | 금융 용어 + IT 용어 매핑 — 용어사전 출처 명시 (terms.fss.or.kr)           |
| 2    | 업무 흐름도  | 손으로 그려도 OK — 최소 5단계 이상으로 구성                               |
| 3    | IT 구현 관점 | "개발자라면 어떻게 구현할까?" — 최소 한 문단 분량                         |
| 4    | 출처 명시    | 복붙 금지 — 참고 URL 또는 문서명 기재 (다른 팀이 검증할 수 있어야 합니다) |
| 5    | 본인 해석    | 조사 내용 + "우리 팀의 생각" 구분해서 작성                                |
| 6    | 면접 연결    | 이 내용을 면접에서 한 문장으로 답한다면? — 마지막에 한 줄 요약            |

| 섹션              | 분량   | 내용                                                      |
| ----------------- | ------ | --------------------------------------------------------- |
| 1. 핵심 한 줄     | 1 줄   | 이번 발표를 한 문장으로 — 면접 답변 연습이라고 생각하세요 |
| 2. 핵심 용어      | 1/2 장 | 5~7 개 용어 · "정의 + 왜 중요 + IT 관점" 3중 구조         |
| 3. 업무 흐름      | 1/2 장 | 5 단계 이상 흐름도 + 각 단계 설명 한 줄                   |
| 4. IT 구현        | 1 장   | 어떤 테이블 / 어떤 API / 어떤 배치인가 — 구체적으로       |
| 5. 출처           | 1/3 장 | 참고 URL, 문서명, 인용 페이지                             |
| 6. 우리 팀의 생각 | 1/3 장 | 조사하면서 든 의문, 신기했던 점, 다른 팀에 묻고 싶은 것   |

## 정리

- 팀 소개 — 핵심 키워드 + Spring Batch 연계도
- 학습 흐름 3단계 — 무엇인가 / 어떻게 돌아가는가 / 어떻게 구현하는가
- 핵심 용어 — 정의 + 왜 중요 + IT 관점
- 업무 흐름 — 실제 시스템에서 데이터가 흐르는 단계
- Spring Batch 연계 — 배치 시나리오와 구현 포인트
- 추천 학습 자료 — 공식 / 실무 / 기술 자료 출처
- 면접 예상 질문 — 답변 접근법까지 함께
