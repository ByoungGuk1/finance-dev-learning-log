## Scrum

requirement ==> scope ==> back log

### 1. 제품 백로그 (Product Backlog)

- 유일한 요구사항 출처: 제품에 필요한 모든 피처(feature), 기능(function), 개선사항, 버그 수정의 우선순위 목록
- 동적/진화적 산출물: 시장 환경, 비즈니스 요구, 기술 변화에 따라 지속적으로 정제 및 업데이트
- DEEP 원칙: 적절히 상세화(Detailed), 추정 가능(Estimated), 지속적 창출(Emergent), 우선순위화(Prioritized)

### 2. 스프린트 백로그 (Sprint Backlog)

- 개발팀의 실행 계획: 선택된 제품 백로그 항목 + 스프린트 목표를 실현하기 위한 작업 계획서
- 개발팀 단독 소유: 스프린트 동안 작업 진행 상황에 따라 오직 개발팀만이 수정 및 재추정

### 구성과 관리

<product owner관리>  
팀의 역량에 맞춰 백로그를 4일치 정도(2~4주로 계획하기도 한다.)의 스프린트로 분리하여 업무량 배분

```
릴리즈 계획 -> 제품 백로그 게획 -> 세부 스프린트 계획 -> 스프린트 백로그 계획 -> 개발자 배분
```

```
epic(몇 주~몇 달) -> story(며칠) -> task(몇 시간)
```

예시

```
월 : 스프린트 계획(오전)
월-목 : 작업
금 : 회고(오전), 정리(문서, 리팩토링, 테스트 ...)(오후)
```
