## 2. 이번 주 핵심

이번 주 Git 정리는 GitHub 협업 실습을 마무리하는 흐름이다.

핵심은 다음과 같다.

```text
브랜치 생성
→ 기능별 작업
→ Pull Request
→ merge
→ conflict 해결
→ revert 또는 브랜치 정리
```

---

## 3. GitHub 협업에서 중요한 기준

| 항목 | 정리 |
|---|---|
| 브랜치 | 기능별 작업 공간을 분리한다 |
| PR | 변경사항을 검토하고 병합 요청을 만든다 |
| merge | 브랜치의 변경사항을 합친다 |
| conflict | 같은 위치를 서로 다르게 수정했을 때 발생한다 |
| revert | 잘못된 변경을 되돌리는 새 커밋을 만든다 |

## 4. Eclipse에서 Git 사용

`5-1 Eclipse에서Git.pptx` 자료는 Eclipse 환경에서 Git을 사용하는 흐름을 다룬다.

정리할 수 있는 흐름은 다음과 같다.

```text
Eclipse 프로젝트 생성
→ Git 저장소 연결
→ 변경 파일 확인
→ commit
→ remote push
→ pull 또는 fetch
```

터미널 Git 명령을 직접 쓰는 방식과 IDE에서 Git을 쓰는 방식은 화면은 다르지만 개념은 같다.

## 5. 실습 레포 기준 확인

`git-practice.zip`의 레포에는 `main`, `develop`, `feature`, `conflict` 계열 브랜치가 남아 있다.
커밋 이력도 기능 추가, PR 병합, conflict 실습, revert 실습이 포함되어 있다.

따라서 이 실습은 코드 완성도보다 Git 흐름 자체를 확인하는 자료로 보는 것이 맞다.

## 7. 이번 주 정리

Git/GitHub 수업은 단순 명령어 암기가 아니라 팀 단위 코드 변경 흐름을 이해하는 것이 핵심이다.
특히 브랜치와 PR은 팀 프로젝트에서 작업 충돌을 줄이고 변경 내용을 검토하기 위한 기본 흐름으로 정리할 수 있다.
