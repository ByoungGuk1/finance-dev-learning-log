## 2. 배열과 반복문

배열은 같은 타입의 데이터를 연속적으로 관리할 때 사용한다.

```java
int[] numbers = new int[3];
```

배열은 생성되면 타입별 기본값으로 초기화된다.

| 타입      | 기본값   |
| --------- | -------- |
| 정수 타입 | `0`      |
| 실수 타입 | `0.0`    |
| `boolean` | `false`  |
| `char`    | `\u0000` |
| 참조 타입 | `null`   |

배열을 그대로 출력하면 배열의 내용이 아니라 참조값 형태의 문자열이 출력된다.

```java
System.out.println(numbers);
```

배열 내용을 확인할 때는 `Arrays.toString()`을 사용한다.

```java
System.out.println(Arrays.toString(numbers));
```

반복문은 배열의 요소를 순서대로 조회하거나, 특정 조건에 맞는 계산을 반복할 때 사용했다.

```java
for (int i = 0; i < numbers.length; i++) {
    System.out.println(numbers[i]);
}
```

향상된 for문은 인덱스가 필요 없고 값만 순서대로 읽을 때 적합하다.

```java
for (int number : numbers) {
    System.out.println(number);
}
```

정리:

- 배열은 생성 시 기본값으로 자동 초기화된다.
- 배열 변수는 배열 객체를 직접 저장하는 것이 아니라 참조한다.
- 배열 내용을 출력할 때는 `Arrays.toString()`을 사용한다.
- 인덱스가 필요하면 일반 for문, 값만 필요하면 향상된 for문을 사용한다.

## 3. 기본형과 참조형

Java의 값 전달 방식을 이해하려면 기본형과 참조형을 구분해야 한다.

| 구분   | 예시                               | 특징                          |
| ------ | ---------------------------------- | ----------------------------- |
| 기본형 | `int`, `double`, `boolean`, `char` | 값 자체를 저장                |
| 참조형 | `String`, 배열, 객체               | 객체를 가리키는 참조값을 저장 |

기본형은 메서드에 전달될 때 값이 복사된다.

```java
int score = 100;
change(score);
System.out.println(score); // 100

static void change(int score) {
    score = 200;
}
```

참조형은 참조값이 복사된다. 그래서 같은 배열 객체를 바라보는 상태라면, 메서드 안에서 배열 요소를 변경했을 때 원본 배열에도 반영된다.

```java
String[] subjects = {"Java", "Oracle", "Spring"};
change(subjects);
System.out.println(Arrays.toString(subjects));

static void change(String[] subjects) {
    subjects[0] = "JAVA";
}
```

정리:

- 기본형은 값이 복사된다.
- 참조형은 참조값이 복사된다.
- 참조형 변수를 복사하면 같은 객체를 바라볼 수 있다.
- 배열이나 객체를 메서드로 넘길 때는 원본 데이터 변경 가능성을 고려해야 한다.

## 4. `String`과 문자열 처리

`String`은 기본형처럼 자주 사용되지만 실제로는 참조 타입이다.

```java
String s1 = "Java";
String s2 = "Java";
String s3 = new String("Java");
```

문자열 비교에서 `==`은 참조값을 비교하고, `equals()`는 문자열 내용을 비교한다.

```java
System.out.println(s1 == s2);      // true
System.out.println(s1 == s3);      // false
System.out.println(s1.equals(s3)); // true
```

`String`은 불변 객체이다. `replace()` 같은 메서드는 원본 문자열을 바꾸지 않고 새로운 문자열을 반환한다.

```java
String text = "이것이 자바다";
text.replace("자바", "JAVA");
System.out.println(text); // 이것이 자바다
```

반환값을 다시 저장해야 변경된 문자열을 사용할 수 있다.

```java
text = text.replace("자바", "JAVA");
```

문자열을 반복해서 누적할 때는 `StringBuilder`를 사용하는 편이 좋다.

```java
StringBuilder sb = new StringBuilder();

for (int i = 1; i <= 100; i++) {
    sb.append(i);
}

String result = sb.toString();
```

정리:

- 문자열 내용 비교는 `equals()`를 사용한다.
- `String`은 불변 객체이다.
- 반복적인 문자열 누적에는 `StringBuilder`가 적합하다.

## 5. 클래스, 객체, 인스턴스

클래스는 객체를 만들기 위한 설계도이다.

```java
public class Car {
    String model;
    int price;
}
```

객체는 클래스를 바탕으로 생성된 실체이다.

```java
Car car = new Car();
```

인스턴스는 특정 클래스로부터 실제 메모리에 생성된 객체를 말한다.

| 용어               | 의미                               |
| ------------------ | ---------------------------------- |
| class              | 객체를 만들기 위한 설계도          |
| object             | 클래스를 이용해 만든 객체          |
| instance           | 특정 클래스로부터 실제 생성된 객체 |
| reference variable | 객체를 참조하는 변수               |

객체지향 프로그래밍에서는 데이터를 필드에 저장하고, 동작은 메서드로 정의한다.

```java
public class Car {
    String model;
    int price;

    void printInfo() {
        System.out.println(model);
        System.out.println(price);
    }
}
```

정리:

- 클래스는 객체를 만들기 위한 설계도이다.
- 객체는 클래스를 기반으로 생성된 실체이다.
- 인스턴스는 특정 클래스로부터 실제 생성된 객체를 강조할 때 사용하는 표현이다.
- 참조 변수는 객체 자체가 아니라 객체를 가리키는 참조값을 저장한다.

## 6. 필드, 생성자, 메서드

Java 클래스의 주요 구성 요소는 필드, 생성자, 메서드이다.

| 구성 요소 | 역할                         |
| --------- | ---------------------------- |
| 필드      | 객체의 데이터 저장           |
| 생성자    | 객체 생성 시 초기화          |
| 메서드    | 객체 또는 클래스의 동작 정의 |

필드는 객체의 상태를 저장한다.

```java
private String name;
private int age;
```

생성자는 객체 생성 시 호출되며, 주로 필드 초기화에 사용한다.

```java
public Member(String name, int age) {
    this.name = name;
    this.age = age;
}
```

메서드는 객체의 동작을 정의한다.

```java
public void printInfo() {
    System.out.println(name);
    System.out.println(age);
}
```

생성자는 메서드처럼 보이지만 반환 타입이 없고, 클래스명과 이름이 같아야 한다.

정리:

- 필드는 객체의 데이터를 저장한다.
- 생성자는 객체 생성 시 호출된다.
- 생성자를 하나도 작성하지 않으면 컴파일러가 기본 생성자를 추가한다.
- 생성자를 하나라도 직접 작성하면 기본 생성자는 자동으로 추가되지 않는다.
- 메서드는 객체의 기능을 실행하는 코드 블록이다.

## 7. `this`와 생성자 오버로딩

`this`는 현재 객체를 의미한다.

```java
public Member(String name) {
    this.name = name;
}
```

필드 이름과 매개변수 이름이 같을 때 `this`를 사용하면 현재 객체의 필드임을 명확히 표현할 수 있다.

`this()`는 같은 클래스의 다른 생성자를 호출할 때 사용한다.

```java
public Member() {
    this("unknown", 0);
}

public Member(String name) {
    this(name, 0);
}

public Member(String name, int age) {
    this.name = name;
    this.age = age;
}
```

`this()`는 생성자 안에서만 사용할 수 있고, 반드시 생성자의 첫 줄에 와야 한다.

정리:

- `this`는 현재 객체를 의미한다.
- `this()`는 같은 클래스의 다른 생성자를 호출한다.
- 생성자 오버로딩은 매개변수의 개수나 타입이 다른 생성자를 여러 개 정의하는 것이다.
- `this()`는 생성자 첫 줄에만 작성할 수 있다.

## 8. `static`, `final`, 초기화 블록

`static`은 객체가 아니라 클래스에 소속된다.

```java
public class Calculator {
    static double pi = 3.141592;

    public static void printPi() {
        System.out.println(pi);
    }
}
```

`static` 멤버는 객체를 생성하지 않고 클래스명으로 접근할 수 있다.

```java
Calculator.printPi();
```

`final`은 한 번 초기화한 뒤 변경할 수 없게 제한한다.

```java
final int score = 100;
static final int MAX_SCORE = 100;
```

`static final`은 클래스 상수로 사용한다. 상수명은 보통 대문자와 언더바를 사용한다.

```java
static final int MAX_BALANCE = 1_000_000;
```

초기화 블록은 실행 시점에 따라 인스턴스 초기화 블록과 `static` 초기화 블록으로 나눌 수 있다.

| 구분                 | 실행 시점                 |
| -------------------- | ------------------------- |
| 인스턴스 초기화 블록 | 객체 생성 시마다 실행     |
| `static` 초기화 블록 | 클래스 로딩 시 한 번 실행 |

```java
{
    System.out.println("instance block");
}

static {
    System.out.println("static block");
}
```

정리:

- `static` 변수와 `static` 블록은 클래스 로딩 시 처리된다.
- 인스턴스 변수와 인스턴스 초기화 블록은 객체 생성 시 처리된다.
- 생성자는 인스턴스 초기화 블록 이후 실행된다.
- `final` 필드는 한 번 초기화하면 변경할 수 없다.
- `static final`은 클래스 단위 상수로 사용한다.

## 9. 접근 제한자와 캡슐화

접근 제한자는 클래스, 필드, 생성자, 메서드에 접근할 수 있는 범위를 정한다.

| 접근 제한자 | 같은 클래스 | 같은 패키지 | 다른 패키지의 자식 클래스 | 다른 패키지 |
| ----------- | ----------: | ----------: | ------------------------: | ----------: |
| `public`    |        가능 |        가능 |                      가능 |        가능 |
| `protected` |        가능 |        가능 |                      가능 |      불가능 |
| default     |        가능 |        가능 |                    불가능 |      불가능 |
| `private`   |        가능 |      불가능 |                    불가능 |      불가능 |

필드는 보통 `private`으로 선언하고, getter/setter를 통해 접근한다.

```java
private String name;

public String getName() {
    return name;
}

public void setName(String name) {
    this.name = name;
}
```

이처럼 필드를 직접 공개하지 않고 필요한 메서드만 제공하는 방식을 캡슐화라고 한다.

정리:

- `public`은 어디서든 접근할 수 있다.
- `protected`는 같은 패키지 또는 상속 관계에서 접근할 수 있다.
- default는 같은 패키지에서만 접근할 수 있다.
- `private`은 같은 클래스 내부에서만 접근할 수 있다.
- 캡슐화는 내부 데이터를 보호하고 필요한 기능만 외부에 공개하는 방식이다.

## 10. 메서드 오버로딩과 가변 인자

메서드 오버로딩은 같은 이름의 메서드를 매개변수의 차이로 여러 개 정의하는 것이다.

```java
int add(int a, int b) {
    return a + b;
}

double add(double a, double b) {
    return a + b;
}
```

오버로딩 기준은 매개변수이다.

| 구분               | 오버로딩 여부 |
| ------------------ | ------------- |
| 매개변수 개수 다름 | 가능          |
| 매개변수 타입 다름 | 가능          |
| 매개변수 순서 다름 | 가능          |
| 리턴 타입만 다름   | 불가능        |
| 접근 제한자만 다름 | 불가능        |

가변 인자를 사용하면 매개변수 개수가 정해져 있지 않은 값을 받을 수 있다.

```java
int add(int... numbers) {
    int total = 0;

    for (int number : numbers) {
        total += number;
    }

    return total;
}
```

정리:

- 오버로딩은 메서드 이름이 같고 매개변수 구성이 달라야 한다.
- 리턴 타입만 다르면 오버로딩이 아니다.
- 접근 제한자만 다르면 오버로딩이 아니다.
- 가변 인자는 내부적으로 배열처럼 처리된다.

## 11. JavaBeans, DTO, MVC

JavaBeans 형식은 데이터를 담는 클래스를 일정한 규칙에 맞춰 작성하는 방식이다.

일반적인 규칙:

- 필드는 `private`
- 기본 생성자 제공
- getter/setter 제공
- 필요하면 `toString()` 재정의

DTO는 계층 간 데이터를 전달하기 위한 객체이다.

```java
public class BookDTO {
    private String title;
    private int price;

    public BookDTO() {
    }

    public BookDTO(String title, int price) {
        this.title = title;
        this.price = price;
    }
}
```

MVC는 역할을 나누어 코드를 구성하는 방식이다.

| 구성 요소  | 역할                   |
| ---------- | ---------------------- |
| Model      | 데이터와 비즈니스 로직 |
| View       | 사용자에게 결과 출력   |
| Controller | 요청을 받고 흐름 제어  |

수업에서는 다음 구조로 책 정보와 계좌 정보를 처리했다.

```text
Controller
→ Service
→ DTO
→ View
```

정리:

- DTO는 데이터를 담고 계층 간 전달하는 역할을 한다.
- Service는 비즈니스 로직을 처리한다.
- View는 출력이나 입력을 담당한다.
- Controller 또는 Application은 전체 흐름을 제어한다.

## 12. `Object` 클래스와 메서드 재정의

Java의 모든 클래스는 `Object` 클래스를 상속받는다.

```java
public class Employee {
}
```

위 코드는 명시하지 않아도 다음처럼 이해할 수 있다.

```java
public class Employee extends Object {
}
```

`Object`의 대표 메서드는 다음과 같다.

| 메서드       | 역할                 |
| ------------ | -------------------- |
| `toString()` | 객체를 문자열로 표현 |
| `equals()`   | 객체 비교            |
| `hashCode()` | 해시값 반환          |

`toString()`을 재정의하면 객체 출력 형식을 원하는 방식으로 바꿀 수 있다.

```java
@Override
public String toString() {
    return name + "(" + id + ")";
}
```

`equals()`를 재정의할 때는 비교 기준을 명확히 정해야 한다.

---

## 13. 싱글톤 패턴

싱글톤 패턴은 객체를 하나만 만들어서 공유하도록 하는 패턴이다.

```java
public class MySingleton {
    private static MySingleton instance;

    private MySingleton() {
    }

    public static MySingleton getInstance() {
        if (instance == null) {
            instance = new MySingleton();
        }
        return instance;
    }
}
```

사용:

```java
MySingleton s1 = MySingleton.getInstance();
MySingleton s2 = MySingleton.getInstance();

System.out.println(s1 == s2); // true
```

정리:

- 생성자를 `private`으로 막는다.
- 클래스 내부에서 객체를 하나만 생성한다.
- 외부에서는 `getInstance()`로 객체를 얻는다.
- 하나의 공유 인스턴스를 통해 공통 기능을 처리할 수 있다.
- 멀티스레드 환경에서는 동시에 객체가 생성되는 상황도 고려해야 한다.

---

## 14. 상속과 `super()`

상속은 이미 작성된 클래스를 재사용해서 새로운 클래스를 만드는 방법이다.

```java
public class CheckingAccount extends Account {
}
```

자식 클래스는 부모 클래스의 필드와 메서드를 물려받을 수 있다. 단, `private` 멤버는 직접 접근할 수 없다.

자식 객체를 생성하면 부모 객체가 먼저 생성된 뒤 자식 객체가 생성된다.

```java
public CheckingAccount(String accNo, String owner, int balance, String cardNo) {
    super(accNo, owner, balance);
    this.cardNo = cardNo;
}
```

정리:

- Java 클래스는 다중 상속을 허용하지 않는다.
- `extends` 키워드로 부모 클래스를 지정한다.
- 부모 생성자는 자식 생성자보다 먼저 실행된다.
- 부모 클래스에 기본 생성자가 없으면 자식 생성자에서 `super(값...)`과 같은 방식으로 명시해야 한다.
- `super()`는 생성자의 첫 줄에 와야 한다.

---

## 15. 오버라이딩과 `final`, `abstract`

오버라이딩은 부모에게 상속받은 메서드를 자식 클래스에서 다시 정의하는 것이다.

```java
@Override
public int withdraw(int amount) {
    if (getBalance() + creditLine < amount) {
        System.err.println("잔액 부족");
        return 0;
    }

    setBalance(getBalance() - amount);
    return amount;
}
```

오버라이딩 조건:

- 부모 메서드와 이름이 같아야 한다.
- 매개변수 목록이 같아야 한다.
- 리턴 타입이 같거나 허용되는 범위 안에서 호환되어야 한다.
- 접근 제한자는 부모 메서드보다 더 좁게 만들 수 없다.

`final` 클래스는 상속할 수 없고, `final` 메서드는 오버라이딩할 수 없다.

```java
final class MyClass {
}
```

추상 클래스는 직접 객체를 만들 수 없는 클래스이다.

```java
public abstract class Shape {
    public abstract double calculateArea();
    public abstract double calculatePerimeter();
}
```

추상 메서드는 구현부가 없고, 자식 클래스에서 구현해야 한다. 단, 자식 클래스도 추상 클래스라면 구현을 미룰 수 있다.

---

## 16. 다형성과 타입 변환

다형성은 같은 사용 방법으로 여러 실행 결과가 나오는 성질이다.

```java
Vehicle v1 = new Bus();
Vehicle v2 = new Taxi();

Driver driver = new Driver();
driver.drive(v1);
driver.drive(v2);
```

부모 타입 변수에 자식 객체를 대입하는 것을 자동 타입 변환 또는 업캐스팅이라고 한다.

```java
Account acc = new CheckingAccount("112", "b", 1000, "999");
```

부모 타입으로 변환되면 부모 타입에 선언된 멤버만 직접 사용할 수 있다.

```java
acc.deposit(1000);
acc.withdraw(500);
// acc.pay("999", 500); // Account 타입에는 pay()가 없어서 호출 불가
```

오버라이딩된 메서드는 실제 객체 타입의 메서드가 실행된다.

```java
Parent parent = new Child();
parent.f1(); // Child의 f1()
```

하지만 필드는 오버라이딩되지 않고, 참조 변수 타입을 기준으로 접근된다.

```java
System.out.println(parent.a); // Parent의 a
```

이를 필드 하이딩이라고 볼 수 있다.

다운캐스팅은 부모 타입으로 변환된 객체를 다시 자식 타입으로 사용할 때 필요하다.

```java
if (parent instanceof Child child) {
    child.f1();
    child.f2();
}
```

정리:

- 부모 타입 변수에 자식 객체를 대입할 수 있다.
- 부모 타입으로 변환되면 부모 타입에 선언된 멤버만 바로 사용할 수 있다.
- 오버라이딩된 메서드는 실제 객체 타입 기준으로 실행된다.
- 필드는 참조 변수 타입 기준으로 접근된다.
- 다운캐스팅 전에는 `instanceof`로 실제 객체 타입을 확인하는 것이 안전하다.

## 17. 이번 주에 헷갈렸던 부분

## 17-1. 참조형과 주소 복사

배열을 다른 변수에 대입하면 값이 복사되는 것이 아니라 같은 배열을 바라보게 된다.

```java
String[] arr1 = {"Java", "Oracle"};
String[] arr2 = arr1;
```

이 상태에서 `arr1[0]`을 바꾸면 `arr2[0]`도 바뀐 것처럼 보인다. 실제로는 두 변수가 같은 배열 객체를 참조하고 있기 때문이다.

---

## 17-2. `String`은 불변 객체

`replace()`를 호출하면 원본 문자열이 바뀐다고 생각할 수 있지만, 실제로는 새 문자열을 반환한다.

```java
text.replace("Java", "JAVA");
```

변경 결과를 사용하려면 반환값을 다시 저장해야 한다.

```java
text = text.replace("Java", "JAVA");
```

---

## 17-3. `static`과 인스턴스 구분

`static`은 클래스 소속이고, 인스턴스 멤버는 객체 소속이다.

```java
Calculator.printPi();
```

`static` 메서드는 객체 없이 호출할 수 있지만, 인스턴스 필드를 바로 사용할 수 없다.

---

## 17-4. 오버로딩 조건

오버로딩은 메서드 이름이 같은 것만으로 성립하지 않는다.

매개변수의 개수, 타입, 순서 중 하나가 달라야 한다.

```java
int add(int a, int b)
double add(int a, int b)
```

위처럼 리턴 타입만 다르면 오버로딩이 아니다.

---

## 17-5. 필드 하이딩과 오버라이딩

이번 주에 가장 헷갈린 부분은 업캐스팅 후 필드와 메서드가 다르게 동작하는 점이었다.

```java
Parent parent = new Child();
```

이 상태에서 메서드는 실제 객체인 `Child` 기준으로 실행되지만, 필드는 참조 변수 타입인 `Parent` 기준으로 접근된다.

처음에는 필드도 자식 클래스 값이 나올 것이라고 예상했지만, 실제 결과는 달랐다. 이 차이를 통해 필드는 오버라이딩되지 않고 하이딩된다는 점을 다시 확인했다.
