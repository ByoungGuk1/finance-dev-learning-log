## 2. 상속 심화와 추상 클래스

상속은 기존 클래스를 재사용해서 새로운 클래스를 만드는 방법이다.

```java
class Student extends Person {
}
```

자식 클래스는 부모 클래스의 필드와 메서드를 물려받을 수 있다.  
단, `private` 멤버는 상속되더라도 자식 클래스에서 직접 접근할 수 없다.

자식 객체를 생성하면 부모 객체가 먼저 생성된다.  
부모 생성자는 자식 생성자에서 `super()`를 통해 호출한다.

```java
public Student(String name, int age, int studentNo) {
    super(name, age);
    this.studentNo = studentNo;
}
```

부모 클래스에 기본 생성자가 없으면 자식 클래스에서 부모 생성자를 명시적으로 호출해야 한다.

추상 클래스는 직접 객체를 만들 수 없는 클래스이다.

```java
abstract class Account {
    public abstract int calculateInterest();
}
```

추상 메서드는 선언만 있고 구현부가 없다.  
상속받은 자식 클래스는 해당 추상 메서드를 구현해야 한다.

```java
class SavingsAccount extends Account {
    @Override
    public int calculateInterest() {
        return 0;
    }
}
```

정리:

- `extends`는 클래스 상속에 사용한다.
- 부모 생성자는 자식 생성자보다 먼저 실행된다.
- `super()`는 부모 생성자를 호출한다.
- `super()`는 생성자의 첫 줄에 와야 한다.
- 추상 클래스는 직접 객체를 생성할 수 없다.
- 추상 메서드는 자식 클래스에서 구현해야 한다.
- 공통 구조는 부모 클래스에 두고, 세부 동작은 자식 클래스에서 구현할 수 있다.

## 3. 다형성, 타입 변환, `instanceof`

다형성은 같은 사용 방법으로 여러 실행 결과가 나오는 성질이다.

```java
Person p1 = new Student();
Person p2 = new Teacher();
```

부모 타입 변수에 자식 객체를 대입하는 것을 자동 타입 변환 또는 업캐스팅이라고 한다.

```java
Account account = new SavingsAccount();
```

업캐스팅된 상태에서는 부모 타입에 선언된 멤버만 직접 사용할 수 있다.  
하지만 오버라이딩된 메서드는 실제 객체 타입 기준으로 실행된다.

```java
Parent parent = new Child();

parent.method(); // Child에서 오버라이딩한 method 실행
```

다운캐스팅은 부모 타입으로 변환된 객체를 다시 자식 타입으로 사용할 때 필요하다.

```java
if (parent instanceof Child child) {
    child.childMethod();
}
```

`instanceof`를 사용하면 실제 객체 타입을 확인한 뒤 안전하게 다운캐스팅할 수 있다.

정리:

- 부모 타입 변수에 자식 객체를 대입할 수 있다.
- 업캐스팅 후에는 부모 타입에 선언된 멤버만 바로 사용할 수 있다.
- 오버라이딩된 메서드는 실제 객체 타입 기준으로 실행된다.
- 필드는 오버라이딩되지 않고 참조 변수 타입을 기준으로 접근된다. (필드 하이딩)
- 다운캐스팅 전에는 `instanceof`로 실제 객체 타입을 확인하는 것이 안전하다.

## 4. `sealed` 클래스

`sealed` 클래스는 상속 가능한 자식 클래스를 제한할 때 사용한다.

```java
sealed abstract class BankEvent
        permits DepositEvent, WithdrawEvent, TransferEvent {
}
```

`permits` 뒤에는 상속을 허용할 자식 클래스를 적는다.

`sealed` 클래스를 상속받는 자식 클래스는 다음 중 하나로 선언해야 한다.

| 키워드       | 의미                  |
| ------------ | --------------------- |
| `final`      | 더 이상 상속 불가     |
| `sealed`     | 다시 상속 대상을 제한 |
| `non-sealed` | 상속 제한 해제        |

예시:

```java
final class DepositEvent extends BankEvent {
}

non-sealed class TransferEvent extends BankEvent {
}
```

`TransferEvent`가 `non-sealed`이면 다른 클래스가 다시 상속할 수 있다.

```java
class InternationalTransfer extends TransferEvent {
}
```

정리:

- `sealed`는 상속 가능한 클래스를 제한한다.
- `permits`로 허용할 자식 클래스를 지정한다.
- 자식 클래스는 `final`, `sealed`, `non-sealed` 중 하나로 선언해야 한다.
- 상속 계층을 명확하게 제한하고 싶을 때 사용할 수 있다.

## 5. 템플릿 메서드 패턴

템플릿 메서드 패턴은 부모 클래스에서 전체 처리 순서를 정하고, 자식 클래스에서 세부 동작을 구현하는 방식이다.

[실습](https://velog.io/@bksong9903/java-day08#14-%ED%85%9C%ED%94%8C%EB%A6%BF-%EB%A9%94%EC%84%9C%EB%93%9C-%ED%8C%A8%ED%84%B4-%EC%8B%A4%EC%8A%B5)에서는 `Notification` 추상 클래스가 발송 흐름을 고정했다.

```java
public final void send() {
    if (!validate()) {
        System.out.println("발송 실패");
        return;
    }

    String formatted = formatMessage();
    deliver(formatted);
    logDelivery();
}
```

`send()`를 `final`로 선언하면 자식 클래스가 발송 순서를 바꿀 수 없다.

자식 클래스는 실제 발송 방식만 구현한다.

```java
protected abstract void deliver(String formattedMessage);
```

흐름:

```text
validate()
→ formatMessage()
→ deliver()
→ logDelivery()
```

정리:

- 부모 클래스가 공통 처리 순서를 정한다.
- 자식 클래스는 바뀌는 부분만 구현한다.
- `final` 메서드로 전체 흐름을 고정할 수 있다.
- `protected` 메서드로 자식 클래스가 공통 로직을 재사용할 수 있다.
- 공통 프로세스가 있고 세부 구현만 달라질 때 사용할 수 있다.

## 6. 인터페이스와 구현체 분리

인터페이스는 클래스가 구현해야 할 규칙을 정의하는 타입이다.

```java
interface PaymentService {
    void transfer(String fromAccount, String toAccount, long amount);
    long getBalance(String accountNumber);
}
```

구현 클래스는 `implements` 키워드로 인터페이스를 구현한다.

```java
class BankTransferService implements PaymentService {
    @Override
    public void transfer(String fromAccount, String toAccount, long amount) {
        System.out.println(amount + "원 이체");
    }

    @Override
    public long getBalance(String accountNumber) {
        return 0;
    }
}
```

사용하는 쪽에서는 구현체 클래스가 아니라 인터페이스 타입에 의존할 수 있다.

```java
class AccountController {
    private PaymentService paymentService;

    public AccountController(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}
```

이렇게 하면 `BankTransferService` 대신 다른 구현체를 넣어도 컨트롤러의 핵심 구조를 유지할 수 있다.

인터페이스에는 다음 메서드들도 선언할 수 있다.

| 메서드 종류      | 특징                             |
| ---------------- | -------------------------------- |
| 추상 메서드      | 구현 클래스가 반드시 구현        |
| `default` 메서드 | 기본 구현을 제공하고 재정의 가능 |
| `static` 메서드  | 인터페이스 이름으로 호출         |
| `private` 메서드 | 인터페이스 내부에서만 사용       |

정리:

- 인터페이스는 구현해야 할 기능의 규칙을 정의한다.
- 인터페이스 타입 변수에는 구현 객체를 대입할 수 있다.
- 구현체를 교체하기 쉬운 구조를 만들 수 있다.
- 클래스는 하나만 상속할 수 있지만 인터페이스는 여러 개 구현할 수 있다.
- 인터페이스 기반 설계는 OCP와 연결된다.

## 7. 중첩 클래스, 익명 객체, 람다식

중첩 클래스는 클래스 안에 선언된 클래스이다.

| 종류                 | 특징                     |
| -------------------- | ------------------------ |
| 인스턴스 멤버 클래스 | 외부 객체를 통해 생성    |
| 정적 멤버 클래스     | 외부 객체 없이 생성 가능 |
| 로컬 클래스          | 메서드 내부에서 선언     |

익명 객체는 이름이 없는 구현 객체를 즉석에서 만드는 방식이다.  
익명 클래스 문법을 사용해서 인터페이스나 추상 클래스를 바로 구현할 수 있다.

인스턴스 멤버 클래스는 외부 클래스 객체가 필요하다.

```java
OuterClass outer = new OuterClass();
OuterClass.InstanceInnerClass inner = outer.new InstanceInnerClass();
```

정적 멤버 클래스는 외부 객체 없이 생성할 수 있다.

```java
OuterClass.StaticInnerClass inner = new OuterClass.StaticInnerClass();
```

익명 객체는 인터페이스나 추상 클래스를 즉석에서 구현할 때 사용한다.

```java
Button.ClickListener listener = new Button.ClickListener() {
    @Override
    public void onClick() {
        System.out.println("버튼 클릭");
    }
};
```

람다식은 추상 메서드가 하나인 함수형 인터페이스를 더 짧게 표현하는 방식이다.

```java
Button.ClickListener listener = () -> System.out.println("버튼 클릭");
```

정리:

- 중첩 클래스는 선언 위치에 따라 인스턴스 멤버 클래스, 정적 멤버 클래스, 로컬 클래스로 나눌 수 있다.
- 인스턴스 멤버 클래스는 외부 객체가 필요하다.
- 정적 멤버 클래스는 외부 객체 없이 생성할 수 있다.
- 익명 객체는 이름 없는 구현 객체를 즉석에서 만들 때 사용한다.
- 람다식은 함수형 인터페이스의 익명 구현을 더 간단히 표현하는 방식이다.
- `default`, `static`, `private` 메서드가 있어도 추상 메서드가 하나라면 람다식 사용이 가능하다.

## 8. Builder 패턴

Builder 패턴은 객체 생성 과정을 별도 Builder 객체로 분리하는 방식이다.

```java
class TransferRequest {
    private String fromAccount;
    private String toAccount;
    private BigDecimal amount;

    static class Builder {
        private TransferRequest req = new TransferRequest();

        Builder from(String acc) {
            req.fromAccount = acc;
            return this;
        }

        Builder to(String acc) {
            req.toAccount = acc;
            return this;
        }

        Builder amount(BigDecimal amt) {
            req.amount = amt;
            return this;
        }

        TransferRequest build() {
            return req;
        }
    }
}
```

사용할 때는 메서드 체이닝 형태로 값을 설정한다.

```java
TransferRequest request = new TransferRequest.Builder()
        .from("110-1234-5678")
        .to("110-9999-0000")
        .amount(new BigDecimal("500000"))
        .build();
```

`from()`, `to()`, `amount()`가 모두 `this`를 반환하기 때문에 연속 호출이 가능하다.

정리:

- Builder 패턴은 객체 생성 과정을 분리한다.
- 정적 중첩 클래스를 이용해 Builder를 만들 수 있다.
- 메서드가 `this`를 반환하면 체이닝할 수 있다.
- 필드가 많거나 생성 과정이 복잡한 객체에서 사용할 수 있다.
- `BigDecimal`처럼 `java.lang`에 없는 클래스는 import가 필요하다.

## 9. JAR, Lombok, 모듈

JAR는 Java Archive의 약자이다.  
Java 클래스 파일과 리소스를 하나의 파일로 묶을 때 사용한다.

터미널 실행:

```powershell
java -jar aa.jar
```

Runnable JAR에는 실행 시작점이 되는 `main()`이 필요하다.

Lombok은 반복 코드를 어노테이션으로 줄여주는 라이브러리이다.

```java
@RequiredArgsConstructor
@AllArgsConstructor
@Data
class Member {
    private final String id;

    @NonNull
    private String name;

    private int age;
}
```

모듈은 `module-info.java`로 의존성과 공개 범위를 관리한다.

```java
module my_application {
    requires my_module_a;
    requires java.sql;
}
```

`exports`는 외부에 공개할 패키지를 지정한다.

```java
module my_module_a {
    exports pack1;
}
```

`requires transitive`는 의존성을 다음 모듈로 전달한다.

```java
module my_module_a {
    requires transitive my_module_b;
}
```

집합 모듈은 여러 모듈 의존성을 묶는 역할을 한다.

```java
module my_application_5 {
    requires transitive my_module_a;
    requires transitive my_module_b;
}
```

정리:

- JAR는 Java 프로젝트를 묶은 파일이다.
- Runnable JAR는 `java -jar`로 실행할 수 있다.
- Lombok은 getter, setter, 생성자, `toString()` 같은 반복 코드를 줄여준다.
- 모듈은 `requires`와 `exports`로 의존성과 공개 범위를 관리한다.
- `java.base`는 기본 모듈이고, `java.lang`은 자동 import된다.
- `java.base`가 아닌 모듈은 `requires`가 필요하다.
- `requires transitive`는 의존성을 다음 모듈로 전달한다.
- 집합 모듈은 여러 모듈을 묶어서 제공할 수 있다.

## 10. 예외 처리와 try-with-resources

예외 처리는 프로그램 실행 중 발생할 수 있는 문제를 처리해서 흐름을 이어가기 위한 방법이다.

```java
try {
    int result = 10 / 0;
    System.out.println(result);
} catch (ArithmeticException e) {
    System.err.println(e.getMessage());
} finally {
    System.out.println("finally 수행");
}
```

`finally`는 예외 발생 여부와 관계없이 실행된다.  
`catch`에서 `return`을 하더라도 `finally`는 실행된다.

`throws`는 예외 처리를 호출한 쪽으로 넘길 때 사용한다.

```java
private static void f2() throws ClassNotFoundException {
    Class.forName("com.shinhan.day10.Cup");
}
```

`throw`는 예외 객체를 직접 발생시킬 때 사용한다.

```java
throw new IllegalArgumentException("매개변수 오류");
```

try-with-resources는 사용한 자원을 자동으로 닫아주는 문법이다.

```java
try (FileReader fr = new FileReader("src/com/shinhan/day11/resourceTest.txt")) {
    int data;

    while ((data = fr.read()) != -1) {
        System.out.print((char) data);
    }
} catch (IOException e) {
    System.err.println(e.getMessage());
}
```

try-with-resources에 들어가는 객체는 `AutoCloseable`을 구현해야 한다.

정리:

- `try-catch-finally`로 예외를 직접 처리할 수 있다.
- `throws`는 예외 처리를 호출한 쪽으로 넘긴다.
- `throw`는 예외 객체를 직접 발생시킨다.
- checked exception은 직접 처리하거나 `throws`로 넘겨야 한다.
- try-with-resources는 자원을 자동으로 닫아준다.
  - `Scanner`, 파일, 스트림처럼 닫아야 하는 자원에서 사용할 수 있다.

## 11. `Object`와 `record`

Java의 모든 클래스는 `Object`를 상속받는다.

대표 메서드는 다음과 같다.

| 메서드       | 역할                  |
| ------------ | --------------------- |
| `toString()` | 객체를 문자열로 표현  |
| `hashCode()` | 객체의 해시 코드 반환 |
| `equals()`   | 객체의 동등성 비교    |

기본 `equals()`는 참조값을 비교한다.  
값 기준 비교가 필요하면 `equals()`를 재정의해야 한다.

```java
@Override
public boolean equals(Object obj) {
    if (!(obj instanceof Money money)) {
        return false;
    }

    return this.amount == money.amount;
}
```

`equals()`를 재정의할 때는 보통 `hashCode()`도 함께 재정의한다.

```java
@Override
public int hashCode() {
    return Integer.hashCode(amount);
}
```

`record`는 값을 담는 객체를 간단히 만들기 위한 문법이다.

```java
public record Person(String name, int age) {
}
```

`record`는 생성자, 접근자, `toString()`, `equals()`, `hashCode()`를 자동으로 만들어준다.

정리:

- `Object`는 Java의 최상위 클래스이다.
- `toString()`은 객체 출력 형식을 정할 때 재정의할 수 있다.
- 값 기준 비교에는 `equals()` 재정의가 필요하다.
- `equals()`를 재정의하면 `hashCode()`도 함께 고려해야 한다.
- `record`는 데이터 전달 목적의 객체를 간결하게 작성할 때 사용할 수 있다.

## 12. 문자열 처리

문자열은 인코딩 방식에 따라 바이트 수가 달라질 수 있다.

```text
UTF-8  : 한글 1자 3바이트
EUC-KR : 한글 1자 2바이트
```

```java
String text = "이것이 자바다";

byte[] byteArr = text.getBytes();
char[] charArr = text.toCharArray();
```

`String`은 불변 객체이다.  
문자열을 반복해서 수정해야 한다면 `StringBuilder`를 사용하는 것이 더 좋다.

```java
StringBuilder sb = new StringBuilder("자바");

sb.append("프로그램");
sb.insert(sb.length(), "!");
sb.delete(0, 1);
sb.replace(0, 1, "J");

String result = sb.toString();
```

문자열을 나눌 때는 `split()`과 `StringTokenizer`를 사용할 수 있다.

```java
String[] arr = datas.split(":|/|,| ");
```

`split()`은 정규 표현식을 기준으로 문자열을 나눈다.

```java
StringTokenizer st = new StringTokenizer(datas, ":/, ");
```

`StringTokenizer`는 전달한 문자들을 각각 구분자로 사용한다.  
정규 표현식이 아니라 구분 문자 목록으로 동작한다.

정리:

- 인코딩 방식에 따라 문자열의 바이트 수가 달라질 수 있다.
- `getBytes()`는 문자열을 바이트 배열로 바꾼다.
- `toCharArray()`는 문자열을 문자 배열로 바꾼다.
- `String`은 불변 객체이다.
- 반복적인 문자열 수정에는 `StringBuilder`를 사용할 수 있다.
- `split()`은 정규 표현식 기준으로 나눈다.
- `StringTokenizer`는 구분 문자 목록 기준으로 나눈다.

## 13. 날짜, 숫자 포맷

Java에서는 날짜와 시간을 여러 타입으로 다룰 수 있다.

| 타입             | 특징                                 |
| ---------------- | ------------------------------------ |
| `java.util.Date` | 레거시 코드에서 자주 볼 수 있음      |
| `java.sql.Date`  | DB의 `DATE` 타입과 연동할 때 사용    |
| `Calendar`       | 연, 월, 일 같은 값을 개별적으로 조회 |
| `LocalDate`      | 날짜 정보                            |
| `LocalDateTime`  | 날짜와 시간 정보                     |
| `Timestamp`      | DB와 날짜/시간 연동 시 사용          |

`Calendar.MONTH`는 0부터 시작하므로 실제 월을 출력하려면 `+ 1`이 필요하다.

```java
Calendar cal = Calendar.getInstance();
System.out.println(cal.get(Calendar.MONTH) + 1);
```

`DecimalFormat`은 숫자를 원하는 형식으로 출력할 때 사용한다.

```java
DecimalFormat df = new DecimalFormat("#,###.##");
System.out.println(df.format(1234567.816));
```

`SimpleDateFormat`은 날짜를 문자열로 포맷할 때 사용한다.

```java
SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");
System.out.println(sdf.format(new Date()));
```

주의할 점:

- `HH`는 24시간 기준이다.
- `hh`는 12시간 기준이다.
- `MM`은 월이다.
- `mm`은 분이다.

정리:

- `java.util.Date`, `Calendar`는 레거시 API이다.
- 새 코드에서는 `LocalDate`, `LocalDateTime`도 같이 고려해야 한다.
- `DecimalFormat`은 숫자 출력 형식을 지정한다.
- `SimpleDateFormat`은 날짜 출력 형식을 지정한다.

## 14. 정규 표현식

정규 표현식은 문자열이 특정 패턴을 만족하는지 확인하거나 특정 패턴을 찾아낼 때 사용한다.

전화번호 형식 확인:

```java
String phoneNumber = "010-1234-5678";
String regExp = "[01]{3}-\\d{3,4}-[0-9]{4}";

boolean result = Pattern.matches(regExp, phoneNumber);
```

문자열 안에서 전화번호 찾기:

```java
String text = "고객센터010-1234-1234 또는 02-5678-5678 팩스는 031-9000-9111";
String regExp = "(\\d{2,3})-(\\d{3,4})-(\\d{4})";

Pattern pattern = Pattern.compile(regExp);
Matcher matcher = pattern.matcher(text);

while (matcher.find()) {
    System.out.println(matcher.group());
    System.out.println(matcher.group(1));
    System.out.println(matcher.group(2));
    System.out.println(matcher.group(3));
}
```

괄호 `()`를 사용하면 캡처 그룹을 만들 수 있다.

이메일 정규식 예시:

```java
String text = "고객센터 user01@example.com 또는 user02@test.com";
String regExp = "\\b([A-Za-z][A-Za-z0-9._%+-]*)@([A-Za-z0-9.-]+\\.[A-Za-z]{2,})\\b";
```

정리:

- `Pattern.matches()`는 전체 문자열이 패턴과 일치하는지 확인한다.
- `Pattern.compile()`과 `Matcher`를 사용하면 문자열 안에서 패턴을 찾을 수 있다.
- `matcher.find()`는 다음 매칭 결과를 찾는다.
- `group()`은 전체 매칭 결과를 반환한다.
- `group(1)`, `group(2)`는 캡처 그룹을 반환한다.
- Java 문자열 안에서는 `\\d`, `\\b`, `\\.`처럼 백슬래시를 한 번 더 이스케이프해야 한다.

## 15. 리플렉션과 어노테이션

리플렉션은 클래스의 메타 정보를 프로그램에서 확인하는 기능이다.

```java
Class<?> cls = Account.class;
System.out.println(cls.getSimpleName());
```

문자열로 클래스 정보를 가져올 수도 있다.

```java
Class<?> cls = Class.forName("com.shinhan.day07.Account");
```

필드 정보 조회:

```java
Field[] fields = cls.getDeclaredFields();

for (Field field : fields) {
    System.out.println(field.getName());
    System.out.println(Modifier.toString(field.getModifiers()));
    System.out.println(field.getType().getSimpleName());
}
```

리소스 파일도 클래스 기준으로 읽을 수 있다.

```java
InputStream is = cls.getResourceAsStream("resourceTest.txt");
```

위 방식은 리소스 파일이 클래스 패스 위치에 있어야 한다.  
위치가 맞지 않으면 `null`이 될 수 있다.

어노테이션은 코드에 붙이는 설정 정보이다.

```java
@Target({ ElementType.METHOD })
@Retention(RetentionPolicy.RUNTIME)
public @interface PrintAnnotation {
    String value() default "-";
    int number() default 7;
}
```

`RetentionPolicy.RUNTIME`이면 실행 중 리플렉션으로 어노테이션 정보를 읽을 수 있다.

```java
PrintAnnotation printAnnotation = method.getAnnotation(PrintAnnotation.class);
```

정리:

- 리플렉션은 클래스의 메타 정보를 확인하는 기능이다.
- `Class<?>` 타입을 사용해 클래스 정보를 다룬다.
- `getFields()`는 public 필드 중심으로 조회한다.
- `getDeclaredFields()`는 선언된 필드를 접근 제한자와 관계없이 조회한다.
- `getResourceAsStream()`은 리소스를 스트림으로 읽는다.
- 어노테이션은 `@`로 작성하는 설정 정보이다.
- `@Target`은 어노테이션을 붙일 수 있는 위치를 지정한다.
- `@Retention`은 어노테이션 정보가 유지되는 범위를 지정한다.
- `method.invoke()`로 리플렉션 기반 메서드 호출이 가능하다.

## 16. 이번 주에 헷갈렸던 부분

### 16-1. 추상 클래스와 인터페이스 구분

추상 클래스와 인터페이스는 둘 다 추상 메서드를 가질 수 있어서 비슷하게 느껴질 수 있다.

- 공통 `상태`와 기본 구조가 필요하면 추상 클래스
- 특정 `기능`을 여러 클래스에 부여하고 싶으면 인터페이스

예를 들어 `Shape`는 도형의 공통 구조와 상태를 가질 수 있으므로 추상 클래스로 두는 것이 자연스럽다.  
반면 `Resizable`은 크기 변경 가능 여부라는 기능만 표현하므로 인터페이스로 분리하는 것이 자연스럽다.

---

### 16-2. 필드 하이딩과 오버라이딩

업캐스팅 후 메서드와 필드는 다르게 동작한다.

```java
Parent parent = new Child();
```

이 상태에서 오버라이딩된 메서드는 실제 객체 타입인 `Child` 기준으로 실행된다.  
하지만 필드는 참조 변수 타입인 `Parent` 기준으로 접근된다.

필드는 오버라이딩되지 않고 하이딩된다는 점을 다시 확인했다.

---

### 16-3. 람다식 사용 조건

람다식은 코드가 짧아져서 편하지만, 아무 인터페이스에나 사용할 수 있는 것은 아니다.

구현해야 할 추상 메서드가 하나인 함수형 인터페이스에서만 사용할 수 있다.  
`default`, `static`, `private` 메서드가 있더라도 추상 메서드가 하나라면 람다식 사용이 가능하다.

---

### 16-4. 모듈의 `exports`와 `requires`

라이브러리 방식과 모듈 방식이 둘 다 외부 코드를 가져다 쓰는 방식이다.

모듈 방식은 `module-info.java`에서 공개할 패키지를 직접 정한다는 점이 다르다.

- `requires`: 사용할 모듈 지정
- `exports`: 외부에 공개할 패키지 지정
- `requires transitive`: 의존성을 다음 모듈로 전달

라이브러리는 가져다 쓰는 느낌에 가깝고, 모듈은 공개 범위까지 관리하는 방식에 가깝다고 정리할 수 있다.

---

### 16-5. 정규 표현식의 백슬래시

정규 표현식 자체에서는 `\d`, `\.`처럼 쓰지만, Java 문자열 안에서는 백슬래시를 한 번 더 이스케이프해야 한다.

```java
String regExp = "\\d+";
```

문서로 볼 때와 Java 코드 안에 넣을 때 표현이 달라져서 헷갈릴 수 있다.

- JAR, Lombok, 모듈

인터페이스와 람다식은 구현체를 분리하고 필요한 동작을 외부에서 주입하는 흐름으로 볼 수 있었다.  
모듈과 어노테이션은 코드 자체뿐 아니라 코드가 공개되고 실행되는 방식까지 관리하는 개념으로 이어졌다.

## 18. 면접 질문과 답변

### Q1. 추상 클래스와 인터페이스의 차이는 무엇인가요?

추상 클래스는 공통 상태와 공통 동작을 부모 클래스에 정의하고, 일부 메서드만 자식 클래스에서 구현하도록 만들 때 사용합니다.

인터페이스는 특정 기능의 규칙을 정의하고, 여러 클래스가 같은 기능을 구현하도록 만들 때 사용합니다.

예를 들어 도형의 공통 필드나 기본 구조가 필요하면 추상 클래스를 사용할 수 있고, 크기 변경 가능 여부처럼 특정 기능만 부여하고 싶다면 인터페이스로 분리하는 것이 자연스럽습니다.

정리하면, 공통 상태와 기본 구조가 필요하면 추상 클래스, 기능의 규칙을 여러 클래스에 적용하고 싶으면 인터페이스를 사용합니다.

---

### Q2. 오버라이딩이란 무엇인가요?

오버라이딩은 부모 클래스에서 상속받은 메서드를 자식 클래스에서 다시 정의하는 것입니다.

부모 타입 변수로 자식 객체를 참조하더라도, 오버라이딩된 메서드는 실제 객체 타입 기준으로 실행됩니다.

```java
Parent parent = new Child();
parent.method(); // Child의 method 실행
```

오버라이딩을 사용하면 같은 메서드 호출로 객체마다 다른 동작을 만들 수 있고, 이것이 다형성과 연결됩니다.

---

### Q3. 업캐스팅과 다운캐스팅의 차이는 무엇인가요?

업캐스팅은 자식 객체를 부모 타입으로 참조하는 것입니다.

```java
Parent parent = new Child();
```

업캐스팅 후에는 부모 타입에 선언된 멤버만 사용할 수 있습니다.
하지만 오버라이딩된 메서드는 실제 객체 타입 기준으로 실행합니다.

다운캐스팅은 부모 타입으로 참조 중인 객체를 다시 자식 타입으로 변환하는 것입니다.

```java
if (parent instanceof Child child) {
    child.childMethod();
}
```

잘못된 다운캐스팅은 `ClassCastException`이 발생할 수 있으므로 `instanceof`로 실제 타입을 확인하는 것이 안전합니다.

---

### Q4. 필드 하이딩과 메서드 오버라이딩의 차이는 무엇인가요?

메서드는 오버라이딩되면 실제 객체 타입 기준으로 실행됩니다.

하지만 필드는 오버라이딩되지 않습니다.
부모와 자식 클래스에 같은 이름의 필드가 있으면, 참조 변수 타입 기준으로 필드에 접근합니다.

```java
Parent parent = new Child();
System.out.println(parent.value); // Parent의 value
```

즉, 메서드는 실제 객체 타입 기준, 필드는 참조 변수 타입 기준으로 동작합니다.

---

### Q5. `sealed` 클래스는 무엇인가요?

`sealed` 클래스는 상속 가능한 자식 클래스를 제한하는 클래스입니다.

```java
sealed class BankEvent permits DepositEvent, WithdrawEvent {
}
```

`permits`를 사용해 어떤 클래스만 상속할 수 있는지 명시합니다.

`sealed` 클래스를 상속받은 클래스는 `final`, `sealed`, `non-sealed` 중 하나로 선언해야 합니다.

- `final`: 더 이상 상속 불가
- `sealed`: 다시 상속 대상을 제한
- `non-sealed`: 상속 제한 해제

상속 계층을 명확하게 제한하고 싶을 때 사용합니다.

---

### Q6. 템플릿 메서드 패턴은 무엇인가요?

템플릿 메서드 패턴은 부모 클래스에서 전체 처리 순서를 정하고, 자식 클래스에서 세부 동작을 구현하는 방식입니다.

예를 들어 알림 발송 흐름이 다음과 같다고 하면,

```text
validate()
→ formatMessage()
→ deliver()
→ logDelivery()
```

부모 클래스는 이 순서를 `final` 메서드로 고정하고, 자식 클래스는 실제 발송 방식인 `deliver()`만 구현하게 만들 수 있습니다.

이렇게 하면 공통 흐름은 유지하면서, 세부 구현만 자식 클래스에서 바꿀 수 있습니다.

---

### Q7. 인터페이스를 사용하는 이유는 무엇인가요?

인터페이스는 구현 클래스가 지켜야 할 규칙을 정의할 때 사용합니다.

사용하는 쪽에서 구현체 클래스가 아니라 인터페이스 타입에 의존하면 구현체를 쉽게 교체할 수 있습니다.

```java
PaymentService paymentService = new BankTransferService();
```

이후 `BankTransferService` 대신 `FintechTransferService`를 넣어도, 사용하는 쪽의 핵심 코드는 크게 바뀌지 않습니다.

이 구조는 확장에는 열려 있고 변경에는 닫혀 있어야 한다는 OCP 원칙과 연결됩니다.

---

### Q8. 인터페이스의 `default`, `static`, `private` 메서드는 각각 어떤 역할인가요?

`default` 메서드는 인터페이스 안에서 기본 구현을 제공합니다.
구현 클래스에서 그대로 사용할 수도 있고, 필요하면 재정의할 수도 있습니다.

`static` 메서드는 인터페이스 이름으로 직접 호출할 수 있습니다.

```java
InterfaceName.staticMethod();
```

`private` 메서드는 인터페이스 내부에서만 사용할 수 있는 메서드입니다.  
주로 `default` 메서드나 `static` 메서드 안의 중복 로직을 분리할 때 사용합니다.

---

### Q9. 익명 객체와 람다식의 차이는 무엇인가요?

익명 객체는 이름 없는 구현 객체를 즉석에서 만드는 방식입니다.

```java
Button.ClickListener listener = new Button.ClickListener() {
    @Override
    public void onClick() {
        System.out.println("클릭");
    }
};
```

람다식은 추상 메서드가 하나인 함수형 인터페이스의 익명 구현을 더 짧게 표현하는 방식입니다.

```java
Button.ClickListener listener = () -> System.out.println("클릭");
```

즉, 람다식은 함수형 인터페이스의 구현을 더 간결하게 표현하는 문법이라고 볼 수 있습니다.  
익명 객체와 비슷하게 사용할 수 있지만, 익명 클래스와 완전히 같은 구조는 아닙니다.

또한 구현해야 할 추상 메서드가 하나인 인터페이스에서만 사용할 수 있습니다.

---

### Q10. Builder 패턴은 왜 사용하나요?

Builder 패턴은 객체 생성 과정을 별도 Builder 객체로 분리하는 방식입니다.

생성자의 매개변수가 많거나, 선택적으로 설정해야 하는 값이 많을 때 생성자 호출이 복잡해질 수 있습니다.

```java
TransferRequest request = new TransferRequest.Builder()
        .from("A")
        .to("B")
        .amount(new BigDecimal("500000"))
        .build();
```

Builder를 사용하면 어떤 값을 설정하는지 코드에서 잘 드러나고, 메서드 체이닝을 통해 객체 생성 과정을 읽기 쉽게 만들 수 있기 때문입니다.

---

### Q11. 라이브러리 방식과 모듈 방식의 차이는 무엇인가요?

라이브러리 방식은 JAR 파일을 classpath에 추가해서 사용하는 방식입니다.

모듈 방식은 `module-info.java`를 통해 어떤 모듈을 사용할지, 어떤 패키지를 외부에 공개할지 명시할 수 있습니다.

```java
module my_application {
    requires my_module_a;
}
```

```java
module my_module_a {
    exports pack1;
}
```

라이브러리 방식은 가져다 쓰는 느낌에 가깝고, 모듈 방식은 의존성과 공개 범위까지 관리하는 방식에 가깝습니다.

---

### Q12. `requires`, `exports`, `requires transitive`의 차이는 무엇인가요?

`requires`는 현재 모듈이 다른 모듈을 사용한다는 의미입니다.

```java
requires my_module_a;
```

`exports`는 현재 모듈의 특정 패키지를 외부에 공개한다는 의미입니다.

```java
exports pack1;
```

`requires transitive`는 의존성을 다음 모듈로 전달하겠다는 의미입니다.

```java
requires transitive my_module_b;
```

즉, A 모듈이 B 모듈을 `requires transitive`로 선언하면, A를 사용하는 다른 모듈도 B의 공개 패키지를 사용할 수 있게 됩니다.

---

### Q13. `throw`와 `throws`의 차이는 무엇인가요?

`throw`는 예외 객체를 직접 발생시킬 때 사용합니다.

```java
throw new IllegalArgumentException("잘못된 값");
```

`throws`는 메서드 내부에서 예외를 직접 처리하지 않고 호출한 쪽으로 넘길 때 사용합니다.

```java
public void method() throws IOException {
}
```

정리하면, `throw`는 예외 발생, `throws`는 예외 처리를 호출한 쪽으로 넘기는 선언입니다.

---

### Q14. checked exception은 무엇인가요?

checked exception은 컴파일 시점에 예외 처리 여부를 확인하는 예외입니다.

대표적으로 `IOException`, `ClassNotFoundException` 등이 있습니다.

checked exception이 발생할 수 있는 코드는 반드시 `try-catch`로 직접 처리하거나, `throws`로 호출한 쪽에 넘겨야 합니다.

```java
public void readFile() throws IOException {
}
```

반면 `RuntimeException` 계열은 unchecked exception으로, 컴파일러가 예외 처리를 강제하지 않습니다.

---

### Q15. try-with-resources는 무엇인가요?

try-with-resources는 사용한 자원을 자동으로 닫아주는 문법입니다.

```java
try (FileReader fr = new FileReader("test.txt")) {
    int data = fr.read();
} catch (IOException e) {
    System.err.println(e.getMessage());
}
```

파일, 스트림, `Scanner`처럼 사용 후 닫아야 하는 자원에 사용할 수 있습니다.

try-with-resources에 들어가는 객체는 `AutoCloseable`을 구현하고 있어야 합니다.

---

### Q16. `equals()`와 `hashCode()`는 왜 같이 재정의해야 하나요?

`equals()`는 두 객체가 같은지 비교하는 메서드이고, `hashCode()`는 객체의 해시 코드를 반환하는 메서드입니다.

`HashSet`, `HashMap` 같은 해시 기반 컬렉션은 객체를 비교할 때 `hashCode()`와 `equals()`를 함께 사용합니다.

값이 같은 객체인데 `hashCode()`가 다르면 해시 기반 컬렉션에서 같은 객체로 처리되지 않을 수 있습니다.

그래서 값 기준 비교가 필요한 클래스에서는 `equals()`와 `hashCode()`를 함께 재정의하는 것이 안전합니다.

---

### Q17. `record`는 무엇인가요?

`record`는 데이터를 담는 객체를 간결하게 만들기 위한 문법입니다.

```java
public record Person(String name, int age) {
}
```

`record`는 생성자, 접근자, `toString()`, `equals()`, `hashCode()`를 자동으로 생성합니다.

일반 getter처럼 `getName()`을 사용하는 것이 아니라, 필드명과 같은 `name()` 형태의 접근자를 사용합니다.

값을 담는 DTO 성격의 객체를 간단히 작성할 때 사용할 수 있습니다.

---

### Q18. `String`과 `StringBuilder`의 차이는 무엇인가요?

`String`은 불변 객체입니다.
문자열을 수정하는 것처럼 보이는 연산을 해도 기존 문자열이 바뀌는 것이 아니라 새로운 문자열 객체가 만들어집니다.

반면 `StringBuilder`는 내부 값을 변경할 수 있습니다.

```java
StringBuilder sb = new StringBuilder("Java");
sb.append(" Study");
```

문자열을 반복해서 수정하거나 누적해야 한다면 `StringBuilder`를 사용하는 것이 더 좋습니다.
