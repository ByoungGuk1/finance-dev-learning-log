## 2. Oracle 기본 조회와 수업 환경

Oracle 11g 기준으로 진행했고, HR 계정의 `EMPLOYEES`, `DEPARTMENTS`, `JOBS` 같은 기본 테이블을 중심으로 진행했다.

기본 조회 구조는 다음과 같다.

```sql
SELECT 컬럼명
FROM 테이블명;
```

전체 컬럼을 조회할 때는 `*`를 사용할 수 있다.

```sql
SELECT *
FROM employees;
```

테이블 구조는 `DESC`로 확인한다.

```sql
DESC employees;
```

Oracle에서는 실제 테이블이 없어도 계산식이나 날짜 함수 결과를 확인하기 위해 `DUAL` 테이블을 사용할 수 있다.

```sql
SELECT SYSDATE
FROM dual;
```

정리:

- Oracle SQL은 `SELECT ... FROM ...` 구조로 조회한다.
- `DESC`는 테이블 구조를 확인할 때 사용한다.
- `DUAL`은 단일 값, 함수 결과, 계산식을 확인할 때 사용하는 더미 테이블이다.
- `SYSDATE`는 현재 날짜와 시간을 반환한다.
- HR 계정의 기본 테이블을 기준으로 수업을 진행했다.

## 3. 무결성 제약조건과 자료형

데이터베이스는 잘못된 데이터가 들어가지 않도록 무결성 제약조건을 사용한다.

정리한 무결성은 다음과 같다.

| 무결성        | 관련 제약조건 | 의미                             |
| ------------- | ------------- | -------------------------------- |
| 개체 무결성   | `PRIMARY KEY` | 각 행을 유일하게 식별            |
| 참조 무결성   | `FOREIGN KEY` | 부모 테이블에 존재하는 값만 참조 |
| 도메인 무결성 | `CHECK`       | 컬럼 값의 범위나 조건 제한       |
| 고유 무결성   | `UNIQUE`      | 특정 컬럼 값 중복 방지           |

`PRIMARY KEY`는 `NOT NULL`과 `UNIQUE` 성격을 함께 가진다.

```text
PRIMARY KEY = NOT NULL + UNIQUE
```

| 자료형         | 의미                               |
| -------------- | ---------------------------------- |
| `VARCHAR2(n)`  | 가변 길이 문자열                   |
| `CLOB`         | 긴 문자열                          |
| `NUMBER`       | 숫자                               |
| `NUMBER(n, m)` | 전체 n자리, 소수점 이하 m자리 숫자 |
| `DATE`         | 날짜와 시간                        |
| `TIMESTAMP`    | 더 정밀한 날짜와 시간              |

정리:

- 제약조건은 데이터 무결성을 지키기 위한 규칙이다.
- 오류 메시지에 나오는 제약조건 이름을 보면 어떤 조건을 위반했는지 추적할 수 있다.
- Oracle의 `DATE`는 날짜뿐 아니라 시, 분, 초까지 포함한다.
- 숫자 타입은 대부분 `NUMBER` 계열로 다룬다.

## 4. `WHERE` 조건 검색과 `NULL`

조건에 맞는 행만 조회할 때는 `WHERE`절을 사용한다.

```sql
SELECT employee_id, first_name, salary
FROM employees
WHERE salary >= 10000;
```

자주 사용한 조건 연산자는 다음과 같다.

| 연산자            | 의미                   |
| ----------------- | ---------------------- |
| `=`               | 같다                   |
| `<>`              | 다르다                 |
| `BETWEEN A AND B` | A 이상 B 이하          |
| `IN`              | 여러 값 중 하나와 일치 |
| `LIKE`            | 문자열 패턴 검색       |
| `IS NULL`         | NULL 여부 확인         |
| `IS NOT NULL`     | NULL이 아닌 값 확인    |

`LIKE`에서는 `%`와 `_`를 사용한다.

| 패턴     | 의미                 |
| -------- | -------------------- |
| `'S%'`   | S로 시작             |
| `'%a%'`  | a 포함               |
| `'_ING'` | 앞 한 글자 + ING     |
| `'A___'` | A로 시작하는 네 글자 |

`NULL`은 값이 없거나 알 수 없다는 의미이다.  
`= NULL`처럼 비교하지 않는다.

```sql
-- 잘못된 방식
WHERE commission_pct = NULL

-- 올바른 방식
WHERE commission_pct IS NULL
```

`NOT IN`에 `NULL`이 포함되면 결과가 예상과 다르게 나올 수 있다.

```sql
WHERE department_id NOT IN (10, NULL)
```

정리:

- `WHERE`는 행 단위 조건 검색이다.
- `BETWEEN`은 양쪽 값을 모두 포함한다.
- `LIKE`에서 `%`는 여러 글자, `_`는 한 글자를 의미한다.
- `NULL`은 `=`로 비교하지 않고 `IS NULL`을 사용한다.
- `NOT IN`에 `NULL`이 섞이면 결과가 나오지 않을 수 있다.
- `AND`가 `OR`보다 먼저 처리되므로 복합 조건은 괄호를 명확히 쓰는 것이 좋다.

## 5. 단일행 함수와 변환 함수

단일행 함수는 한 행을 입력받아 한 행의 결과를 반환하는 함수이다.

### 문자 함수

| 함수               | 의미                    |
| ------------------ | ----------------------- |
| `UPPER()`          | 대문자 변환             |
| `LOWER()`          | 소문자 변환             |
| `INITCAP()`        | 각 단어 첫 글자 대문자  |
| `SUBSTR()`         | 문자열 일부 추출        |
| `INSTR()`          | 특정 문자열 위치        |
| `LENGTH()`         | 문자열 길이             |
| `REPLACE()`        | 문자열 치환             |
| `TRIM()`           | 공백 제거               |
| `LPAD()`, `RPAD()` | 왼쪽/오른쪽 문자 채우기 |

### 숫자 함수

| 함수      | 의미   |
| --------- | ------ |
| `ROUND()` | 반올림 |
| `TRUNC()` | 버림   |
| `CEIL()`  | 올림   |
| `FLOOR()` | 내림   |

### 날짜 함수

| 함수               | 의미                  |
| ------------------ | --------------------- |
| `SYSDATE`          | 현재 날짜와 시간      |
| `MONTHS_BETWEEN()` | 두 날짜 사이 개월 수  |
| `ADD_MONTHS()`     | 날짜에 개월 수 더하기 |
| `LAST_DAY()`       | 해당 월의 마지막 날짜 |
| `EXTRACT()`        | 연, 월, 일 추출       |

근무년차 계산식:

```sql
TRUNC(MONTHS_BETWEEN(SYSDATE, hire_date) / 12)
```

변환 함수는 문자, 숫자, 날짜의 표현 방식을 바꿀 때 사용한다.

| 함수          | 의미                      |
| ------------- | ------------------------- |
| `TO_CHAR()`   | 날짜나 숫자를 문자로 변환 |
| `TO_NUMBER()` | 문자를 숫자로 변환        |
| `TO_DATE()`   | 문자를 날짜로 변환        |

정리:

- 날짜를 출력 형식에 맞게 보여줄 때는 `TO_CHAR()`를 사용한다.
- 문자를 날짜로 바꿀 때는 `TO_DATE()`를 사용한다.
- 현재 날짜는 `SYSDATE`이고, `DATE`는 자료형 이름이다.
- `MONTHS_BETWEEN()`을 이용해 근무개월 수와 근무년차를 계산할 수 있다.

## 6. 그룹 함수, `GROUP BY`, `HAVING`

그룹 함수는 여러 행을 입력받아 하나의 결과를 반환한다.

| 함수          | 의미                |
| ------------- | ------------------- |
| `COUNT(*)`    | 전체 행 수          |
| `COUNT(컬럼)` | NULL이 아닌 값의 수 |
| `SUM()`       | 합계                |
| `AVG()`       | 평균                |
| `MIN()`       | 최솟값              |
| `MAX()`       | 최댓값              |

`GROUP BY`는 특정 기준으로 데이터를 묶을 때 사용한다.

```sql
SELECT department_id,
       COUNT(*) AS "직원수",
       AVG(salary) AS "평균급여"
FROM employees
GROUP BY department_id;
```

그룹화된 결과에 조건을 걸 때는 `HAVING`을 사용한다.

```sql
SELECT department_id,
       COUNT(*) AS "직원수"
FROM employees
GROUP BY department_id
HAVING COUNT(*) >= 5;
```

소계와 총계를 함께 볼 때는 `ROLLUP`을 사용할 수 있다.

```sql
SELECT department_id,
       job_id,
       SUM(salary)
FROM employees
GROUP BY ROLLUP(department_id, job_id);
```

정리:

- `COUNT(*)`는 전체 행 수를 센다.
- `COUNT(컬럼)`은 NULL을 제외한다.
- 그룹 함수가 아닌 컬럼을 `SELECT`에 쓰면 `GROUP BY`에 포함해야 한다.
- 행 단위 조건은 `WHERE`, 그룹 단위 조건은 `HAVING`에 작성한다.
- `ROLLUP`은 소계와 총계를 함께 만들 수 있다.
- `GROUPING()`은 일반 행과 소계/총계 행을 구분할 때 사용한다.
- `LISTAGG()`는 여러 행의 문자열을 한 줄로 모을 때 사용한다.

## 7. `JOIN`

`JOIN`은 두 개 이상의 테이블을 연결해서 조회하는 문법이다.

가장 기본적인 조인은 `INNER JOIN`이다.

```sql
SELECT e.first_name,
       d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id;
```

`OUTER JOIN`은 한쪽 테이블을 기준으로 매칭되지 않는 데이터도 포함한다.

```sql
SELECT e.first_name,
       NVL(d.department_name, '<부서없음>') AS department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.department_id;
```

같은 테이블을 두 번 사용하면 `SELF JOIN`이다.

```sql
SELECT e.first_name AS employee_name,
       m.first_name AS manager_name
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.employee_id;
```

정리:

- `INNER JOIN`은 양쪽 테이블에 모두 매칭되는 데이터만 출력한다.
- `LEFT JOIN`은 왼쪽 테이블 기준으로 모두 출력한다.
- `RIGHT JOIN`은 오른쪽 테이블 기준으로 모두 출력한다.
- `FULL OUTER JOIN`은 양쪽에서 매칭되지 않는 데이터까지 출력한다.
- `SELF JOIN`은 같은 테이블에 서로 다른 별칭을 붙여 조인한다.
- 직원과 관리자 관계처럼 같은 테이블 내부 관계를 조회할 때 `SELF JOIN`을 사용할 수 있다.

## 8. 서브쿼리와 다중행 연산자

서브쿼리는 SQL 안에 포함된 또 다른 SQL이다.

조건값을 직접 쓰지 않고 다른 조회 결과로 대체할 수 있다.

```sql
SELECT first_name, salary
FROM employees
WHERE salary >= (
    SELECT AVG(salary)
    FROM employees
);
```

서브쿼리는 결과 개수에 따라 단일행 서브쿼리와 다중행 서브쿼리로 나눌 수 있다.

| 구분            | 설명           | 사용 연산자                  |
| --------------- | -------------- | ---------------------------- |
| 단일행 서브쿼리 | 결과가 하나    | `=`, `>`, `<`, `>=`, `<=`    |
| 다중행 서브쿼리 | 결과가 여러 행 | `IN`, `ANY`, `ALL`, `EXISTS` |

`ANY`와 `ALL`은 방향을 잘 구분해야 한다.

| 조건    | 의미                       | 집계로 보면  |
| ------- | -------------------------- | ------------ |
| `< ANY` | 값들 중 하나보다 작으면 참 | `< MAX(...)` |
| `> ANY` | 값들 중 하나보다 크면 참   | `> MIN(...)` |
| `< ALL` | 모든 값보다 작아야 참      | `< MIN(...)` |
| `> ALL` | 모든 값보다 커야 참        | `> MAX(...)` |

`EXISTS`는 값 비교보다 행의 존재 여부를 확인한다.

```sql
SELECT *
FROM departments d
WHERE EXISTS (
    SELECT 1
    FROM employees e
    WHERE e.department_id = d.department_id
);
```

정리:

- 서브쿼리는 조건을 동적으로 만들 때 사용한다.
- 단일행 서브쿼리는 결과가 하나여야 한다.
- 다중행 서브쿼리에는 `IN`, `ANY`, `ALL`, `EXISTS`를 사용한다.
- `IN`은 여러 값 중 하나라도 일치하면 참이다.
- `EXISTS`는 조건에 맞는 행이 존재하는지 확인한다.
- `NOT IN`은 `NULL`에 취약하므로 필요하면 `NOT EXISTS`를 고려한다.

## 9. 인라인 뷰와 Top-N Query

인라인 뷰는 `FROM`절에 사용하는 서브쿼리이다.

```sql
SELECT *
FROM (
    SELECT *
    FROM employees
    ORDER BY salary DESC
)
WHERE ROWNUM <= 5;
```

Oracle 11g 기준으로 정렬 후 상위 N개를 조회하려면 인라인 뷰와 `ROWNUM`을 함께 사용한다.

주의할 점은 `ROWNUM`이 정렬 후 순번이 아니라 조회 과정에서 먼저 붙는다는 점이다.

잘못된 예:

```sql
SELECT *
FROM employees
WHERE ROWNUM <= 5
ORDER BY salary DESC;
```

위 쿼리는 먼저 5명을 뽑고, 그 5명 안에서 정렬될 수 있다.

정리:

- 인라인 뷰는 `FROM`절의 서브쿼리이다.
- `ROWNUM`은 조회 과정에서 먼저 부여된다.
- 정렬 후 상위 N개를 구하려면 안쪽 쿼리에서 먼저 정렬한다.
- 바깥 쿼리에서 `ROWNUM <= N` 조건을 건다.
- N번째만 조회하려면 `ROWNUM`을 별칭으로 만든 뒤 다시 바깥에서 필터링할 수 있다.

## 10. DML, `MERGE`, 트랜잭션

DML은 테이블 안의 데이터를 추가, 수정, 삭제하는 명령어이다.

| 명령어   | 의미                       |
| -------- | -------------------------- |
| `INSERT` | 행 추가                    |
| `UPDATE` | 행 수정                    |
| `DELETE` | 행 삭제                    |
| `MERGE`  | 조건에 따라 수정 또는 추가 |

`UPDATE`와 `DELETE`는 `WHERE` 조건을 반드시 확인해야 한다.

```sql
UPDATE account_test
SET balance = balance - 500000
WHERE customer_name = '홍길동';
```

`MERGE`는 대상 테이블에 같은 데이터가 있으면 `UPDATE`, 없으면 `INSERT`를 수행한다.

```sql
MERGE INTO emp_test t
USING emp_new s
ON (t.employee_id = s.employee_id)
WHEN MATCHED THEN
    UPDATE SET
        t.salary = s.salary,
        t.job_id = s.job_id
WHEN NOT MATCHED THEN
    INSERT (
        employee_id, first_name, last_name, email,
        phone_number, hire_date, job_id, salary,
        commission_pct, manager_id, department_id
    )
    VALUES (
        s.employee_id, s.first_name, s.last_name, s.email,
        s.phone_number, s.hire_date, s.job_id, s.salary,
        s.commission_pct, s.manager_id, s.department_id
    );
```

트랜잭션은 여러 DML을 하나의 작업 단위로 묶는다.

```text
홍길동 계좌에서 차감
김영희 계좌에 증가
```

두 작업 중 하나만 성공하면 데이터 일관성이 깨진다.
그래서 모두 성공하면 `COMMIT`, 문제가 있으면 `ROLLBACK`해야 한다.

```sql
COMMIT;
ROLLBACK;
SAVEPOINT sp1;
ROLLBACK TO sp1;
```

정리:

- DML은 데이터를 변경한다.
- `UPDATE`, `DELETE`에서 `WHERE`가 빠지면 전체 행이 변경될 수 있다.
- `MERGE`는 기존 데이터가 있으면 수정하고 없으면 추가한다.
- 트랜잭션은 여러 DML을 하나의 작업 단위로 묶는다.
- `COMMIT` 전에는 `ROLLBACK`할 수 있다.
- `COMMIT` 후에는 일반적인 `ROLLBACK`으로 되돌릴 수 없다.
- `SAVEPOINT`는 트랜잭션 중간 지점을 저장한다.
- `SELECT FOR UPDATE`는 조회한 행에 잠금을 건다.

## 11. DDL과 제약조건

DDL은 테이블이나 객체의 구조를 정의하거나 변경하는 명령어이다.

| 명령어     | 의미                  |
| ---------- | --------------------- |
| `CREATE`   | 객체 생성             |
| `ALTER`    | 객체 구조 변경        |
| `DROP`     | 객체 삭제             |
| `TRUNCATE` | 데이터 전체 삭제      |
| `COMMENT`  | 테이블/컬럼 설명 추가 |

테이블 생성 예시:

```sql
CREATE TABLE accounts (
    account_id NUMBER(10) NOT NULL,
    account_no CHAR(14) NOT NULL,
    customer_name VARCHAR2(50) NOT NULL,
    balance NUMBER(18, 2) DEFAULT 0,
    CONSTRAINT pk_accounts PRIMARY KEY (account_id),
    CONSTRAINT uq_account_no UNIQUE (account_no),
    CONSTRAINT ck_balance CHECK (balance >= 0)
);
```

기존 테이블을 복사해 새 테이블을 만들 수도 있다.

```sql
CREATE TABLE emp_backup AS
SELECT *
FROM employees;
```

구조만 복사하려면 항상 거짓인 조건을 사용한다.

```sql
CREATE TABLE emp_empty AS
SELECT *
FROM employees
WHERE 1 = 0;
```

정리:

- DDL은 객체 구조를 다룬다.
- Oracle에서 DDL은 실행 시 자동 `COMMIT`이 발생한다.
- `CREATE TABLE AS SELECT`는 구조와 데이터를 복사할 수 있다.
- 기본키나 외래키 같은 제약조건은 그대로 복사되지 않을 수 있다.
- `DROP`은 객체 자체 삭제, `TRUNCATE`는 데이터 전체 삭제이다.
- 둘 다 일반적인 `ROLLBACK`으로 되돌리기 어렵다.
- 제약조건 이름을 명시하면 오류 추적과 관리가 쉽다.

## 12. 데이터베이스 객체

### INDEX

인덱스는 조회 속도를 높이기 위한 객체이다.

```sql
CREATE INDEX idx_emp_dept
ON employees(department_id);
```

정리:

- `PRIMARY KEY`, `UNIQUE` 제약조건 생성 시 인덱스가 자동 생성된다.
- 자주 검색, 조인, 정렬에 사용되는 컬럼은 인덱스 후보가 될 수 있다.
- 반환 행이 많거나 테이블이 작으면 Full Table Scan이 더 유리할 수 있다.
- `INSERT`, `UPDATE`, `DELETE`가 많으면 인덱스 유지 비용이 커질 수 있다.
- 실행 계획은 `EXPLAIN PLAN`과 `DBMS_XPLAN.DISPLAY`로 확인할 수 있다.

### SEQUENCE

시퀀스는 자동 번호를 생성하는 객체이다.

```sql
CREATE SEQUENCE seq_number
START WITH 1
INCREMENT BY 1;
```

```sql
SELECT seq_number.NEXTVAL FROM dual;
SELECT seq_number.CURRVAL FROM dual;
```

정리:

- `NEXTVAL`은 다음 번호를 가져온다.
- `CURRVAL`은 현재 세션에서 마지막으로 가져온 번호를 확인한다.
- `CURRVAL`은 `NEXTVAL`을 먼저 실행한 뒤 사용할 수 있다.

### VIEW

뷰는 `SELECT` 문을 저장한 논리적 객체이다.

```sql
CREATE VIEW vw_emp_dept AS
SELECT e.employee_id,
       e.first_name,
       d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id;
```

정리:

- 뷰는 실제 데이터를 직접 저장하는 일반 테이블은 아니다.
- 저장된 `SELECT` 문을 테이블처럼 조회할 수 있게 한다.
- 복잡한 SQL을 단순화하거나 특정 컬럼만 공개할 때 사용할 수 있다.

### SYNONYM

시노님은 다른 객체에 대한 별칭이다.

```sql
CREATE SYNONYM emp
FOR hr.employees;
```

정리:

- 시노님은 테이블, 뷰, 시퀀스 등에 붙이는 별칭이다.
- 긴 객체명을 줄이거나 다른 스키마 객체에 편하게 접근할 때 사용한다.
- Private Synonym은 생성한 사용자만 사용할 수 있다.
- Public Synonym은 모든 사용자가 사용할 수 있다.

## 13. 사용자, 권한, 롤

Oracle에서는 사용자 계정을 생성하고, 필요한 권한을 부여해야 한다.

```sql
CREATE USER db_student
IDENTIFIED BY student123
DEFAULT TABLESPACE users
TEMPORARY TABLESPACE temp
QUOTA UNLIMITED ON users;
```

사용자 생성만으로는 접속할 수 없다.
접속하려면 `CREATE SESSION` 권한이 필요하다.

```sql
GRANT CREATE SESSION TO db_student;
```

권한은 크게 시스템 권한과 객체 권한으로 나눌 수 있다.

| 구분        | 의미                     | 예시                             |
| ----------- | ------------------------ | -------------------------------- |
| 시스템 권한 | DB 작업 자체에 대한 권한 | `CREATE SESSION`, `CREATE TABLE` |
| 객체 권한   | 특정 객체에 대한 권한    | `SELECT ON hr.employees`         |

권한 부여와 회수는 `GRANT`, `REVOKE`로 처리한다.

```sql
GRANT SELECT ON hr.employees TO db_student;
REVOKE SELECT ON hr.employees FROM db_student;
```

롤은 여러 권한을 묶어둔 권한 그룹이다.

```sql
CREATE ROLE role_fin_read;
GRANT SELECT ON accounts TO role_fin_read;
GRANT role_fin_read TO db_student;
```

정리:

- 사용자는 DB에 접속하는 계정이다.
- 접속하려면 `CREATE SESSION` 권한이 필요하다.
- 시스템 권한과 객체 권한을 구분해야 한다.
- `GRANT`는 권한 부여, `REVOKE`는 권한 회수이다.
- 롤은 여러 권한을 묶어 관리하기 위한 객체이다.

## 14. PL/SQL 기본 구조

PL/SQL은 Oracle에서 사용하는 절차형 SQL 언어이다.

SQL에 변수, 조건문, 반복문, 예외 처리 같은 절차형 문법을 추가해 여러 로직을 하나의 블록으로 묶을 수 있다.

기본 구조:

```sql
DECLARE
    -- 변수 선언
BEGIN
    -- 실행 로직
EXCEPTION
    -- 예외 처리
END;
/
```

| 영역        | 필수 여부 | 역할                  |
| ----------- | --------: | --------------------- |
| `DECLARE`   |      선택 | 변수, 상수, 커서 선언 |
| `BEGIN`     |      필수 | 실행 로직             |
| `EXCEPTION` |      선택 | 예외 처리             |
| `END`       |      필수 | 블록 종료             |

변수 선언 예시:

```sql
DECLARE
    v_emp_id NUMBER := 100;
    v_salary employees.salary%TYPE;
    c_bonus_rate CONSTANT NUMBER := 0.1;
BEGIN
    DBMS_OUTPUT.PUT_LINE(v_emp_id);
END;
/
```

`%TYPE` : 특정 column의 단일 타입

`%ROWTYPE` : 해당 행의 모든 타입

```sql
v_salary employees.salary%TYPE;
v_emp employees%ROWTYPE;
```

정리:

- PL/SQL은 SQL에 절차형 문법을 추가한 구조이다.
- `BEGIN ~ END`는 필수이다.
- `DECLARE`는 변수나 커서를 선언할 때 사용한다.
- `EXCEPTION`은 오류 처리 로직을 작성할 때 사용한다.
- `%TYPE`은 컬럼 타입을 참조한다.
- `%ROWTYPE`은 테이블의 한 행 전체 구조를 참조한다.
- 테이블 구조 변경에 덜 취약한 코드를 만들 수 있다.

## 15. 커서와 예외 처리

`SELECT INTO`는 조회 결과를 변수에 저장한다.

```sql
SELECT first_name, salary
INTO v_name, v_salary
FROM employees
WHERE employee_id = 100;
```

하지만 결과가 정확히 1행이어야 한다.

| 결과     | 발생 가능 예외  |
| -------- | --------------- |
| 0행      | `NO_DATA_FOUND` |
| 2행 이상 | `TOO_MANY_ROWS` |

여러 행을 처리하려면 커서를 사용한다.

명시적 커서 흐름:

```text
OPEN
FETCH
CLOSE
```

```sql
DECLARE
    CURSOR c_emp IS
        SELECT employee_id, first_name, salary
        FROM employees
        WHERE department_id = 90;

    v_id employees.employee_id%TYPE;
    v_name employees.first_name%TYPE;
    v_sal employees.salary%TYPE;
BEGIN
    OPEN c_emp;

    LOOP
        FETCH c_emp INTO v_id, v_name, v_sal;
        EXIT WHEN c_emp%NOTFOUND;

        DBMS_OUTPUT.PUT_LINE(v_id || ' | ' || v_name || ' | ' || v_sal);
    END LOOP;

    CLOSE c_emp;
END;
/
```

Cursor FOR LOOP를 사용하면 커서 열기, 가져오기, 닫기를 자동으로 처리한다.

```sql
BEGIN
    FOR r IN (
        SELECT first_name, salary
        FROM employees
        WHERE department_id = 90
    ) LOOP
        DBMS_OUTPUT.PUT_LINE(r.first_name || ': ' || r.salary);
    END LOOP;
END;
/
```

정리:

- `SELECT INTO`는 단일 행 조회용이다.
- 여러 행은 커서로 처리한다.
- 묵시적 커서는 Oracle이 자동으로 관리한다.
- 명시적 커서는 개발자가 `OPEN`, `FETCH`, `CLOSE`를 직접 제어한다.
- Cursor FOR LOOP는 커서 처리를 자동화한다.
- `SQL%ROWCOUNT`는 직전 DML 처리 행 수를 확인할 때 사용한다.
- 예외 처리에서는 `SQLCODE`, `SQLERRM`을 함께 확인하면 원인 파악에 좋다.

## 16. 프로시저, 함수, 패키지

프로시저와 함수는 DB에 저장되는 PL/SQL 서브프로그램이다.

| 구분      | 프로시저            | 함수                           |
| --------- | ------------------- | ------------------------------ |
| 목적      | 작업 수행           | 값 반환                        |
| 반환      | 직접 `RETURN` 없음  | 반드시 `RETURN` 있음           |
| 실행      | `EXEC`, `CALL`      | `SELECT 함수명(...) FROM dual` |
| 결과 전달 | `OUT` 매개변수 가능 | `RETURN`                       |

프로시저 예시:

```sql
CREATE OR REPLACE PROCEDURE raise_salary (
    p_emp_id IN employees.employee_id%TYPE,
    p_pct IN NUMBER DEFAULT 0.1
)
IS
BEGIN
    UPDATE employees
    SET salary = salary * (1 + p_pct)
    WHERE employee_id = p_emp_id;
END;
/
```

함수 예시:

```sql
CREATE OR REPLACE FUNCTION get_annual_sal (
    p_emp_id IN employees.employee_id%TYPE
)
RETURN NUMBER
IS
    v_monthly employees.salary%TYPE;
BEGIN
    SELECT salary
    INTO v_monthly
    FROM employees
    WHERE employee_id = p_emp_id;

    RETURN v_monthly * 12;
END;
/
```

패키지는 관련된 프로시저, 함수, 변수, 커서, 타입을 하나로 묶는 객체이다.

```text
PACKAGE       -> 명세, 공개 API 선언
PACKAGE BODY  -> 실제 구현
```

정리:

- 프로시저는 작업 수행에 초점이 있다.
- 함수는 값을 반환하는 데 초점이 있다.
- 프로시저는 `IN`, `OUT`, `IN OUT` 매개변수를 사용할 수 있다.
- 함수는 반드시 하나의 값을 `RETURN`해야 한다.
- 패키지는 관련 기능을 묶어 모듈화할 때 사용한다.
- 패키지 명세는 외부에 공개할 부분이고, 본문은 실제 구현이다.
- `USER_OBJECTS`, `USER_SOURCE`, `USER_ERRORS`로 객체 상태, 소스, 오류를 확인할 수 있다.

## 17. 트리거

트리거는 특정 테이블에 DML 이벤트가 발생했을 때 자동으로 실행되는 PL/SQL 객체이다.

```text
INSERT
UPDATE
DELETE
```

프로시저와 트리거의 차이는 실행 방식이다.

| 구분          | 프로시저  | 트리거                                    |
| ------------- | --------- | ----------------------------------------- |
| 실행 방식     | 직접 호출 | DML 이벤트 발생 시 자동 실행              |
| 매개변수      | 사용 가능 | 없음                                      |
| 값 참조       | 매개변수  | `:NEW`, `:OLD`                            |
| 트랜잭션 제어 | 가능      | 일반적으로 직접 `COMMIT`, `ROLLBACK` 불가 |

문장 레벨 트리거는 SQL 문장당 한 번 실행된다.

```sql
CREATE OR REPLACE TRIGGER trg_01
AFTER INSERT
ON emp01
BEGIN
    DBMS_OUTPUT.PUT_LINE('신입사원이 입사했습니다.');
END;
/
```

행 레벨 트리거는 변경된 행마다 실행된다.

```sql
CREATE OR REPLACE TRIGGER trg_02
AFTER INSERT
ON emp01
FOR EACH ROW
BEGIN
    INSERT INTO sal01
    VALUES (
        sal01_salno_seq.NEXTVAL,
        100,
        :NEW.empno
    );
END;
/
```

`:NEW`와 `:OLD`는 행 레벨 트리거에서 사용한다.

| 이벤트   | `:NEW`     | `:OLD`      |
| -------- | ---------- | ----------- |
| `INSERT` | 새 값      | 사용 불가   |
| `UPDATE` | 변경 후 값 | 변경 전 값  |
| `DELETE` | 사용 불가  | 삭제되는 값 |

정리:

- 트리거는 직접 호출하지 않는다.
- DML 이벤트가 발생하면 자동 실행된다.
- `BEFORE`는 DML 실행 전, `AFTER`는 DML 실행 후 트리거이다.
- 문장 레벨 트리거는 SQL 문장당 한 번 실행된다.
- 행 레벨 트리거는 변경된 행마다 실행된다.
- `:NEW`, `:OLD`는 행 레벨 트리거에서만 사용할 수 있다.
- 트리거는 자동 처리에 유용하지만, 데이터 변경 흐름이 숨겨질 수 있으므로 주의해야 한다.

## 18. 이번 주에 다시 볼 부분

### 18-1. `ROWNUM`과 정렬 순서

`ROWNUM`은 정렬 후 순번이 아니라 조회 과정에서 먼저 붙는다.

```sql
SELECT *
FROM employees
WHERE ROWNUM <= 5
ORDER BY salary DESC;
```

이렇게 작성하면 급여 상위 5명을 구하는 것이 아니라, 먼저 조회된 5명을 급여순으로 정렬할 수 있다.

정렬 후 상위 N개를 구하려면 인라인 뷰 안에서 먼저 정렬해야 한다.

```sql
SELECT *
FROM (
    SELECT *
    FROM employees
    ORDER BY salary DESC
)
WHERE ROWNUM <= 5;
```

---

### 18-2. `NULL` 비교와 `NOT IN`

`NULL`은 값이 아니라 알 수 없음에 가깝다.

그래서 `= NULL`이나 `<> NULL`로 비교하면 안 된다.

```sql
WHERE commission_pct IS NULL
```

`NOT IN`에 `NULL`이 포함되면 조건 전체가 UNKNOWN이 되어 결과가 나오지 않을 수 있다.

```sql
WHERE department_id NOT IN (10, NULL)
```

서브쿼리에서 `NOT IN`을 사용할 때는 `IS NOT NULL` 조건을 같이 두거나 `NOT EXISTS`를 고려해야 한다.

---

### 18-3. `WHERE`와 `HAVING`

`WHERE`와 `HAVING`은 둘 다 조건이지만 적용 시점이 다르다.

```text
WHERE  -> 그룹화 전 행 필터
HAVING -> 그룹화 후 그룹 필터
```

집계 함수 조건은 `HAVING`에 작성해야 한다.

```sql
SELECT department_id, COUNT(*)
FROM employees
GROUP BY department_id
HAVING COUNT(*) >= 5;
```

---

### 18-4. `ANY`와 `ALL`

`ANY`는 하나라도 만족하면 참이다.
`ALL`은 전부 만족해야 참이다.

```text
> ANY -> > MIN(...)
> ALL -> > MAX(...)
< ANY -> < MAX(...)
< ALL -> < MIN(...)
```

비교 연산자를 OR로 풀어 보면 이해하기 쉽다.

---

### 18-5. `UPDATE`, `DELETE`의 `WHERE`

`UPDATE`와 `DELETE`에서 `WHERE`가 빠지면 전체 행이 변경될 수 있다.

```sql
UPDATE account_test
SET balance = balance - 500000;
```

위 코드는 특정 계좌가 아니라 전체 계좌 잔액을 차감한다.

수정/삭제 전에는 항상 대상 행을 `SELECT`로 먼저 확인하는 습관이 필요하다.

---

### 18-6. DDL의 자동 `COMMIT`

DDL은 객체 구조를 변경하는 명령어이다.

Oracle에서는 DDL 실행 시 자동 `COMMIT`이 발생한다.  
그래서 DDL 실행 전의 미완료 DML도 같이 `COMMIT`될 수 있다.

```sql
CREATE TABLE emp_backup AS
SELECT *
FROM employees;
```

`DROP`, `TRUNCATE`도 일반적인 `ROLLBACK`으로 되돌리기 어렵기 때문에 실행 전에 확인해야 한다.

---

### 18-7. 인덱스는 항상 빠른가?

인덱스는 조회 속도를 높일 수 있지만 항상 좋은 것은 아니다.

조회해야 하는 행이 많으면 인덱스를 타고 여러 번 접근하는 것보다 전체 테이블을 읽는 것이 더 빠를 수 있다.  
또한 DML이 발생하면 인덱스도 함께 갱신되어야 한다.

정리하면 인덱스는 조회에는 도움이 될 수 있지만, 쓰기 작업에는 비용이 생긴다.

---

### 18-8. `SELECT INTO`는 왜 여러 행을 처리하지 못할까?

`SELECT INTO`는 조회 결과를 변수에 직접 담는다.

변수 하나에는 한 행의 값만 담을 수 있다.
따라서 결과가 여러 행이면 어떤 행을 넣어야 하는지 결정할 수 없다.

```text
0행      -> NO_DATA_FOUND
2행 이상 -> TOO_MANY_ROWS
```

여러 행을 처리하려면 커서를 사용해야 한다.

---

### 18-9. 프로시저와 함수 차이

프로시저는 작업을 수행하는 로직에 적합하다.

```text
프로시저 -> 급여 인상, 계좌 이체, 데이터 변경
```

함수는 값을 계산해서 반환하는 로직에 적합하다.

```text
함수 -> 연봉 계산, 등급 계산, 결과값 반환
```

함수는 반드시 `RETURN`이 있어야 한다.

---

### 18-10. 문장 레벨 트리거와 행 레벨 트리거

문장 레벨 트리거는 DML 문장당 한 번 실행된다.

행 레벨 트리거는 변경된 행마다 실행된다.

```text
문장 레벨 트리거 -> SQL 문장당 1회
행 레벨 트리거   -> 변경된 행마다 1회
```

`:NEW`, `:OLD`는 행 레벨 트리거에서만 사용할 수 있다.

---

## 19. 이번 주 정리

초반에는 `SELECT`, `WHERE`, `ORDER BY`, `ROWNUM`, `NULL` 처리, 무결성 제약조건을 정리했다.  
Oracle의 기본 조회 구조와 함께 `DUAL`, `SYSDATE`, `DESC` 같은 Oracle 특유의 기본 사용법도 확인했다.

중반에는 함수, 집계, 조인, 서브쿼리를 다뤘다.  
문자·숫자·날짜 함수와 변환 함수를 사용해 조회 결과를 가공했고, `GROUP BY`와 `HAVING`으로 그룹별 통계를 구했다.  
`JOIN`에서는 테이블 간 관계를 연결하는 방법을 정리했고, `SELF JOIN`을 통해 직원과 관리자처럼 같은 테이블 내부 관계를 조회하는 방법도 확인했다.

서브쿼리에서는 단일행 서브쿼리와 다중행 서브쿼리를 구분했다.  
`IN`, `ANY`, `ALL`, `EXISTS`의 의미를 비교했고, `ROWNUM`과 인라인 뷰를 이용해 Oracle 11g 기준 Top-N Query를 작성했다.

DML과 트랜잭션에서는 `INSERT`, `UPDATE`, `DELETE`, `MERGE`를 실습했다.  
특히 `UPDATE`, `DELETE`는 `WHERE` 조건에 따라 데이터가 크게 바뀔 수 있으므로 실행 전후 확인이 중요했다.  
트랜잭션에서는 `COMMIT`, `ROLLBACK`, `SAVEPOINT`, `SELECT FOR UPDATE`를 통해 데이터 변경을 안전하게 관리하는 흐름을 확인했다.

후반에는 DDL과 데이터베이스 객체를 정리했다.  
`CREATE TABLE`, `ALTER TABLE`, `DROP`, `TRUNCATE`, `COMMENT`를 통해 테이블 구조를 관리했고, `INDEX`, `SEQUENCE`, `VIEW`, `SYNONYM` 같은 객체도 확인했다.  
사용자, 권한, 롤에서는 시스템 권한과 객체 권한을 구분하고, 최소 권한 원칙을 기준으로 권한을 관리해야 한다는 점을 정리했다.

마지막으로 PL/SQL에서는 SQL에 절차형 로직을 추가하는 방법을 배웠다.  
변수, 조건문, 반복문, 예외 처리, 커서, 프로시저, 함수, 패키지를 정리했고, 트리거를 통해 DML 이벤트에 자동으로 반응하는 객체를 확인했다.

SQL을 단순 조회 언어로만 보는 것이 아니라  
데이터 무결성, 트랜잭션, 객체 관리, 권한, 자동화 로직까지 포함하는 데이터베이스 작업 흐름으로 보는 것이 핵심이다.

## 20. 면접 질문과 답변

### Q1. `WHERE`와 `HAVING`의 차이는 무엇인가요?

`WHERE`는 그룹화 전에 행 단위로 조건을 거는 절입니다.

`HAVING`은 `GROUP BY`로 그룹화한 뒤 그룹 결과에 조건을 거는 절입니다.

예를 들어 부서별 직원 수가 5명 이상인 부서를 찾는다면 집계 함수 `COUNT(*)` 조건이 필요하므로 `HAVING`을 사용합니다.

```sql
SELECT department_id, COUNT(*)
FROM employees
GROUP BY department_id
HAVING COUNT(*) >= 5;
```

정리하면, 일반 행 필터는 `WHERE`, 집계 결과 필터는 `HAVING`입니다.

---

### Q2. `COUNT(*)`와 `COUNT(컬럼)`의 차이는 무엇인가요?

`COUNT(*)`는 전체 행 수를 셉니다.

반면 `COUNT(컬럼)`은 해당 컬럼 값이 `NULL`이 아닌 행만 셉니다.

예를 들어 `commission_pct`가 `NULL`인 직원이 많다면 `COUNT(*)`와 `COUNT(commission_pct)` 결과는 다를 수 있습니다.

```sql
SELECT COUNT(*),
       COUNT(commission_pct)
FROM employees;
```

정리하면, 전체 행 수는 `COUNT(*)`, 특정 컬럼에 값이 있는 행 수는 `COUNT(컬럼)`을 사용합니다.

---

### Q3. `INNER JOIN`과 `OUTER JOIN`의 차이는 무엇인가요?

`INNER JOIN`은 양쪽 테이블에서 조건이 일치하는 데이터만 출력합니다.

`OUTER JOIN`은 한쪽 테이블을 기준으로 매칭되지 않는 데이터도 포함합니다.

예를 들어 직원과 부서를 조인할 때 `INNER JOIN`을 사용하면 부서가 없는 직원은 제외될 수 있습니다.  
부서가 없는 직원까지 보고 싶다면 `LEFT JOIN`을 사용합니다.

```sql
SELECT e.first_name,
       NVL(d.department_name, '<부서없음>') AS department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.department_id;
```

정리하면, 매칭된 데이터만 필요하면 `INNER JOIN`, 기준 테이블의 누락 데이터까지 보고 싶으면 `OUTER JOIN`을 사용합니다.

---

### Q4. 서브쿼리와 조인은 어떻게 구분해서 사용할 수 있나요?

서브쿼리는 다른 쿼리의 결과를 조건값으로 사용할 때 유용합니다.

예를 들어 전체 평균 급여보다 높은 직원을 찾을 때는 평균 급여를 서브쿼리로 구할 수 있습니다.

```sql
SELECT first_name, salary
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);
```

조인은 여러 테이블의 컬럼을 함께 조회해야 할 때 사용합니다.

```sql
SELECT e.first_name, d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id;
```

정리하면, 조건값을 동적으로 구할 때는 서브쿼리, 여러 테이블의 컬럼을 함께 출력할 때는 조인이 자연스럽습니다.

---

### Q5. `ANY`와 `ALL`의 차이는 무엇인가요?

`ANY`는 여러 값 중 하나라도 조건을 만족하면 참입니다.

`ALL`은 여러 값 전체에 대해 조건을 만족해야 참입니다.

```text
> ANY -> 최솟값보다 크면 참
> ALL -> 최댓값보다 커야 참
```

예를 들어 `salary > ANY (3000, 5000, 7000)`은 3000보다만 커도 참입니다.
반면 `salary > ALL (3000, 5000, 7000)`은 7000보다 커야 참입니다.

정리하면 `ANY`는 하나라도 만족, `ALL`은 전부 만족입니다.

---

### Q6. `ROWNUM`으로 정렬 후 상위 N개를 바로 조회할 수 있나요?

바로 조회하면 의도와 다를 수 있습니다.

`ROWNUM`은 정렬 후가 아니라 조회 과정에서 먼저 부여됩니다.

따라서 정렬 후 상위 N개를 구하려면 인라인 뷰 안에서 먼저 정렬하고, 바깥에서 `ROWNUM` 조건을 걸어야 합니다.

```sql
SELECT *
FROM (
    SELECT *
    FROM employees
    ORDER BY salary DESC
)
WHERE ROWNUM <= 5;
```

Oracle 11g 기준 Top-N Query는 인라인 뷰와 `ROWNUM`을 함께 사용합니다.

---

### Q7. `MERGE`는 언제 사용하나요?

`MERGE`는 같은 키가 있으면 수정하고, 없으면 추가해야 할 때 사용합니다.

예를 들어 `emp_new`에 변경 대상 직원과 신규 직원이 섞여 있고, `emp_test`에 반영해야 한다면 `employee_id`를 기준으로 비교할 수 있습니다.

```text
employee_id가 이미 있음 -> UPDATE
employee_id가 없음      -> INSERT
```

배치 작업이나 데이터 적재 작업처럼 기존 데이터와 신규 데이터를 한 번에 반영해야 할 때 유용합니다.

---

### Q8. 트랜잭션이 필요한 이유는 무엇인가요?

트랜잭션은 여러 DML을 하나의 작업 단위로 묶기 위해 필요합니다.

예를 들어 계좌 이체는 출금과 입금이 모두 성공해야 합니다.

```text
홍길동 계좌에서 차감
김영희 계좌에 증가
```

둘 중 하나만 성공하면 데이터 일관성이 깨집니다.  
따라서 모두 성공하면 `COMMIT`, 문제가 생기면 `ROLLBACK`해야 합니다.

정리하면 트랜잭션은 데이터 변경 작업의 원자성과 일관성을 지키기 위한 장치입니다.

---

### Q9. DDL과 DML의 차이는 무엇인가요?

DML은 테이블 안의 데이터를 변경하는 명령어입니다.

```text
INSERT
UPDATE
DELETE
MERGE
```

DDL은 테이블이나 객체의 구조를 변경하는 명령어입니다.

```text
CREATE
ALTER
DROP
TRUNCATE
COMMENT
```

Oracle에서는 DDL 실행 시 자동 `COMMIT`이 발생합니다.  
그래서 DDL은 실행 전 확인이 중요합니다.

---

### Q10. `PRIMARY KEY`와 `UNIQUE`의 차이는 무엇인가요?

둘 다 중복을 막는 제약조건입니다.

하지만 `PRIMARY KEY`는 행을 식별하는 대표 컬럼이므로 `NULL`을 허용하지 않습니다.

`UNIQUE`는 중복은 막지만 `NULL`은 허용될 수 있습니다.

```text
PRIMARY KEY -> 중복 불가 + NULL 불가
UNIQUE      -> 중복 불가 + NULL 가능
```

또한 한 테이블에는 기본키가 하나만 있을 수 있지만, `UNIQUE` 제약조건은 여러 개 만들 수 있습니다.

---

### Q11. 인덱스는 항상 성능을 향상시키나요?

항상 그렇지는 않습니다.

인덱스는 조건에 맞는 행을 빠르게 찾는 데 도움이 됩니다.  
하지만 조회해야 하는 행이 많으면 인덱스를 타고 여러 번 접근하는 것보다 전체 테이블을 읽는 것이 더 빠를 수 있습니다.

또한 `INSERT`, `UPDATE`, `DELETE`가 발생하면 인덱스도 같이 갱신되어야 합니다.

정리하면 인덱스는 조회 성능을 높일 수 있지만, DML 비용도 함께 고려해야 합니다.

---

### Q12. 뷰는 테이블인가요?

뷰는 테이블처럼 조회할 수 있지만 실제 데이터를 저장하는 일반 테이블은 아닙니다.

뷰는 `SELECT` 문을 저장한 논리적 객체입니다.

```sql
CREATE VIEW vw_emp_dept AS
SELECT e.employee_id,
       e.first_name,
       d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id;
```

정리하면 뷰는 테이블처럼 사용하지만, 기본적으로는 저장된 조회문입니다.

---

### Q13. PL/SQL의 기본 구조는 어떻게 되나요?

PL/SQL 블록은 보통 `DECLARE`, `BEGIN`, `EXCEPTION`, `END` 구조입니다.

```sql
DECLARE
    -- 선언부
BEGIN
    -- 실행부
EXCEPTION
    -- 예외 처리부
END;
/
```

`BEGIN`과 `END`는 필수이고, `DECLARE`와 `EXCEPTION`은 선택하여 사용합니다.

변수, 조건문, 반복문, 예외 처리를 함께 사용할 수 있어서 여러 SQL과 로직을 하나의 블록으로 묶을 수 있습니다.

---

### Q14. 프로시저와 함수의 차이는 무엇인가요?

프로시저는 작업 수행에 초점이 있습니다.

예를 들어 급여 인상, 계좌 이체, 데이터 변경 같은 작업은 프로시저가 자연스럽습니다.

함수는 값을 계산해서 반환하는 데 초점이 있습니다.

예를 들어 직원의 연봉을 계산해서 반환하는 작업은 함수가 자연스럽습니다.

```text
프로시저 -> 작업 수행
함수     -> 값 반환
```

함수는 반드시 `RETURN` 값을 가져야 합니다.

---

### Q15. 트리거는 프로시저와 무엇이 다른가요?

프로시저는 사용자가 직접 호출합니다.

```sql
EXEC raise_salary(103);
```

트리거는 직접 호출하지 않습니다.  
테이블에 `INSERT`, `UPDATE`, `DELETE`가 발생하면 DB가 자동으로 실행합니다.

```text
프로시저 -> 직접 호출
트리거   -> DML 이벤트 발생 시 자동 실행
```

또한 트리거는 호출한 DML의 트랜잭션에 묶이므로 일반적으로 트리거 안에서 `COMMIT`, `ROLLBACK`을 직접 실행하지 않습니다.

---

### Q16. 문장 레벨 트리거와 행 레벨 트리거의 차이는 무엇인가요?

문장 레벨 트리거는 SQL 문장 하나당 한 번 실행됩니다.

행 레벨 트리거는 변경된 행마다 실행됩니다.

```text
문장 레벨 트리거 -> SQL 문장당 1회
행 레벨 트리거   -> 변경된 행마다 1회
```

행 레벨 트리거에서는 `:NEW`, `:OLD`를 사용해 변경 전후 값을 참조할 수 있습니다.
