## 2. 이번 주 핵심 흐름

이번 구간은 SQL 문법 자체보다 **데이터베이스를 어떻게 설계하고, Java에서 어떻게 연결해서 사용하는가**로 넘어가는 흐름이었다.

전체 절차는 다음 순서로 정리할 수 있다.

```text
요구사항 분석
→ 개념적 설계
→ 논리적 설계
→ 물리적 설계
→ 구현
```

메모에서도 이 절차를 기준으로 정리했고, 논리적 설계 단계에서는 정규화, 물리적 설계 단계에서는 DBMS를 통해 테이블을 구체화한다고 정리했다.

---

## 3. 데이터 모델링

데이터 모델링은 현실의 업무를 데이터베이스 구조로 옮기기 위한 설계 과정이다.

수업 자료 기준으로 데이터베이스 설계 흐름은 다음과 같다.

| 단계 | 내용 | 산출물 |
|---|---|---|
| 요구사항 수집·분석 | 사용자 인터뷰, 업무 분석, 기존 문서 확인 | 요구사항 명세서 |
| 개념적 설계 | 핵심 개체와 관계 추출 | ERD |
| 논리적 설계 | ERD를 테이블 구조로 변환하고 정규화 | 테이블 정의서, 스키마 |
| 물리적 설계 | DBMS 특성에 맞춰 타입, 인덱스, 제약조건 결정 | DDL 스크립트 |
| 구현 | 실제 DBMS에 테이블 생성 | 운영 DB |

이전까지는 SQL을 사용해서 이미 만들어진 테이블을 조회하거나 조작했다면, 이번에는 **테이블이 만들어지기 전의 설계 과정**을 다뤘다.

---

## 4. ER 모델

ER 모델은 현실의 사물을 다음 세 가지로 표현한다.

| 요소 | 의미 |
|---|---|
| Entity | 관리해야 할 대상. 예: 고객, 계좌, 주문, 상품 |
| Attribute | 개체가 가지는 속성. 예: 고객명, 계좌번호, 주문일자 |
| Relationship | 개체 간의 관계. 예: 고객이 계좌를 보유한다 |

관계는 카디널리티에 따라 구분된다.

```text
1:1
1:N
M:N
```

특히 M:N 관계는 관계형 데이터베이스에서 그대로 표현하기 어렵기 때문에 보통 교차 테이블을 만들어 해소한다.

예를 들어 학생과 수업이 M:N 관계라면 `수강` 같은 중간 테이블을 둔다.

## 5. 정규화

정규화는 테이블의 중복을 줄이고 이상현상을 방지하기 위한 과정이다.

자료 기준으로 핵심은 다음과 같다.

| 구분 | 의미 |
|---|---|
| 삽입 이상 | 불필요한 데이터가 없으면 새 데이터를 넣지 못하는 문제 |
| 수정 이상 | 같은 값이 여러 곳에 중복되어 일부만 수정되는 문제 |
| 삭제 이상 | 특정 데이터를 삭제할 때 필요한 정보까지 같이 사라지는 문제 |

정규화는 함수 종속성을 기준으로 테이블을 분리한다.

```text
A → B
```

위 표기는 A가 결정되면 B가 하나로 결정된다는 뜻이다.

예시:

```text
고객ID → 고객명
상품ID → 상품명, 카테고리, 단가
주문번호 + 상품ID → 수량
```

## 6. ERDCloud 실습

ERDCloud는 브라우저 기반 ERD 설계 도구로, 개체와 관계를 시각적으로 설계하고 SQL로 내보낼 수 있는 도구로 정리했다.

실습에서 중요한 부분은 단순히 ERD를 그리는 것이 아니라 다음 흐름을 이해하는 것이다.

```text
업무 요구사항
→ 개체/속성/관계 도출
→ PK/FK 결정
→ 관계선 설정
→ DDL 생성
```

## 7. JDBC 개요

JDBC는 Java 애플리케이션과 DBMS를 연결하는 표준 인터페이스다.

수업 자료에서 정리한 JDBC 실행 흐름은 다음과 같다.

```text
1. ojdbc11.jar를 Build Path에 추가
2. DriverManager.getConnection()으로 Connection 획득
3. conn.prepareStatement(sql)로 PreparedStatement 생성
4. pstmt.setXxx()로 ?에 값 바인딩
5. executeUpdate() 또는 executeQuery() 실행
6. SELECT 결과는 ResultSet.next()로 읽기
7. ResultSet → PreparedStatement → Connection 순서로 자원 반환
```

---

## 8. JDBC 주요 객체

| 객체 | 역할 |
|---|---|
| DriverManager | DB 연결 생성 |
| Connection | DB와 연결된 세션 |
| PreparedStatement | SQL 실행 객체. `?` 바인딩 가능 |
| ResultSet | SELECT 결과 집합 |
| CallableStatement | 프로시저/함수 호출 |

특히 `Statement`보다 `PreparedStatement`를 사용하는 이유는 SQL 인젝션 위험을 줄이고, 값 바인딩을 명확하게 하기 위해서다.

## 9. DAO / VO 구조

JDBC 코드를 직접 작성하면 SQL 실행, 자원 반환, 결과 매핑 코드가 반복된다.
그래서 DAO와 VO 구조로 분리한다.

| 구분 | 역할 |
|---|---|
| VO / DTO | DB 결과를 담는 객체 |
| DAO | SQL 실행과 DB 접근 담당 |
| Service | 비즈니스 흐름 담당 |
| Controller / View | 입력과 출력 담당 |

이 구조는 이후 개인 JDBC 프로젝트나 Spring Boot의 Repository/Service 구조로 이어진다.

---

## 10. 트랜잭션

JDBC에서 트랜잭션을 직접 제어하려면 자동 커밋을 꺼야 한다.

```java
conn.setAutoCommit(false);

try {
    // DML 실행
    conn.commit();
} catch (SQLException e) {
    conn.rollback();
}
```

기본값은 `autoCommit = true`이므로 INSERT, UPDATE, DELETE가 실행되면 바로 반영된다.
여러 작업을 하나의 단위로 묶으려면 직접 commit/rollback을 제어해야 한다.

이번 주 Oracle 수업은 SQL 문법 학습에서 한 단계 넘어가서, **데이터베이스 설계와 Java 연동 구조**를 다룬 구간이었다.
