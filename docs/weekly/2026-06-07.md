## 2. 제네릭

제네릭은 클래스나 메서드에서 사용할 타입을 미리 고정하지 않고, 사용하는 시점에 정할 수 있게 해주는 문법이다.

제네릭을 사용하지 않으면 여러 타입을 담기 위해 `Object`를 사용할 수 있다.

```java
class OldBox {
    Object content;
    // getter,setter 생략
}
```

하지만 `Object`를 사용하면 값을 꺼낼 때 직접 형 변환이 필요하다.

```java
OldBox box = new OldBox();

box.setContent("Java");
String data = (String) box.getContent();
```

이 방식은 잘못된 타입으로 형 변환할 경우 실행 중 오류가 발생할 수 있다.

제네릭을 사용하면 사용할 타입을 외부에서 지정할 수 있다.

```java
class Box<T> {
    private T content;
    // getter,setter 생략
}
```

```java
Box<String> box = new Box<>();
box.setContent("Java");

String data = box.getContent();
```

제네릭을 사용하면 형 변환이 줄어들고, 컴파일 시점에 타입 오류를 더 빨리 확인할 수 있다.

제네릭은 클래스뿐 아니라 인터페이스와 메서드에도 사용할 수 있다.

```java
interface Rentable<P> {
    P rent();
}
```

```java
public <T> void printArray(T[] arr) {
    for (T data : arr) {
        System.out.println(data);
    }
}
```

제네릭 클래스는 객체를 만들 때 타입이 결정되고, 제네릭 메서드는 메서드를 호출할 때 타입이 결정된다.

| 구분          | 타입 결정 시점   | 사용 범위   |
| ------------- | ---------------- | ----------- |
| 제네릭 클래스 | 객체 생성 시점   | 클래스 전체 |
| 제네릭 메서드 | 메서드 호출 시점 | 메서드 내부 |

정리:

- 제네릭은 타입을 나중에 정할 수 있게 한다.
- `Object` 기반 코드보다 타입 안정성이 높다.
- 불필요한 형 변환을 줄일 수 있다.
- 컬렉션, DTO, 공통 유틸 클래스에서 자주 사용된다.

## 3. 와일드카드

와일드카드는 제네릭에서 타입의 허용 범위를 지정할 때 사용한다.

가장 기본적인 와일드카드는 `?`이다.

```java
public static void registerCourse1(Applicant<?> applicant) {
}
```

`Applicant<?>`는 어떤 타입의 `Applicant`든 받을 수 있다는 뜻이다.

`? extends Student`는 `Student` 또는 `Student`의 하위 타입만 허용한다.

```java
public static void registerCourse2(Applicant<? extends Student> applicant) {
}
```

가능한 타입:

```text
Applicant<Student>
Applicant<HighStudent>
Applicant<MiddleStudent>
```

반대로 `? super Worker`는 `Worker` 또는 `Worker`의 상위 타입을 허용한다.

```java
public static void registerCourse3(Applicant<? super Worker> applicant) {
}
```

가능한 타입:

```text
Applicant<Worker>
Applicant<Person>
Applicant<Object>
```

정리:

| 표현            | 의미                       |
| --------------- | -------------------------- |
| `<?>`           | 타입 제한 없음             |
| `<? extends T>` | `T`와 `T`의 하위 타입 허용 |
| `<? super T>`   | `T`와 `T`의 상위 타입 허용 |

`extends`와 `super`는 방향이 반대라서 다시 볼 필요가 있다.  
`extends`는 아래쪽으로 제한하고, `super`는 위쪽으로 허용한다.

## 4. 스레드 기초

스레드는 프로그램 안에서 코드를 실행하는 흐름이다.

Java 프로그램은 `main()` 메서드를 실행하는 메인 스레드에서 시작한다.  
여기에 작업 스레드를 추가하면 여러 실행 흐름을 만들 수 있다.

스레드를 만드는 대표적인 방법은 두 가지이다.

```text
1. Thread 클래스를 상속한다.
2. Runnable 인터페이스를 구현한다.
```

`Thread`를 상속하는 방식:

```java
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("스레드 실행");
    }
}
```

실행할 때는 `run()`이 아니라 `start()`를 호출해야 한다.

```java
MyThread t = new MyThread();
t.start();
```

`Runnable`을 구현하는 방식:

```java
class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println("Runnable 실행");
    }
}
```

```java
Runnable task = new MyRunnable();
Thread t = new Thread(task);

t.start();
```

`run()`을 직접 호출하면 새로운 스레드가 만들어지지 않는다.  
현재 스레드에서 일반 메서드처럼 실행된다.

정리:

| 호출      | 의미                                      |
| --------- | ----------------------------------------- |
| `run()`   | 현재 스레드에서 일반 메서드처럼 실행      |
| `start()` | 새 스레드를 만들고 그 안에서 `run()` 실행 |

멀티스레드 실행을 원하면 반드시 `start()`를 호출해야 한다.

## 5. 스레드 제어와 동기화

여러 스레드가 같은 객체를 동시에 사용하면 실행 순서에 따라 결과가 달라질 수 있다.

이런 공유 자원 문제를 막기 위해 `synchronized`를 사용할 수 있다.

```java
public synchronized void transfer() {
    int amount = lee.withdraw(100);
    sung.deposit(amount);
}
```

`synchronized`가 붙은 메서드는 한 스레드가 실행 중일 때 다른 스레드가 동시에 들어오지 못한다.

스레드 실행 흐름을 제어하는 메서드는 아래에서 서술한다.

### `join()`

`join()`은 특정 스레드가 끝날 때까지 현재 스레드를 기다리게 한다.

```java
sumThread.start();
sumThread.join();

System.out.println(sumThread.getSum());
```

작업 스레드의 결과가 필요할 때 사용할 수 있다.

### `yield()`

`yield()`는 현재 스레드가 실행 기회를 양보하는 메서드이다.

```java
if (!work) {
    Thread.yield();
}
```

다만 `yield()`를 호출한다고 해서 반드시 다른 스레드가 바로 실행되는 것은 아니다.  
실제 실행 순서는 스케줄러에 따라 달라질 수 있다.

### `wait()`와 `notify()`

`wait()`는 현재 스레드를 대기 상태로 만들고, `notify()`는 대기 중인 스레드 하나를 깨운다.

```java
public synchronized void use() {
    try {
        wait();
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }

    notify();
}
```

`wait()`는 현재 스레드를 대기 상태로 만들고, `notify()`는 같은 객체의 모니터에서 대기 중인 스레드 하나를 깨운다.  
두 메서드는 반드시 `synchronized` 영역 안에서 사용해야 한다.

### `interrupt()`

`interrupt()`는 스레드에 중단 요청을 보내는 방식이다.

```java
thread.interrupt();
```

작업 스레드는 인터럽트 상태를 확인하고 반복을 종료할 수 있다.

정리:

- 공유 객체를 여러 스레드가 사용하면 동기화가 필요하다.
- `synchronized`는 동시 접근을 제한한다.
- `join()`은 다른 스레드가 끝날 때까지 기다린다.
- `yield()`는 실행 기회를 양보한다.
- `wait()`와 `notify()`는 동기화 영역에서 사용한다.
- `interrupt()`는 안전 종료 흐름을 만들 때 사용할 수 있다.

## 6. 스레드 풀, Runnable, Callable

스레드를 작업마다 새로 만들면 비용이 커질 수 있다.  
스레드 풀은 미리 정해진 개수의 스레드를 만들어두고 작업을 처리하는 방식이다.

```java
ExecutorService executorService = Executors.newFixedThreadPool(5);
```

반환값이 없는 작업은 `Runnable`로 정의할 수 있다.

```java
executorService.execute(new Runnable() {
    @Override
    public void run() {
        System.out.println("작업 실행");
    }
});
```

작업 결과가 필요한 경우에는 `Callable`을 사용한다.

```java
Callable<Integer> task = new Callable<>() {
    @Override
    public Integer call() {
        return 100;
    }
};
```

`Callable` 작업은 `submit()`으로 제출하고, 결과는 `Future`로 받는다.

```java
Future<Integer> result = executorService.submit(task);
Integer value = result.get();
```

정리:

| 구분       | 반환값 | 실행 메서드 |
| ---------- | ------ | ----------- |
| `Runnable` | 없음   | `run()`     |
| `Callable` | 있음   | `call()`    |

- `execute()`는 반환값이 없는 작업에 사용한다.
- `submit()`은 작업 결과를 `Future`로 받을 수 있다.
- 스레드 풀 사용 후에는 `shutdown()`을 호출해야 한다.

## 7. 컬렉션 프레임워크

컬렉션은 여러 데이터를 저장하고 처리하기 위한 자료구조이다.

대표적인 구조는 `List`, `Set`, `Map`이다.

| 구분   | 특징                            |
| ------ | ------------------------------- |
| `List` | 순서 있음, 중복 가능            |
| `Set`  | 중복 불가, 일반적으로 순서 없음 |
| `Map`  | key-value 구조, key 중복 불가   |

`ArrayList`는 배열 기반 리스트이다.  
인덱스 조회와 맨 뒤 추가에 유리하다.

`Vector`는 주요 메서드에 동기화가 적용된 `List` 구현체이다.  
멀티스레드 환경에서 `ArrayList`보다 안전할 수 있지만, 동기화 비용이 있다.

`LinkedList`는 노드가 서로 연결된 구조이다.  
중간 삽입과 삭제에 유리할 수 있지만, 인덱스 기반 조회에는 불리하다.

`HashSet`은 중복을 허용하지 않는다.  
직접 만든 객체의 중복 판단은 `equals()`와 `hashCode()`를 기준으로 한다.

`Map`은 key-value 구조이다.

```java
Map<String, Integer> map = new HashMap<>();

map.put("A", 100);
map.put("A", 90);
```

같은 key로 값을 다시 넣으면 기존 값이 덮어써진다.

정리:

- `List`는 순서와 중복을 허용한다.
- `Set`은 중복을 허용하지 않는다.
- `Map`은 key-value 쌍으로 데이터를 저장한다.
- `HashSet`은 `equals/hashCode` 기준으로 중복을 판단한다.
- `Map`의 key는 중복될 수 없다.

## 8. 정렬 기준: Comparable과 Comparator

정렬이 필요한 컬렉션에서는 비교 기준이 필요하다.

`Comparable`은 객체 자신의 기본 정렬 기준을 정의할 때 사용한다.

```java
public class Student implements Comparable<Student> {
    @Override
    public int compareTo(Student o) {
        return this.number.compareTo(o.getNumber());
    }
}
```

`Comparator`는 외부에서 별도의 정렬 기준을 제공할 때 사용한다.

```java
Arrays.sort(arr, new Comparator<Integer>() {
    @Override
    public int compare(Integer o1, Integer o2) {
        return Integer.compare(o2, o1);
    }
});
```

`TreeSet`과 `TreeMap`은 정렬된 상태를 유지한다.

`TreeSet`은 요소를 기준으로 정렬하고, `TreeMap`은 key를 기준으로 정렬한다.

주의할 점은 `HashSet`과 `TreeSet`의 중복 판단 기준이 다르다는 점이다.

```text
HashSet  -> equals(), hashCode()
TreeSet  -> compareTo() 또는 Comparator
```

`TreeSet`에서는 `compareTo()` 결과가 `0`이면 같은 요소로 판단될 수 있다.

정리:

- `Comparable`은 객체 내부의 기본 정렬 기준이다.
- `Comparator`는 외부에서 제공하는 정렬 기준이다.
- `HashSet`은 `equals/hashCode` 기준으로 중복을 판단한다.
- `TreeSet`은 정렬 기준으로 중복을 판단한다.
- 숫자 비교는 뺄셈보다 `Integer.compare()`가 더 안전하다.

## 9. 스택과 큐

스택은 나중에 들어온 데이터가 먼저 나가는 구조이다.

```text
LIFO: Last In First Out
```

```java
Stack<String> stack = new Stack<>();

stack.push("A");
stack.push("B");

System.out.println(stack.pop()); // B
```

큐는 먼저 들어온 데이터가 먼저 나가는 구조이다.

```text
FIFO: First In First Out
```

```java
Queue<String> queue = new LinkedList<>();

queue.offer("A");
queue.offer("B");

System.out.println(queue.poll()); // A
```

`Queue`는 인터페이스이므로 보통 `LinkedList`나 `ArrayDeque` 같은 구현체를 통해 사용한다.

정리:

| 구조  | 방식 | 주요 메서드                   |
| ----- | ---- | ----------------------------- |
| Stack | LIFO | `push()`, `pop()`             |
| Queue | FIFO | `offer()`, `poll()`, `peek()` |

## 10. 람다식과 함수형 인터페이스

함수형 인터페이스는 추상 메서드가 하나인 인터페이스이다.

```java
@FunctionalInterface
interface Calculable {
    double calc(double a, double b);
}
```

람다식은 함수형 인터페이스의 구현을 간단하게 표현하는 문법이다.

```java
Calculable add = (a, b) -> a + b;
```

익명 구현 객체로 작성하면 다음과 같다.

```java
Calculable add = new Calculable() {
    @Override
    public double calc(double a, double b) {
        return a + b;
    }
};
```

람다식과 익명 구현 객체는 비슷해 보이지만 `this`가 가리키는 대상이 다르다.

익명 구현 객체에서 `this`는 익명 객체 자신을 의미한다.  
람다식에서 `this`는 람다식을 감싼 외부 객체를 의미한다.

제네릭 함수형 인터페이스도 사용할 수 있다.

```java
@FunctionalInterface
interface MyInterface<T> {
    void print(T t);
}
```

```java
MyInterface<String> my = data -> System.out.println(data);
my.print("hello");
```

정리:

- 함수형 인터페이스는 추상 메서드가 하나인 인터페이스이다.
- 람다식은 함수형 인터페이스의 구현을 간단히 표현한다.
- `@FunctionalInterface`는 조건을 컴파일 시점에 확인해준다.
- 익명 구현 객체와 람다식은 `this`의 의미가 다르다.

## 11. 메서드 참조와 생성자 참조

메서드 참조는 기존 메서드를 람다식 대신 전달하는 문법이다.

```java
double result = action(Math::max, 10, 20);
```

정적 메서드는 `클래스명::메서드명` 형태로 참조한다.

```java
Computer::staticMethod
```

인스턴스 메서드는 `객체참조변수::메서드명` 형태로 참조한다.

```java
computer::instanceMethod
```

생성자 참조는 객체 생성 람다식을 짧게 표현하는 문법이다.

```java
Accountable acc = Account::new;
```

이때 함수형 인터페이스의 추상 메서드 매개변수와 생성자의 매개변수가 맞아야 한다.

```java
@FunctionalInterface
interface Accountable {
    Account makeAccount(String accNo, String ownerName, int balance);
}
```

위 인터페이스는 문자열 2개와 정수 1개를 받아 `Account`를 반환한다.
따라서 같은 매개변수 구조를 가진 `Account` 생성자와 연결될 수 있다.

정리:

- 메서드 참조는 `::` 문법을 사용한다.
- 정적 메서드는 `클래스명::메서드명`으로 참조한다.
- 인스턴스 메서드는 `객체::메서드명`으로 참조한다.
- 생성자 참조는 `클래스명::new`로 작성한다.
- 함수형 인터페이스의 추상 메서드 형태와 참조 대상의 형태가 맞아야 한다.

## 12. 스트림

스트림은 컬렉션이나 배열의 데이터를 선언형으로 처리할 수 있게 해주는 API이다.

스트림은 다음 흐름으로 처리된다.

```text
원본 데이터
→ stream()
→ 중간 처리
→ 최종 처리
```

중간 처리는 스트림을 다시 스트림으로 반환한다.

대표 중간 처리:

| 메서드       | 역할                    |
| ------------ | ----------------------- |
| `filter()`   | 조건에 맞는 요소만 통과 |
| `distinct()` | 중복 제거               |
| `sorted()`   | 정렬                    |
| `map()`      | 요소 변환               |
| `mapToInt()` | int 스트림으로 변환     |
| `flatMap()`  | 중첩 구조 펼치기        |
| `peek()`     | 중간 데이터 확인        |

최종 처리는 스트림을 소비하고 결과를 만든다.

대표 최종 처리:

| 메서드        | 역할                    |
| ------------- | ----------------------- |
| `forEach()`   | 요소 처리               |
| `sum()`       | 합계                    |
| `average()`   | 평균                    |
| `count()`     | 개수                    |
| `collect()`   | 결과 수집               |
| `allMatch()`  | 모든 요소 조건 검사     |
| `anyMatch()`  | 하나라도 조건 만족 검사 |
| `noneMatch()` | 모두 조건 불만족 검사   |

`peek()`과 `forEach()`는 둘 다 출력에 사용할 수 있지만 역할이 다르다.

```text
peek()    -> 중간 처리
forEach() -> 최종 처리
```

리스트를 `Map`으로 바꿀 때는 `Collectors.toMap()`을 사용할 수 있다.

```java
Map<String, Integer> newMap = memList.stream()
        .collect(Collectors.toMap(Member::getName, Member::getScore));
```

특정 기준으로 묶을 때는 `groupingBy()`를 사용한다.

```java
Map<String, List<Member>> groupMember = memList.stream()
        .collect(Collectors.groupingBy(Member::getGender));
```

정리:

- 스트림은 원본 데이터를 직접 변경하지 않는다.
- 중간 처리와 최종 처리로 나뉜다.
- `peek()`은 중간 확인용, `forEach()`는 최종 소비용이다.
- `Collectors.toMap()`은 리스트를 `Map`으로 변환한다.
- `groupingBy()`는 특정 기준으로 데이터를 묶는다.

## 13. 입출력

Java 입출력은 데이터 단위에 따라 나눌 수 있다.

| 구분        | 대표 클래스                            | 특징                    |
| ----------- | -------------------------------------- | ----------------------- |
| 바이트 기반 | `InputStream`, `OutputStream`          | 1byte 단위 처리         |
| 문자 기반   | `Reader`, `Writer`                     | 문자 데이터 처리        |
| 보조 스트림 | `BufferedReader`, `DataInputStream` 등 | 기존 스트림에 기능 추가 |

파일을 바이트 단위로 읽을 때는 `FileInputStream`을 사용할 수 있다.

```java
try (FileInputStream fis = new FileInputStream("data.txt")) {
    int data;
    while ((data = fis.read()) != -1) {
        System.out.print((char) data);
    }
}
```

문자 단위로 읽을 때는 `FileReader`를 사용할 수 있다.

```java
try (FileReader fr = new FileReader("data.txt")) {
    int data;
    while ((data = fr.read()) != -1) {
        System.out.print((char) data);
    }
}
```

줄 단위로 읽을 때는 `BufferedReader`를 사용한다.

```java
try (BufferedReader br = new BufferedReader(new FileReader("data.txt"))) {
    String line;

    while ((line = br.readLine()) != null) {
        System.out.println(line);
    }
}
```

기본형 데이터를 쓸 때는 `DataOutputStream`을 사용할 수 있다.

```java
dos.writeInt(100);
dos.writeChar('김');
dos.writeFloat(3.14f);
dos.writeUTF("문자열 utf");
```

읽을 때는 같은 순서로 읽어야 한다.

```java
int intData = dis.readInt();
char charData = dis.readChar();
float floatData = dis.readFloat();
String strData = dis.readUTF();
```

정리:

- 바이트 기반 스트림은 1byte 단위로 처리한다.
- 문자 기반 스트림은 문자 데이터를 처리한다.
- `BufferedReader`는 줄 단위 읽기에 유용하다.
- `DataOutputStream`과 `DataInputStream`은 기본형 데이터를 처리한다.
- 기본형 데이터는 쓴 순서와 읽는 순서가 같아야 한다.

## 14. 직렬화와 transient

객체를 파일에 저장하려면 직렬화가 필요하다.

직렬화 대상 클래스는 `Serializable`을 구현해야 한다.

```java
class Member implements Serializable {
    private static final long serialVersionUID = 1L;

    String name;
    String gender;
    int score;
    transient String password;
}
```

객체를 쓸 때는 `ObjectOutputStream`을 사용한다.

```java
oos.writeObject(member);
```

객체를 읽을 때는 `ObjectInputStream`을 사용한다.

```java
Object obj = ois.readObject();

if (obj instanceof Member m) {
    memList.add(m);
}
```

파일 끝까지 읽으면 `EOFException`이 발생할 수 있다.  
수업에서는 이 예외를 이용해 반복 읽기를 종료했다.

`transient`는 직렬화에서 제외할 필드에 사용한다.

```java
transient String password;
```

비밀번호처럼 저장하면 안 되는 값이나, 실행 중에만 필요한 값은 직렬화 대상에서 제외할 수 있다.

정리:

- 객체를 파일로 저장하려면 직렬화가 필요하다.
- 직렬화 대상 클래스는 `Serializable`을 구현해야 한다.
- `ObjectOutputStream`은 객체를 쓴다.
- `ObjectInputStream`은 객체를 읽는다.
- `transient` 필드는 직렬화 대상에서 제외된다.

## 15. JSON

JSON은 key-value 형태의 데이터 표현 방식이다.

```json
{
  "name": "홍길동",
  "age": 20
}
```

Java에서는 `JSONObject`, `JSONArray`를 사용해서 JSON 데이터를 다룰 수 있다.

```java
JSONObject jo = new JSONObject();

jo.put("id", "winter");
jo.put("name", "홍길동");
jo.put("age", 25);
```

배열 구조는 `JSONArray`로 표현할 수 있다.

```java
JSONArray skill = new JSONArray();

skill.put("Java");
skill.put("c");
skill.put("python");

jo.put("skill", skill);
```

문자열 JSON을 다시 `JSONObject`로 파싱할 수도 있다.

```java
JSONObject data = new JSONObject(jsonData);
```

`toMap()`을 사용하면 JSON 객체를 `Map` 형태로 다룰 수 있다.

```java
jsonData.toMap()
        .entrySet()
        .forEach(data -> {
            System.out.println(data.getKey() + " => " + data.getValue());
        });
```

정리:

- JSON은 key-value 형태의 데이터 표현 방식이다.
- `JSONObject`는 JSON 객체를 표현한다.
- `JSONArray`는 JSON 배열을 표현한다.
- 문자열 JSON을 파싱할 수 있다.
- `toMap()`으로 `Map` 형태로 변환할 수 있다.
- `org.json` 라이브러리가 필요하다.

## 16. 네트워크 입출력

네트워크 입출력은 다른 컴퓨터 또는 프로세스와 데이터를 주고받는 구조이다.

수업에서는 TCP와 UDP를 비교했다.

| 구분        | TCP                      | UDP                                |
| ----------- | ------------------------ | ---------------------------------- |
| 방식        | 연결 기반                | 비연결 기반                        |
| 신뢰성      | 높음                     | 낮음                               |
| 속도        | 상대적으로 느림          | 상대적으로 빠름                    |
| 데이터 손실 | 적음                     | 발생 가능                          |
| 대표 클래스 | `Socket`, `ServerSocket` | `DatagramSocket`, `DatagramPacket` |

TCP는 연결을 맺고 데이터를 주고받는다.

```java
Socket socket = new Socket();
socket.connect(new InetSocketAddress("localhost", 50001));
```

서버는 `ServerSocket`으로 클라이언트 연결을 기다린다.

```java
ServerSocket serverSocket = new ServerSocket(50001);
Socket socket = serverSocket.accept();
```

UDP는 연결 없이 데이터를 패킷 단위로 보낸다.

```java
DatagramPacket sendPacket = new DatagramPacket(
        sendBuffer,
        sendBuffer.length,
        serverAddress,
        serverPort
);
```

```java
socket.send(sendPacket);
```

UDP는 데이터 도착과 순서를 보장하지 않는다.  
따라서 신뢰성이 필요하면 애플리케이션 레벨에서 별도 처리가 필요하다.

채팅 예제에서는 송신과 수신을 동시에 처리하기 위해 역할을 나눴다.

```text
메인 스레드: 키보드 입력을 읽고 서버로 전송
수신 스레드: 서버 메시지를 계속 읽어서 콘솔에 출력
```

정리:

- TCP는 연결 기반이고 신뢰성이 높다.
- UDP는 비연결 기반이고 데이터 손실 가능성이 있다.
- TCP는 `Socket`, `ServerSocket`을 사용한다.
- UDP는 `DatagramSocket`, `DatagramPacket`을 사용한다.
- 채팅 프로그램에서는 송신과 수신을 분리해야 한다.

## 17. 이번 주에 헷갈렸던 부분

### `start()`와 `run()` 차이

`run()`은 일반 메서드 호출이고, 새 스레드를 만드는 것은 `start()`이다.

```java
thread.run();   // 현재 스레드에서 일반 메서드처럼 실행
thread.start(); // 새 스레드 생성 후 run() 실행
```

멀티스레드 실행을 하려면 `start()`를 호출해야 한다.

---

### `? extends`와 `? super`

`? extends Student`와 `? super Worker`는 둘 다 타입 제한처럼 보이지만 방향이 다르다.

```text
? extends Student -> Student와 하위 타입
? super Worker    -> Worker와 상위 타입
```

`extends`는 아래쪽으로 제한하고, `super`는 위쪽으로 허용한다.
이 방향을 구분해서 봐야 한다.

---

### `HashSet`과 `TreeSet`의 중복 판단 기준

둘 다 중복을 허용하지 않지만 기준이 다르다.

```text
HashSet -> equals(), hashCode()
TreeSet -> compareTo() 또는 Comparator
```

`HashSet`에서는 같은 객체로 보이더라도, `TreeSet`에서는 정렬 기준이 다르면 다른 객체처럼 들어갈 수 있다.  
반대로 `compareTo()` 결과가 `0`이면 `TreeSet`에서는 같은 요소로 취급될 수 있다.

---

### 람다식과 익명 구현 객체의 `this`

익명 구현 객체에서 `this`는 익명 객체 자신을 의미한다.

하지만 람다식의 `this`는 람다식을 감싼 외부 객체를 의미한다.

비슷하게 생겼지만 스코프가 다르기 때문에 구분해야 한다.

---

### `peek()`과 `forEach()`

`peek()`과 `forEach()`는 둘 다 출력에 사용할 수 있다.

하지만 `peek()`은 중간 처리이고, `forEach()`는 최종 처리이다.

```text
peek()    -> 중간 데이터 확인
forEach() -> 최종 소비
```

`peek()` 뒤에는 `map()`, `toList()` 같은 처리를 이어갈 수 있다.  
`forEach()`는 최종 처리이므로 그 뒤에 스트림 연산을 이어갈 수 없다.

---

### `DataInputStream`은 왜 같은 순서로 읽어야 하는가?

`DataOutputStream`으로 데이터를 쓸 때는 타입별 형식에 맞게 값이 기록된다.

```java
dos.writeInt(100);
dos.writeChar('김');
dos.writeFloat(3.14f);
dos.writeUTF("문자열 utf");
```

읽을 때는 같은 순서로 읽어야 한다.

```java
int intData = dis.readInt();
char charData = dis.readChar();
float floatData = dis.readFloat();
String strData = dis.readUTF();
```

파일 안에 타입 이름이 자동으로 붙어 있는 것이 아니므로, 읽는 쪽에서 순서를 맞춰야 한다.

## 18. 이번 주 정리

이번 주에는 제네릭, 스레드, 컬렉션, 람다식, 스트림, 입출력, 네트워크까지 Java의 핵심 API를 넓게 학습했다.

초반에는 제네릭을 통해 타입 안정성을 높이는 방법을 배웠다.  
제네릭 클래스, 제네릭 메서드, 제네릭 인터페이스를 나누어 보면서 타입이 결정되는 위치가 다르다는 점을 익혔다.

스레드에서는 `start()`와 `run()`의 차이, 공유 객체의 동기화, `join()`, `yield()`, `wait()`, `notify()`, `interrupt()` 같은 제어 메서드를 정리했다.  
특히 여러 스레드가 같은 객체를 사용할 때 동기화가 필요하다는 점이 중요했다.

컬렉션에서는 `List`, `Set`, `Map`의 구조와 각 구현체의 차이를 확인했다.  
`HashSet`과 `TreeSet`의 중복 판단 기준이 다르다는 점도 다시 정리했다.

람다식에서는 함수형 인터페이스가 기준이 되고, 메서드 참조와 생성자 참조는 함수형 인터페이스의 추상 메서드 형태와 맞아야 사용할 수 있다는 점을 확인했다.

스트림에서는 중간 처리와 최종 처리를 나누어 봤다.  
`filter`, `map`, `flatMap`, `sorted`, `peek` 같은 중간 처리와 `forEach`, `sum`, `average`, `collect` 같은 최종 처리를 연결해서 데이터를 처리했다.

입출력에서는 바이트 기반, 문자 기반, 보조 스트림을 구분했다.  
또한 `DataOutputStream`, `DataInputStream`, `ObjectOutputStream`, `ObjectInputStream`을 통해 기본형 데이터와 객체를 파일에 쓰고 읽는 방법을 확인했다.

마지막으로 네트워크에서는 TCP와 UDP의 차이를 확인했다.  
TCP는 신뢰성이 필요한 통신에 적합하고, UDP는 일부 손실보다 속도와 실시간성이 중요한 경우에 사용할 수 있다는 점을 정리했다.

전체적으로 이번 주 내용은 Java 백엔드 개발에서 자주 쓰이는 기반 API에 가까웠다.  
컬렉션과 스트림은 데이터 처리에 직접 연결되고, 입출력과 네트워크는 파일 처리나 서버 통신 구조를 이해하는 데 필요하므로 다시 복습할 필요가 있다.

## 19. 면접 질문과 답변

### Q1. 제네릭을 사용하는 이유는 무엇인가요?

제네릭은 사용할 타입을 나중에 지정할 수 있게 해주는 문법입니다.

제네릭을 사용하면 `Object`를 사용할 때보다 타입 안정성이 높아지고, 값을 꺼낼 때 불필요한 형 변환을 줄일 수 있습니다.

또한 잘못된 타입 사용을 컴파일 시점에 확인할 수 있습니다.

---

### Q2. `? extends T`와 `? super T`의 차이는 무엇인가요?

`? extends T`는 `T`와 `T`의 하위 타입을 허용합니다.

반대로 `? super T`는 `T`와 `T`의 상위 타입을 허용합니다.

예를 들어 `? extends Student`는 `Student`, `HighStudent`, `MiddleStudent`를 받을 수 있고, `? super Worker`는 `Worker`, `Person`, `Object`를 받을 수 있습니다.

---

### Q3. `start()`와 `run()`의 차이는 무엇인가요?

`run()`은 일반 메서드 호출입니다.  
직접 호출하면 현재 스레드에서 실행됩니다.

`start()`는 새로운 스레드를 생성하고, 그 새 스레드 안에서 `run()`을 실행합니다.

따라서 멀티스레드로 동작시키려면 `run()`이 아니라 `start()`를 호출해야 합니다.

---

### Q4. `synchronized`는 왜 사용하나요?

여러 스레드가 같은 객체나 데이터를 동시에 사용하면 데이터 불일치가 발생할 수 있습니다.

`synchronized`는 한 번에 하나의 스레드만 해당 메서드나 블록에 접근하도록 제한해서 공유 자원을 안전하게 사용할 수 있게 합니다.

---

### Q5. `Runnable`과 `Callable`의 차이는 무엇인가요?

`Runnable`은 반환값이 없고, `run()` 메서드를 구현합니다.

`Callable`은 반환값이 있고, `call()` 메서드를 구현합니다.

작업 결과가 필요하면 `Callable`을 사용하고, `submit()`으로 실행하면 `Future`를 통해 결과를 받을 수 있습니다.

---

### Q6. `List`, `Set`, `Map`의 차이는 무엇인가요?

`List`는 순서가 있고 중복을 허용합니다.

`Set`은 중복을 허용하지 않습니다.

`Map`은 key-value 구조로 데이터를 저장하며, key는 중복될 수 없습니다.

---

### Q7. `HashSet`과 `TreeSet`의 중복 판단 기준은 어떻게 다른가요?

`HashSet`은 `equals()`와 `hashCode()`를 기준으로 중복을 판단합니다.

`TreeSet`은 정렬 기준인 `compareTo()` 또는 `Comparator`를 기준으로 중복을 판단합니다.

따라서 두 기준이 다르면 `HashSet`과 `TreeSet`에서 중복 판단 결과가 달라질 수 있습니다.

---

### Q8. 함수형 인터페이스란 무엇인가요?

함수형 인터페이스는 추상 메서드가 하나인 인터페이스입니다.

람다식은 함수형 인터페이스를 구현하는 간단한 표현입니다.

`@FunctionalInterface`를 붙이면 컴파일러가 함수형 인터페이스 조건을 검사해줍니다.

---

### Q9. `peek()`과 `forEach()`의 차이는 무엇인가요?

`peek()`은 스트림의 중간 처리입니다.  
중간 데이터를 확인한 뒤 다음 연산을 이어갈 수 있습니다.

`forEach()`는 최종 처리입니다.  
스트림을 소비하기 때문에 그 뒤에 다른 스트림 연산을 이어갈 수 없습니다.

---

### Q10. `DataInputStream`과 `DataOutputStream`을 사용할 때 주의할 점은 무엇인가요?

`DataOutputStream`으로 데이터를 쓴 순서와 `DataInputStream`으로 데이터를 읽는 순서가 같아야 합니다.

예를 들어 `int`, `char`, `float`, `UTF 문자열` 순서로 썼다면 읽을 때도 같은 순서로 읽어야 합니다.

순서가 다르면 데이터가 깨지거나 잘못 해석될 수 있습니다.

---

### Q11. 직렬화란 무엇인가요?

직렬화는 객체를 파일이나 네트워크로 전송할 수 있는 형태로 변환하는 과정입니다.

Java에서는 직렬화 대상 클래스가 `Serializable`을 구현해야 합니다.

객체를 쓸 때는 `ObjectOutputStream`, 읽을 때는 `ObjectInputStream`을 사용할 수 있습니다.

---

### Q12. `transient`는 언제 사용하나요?

`transient`는 직렬화에서 제외할 필드에 사용합니다.

비밀번호처럼 저장하면 안 되는 값이나, 실행 중에만 필요한 임시 값은 `transient`로 선언해서 직렬화 대상에서 제외할 수 있습니다.

---

### Q13. TCP와 UDP의 차이는 무엇인가요?

TCP는 연결 기반 통신이며 신뢰성이 높습니다.  
데이터가 순서대로 정확히 전달되는 것이 중요할 때 사용합니다.

UDP는 비연결 기반 통신이며 데이터 손실 가능성이 있습니다.  
대신 구조가 단순하고 빠르기 때문에 실시간성이 중요한 경우에 사용할 수 있습니다.

---

### Q14. 채팅 프로그램에서 송신과 수신을 스레드로 분리하는 이유는 무엇인가요?

채팅 프로그램에서는 사용자가 입력하는 동안에도 서버에서 메시지가 올 수 있습니다.

메인 스레드가 키보드 입력만 기다리고 있으면 서버 메시지를 즉시 받지 못할 수 있습니다.

그래서 메인 스레드는 송신을 담당하고, 별도의 수신 스레드는 서버 메시지를 계속 읽도록 분리합니다.
