## 2. 이번 주 핵심 흐름

Spring Boot 구간은 기존 Servlet/JSP 방식에서 Spring 기반 백엔드 구조로 넘어가는 시작점이다.

```text
기존 Servlet/JSP
→ Spring Framework 개념
→ Spring Boot 프로젝트 생성
→ Controller 작성
→ DTO와 Lombok
→ IoC / DI
→ Bean 관리
→ AOP 개념
```

---

## 3. Spring Boot의 위치

Spring Boot는 Spring Framework를 더 쉽게 사용할 수 있게 해주는 도구다.

| 구분 | Spring Framework | Spring Boot |
|---|---|---|
| 설정 | 직접 설정 많음 | 자동 설정 중심 |
| 서버 | 외부 Tomcat 설정 필요 | 내장 Tomcat 제공 |
| 실행 | 배포 설정 필요 | `java -jar` 실행 가능 |
| 프로젝트 생성 | 직접 구성 | Spring Initializr 사용 |

---

## 4. 기존 웹 프로젝트와의 차이

Servlet/JSP 프로젝트에서는 Servlet 클래스가 요청을 처리하고 JSP가 화면을 담당했다.
Spring Boot에서는 Controller가 요청을 받고, 객체 생성과 의존성 관리는 Spring Container가 담당한다.

```text
Servlet 직접 매핑
→ @GetMapping / @PostMapping

직접 객체 생성
→ Spring Container Bean 관리

직접 Tomcat 설정
→ 내장 Tomcat 자동 실행
```

## 5. IoC와 DI

IoC는 객체 생성과 제어의 주체가 개발자 코드에서 Spring Container로 넘어가는 개념이다.

DI는 필요한 의존 객체를 외부에서 주입받는 방식이다.

```java
public class AccountService {
    private final AccountRepository accountRepository;

    public AccountService(AccountRepository accountRepository) {
        this.accountRepository = accountRepository;
    }
}
```

이 구조는 클래스 간 결합도를 낮추고 테스트를 쉽게 만든다.

## 6. Annotation 기반 개발

Spring Boot에서는 Annotation을 통해 객체 등록과 요청 매핑을 처리한다.

| Annotation | 역할 |
|---|---|
| `@SpringBootApplication` | Spring Boot 시작 클래스 |
| `@RestController` | REST 응답 Controller |
| `@GetMapping` | GET 요청 매핑 |
| `@Component` | Bean 등록 |
| `@Service` | Service 계층 Bean 등록 |
| `@Repository` | Repository 계층 Bean 등록 |
| `@Configuration` | 설정 클래스 |
| `@Bean` | 수동 Bean 등록 |

## 7. AOP

AOP는 공통 기능을 핵심 로직에서 분리하는 방식이다.

대표적인 공통 관심사는 다음과 같다.

- 로깅
- 실행 시간 측정
- 트랜잭션
- 보안
- 예외 처리

AOP를 사용하면 여러 Service 메서드에 반복되는 코드를 한 곳으로 분리할 수 있다.

## 9. 면접 질문과 답변

### Spring Boot는 Spring Framework와 어떤 차이가 있나요?

Spring Framework는 기반 프레임워크이고, Spring Boot는 자동 설정과 내장 Tomcat을 제공해 Spring 애플리케이션을 더 쉽게 만들 수 있게 해주는 도구다.

### IoC란 무엇인가요?

객체 생성과 제어 흐름을 개발자가 직접 관리하지 않고 Spring Container가 관리하도록 제어권이 넘어가는 개념이다.

### DI란 무엇인가요?

객체가 필요한 의존 객체를 직접 생성하지 않고 외부에서 주입받는 방식이다.

### AOP는 언제 사용하나요?

로깅, 트랜잭션, 실행 시간 측정처럼 여러 곳에서 반복되는 공통 관심사를 핵심 로직과 분리할 때 사용한다.
