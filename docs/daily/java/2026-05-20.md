## 2. 클래스의 기본 구성 요소

클래스는 객체를 만들기 위한 설계도이다.
클래스 내부에는 데이터를 저장하는 필드와 객체를 초기화하는 생성자, 기능을 수행하는 메서드가 들어갈 수 있다.

```java
public class Car {
    private String model;
    private int price;

    public Car() {
    }

    public Car(String model, int price) {
        this.model = model;
        this.price = price;
    }

    public void printInfo() {
        System.out.println(model);
        System.out.println(price);
    }
}
```

정리:

| 구성 요소               | 역할                                             |
| ----------------------- | ------------------------------------------------ |
| 필드 field              | 객체의 데이터를 저장                             |
| 생성자 constructor      | 객체 생성 시 초기화 담당                         |
| 메서드 method           | 객체의 동작 정의                                 |
| 블록 block              | 객체 생성 또는 클래스 로딩 시 실행되는 문장 묶음 |
| 내부 클래스 inner class | 클래스 내부에 선언되는 클래스                    |

## 3. 필드와 캡슐화

필드는 객체의 상태를 저장하는 변수이다.

```java
private String name;
private int age;
private int balance;
```

필드는 외부에서 직접 접근하지 못하게 `private`으로 선언하는 것이 일반적이다.  
대신 외부에서 사용할 땐 getter와 setter 메서드를 통해 값을 읽거나 변경한다.

```java
public String getName() {
    return name;
}

public void setName(String name) {
    this.name = name;
}
```

이렇게 필드를 감추고 필요한 메서드만 외부에 공개하는 방식을 캡슐화라고 한다.

정리:

- 필드는 객체의 데이터를 저장한다.
- 필드는 보통 `private`으로 선언한다.
- 외부 접근은 getter/setter 메서드로 제어한다.
- 내부 구현을 숨기고 필요한 기능만 제공하는 것이 캡슐화이다.

## 4. 접근 제한자

접근 제한자는 클래스, 필드, 생성자, 메서드에 접근할 수 있는 범위를 정한다.

| 접근 제한자  | 같은 클래스 | 같은 패키지 | 다른 패키지의 자식 클래스 | 다른 패키지 |
| ------------ | ----------: | ----------: | ------------------------: | ----------: |
| `public`     |        가능 |        가능 |                      가능 |        가능 |
| `protected`  |        가능 |        가능 |                      가능 |      불가능 |
| 생략 default |        가능 |        가능 |                    불가능 |      불가능 |
| `private`    |        가능 |      불가능 |                    불가능 |      불가능 |

예시:

```java
public void powerOn1() {
}

protected void powerOn2() {
}

void powerOn3() {
}

private void powerOn4() {
}
```

`private` 메서드는 같은 클래스 내부에서만 사용할 수 있다.

## 5. 생성자와 생성자 오버로딩

생성자는 객체가 생성될 때 호출되며, 주로 필드 초기화에 사용된다.

```java
public class Korean {
    private String nation = "대한민국";
    private String name;
    private String ssn;

    public Korean() {
    }

    public Korean(String name) {
        this.name = name;
    }

    public Korean(String name, String ssn) {
        this.name = name;
        this.ssn = ssn;
    }
}
```

같은 클래스 안에서 매개변수의 개수나 타입이 다른 생성자를 여러 개 정의할 수 있다.  
이를 생성자 오버로딩이라고 한다.

정리:

- 생성자는 클래스 이름과 같아야 한다.
- 생성자는 반환 타입을 쓰지 않는다.
- 생성자를 하나도 작성하지 않으면 컴파일러가 기본 생성자를 추가한다.
- 생성자를 하나라도 직접 작성하면 기본 생성자는 자동으로 추가되지 않는다.
- 매개변수가 다른 생성자를 여러 개 만들 수 있다.

## 6. `this`와 `this()`

`this`는 현재 객체를 의미한다.  
필드 이름과 매개변수 이름이 같을 때 구분하기 위해 사용한다.

```java
public Korean(String name, String ssn) {
    this.name = name;
    this.ssn = ssn;
}
```

`this()`는 같은 클래스의 다른 생성자를 호출할 때 사용한다.

```java
public BankCustomer() {
    this(null, 0, 0);
}

public BankCustomer(String name) {
    this(name, 0, 0);
}

public BankCustomer(String name, int age, int balance) {
    this.name = name;
    this.age = age;
    this.balance = balance;
}
```

`this()`는 생성자 안에서만 사용할 수 있고, 생성자의 첫 줄에 와야 한다.

## 7. 인스턴스 변수와 클래스 변수

필드는 크게 인스턴스 변수와 클래스 변수로 나눌 수 있다.

```java
private static int numberOfPerson;
private int age;
private String name;
```

| 구분          | 선언 방식           | 특징                               |
| ------------- | ------------------- | ---------------------------------- |
| 인스턴스 변수 | `private int age;`  | 객체마다 따로 생성                 |
| 클래스 변수   | `static int count;` | 클래스 단위로 하나만 생성되어 공유 |

예시:

```java
public class Person {
    private static int numberOfPerson;
    private int age;
    private String name;

    {
        numberOfPerson++;
    }
}
```

객체가 생성될 때마다 `numberOfPerson`이 증가하면 전체 객체 수를 관리할 수 있다.

## 8. 인스턴스 메서드와 static 메서드

메서드도 인스턴스 메서드와 `static` 메서드로 나눌 수 있다.

```java
public void powerOn() {
}

public static void powerOff() {
}
```

| 구분            | 호출 방식           | 특징                     |
| --------------- | ------------------- | ------------------------ |
| 인스턴스 메서드 | `객체.메서드()`     | 객체 생성 후 사용        |
| static 메서드   | `클래스명.메서드()` | 객체 생성 없이 사용 가능 |

예시:

```java
Calculator calc = new Calculator();
calc.powerOn();

Calculator.powerOff();
```

Eclipse 자동완성에서 `S` 표시가 붙은 메서드는 `static` 메서드이다.  
`static` 메서드는 객체를 통해 호출할 수도 있지만, 권장 방식은 클래스명으로 호출하는 것이다.

```java
Calculator.powerOff(); // 권장
```

## 9. 초기화 블록

초기화 블록은 객체 생성 시 또는 클래스 로딩 시 실행되는 코드 블록이다.

## 9-1. 인스턴스 초기화 블록

```java
{
    name = "Anonymous";
    age = 12;
    numberOfPerson++;
}
```

인스턴스 초기화 블록은 객체가 생성될 때마다 실행된다.  
생성자 본문이 실행되기 전에 공통 초기화 작업을 처리할 수 있다.

## 9-2. static 초기화 블록

```java
static {
    System.out.println("class load 시 1회만 수행");
}
```

`static` 초기화 블록은 클래스가 로딩될 때 한 번만 실행된다.

정리:

| 블록                 | 실행 시점                     |
| -------------------- | ----------------------------- |
| 인스턴스 초기화 블록 | 객체가 생성될 때마다 실행     |
| static 초기화 블록   | 클래스가 로딩될 때 한 번 실행 |

## 10. 메서드 오버로딩

메서드 오버로딩은 같은 이름의 메서드를 매개변수의 개수나 타입을 다르게 하여 여러 개 정의하는 것이다.

```java
int add(int num1, int num2) {
    return num1 + num2;
}

double add(double num1, double num2) {
    return num1 + num2;
}

String add(String num1, String num2) {
    return num1 + num2;
}
```

호출할 때 전달한 인자의 타입과 개수에 따라 실행되는 메서드가 결정된다.

```java
Computer com = new Computer();

System.out.println(com.add("a", "b"));
System.out.println(com.add(100, 200));
System.out.println(com.add(1.2, 1.5));
```

## 11. 가변 인자

가변 인자를 사용하면 매개변수 개수가 정해져 있지 않은 값을 받을 수 있다.

```java
int add(int... numbers) {
    int total = 0;

    for (int number : numbers) {
        total += number;
    }

    return total;
}
```

호출 예시:

```java
System.out.println(com.add(1, 2, 3));
System.out.println(com.add(1, 2, 3, 4));
```

가변 인자는 내부적으로 배열처럼 처리된다.
따라서 배열을 직접 전달할 수도 있다.

```java
int[] numbers = {1, 2, 3, 4, 5};
System.out.println(com.add(numbers));
```

## 12. Object 클래스와 `toString()`

Java의 모든 클래스는 최상위 클래스인 `Object`를 상속받는다.

```java
public class Car {
}
```

위 코드는 명시하지 않아도 다음처럼 이해할 수 있다.

```java
public class Car extends Object {
}
```

`Object` 클래스에는 `toString()` 메서드가 있다.
객체를 출력하면 기본적으로 `toString()` 결과가 출력된다.

```java
System.out.println(car);
```

기본 출력 대신 객체 정보를 보기 쉽게 출력하려면 `toString()`을 재정의한다.

```java
@Override
public String toString() {
    return "Car [model=" + model + ", price=" + price + "]";
}
```

## 13. JavaBeans, VO, DTO

JavaBeans는 데이터를 담기 위한 객체 작성 방식으로 이해할 수 있다.  
보통 필드를 `private`으로 두고, 기본 생성자와 getter/setter를 제공한다.

```java
public class BookDTO {
    private String title;
    private int price;

    public BookDTO() {
    }

    public BookDTO(String title, int price) {
        this.title = title;
        this.price = price;
    }

    public String getTitle() {
        return title;
    }

    public void setTitle(String title) {
        this.title = title;
    }
}
```

VO와 DTO는 데이터를 담고 전달하기 위한 객체로 사용된다.

| 용어 | 의미                                           |
| ---- | ---------------------------------------------- |
| VO   | Value Object, 값을 표현하는 객체               |
| DTO  | Data Transfer Object, 계층 간 데이터 전달 객체 |

오늘 실습에서는 책 정보를 `BookDTO`에 담고, Service와 View에서 이 데이터를 사용했다.

## 14. MVC 패턴 기초

MVC는 역할을 나누어 코드를 구성하는 방식이다.

| 구성 요소  | 역할                   |
| ---------- | ---------------------- |
| Model      | 데이터와 비즈니스 로직 |
| View       | 사용자에게 결과 출력   |
| Controller | 요청을 받고 흐름 제어  |

이번 실습에서는 다음 구조로 나누어 책 정보를 처리했다.

```text
BookController
BookDTO
BookService
BookView
```

각 클래스 역할:

| 클래스           | 역할                                            |
| ---------------- | ----------------------------------------------- |
| `BookController` | 실행 흐름 제어                                  |
| `BookDTO`        | 책 데이터 저장                                  |
| `BookService`    | 책 제목 수정, 가격 변경 같은 비즈니스 로직 처리 |
| `BookView`       | 책 목록과 결과 출력                             |

흐름:

```text
Controller
→ Service 호출
→ DTO 데이터 처리
→ View 출력
```

실습 코드에서는 별도의 DAO를 만들지 않고 배열 데이터를 직접 사용했다.  
DB 접근이 들어가면 DAO가 데이터 접근 역할을 맡게 된다.

## 15. MVC 실습 흐름

책 정보를 배열에 저장한 뒤 Service에서 데이터를 수정하고 View에서 출력했다.

```java
BookDTO[] books = new BookDTO[5];

books[0] = new BookDTO("Java Program", 30000);
books[1] = new BookDTO("JSP Program", 25000);
books[2] = new BookDTO("SQL Fundamentals", 20000);
books[3] = new BookDTO("JDBC Program", 32000);
books[4] = new BookDTO("EJB Program", 25000);
```

Service에서는 책 제목과 가격을 변경한다.

```java
public BookDTO[] updateTitle(BookDTO[] bookList, String company) {
    for (BookDTO book : bookList) {
        book.setTitle(company + book.getTitle());
    }

    return bookList;
}

public BookDTO[] updatePrice(BookDTO[] bookList, double rate) {
    for (BookDTO book : bookList) {
        book.setPrice((int)(book.getPrice() * rate));
    }

    return bookList;
}
```

View에서는 출력만 담당한다.

```java
public static void printBookListInfo(BookDTO[] bookList) {
    for (BookDTO book : bookList) {
        System.out.println(book);
    }
}
```

정리하면 Controller는 흐름을 제어하고, Service는 로직을 처리하고, View는 출력만 담당한다.

## 16. 다시 볼 부분

- `static` 변수와 인스턴스 변수의 차이를 확실히 구분하기
- `static` 메서드는 객체보다 클래스명으로 호출하는 것이 권장
- 인스턴스 초기화 블록은 생성자 본문보다 먼저 실행
- `this`는 현재 객체를 의미하고, `this()`는 같은 클래스의 다른 생성자를 호출
- 메서드 이름이 같고 매개변수의 개수나 타입이 다를 때 메서드 오버로딩이라고 한다.
- 가변 인자 `int... numbers`는 내부적으로 배열처럼 처리
- DTO는 데이터를 담는 역할이고, Service는 비즈니스 로직을 처리
- MVC 패턴에서는 Controller, Service, View의 역할을 분리해서 이해하기

## 정리

- 클래스는 객체를 만들기 위한 설계도이다.
- 필드는 데이터를 저장하고, 생성자는 객체 초기화에 사용되며, 메서드는 기능을 수행한다.
- 필드는 보통 `private`으로 선언하고 getter/setter로 접근한다.
- 접근 제한자는 코드 접근 범위를 제어한다.
- 생성자는 클래스명과 같고 반환 타입이 없다.
- 생성자 오버로딩을 통해 다양한 방식으로 객체를 초기화할 수 있다.
- `this`는 현재 객체, `this()`는 같은 클래스의 다른 생성자 호출을 의미한다.
- `static` 변수는 클래스 단위로 공유되고, 인스턴스 변수는 객체마다 따로 생성된다.
- `static` 메서드는 객체 생성 없이 클래스명으로 호출할 수 있다.
- 인스턴스 초기화 블록은 객체 생성 시마다 실행되고, `static` 초기화 블록은 클래스 로딩 시 한 번 실행된다.
- 메서드 오버로딩은 같은 이름의 메서드를 매개변수 차이로 여러 개 정의하는 것이다.
- 가변 인자를 사용하면 개수가 정해지지 않은 인자를 받을 수 있다.
- 모든 클래스는 `Object` 클래스를 상속받고, 필요하면 `toString()`을 재정의할 수 있다.
- DTO는 계층 간 데이터를 전달하기 위한 객체이다.
- MVC 패턴은 Controller, Model, View의 역할을 분리하는 구조이다.
