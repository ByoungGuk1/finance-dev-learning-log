## 3. 패키지와 default package

Java 파일 맨 위에 `package`를 작성하면 해당 클래스가 특정 패키지에 소속된다.

```java
package com.example.project.day06;
```

패키지 선언이 없으면 `src` 바로 아래의 default package에 속한다.

```java
public class Example {
}
```

패키지를 명확히 두면 클래스의 위치와 역할을 구분하기 쉽다.

패키지 이름은 보통 모두 소문자로 작성한다.

일반적인 작성 방식:

```text
회사 도메인 역순 + 프로젝트 또는 기능명
```

예시:

```java
package com.example.learning.day06;
```

정리:

- 패키지 이름은 소문자로 작성한다.
- 서로 중복되지 않도록 도메인 역순을 사용한다.

## 5. import와 패키지 탐색

다른 패키지의 클래스를 사용하려면 `import`를 사용할 수 있다.

```java
import java.util.Date;
import java.util.Calendar;
import java.time.LocalDateTime;
```

같은 이름의 클래스가 여러 패키지에 있을 때는 전체 경로를 직접 적어 사용한다.

```java
Date utilDate = new Date();

long time = utilDate.getTime();
java.sql.Date sqlDate = new java.sql.Date(time);
```

정리:

- `java.lang` 패키지는 자동으로 import된다.
- 그 외 패키지는 보통 import가 필요하다.
- 같은 클래스명이 충돌하면 전체 패키지 경로를 직접 사용한다.

## 6. 클래스 실행 흐름

클래스가 사용될 때는 `static` 영역과 인스턴스 영역의 실행 시점을 구분해야 한다.

수업에서 정리한 흐름:

```text
1. static 변수 초기화
2. static 초기화 블록 실행
3. static 메서드는 클래스명으로 호출 가능
4. 인스턴스 변수 초기화
5. 인스턴스 초기화 블록 실행
6. 생성자 실행
7. 인스턴스 메서드는 객체 생성 후 호출 가능
```

예시:

```java
public class Person {
    static int count;

    static {
        System.out.println("static block");
    }

    String name;

    {
        System.out.println("instance block");
    }

    public Person(String name) {
        this.name = name;
        System.out.println("constructor");
    }
}
```

정리:

| 구분                 | 실행 시점                               |
| -------------------- | --------------------------------------- |
| `static` 변수        | 클래스 로딩 시                          |
| `static` 블록        | 클래스 로딩 시 한 번                    |
| 인스턴스 변수        | 객체 생성 시                            |
| 인스턴스 초기화 블록 | 객체 생성 시마다                        |
| 생성자               | 객체 생성 시, 인스턴스 초기화 블록 이후 |
| 인스턴스 메서드      | 객체 생성 후 호출                       |

## 7. static 변수와 static 메서드

`static`은 객체가 아니라 클래스에 소속된다.

```java
public class Calculator {
    static double pi = 3.141592;

    public static void printPi() {
        System.out.println(pi);
    }
}
```

호출 방식:

```java
Calculator.printPi();
```

`static` 메서드는 객체를 만들지 않고 클래스명으로 호출할 수 있다.

```java
Calculator calc = new Calculator();

// 가능은 하지만 권장하지 않음
calc.printPi();

// 권장
Calculator.printPi();
```

정리:

- `static` 필드는 클래스 단위로 공유된다.
- `static` 메서드는 객체 생성 없이 호출할 수 있다.
- `static` 메서드에서는 인스턴스 필드를 바로 사용할 수 없다.
- 인스턴스 필드를 사용하려면 객체가 필요하다.

## 8. final 필드와 static final 상수

`final`은 값을 한 번만 할당할 수 있게 한다.

```java
public class Calculator {
    final int score = 100;
}
```

`final` 인스턴스 필드는 생성자를 통해서 초기화할 수 있다.

```java
public class Calculator {
    final int score;

    public Calculator() {
        score = 100;
    }
}
```

또는 인스턴스 초기화 블록을 통해 초기화할 수 있다.

```java
public class Calculator {
    final int score;

    {
        score = 100;
    }
}
```

`static final`은 클래스 상수로 사용된다.

```java
public class Calculator {
    static final int MAX_SCORE = 100;
}
```

상수 이름은 보통 대문자와 언더바를 사용한다.

```java
static final int MIN_BALANCE = 0;
static final int MAX_BALANCE = 1_000_000;
```

정리:

| 구분                | 특징                                             |
| ------------------- | ------------------------------------------------ |
| `final` 필드        | 객체마다 가질 수 있고, 한 번 초기화 후 변경 불가 |
| `static final` 상수 | 클래스 단위로 하나만 존재하고 변경 불가          |
| 상수명 관례         | 대문자 + 언더바                                  |

## 9. 접근 제한자

접근 제한자는 클래스, 필드, 생성자, 메서드의 사용 범위를 제한한다.

| 접근 제한자 | 같은 클래스 | 같은 패키지 | 다른 패키지의 자식 클래스 | 다른 패키지 |
| ----------- | ----------: | ----------: | ------------------------: | ----------: |
| `public`    |        가능 |        가능 |                      가능 |        가능 |
| `protected` |        가능 |        가능 |                      가능 |      불가능 |
| default     |        가능 |        가능 |                    불가능 |      불가능 |
| `private`   |        가능 |      불가능 |                    불가능 |      불가능 |

예시:

```java
public class Car {
    public int speed1;
    protected int speed2;
    int speed3;
    private int speed4;
}
```

정리:

- `public`은 외부 어디서든 접근할 수 있다.
- `protected`는 같은 패키지 또는 상속 관계에서 접근할 수 있다.
- default는 같은 패키지에서만 접근할 수 있다.
- `private`은 같은 클래스 내부에서만 접근할 수 있다.

## 10. 기타 modifier

수업에서 배운 modifier는 다음과 같다.

| modifier       | 의미                         |
| -------------- | ---------------------------- |
| `static`       | 클래스 소속                  |
| `final`        | 변경 또는 재정의 불가        |
| `abstract`     | 추상 클래스 또는 추상 메서드 |
| `synchronized` | 멀티스레드 환경에서 동기화   |
| `transient`    | 직렬화 대상에서 제외         |

예시:

```java
public final void func1() {
}
```

`final` 메서드는 자식 클래스에서 오버라이딩할 수 없다.

```java
synchronized void func3() {
}
```

`synchronized`는 여러 스레드가 동시에 접근할 때 공유 자원 문제를 막기 위해 사용한다.

```java
transient int speed;
```

`transient`는 객체를 직렬화할 때 해당 필드를 제외한다.

##### 직렬화 : 객체 상태를 파일이나 네트워크 전송이 가능한 형태로 변환하는 것

## 11. 메서드 오버로딩 조건

오버로딩은 같은 이름의 메서드를 여러 개 선언하는 것이다.

단, 매개변수의 구성이 달라야 한다.

오버로딩이 되는 경우:

```java
void print(int value) {
}

void print(String value) {
}

void print(int value, String message) {
}
```

오버로딩이 되지 않는 경우:

```java
public void print(int value) {
}

private void print(int value) {
}
```

접근 제한자만 다르고 매개변수 구성이 같으면 오버로딩이 아니다.

```java
int add(int a, int b) {
    return a + b;
}

double add(int a, int b) {
    return a + b;
}
```

리턴 타입만 다르게 하는 것도 오버로딩이 아니다.

정리:

- 메서드 이름은 같아도 된다.
- 매개변수의 개수, 타입, 순서가 달라야 한다.
- 접근 제한자만 다르면 오버로딩이 아니다.
- 리턴 타입만 다르면 오버로딩이 아니다.

## 12. JavaBeans와 getter/setter

JavaBeans 형식은 데이터를 담는 클래스를 일정한 규칙으로 작성하는 방식이다.

일반적인 규칙:

- 필드는 `private`
- 기본 생성자 제공
- getter/setter 제공
- 필요하면 `toString()` 재정의

예시:

```java
public class Employee {
    private String id;
    private String name;
    private int baseSalary;

    public Employee() {
    }

    public Employee(String id, String name, int baseSalary) {
        this.id = id;
        this.name = name;
        this.baseSalary = baseSalary;
    }

    public String getId() {
        return id;
    }

    public void setId(String id) {
        this.id = id;
    }
}
```

getter는 값을 읽을 때 사용한다.

```java
public String getName() {
    return name;
}
```

setter는 값을 변경할 때 사용한다.

```java
public void setName(String name) {
    this.name = name;
}
```

## 13. Object 클래스와 메서드 재정의

Java의 모든 클래스는 `Object` 클래스를 상속받는다.

```java
public class Employee {
}
```

위 코드는 명시하지 않아도 다음처럼 생각하면 된다.

```java
public class Employee extends Object {
}
```

`Object`의 대표 메서드:

| 메서드       | 역할                 |
| ------------ | -------------------- |
| `toString()` | 객체를 문자열로 표현 |
| `equals()`   | 객체 비교            |
| `hashCode()` | 해시값 반환          |

`toString()`을 재정의하면 객체를 출력할 때 원하는 형식으로 출력할 수 있다.

```java
@Override
public String toString() {
    return name + "(" + id + ") 사원의 기본급은 " + baseSalary + "원 입니다.";
}
```

`equals()`도 재정의할 수 있다.

```java
@Override
public boolean equals(Object obj) {
    return true;
}
```

주의: `equals()`를 재정의할 때는, 비교 기준을 명확히 정해야 한다.

## 14. 싱글톤 패턴

싱글톤 패턴은 객체를 하나만 만들어서 공유하도록 하는 패턴이다.

기본 구조:

```java
public class MySingleton {
    private static MySingleton instance;

    private MySingleton() {
    }

    public static MySingleton getInstance() {
        if (instance == null) {
            instance = new MySingleton();
        }
        return instance;
    }
}
```

사용:

```java
MySingleton s1 = MySingleton.getInstance();
MySingleton s2 = MySingleton.getInstance();

System.out.println(s1 == s2); // true
```

핵심:

- 생성자를 `private`으로 막는다.
- 클래스 내부에서 객체를 하나만 생성한다.
- 외부에서는 `getInstance()`로 객체를 얻는다.

서블릿은 일반적으로 하나의 인스턴스를 여러 요청이 공유하는 방식으로 동작하므로, 싱글톤과 유사하게 이해할 수 있다.

정리:

- 싱글톤은 여러 객체를 만들 필요가 없고, 하나의 객체를 공유할 때 사용한다.
- 생성자를 오버로딩하여 여러 개 만들 필요가 없다.
- 하나의 인스턴스를 공유하여 공통 기능을 처리할 수 있다.
- 멀티스레드 환경에서는 동시에 동작하는 상황도 고려해야 한다.

## 15. 계좌 잔고 제한 실습

계좌 객체에서 잔고는 외부에서 직접 바꾸지 못하게 `private`으로 막는다.  
그리고 setter에서 허용 범위를 검사한다.

```java
public class Account {
    private static final int MIN_BALANCE = 0;
    private static final int MAX_BALANCE = 1_000_000;

    private int balance;

    public int getBalance() {
        return balance;
    }

    public void setBalance(int balance) {
        if (balance < MIN_BALANCE || balance > MAX_BALANCE) {
            return;
        }

        this.balance = balance;
    }
}
```

정리:

- `balance`는 `private`으로 보호한다.
- `MIN_BALANCE`, `MAX_BALANCE`는 상수로 선언한다.
- setter에서 유효하지 않은 값은 반영하지 않는다.

## 16. 계좌 관리 프로그램 실습

계좌 관리 프로그램은 역할을 나누어 구성했다.

```text
AccountDTO
AccountService
AccountView
BankApplication
```

역할:

| 클래스            | 역할                             |
| ----------------- | -------------------------------- |
| `AccountDTO`      | 계좌번호, 이름, 잔액 데이터 저장 |
| `AccountService`  | 계좌 생성, 조회, 입금, 출금 처리 |
| `AccountView`     | 메뉴 출력과 사용자 입력 처리     |
| `BankApplication` | 프로그램 실행 흐름 제어          |

흐름:

```text
사용자 입력
→ View
→ Application
→ Service
→ DTO 변경
→ View 출력
```

계좌 조회는 계좌번호를 기준으로 수행한다.

```java
public static AccountDTO findAccount(String accountNumber, AccountDTO[] accountList) {
    for (AccountDTO account : accountList) {
        if (account == null) {
            break;
        }

        if (account.getAccountNumber().equals(accountNumber)) {
            return account;
        }
    }

    return null;
}
```

현재 구조에서는 계좌가 앞에서부터 순서대로 저장된다고 가정했기 때문에 `null`을 만나면 반복을 종료했다.
나중에 삭제 기능이 추가되어 중간에 `null`이 생길 수 있다면 `break` 대신 `continue`나 다른 방법을 고려해야한다.

출금은 잔액보다 큰 금액이면 실패하도록 처리할 수 있다.

```java
public static AccountDTO withdraw(AccountDTO account, int money) {
    if (account.getBalance() < money) {
        return null;
    }

    account.setBalance(account.getBalance() - money);
    return account;
}
```

## 17. 다시 볼 부분

- 클래스 로딩 시 실행되는 `static` 초기화와 객체 생성 시 실행되는 인스턴스 초기화를 구분하기
- `static final` 상수는 선언 시 또는 `static` 블록에서 초기화 가능
- 생성자에서는 일반 `static` 변수의 변경은 가능하지만, `static final` 상수 초기화는 할 수 없다.
- modifier의 역할에 대해 구분하기
- 오버로딩은 매개변수의 개수, 타입, 순서가 달라야 한다.
- 리턴 타입이나 접근 제한자만 다르면 오버로딩이 아니다.
- 싱글톤 패턴에서 생성자를 `private`으로 막는 이유

## 정리

- 패키지를 선언하지 않으면 default package에 속한다.
- 패키지 이름은 보통 소문자로 작성하고, 도메인 역순 구조를 사용한다.
- `static` 변수와 `static` 블록은 클래스 로딩 시 처리된다.
- 인스턴스 변수와 인스턴스 초기화 블록은 객체 생성 시 처리된다.
- 생성자는 인스턴스 초기화 블록 이후 실행된다.
- `static` 메서드는 객체 생성 없이 클래스명으로 호출할 수 있다.
- `final` 필드는 한 번 초기화하면 변경할 수 없다.
- `static final`은 클래스 상수로 사용한다.
- 접근 제한자는 코드의 접근 범위를 제어한다.
- `transient`는 직렬화 대상에서 제외할 때 사용한다.
- `synchronized`는 멀티스레드 환경에서 공유 자원 접근을 제어할 때 사용한다.
- 오버로딩은 메서드 이름은 같고 매개변수 구성이 달라야 한다.
- JavaBeans는 `private` 필드, 기본 생성자, getter/setter를 갖는 형식으로 작성한다.
- 모든 클래스는 `Object`를 상속받으며, 필요하면 `toString()`과 `equals()`를 재정의할 수 있다.
- 싱글톤 패턴은 객체를 하나만 만들어 공유하기 위한 패턴이다.
- 계좌 관리 실습에서는 DTO, Service, View, Application 역할을 나누어 보았다.
