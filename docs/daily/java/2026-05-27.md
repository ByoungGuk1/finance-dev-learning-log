## 2. 인터페이스

인터페이스는 클래스가 구현해야 할 규칙을 정의하는 타입이다.

```java
public interface RemoteControl {
    void turnOn();
    void turnOff();
}
```

인터페이스 안의 추상 메서드는 기본적으로 `public abstract`가 생략된 형태로 볼 수 있다.

```java
void turnOn();
```

위 코드는 다음과 비슷하게 이해할 수 있다.

```java
public abstract void turnOn();
```

인터페이스는 직접 객체를 생성할 수 없고, 구현 클래스를 통해 사용한다.

```java
public class Television implements RemoteControl {
    @Override
    public void turnOn() {
        System.out.println("TV 전원 켬");
    }

    @Override
    public void turnOff() {
        System.out.println("TV 전원 끔");
    }
}
```

정리:

- 인터페이스는 객체가 가져야 할 기능의 규격을 정의한다.
- 인터페이스 자체로는 객체를 만들 수 없다.
- 구현 클래스는 `implements` 키워드로 인터페이스를 구현한다.
- 구현 클래스는 인터페이스의 추상 메서드를 반드시 구현해야 한다.

## 3. 인터페이스의 상수와 추상 메서드

인터페이스에 선언한 필드는 기본적으로 `public static final` 상수이다.

```java
public interface JDBCInterface {
    int MAX_VALUE = 1000;
}
```

위 코드는 다음과 비슷하게 이해할 수 있다.

```java
public static final int MAX_VALUE = 1000;
```

인터페이스의 추상 메서드는 기본적으로 `public abstract`이다.

```java
void getConnection();
```

위 코드는 다음과 같다.

```java
public abstract void getConnection();
```

정리:

- 인터페이스의 필드는 기본적으로 `public static final` 즉, 상수이다.
- 인터페이스의 메서드는 기본적으로 `public abstract` 즉, 추상메서드이다.
- 생략 가능하지만, 의미를 정확히 알고 있어야 한다.
- 메서드는 추가적으로 `default`, `static`, `private` 메서드를 가질 수 있다.

## 4. `default` 메서드

인터페이스는 기본 구현을 가진 `default` 메서드를 가질 수 있다.

```java
public interface PaymentService {
    default void printReceipt(int amount) {
        System.out.println("내역 : " + amount);
    }
}
```

`default` 메서드는 구현 클래스에서 그대로 사용할 수도 있고, 필요하면 재정의할 수도 있다.

```java
public class FintechTransferService implements PaymentService {
    @Override
    public void printReceipt(int amount) {
        PaymentService.super.printReceipt(amount);
        System.out.println("추가 출력");
    }
}
```

정리:

- `default` 메서드는 인터페이스 안에서 구현부를 가질 수 있다.
- 구현 클래스는 `default` 메서드를 그대로 사용할 수 있다.
- 필요하면 구현 클래스에서 오버라이딩할 수 있다.
- 기존 인터페이스에 기능을 추가할 때 구현 클래스의 변경 부담을 줄일 수 있다.

## 5. `static` 메서드

인터페이스는 `static` 메서드를 가질 수 있다.

```java
public interface PaymentService {
    static void printReceipt2(int amount) {
        System.out.println("내역 : " + amount);
    }
}
```

인터페이스의 `static` 메서드는 인터페이스 이름으로 호출한다.

```java
PaymentService.printReceipt2(10000);
```

구현 객체를 통해 호출하는 것이 아니라 인터페이스 자체에 소속된 메서드로 이해하면 된다.

정리:

- 인터페이스의 `static` 메서드는 인터페이스 이름으로 호출한다.
- 구현 클래스에서 오버라이딩할 수 없다.
- 공통 유틸성 기능을 둘 때 사용할 수 있다.

## 6. 인터페이스의 `private` 메서드

인터페이스 내부에서만 사용할 수 있는 `private` 메서드를 선언할 수 있다.

```java
public interface JDBCInterface {
    default void print() {
        printPrivate();
    }

    private void printPrivate() {
        System.out.println("인터페이스 내부에서만 사용");
    }
}
```

`private` 메서드는 `default` 메서드나 `static` 메서드의 중복 로직을 분리할 때 사용할 수 있다.

```java
public static void printStatic() {
    printPrivateStatic();
}

private static void printPrivateStatic() {
    System.out.println("private static method");
}
```

정리:

- 인터페이스의 `private` 메서드는 외부에서 호출할 수 없다.
- 인터페이스 내부의 중복 로직을 줄일 때 사용한다.
- `private static` 메서드는 `static` 메서드 내부에서 사용할 수 있다.

## 7. 인터페이스 구현과 다형성

인터페이스 타입 변수에는 해당 인터페이스를 구현한 객체를 대입할 수 있다.

```java
RemoteControl remote = new Television();
```

이렇게 하면 실제 객체가 `Television`이어도, 사용하는 쪽에서는 `RemoteControl` 타입으로 다룰 수 있다.

```java
remote.turnOn();
remote.turnOff();
```

인터페이스 타입을 사용하면 구현체를 바꿔도 사용하는 코드를 크게 바꾸지 않아도 된다.

```java
RemoteControl remote = new Audio();
```

정리:

- 인터페이스 타입 변수에 구현 객체를 대입할 수 있다.
- 실제 실행되는 메서드는 구현 클래스의 메서드이다.
- 인터페이스를 기준으로 코드를 작성하면 구현체 변경에 유리하다.

## 8. 인터페이스 다중 구현

Java 클래스는 클래스 다중 상속을 허용하지 않는다.  
하지만 인터페이스는 여러 개를 동시에 구현할 수 있다.

```java
class MyClass implements MyInterA, MyInterB {
    @Override
    public void f1() {
    }

    @Override
    public void f2() {
    }
}
```

상속과 인터페이스 구현을 함께 사용할 수도 있다.

```java
class MyClass extends Parent implements MyInterA, MyInterB {
}
```

정리:

- 클래스 상속은 하나만 가능하다.
- 인터페이스 구현은 여러 개 가능하다.
- `extends`는 클래스 상속에 사용한다.
- `implements`는 인터페이스 구현에 사용한다.

## 9. 인터페이스 상속

인터페이스끼리는 `extends`를 사용해 상속할 수 있다.

```java
interface MyInterA {
    void f1();
}

interface MyInterB {
    void f2();
}

interface MyInterC extends MyInterA, MyInterB {
    void f3();
}
```

인터페이스는 여러 인터페이스를 동시에 상속할 수 있다.

`MyInterC`를 구현하는 클래스는 `f1()`, `f2()`, `f3()`를 모두 구현해야 한다.

```java
class MyClass implements MyInterC {
    @Override
    public void f1() {
    }

    @Override
    public void f2() {
    }

    @Override
    public void f3() {
    }
}
```

정리:

- 인터페이스끼리는 다중 상속이 가능하다.
- 인터페이스 상속에도 `extends`를 사용한다.
- 하위 인터페이스를 구현하면 상위 인터페이스의 메서드까지 구현해야 한다.

## 10. JDBC와 인터페이스 기반 설계

JDBC는 Java Database Connectivity의 약자로, Java에서 데이터베이스에 연결하기 위한 기술이다.

수업에서는 JDBC 자체를 깊게 다루기보다, 인터페이스를 이용해서 구현체를 바꿔 끼우는 구조를 확인했다.

```java
public interface JDBCInterface {
    void getConnection();
    void getConnection2();
}
```

구현체는 각각 다른 방식으로 연결 로직을 구현할 수 있다.

```java
public class OracleJDBCImpl implements JDBCInterface {
    @Override
    public void getConnection() {
        System.out.println("Oracle 연결");
    }
}
```

```java
public class SybaseJDBCImpl implements JDBCInterface {
    @Override
    public void getConnection() {
        System.out.println("Sybase 연결");
    }
}
```

사용하는 쪽에서는 구현체가 무엇인지보다 인터페이스 타입에 의존한다.

```java
private static void work(JDBCInterface inter) {
    inter.getConnection();
    inter.getConnection2();
}
```

정리:

- JDBC는 Java와 DB를 연결하기 위한 기술이다.
- 인터페이스를 사용하면 구현체를 분리할 수 있다.
- 사용하는 쪽은 인터페이스에 의존하고, 실제 구현은 구현 클래스가 담당한다.
- 구현체가 바뀌어도 사용하는 코드의 변경을 줄일 수 있다.

## 11. 팩토리 메서드 방식의 객체 생성

팩토리 메서드는 객체 생성을 별도 메서드로 분리하는 방식이다.

```java
public static PaymentService createService(String type) {
    if ("bank".equals(type)) {
        return new BankTransferService();
    }

    return new FintechTransferService();
}
```

사용하는 쪽에서는 new를 직접 여러 곳에 쓰지 않고, 메서드를 통해 필요한 구현체를 받을 수 있다.

## 12. OCP와 구현체 교체

`OCP`는 Open-Closed Principle의 약자이다.
**확장에는 열려 있고, 변경에는 닫혀 있어야 한다**는 객체지향 설계 원칙이다.

인터페이스를 사용하면 기존 코드를 크게 수정하지 않고 구현체를 교체할 수 있다.

```java
PaymentService ps1 = new BankTransferService();
PaymentService ps2 = new FintechTransferService();
```

컨트롤러는 구체 클래스가 아니라 인터페이스 타입에 의존한다.

```java
public class AccountController {
    private PaymentService paymentService;

    public AccountController(PaymentService paymentService) {
        this.paymentService = paymentService;
    }

    public void processTransfer() {
        paymentService.transfer("112", "999", 50_000);
    }
}
```

이 구조에서는 `BankTransferService`를 쓰다가 `FintechTransferService`로 바꿔도 컨트롤러의 핵심 로직은 유지할 수 있다.

정리:

- 인터페이스는 구현체 교체를 쉽게 만든다.
- 사용하는 쪽은 구체 클래스보다 인터페이스에 의존하는 것이 좋다.
- 구현체를 추가해도 기존 코드 변경을 줄일 수 있다.
- OCP 원칙과 연결된다.

## 13. Volume 인터페이스 실습

볼륨 조절 실습에서는 `Volume` 인터페이스를 만들고, 여러 기기에서 구현했다.

```text
Volume
├─ Speaker
├─ Radio
└─ TV
```

인터페이스는 볼륨을 올리고 내리는 기능을 정의한다.

```java
public interface Volume {
    void volumeUp(int amount);
    void volumeDown(int amount);
}
```

구현 클래스는 각자 방식대로 볼륨을 조절한다.

```java
public class Speaker implements Volume {
    @Override
    public void volumeUp(int amount) {
        volumeValue = Math.min(volumeValue + amount, 100);
    }

    @Override
    public void volumeDown(int amount) {
        volumeValue = Math.max(volumeValue - amount, 0);
    }
}
```

배열을 인터페이스 타입으로 만들면 여러 구현체를 함께 관리할 수 있다.

```java
Volume[] volumes = new Volume[3];

volumes[0] = new Speaker();
volumes[1] = new Radio();
volumes[2] = new TV();
```

정리:

- 인터페이스는 여러 구현체의 공통 기능을 정의한다.
- 구현 클래스는 같은 메서드를 각자 다르게 구현할 수 있다.
- 인터페이스 배열을 사용하면 여러 구현체를 하나의 타입으로 처리할 수 있다.

## 14. Shape와 Resizable 실습

도형 실습에서는 추상 클래스와 인터페이스를 함께 사용했다.

```text
Shape
├─ Rectangle implements Resizable
└─ RectTriangle
```

`Shape`는 도형의 공통 구조를 추상 클래스로 정의했다.

```java
public abstract class Shape {
    private int numSides;

    public abstract double getArea();
    public abstract double getPerimeter();
}
```

`Resizable`은 크기 변경 기능만 따로 정의한 인터페이스이다.

```java
public interface Resizable {
    void resize(double size);
}
```

`Rectangle`은 `Shape`를 상속받으면서 `Resizable`도 구현한다.

```java
public class Rectangle extends Shape implements Resizable {
}
```

반면 `RectTriangle`은 `Shape`만 상속받고 `Resizable`은 구현하지 않는다.

이후 `instanceof`를 이용하면 크기 변경 가능한 도형만 골라서 처리할 수 있다.

```java
if (shape instanceof Resizable resizable) {
    resizable.resize(0.5);
}
```

정리:

- 추상 클래스는 공통 상태와 공통 구조를 정의할 때 적합하다.
- 인터페이스는 특정 기능을 부여할 때 적합하다.
- 클래스는 하나만 상속할 수 있지만 인터페이스는 여러 개 구현할 수 있다.
- `instanceof`를 사용하면 특정 인터페이스 구현 여부를 확인할 수 있다.

## 15. 결제 서비스 인터페이스 실습

결제 서비스 실습에서는 `PaymentService` 인터페이스를 만들고, 일반 계좌 이체와 핀테크 송금을 구현체로 분리했다.

```text
PaymentService
├─ BankTransferService
└─ FintechTransferService
```

인터페이스는 이체와 잔액 조회 기능을 정의한다.

```java
public interface PaymentService {
    void transfer(String fromAccount, String toAccount, long amount);

    long getBalance(String accountNumber);
}
```

구현체는 같은 메서드를 다른 방식으로 구현한다.

```java
public class BankTransferService implements PaymentService {
    @Override
    public void transfer(String fromAccount, String toAccount, long amount) {
        System.out.println(fromAccount + " → " + toAccount + " : " + amount + "원 이체");
    }
}
```

```java
public class FintechTransferService implements PaymentService {
    @Override
    public void transfer(String fromAccount, String toAccount, long amount) {
        System.out.println("[핀테크] 즉시송금: " + amount + "원");
    }
}
```

컨트롤러는 `PaymentService` 타입을 받아서 처리한다.

```java
public class AccountController {
    private PaymentService paymentService;

    public AccountController(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}
```

정리:

- 인터페이스를 기준으로 컨트롤러를 작성하면 구현체 교체가 쉬워진다.
- 일반 계좌 이체와 핀테크 송금을 같은 타입으로 처리할 수 있다.
- 서비스 구현체가 바뀌어도 컨트롤러 구조는 유지된다.
- 다형성과 OCP 원칙을 같이 확인할 수 있다.

## 16. 버그 헌팅 실습

수업에서는 금융 상품 코드에서 의도적으로 들어간 문제를 찾고 수정하는 실습도 진행했다.

대표적으로 배열 크기를 넘어가는 경우 인덱스 오류가 발생할 수 있었다.

```java
if (productCount >= 10) {
    System.out.println("상품 한도 초과");
    return;
}
```

또한 `instanceof` 검사 순서도 중요했다.

```java
if (p instanceof FinancialProduct) {
    System.out.println("[공통처리] " + p.getProductName());
} else if (p instanceof SavingsAccount) {
    // 실행되지 않음
}
```

위 구조에서는 `SavingsAccount`도 `FinancialProduct`이기 때문에 첫 번째 조건에서 항상 먼저 걸린다.  
따라서 구체적인 자식 타입을 먼저 검사하거나, 공통 처리는 분리해서 작성해야 한다.

강제 타입 변환도 주의해야 한다.

```java
LoanAccount la = (LoanAccount) products[i];
```

`products[i]`가 실제로 `LoanAccount`가 아니라면 `ClassCastException`이 발생한다.  
다운캐스팅 전에는 `instanceof`로 확인해야 한다.

```java
if (products[i] instanceof LoanAccount la) {
    System.out.println(la.getLoanAmount());
}
```

정리:

- 배열에 값을 추가할 때는 배열 크기를 넘지 않도록 검사해야 한다.
- 업캐스팅된 객체를 다운캐스팅할 때는 `instanceof`를 사용하여 실제 객체 타입을 확인해야 한다.

## 17. 중첩 클래스

중첩 클래스는 클래스 안에 선언된 클래스이다.

종류는 크게 다음과 같이 나눌 수 있다.

| 종류                 | 선언 위치                           |
| -------------------- | ----------------------------------- |
| 인스턴스 멤버 클래스 | 클래스 내부, 인스턴스 멤버처럼 선언 |
| 정적 멤버 클래스     | 클래스 내부, `static`으로 선언      |
| 로컬 클래스          | 메서드 내부에 선언                  |
| 익명 객체            | 이름 없이 즉석에서 구현             |

## 17-1. 인스턴스 멤버 클래스

인스턴스 멤버 클래스는 외부 클래스의 객체를 통해 생성할 수 있다.

```java
OuterClass outer = new OuterClass();
OuterClass.InstanceInnerClass inner = outer.new InstanceInnerClass();
//또는
// OuterClass.InstanceInnerClass inner = new OuterClass().new InstanceInnerClass();
```

인스턴스 멤버 클래스에서는 외부 클래스의 인스턴스 멤버(필드, 메서드)에 접근할 수 있다.

```java
OuterClass.this.message
```

## 17-2. 정적 멤버 클래스

정적 멤버 클래스는 외부 클래스 객체 없이 생성할 수 있다.

```java
OuterClass.StaticInnerClass inner = new OuterClass.StaticInnerClass();
```

정적 멤버 클래스는 외부 클래스의 인스턴스 멤버에 바로 접근할 수 없다.

## 17-3. 로컬 클래스

로컬 클래스는 메서드 내부에 선언하는 클래스이다.

```java
public void method1() {
    class LocalClass {
        void print() {
            System.out.println("local class");
        }
    }

    LocalClass local = new LocalClass();
    local.print();
}
```

로컬 클래스가 메서드의 지역 변수를 사용하면, 해당 지역 변수는 사실상 final처럼 동작한다.

```java
public void method1() {
    int value = 10;

    class LocalClass {
        void print() {
            System.out.println(value);
        }
    }

    // value++; // 로컬 클래스에서 사용 중이면 수정 불가
}
```

정리:

- 중첩 클래스는 클래스 내부에 선언된 클래스이다.
- 인스턴스 멤버 클래스는 외부 객체를 통해 생성한다.
- 정적 멤버 클래스는 외부 객체 없이 생성할 수 있다.
- 로컬 클래스는 메서드 내부에서만 사용할 수 있다.
- 로컬 클래스가 사용하는 지역 변수는 사실상 final처럼 동작한다.
- 로컬 클래스에서 외부 객체의 멤버를 접근할 땐 `외부클래스명.this.멤버`로 접근한다.
- 로컬 클래스에서 해당 클래스의 멤버를 접근할 땐 `this.멤버` 또는 `멤버`로 접근한다.
- 로컬 클래스에서 메서드의 지역 변수를 접근할 땐 `변수명`으로 접근한다. 단, 접근하게 되면 해당 변수는 final처럼 동작하게 된다.

## 18. 익명 객체

익명 객체는 이름 없는 객체이다.  
인터페이스나 추상 클래스의 구현체가 한 번만 필요할 때 사용할 수 있다.

```java
RemoteControl remote = new RemoteControl() {
    @Override
    public void turnOn() {
        System.out.println("전원 켬");
    }

    @Override
    public void turnOff() {
        System.out.println("전원 끔");
    }
};
```

익명 객체를 사용하면 별도 구현 클래스를 만들지 않고도 바로 구현을 작성할 수 있다.

정리:

- 익명 객체는 이름이 없는 구현 객체이다.
- 인터페이스나 추상 클래스를 즉석에서 구현할 때 사용할 수 있다.
- 한 번만 사용할 구현체라면 익명 객체가 간단할 수 있다.
- 코드가 길어지면 별도 클래스로 분리하는 것이 더 좋다.

## 19. 다시 볼 부분

- 인터페이스의 필드는 기본적으로 `public static final`이다.
- 인터페이스의 추상 메서드는 기본적으로 `public abstract`이다.
- 인터페이스의 `default` 메서드는 구현 클래스에서 재정의할 수 있다.
- 인터페이스의 `static` 메서드는 인터페이스 이름으로 호출한다.
- 인터페이스는 여러 개를 동시에 구현할 수 있다.
- 인터페이스끼리는 다중 상속이 가능하다.
- 클래스는 하나만 상속할 수 있지만 인터페이스는 여러 개 구현할 수 있다.
- 인터페이스 타입 변수에는 구현 객체를 대입할 수 있다.
- 구현체 교체를 쉽게 하기 위해 구현체 클래스보다 인터페이스에 의존하는 구조가 좋다.
- 다운캐스팅 전에는 실제 객체 타입을 확인해야 한다.
- 중첩 클래스는 선언 위치에 따라 인스턴스 멤버 클래스, 정적 멤버 클래스, 로컬 클래스로 나뉜다.
- 로컬 클래스에서 사용하는 지역 변수는 사실상 final처럼 동작한다.
- 익명 객체는 한 번만 사용할 구현체를 즉석에서 만들 때 사용할 수 있다.

## 20. 수업 진행 중 생겼던 의문

### 추상 클래스와 인터페이스를 어떻게 구분해서 사용하는지

실습을 통해 기준을 나눠보았다.

`Shape`는 도형이라는 `공통 분류`와 변의 개수 같은 `상태`를 가질 수 있기 때문에 추상 클래스로 두는 것이 자연스러웠다.

```java
public abstract class Shape {
    private int numSides;

    public abstract double getArea();
    public abstract double getPerimeter();
}
```

반면 `Resizable`은 크기 변경 가능 여부라는 `기능`만 표현한다.

```java
public interface Resizable {
    void resize(double size);
}
```

그래서 모든 도형이 아니라 크기 변경이 가능한 도형만 `Resizable` 인터페이스를 분리하여 구현하도록 만들었다.

정리하면, `공통 상태`와 `기본 구조`가 필요하면 `추상 클래스`를 사용하고, 특정 `기능`을 여러 클래스에 부여하고 싶으면 `인터페이스`를 사용한다.

## 정리

- 인터페이스는 클래스가 구현해야 할 규칙을 정의하는 타입이다.
- 인터페이스의 필드는 기본적으로 `public static final` 즉, 상수이다.
- 인터페이스의 메서드는 기본적으로 `public abstract` 즉, 추상 메서드이다.
- `default` 메서드는 구현 클래스에서 그대로 사용하거나 재정의할 수 있다.
- `static` 메서드는 인터페이스 이름으로 호출한다.
- 인터페이스는 여러 개를 동시에 구현할 수 있다.
- 인터페이스끼리는 다중 상속이 가능하다.
- 인터페이스 타입을 사용하면 여러 구현체를 하나의 타입으로 처리할 수 있다.
- JDBC 구조처럼 인터페이스를 사용하면 구현체 교체가 쉬워진다.
- 인터페이스 기반 설계는 OCP 원칙과 연결된다.
- 추상 클래스는 공통 상태와 구조를 표현할 때 적합하다.
- 인터페이스는 특정 기능을 부여할 때 적합하다.
- 중첩 클래스는 클래스 내부에 선언된 클래스이다.
- 로컬 클래스가 지역 변수를 사용하면 해당 변수는 사실상 final처럼 동작한다.
- 익명 객체는 한 번만 사용할 구현체를 즉석에서 만들 때 사용할 수 있다.
