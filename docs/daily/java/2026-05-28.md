## 2. `Map.Entry`

`Entry`는 `Map` 안에서 key와 value 한 쌍을 의미한다.

```java
Map<String, Integer> map = new HashMap<>();
map.put("Java", 100);
map.put("Oracle", 90);
```

`Map`은 key와 value를 한 쌍으로 저장한다.

```java
for (Map.Entry<String, Integer> entry : map.entrySet()) {
    System.out.println(entry.getKey());
    System.out.println(entry.getValue());
}
```

정리:

- `Map`은 key와 value를 한 쌍으로 저장한다.
- `Entry`는 `Map` 안의 key-value 한 쌍을 의미한다.
- `entrySet()`을 사용하면 `Map`의 모든 key-value 쌍을 순회할 수 있다.

## 3. 정적 중첩 클래스와 Builder 패턴

Builder 패턴은 객체 생성 과정을 별도 Builder 객체로 분리하는 방식이다.

수업에서는 정적 중첩 클래스를 이용해 Builder 구조를 확인했다.

```java
class TransferRequest {
    private String fromAccount;
    private String toAccount;
    private BigDecimal amount;

    static class Builder {
        private TransferRequest req = new TransferRequest();

        Builder from(String acc) {
            req.fromAccount = acc;
            return this;
        }

        Builder to(String acc) {
            req.toAccount = acc;
            return this;
        }

        Builder amount(BigDecimal amt) {
            req.amount = amt;
            return this;
        }

        TransferRequest build() {
            return req;
        }
    }
}
```

사용할 때는 메서드 체이닝 형태로 객체에 값을 채운다.

```java
TransferRequest request = new TransferRequest.Builder()
        .from("110-1234-5678")
        .to("110-9999-0000")
        .amount(new BigDecimal("500000"))
        .build();
```

`from()`, `to()`, `amount()`가 모두 `this`를 반환하기 때문에 연속해서 호출할 수 있다.

`BigDecimal`은 `java.lang` 패키지가 아니기 때문에 import가 필요하다.

```java
import java.math.BigDecimal;
```

정리:

- Builder 패턴은 객체 생성 과정을 분리하는 방식이다.
- 정적 중첩 클래스를 이용해 Builder를 만들 수 있다.
- 각 설정 메서드가 `this`를 반환하면 메서드 체이닝이 가능하다.
- `java.lang` 패키지에 없는 클래스는 import 후 사용해야 한다.
- 생성자나 setter 호출이 많아지는 객체에서 Builder 패턴을 사용할 수 있다.

## 4. Builder 방식과 setter 방식

수업 코드에서는 Builder 방식과 setter 방식도 같이 비교했다.

Builder 방식:

```java
TransferRequest request = new TransferRequest.Builder()
        .from("110-1234-5678")
        .to("110-9999-0000")
        .amount(new BigDecimal("500000"))
        .build();
```

setter 방식:

```java
TransferRequest request2 = new TransferRequest();

request2.setFromAccount("110-9999-0000");
request2.setToAccount("110-1234-5678");
request2.setAmount(new BigDecimal("50000"));
```

setter 방식은 객체를 만든 뒤 값을 하나씩 넣는다.  
Builder 방식은 객체 생성 과정에서 필요한 값을 연속해서 설정한다.

정리:

- setter 방식은 객체 생성 후 필드 값을 순서대로 넣는다.
- Builder 방식은 생성 과정 자체를 별도 Builder가 담당한다.
- Builder 방식은 값이 많은 객체에서 읽기 쉽고, 생성 과정을 한 곳에 모으기 좋다.

## 5. 함수형 인터페이스와 람다식

람다식은 익명 구현 객체를 더 간단히 표현하는 문법이다.

인터페이스에 구현해야 할 추상 메서드가 하나만 있을 때 사용할 수 있다.

```java
interface MyInterface {
    int add(int num1, int num2);
}
```

일반 구현 클래스 방식:

```java
class MyInterfaceImpl implements MyInterface {
    @Override
    public int add(int num1, int num2) {
        return num1 + num2;
    }
}
```

익명 구현 객체 방식:

```java
MyInterface inter = new MyInterface() {
    @Override
    public int add(int num1, int num2) {
        return num1 + num2;
    }
};
```

람다식 방식:

```java
MyInterface inter = (num1, num2) -> num1 + num2;
```

정리:

- 람다식은 익명 구현 객체를 간단히 표현하는 방식이다.
- 추상 메서드가 하나인 인터페이스에서 사용할 수 있다.
- 이런 인터페이스를 함수형 인터페이스라고 한다.
- 람다식은 코드가 짧아지지만, 인터페이스의 메서드 구조를 먼저 이해해야 한다.

## 6. 버튼 클릭 리스너 실습

`Button` 클래스 안에 `ClickListener` 인터페이스를 내부 인터페이스 형태로 선언했다.

```java
public class Button {
    private ClickListener clickListener;

    public void setClickListener(ClickListener clickListener) {
        this.clickListener = clickListener;
    }

    public void buttonClick() {
        clickListener.onClick();
    }

    public static interface ClickListener {
        void onClick();
    }
}
```

사용하는 쪽에서는 클릭 시 실행할 동작을 구현해서 넘긴다.

`Button`은 어떤 버튼이 눌렸는지만 알고, 실제 눌렸을 때 무엇을 할지는 `ClickListener` 구현체가 결정한다.

구현 클래스 방식:

```java
class OkButtonImpl implements Button.ClickListener {
    @Override
    public void onClick() {
        System.out.println("Ok 버튼 클릭됨");
    }
}
```

익명 구현 객체 방식:

```java
call(new Button.ClickListener() {
    @Override
    public void onClick() {
        System.out.println("익명 구현 클래스 사용");
    }
});
```

람다식 방식:

```java
call(() -> System.out.println("람다식 사용해서 버튼 클릭"));
```

정리:

- 인터페이스를 이용하면 실행할 동작을 외부에서 전달할 수 있다.
- 구현 클래스, 익명 구현 객체, 람다식으로 같은 기능을 구현할 수 있다.
- 익명 구현 객체를 사용하면 별도 클래스를 만들지 않아도 된다.
- 추상 메서드가 하나라면 람다식으로 더 짧게 표현할 수 있다.
- 버튼 클릭처럼 특정 시점에 실행할 동작을 넘길 때 인터페이스를 활용할 수 있다.

## 7. JAR 파일

JAR는 Java Archive의 약자이다.

Java 클래스 파일과 관련 리소스를 하나의 파일로 묶을 때 사용한다.

Runnable JAR 파일은 실행 가능한 JAR 파일이다.

```powershell
# 터미널에서 jar 파일 실행하기
java -jar aa.jar
```

Eclipse에서 Runnable JAR를 만들 때는 다음 순서로 진행한다.

```text
프로젝트 우클릭
→ Export
→ Java
→ Runnable JAR file
→ Launch configuration 선택
→ Export destination 지정
```

정리:

- JAR는 Java 프로젝트를 하나로 묶은 파일이다.
- Runnable JAR는 `java -jar` 명령으로 실행할 수 있다.
- 실행 가능한 JAR에는 시작 지점이 되는 `main()`이 필요하다.
- 실행할 main이 여러 개라면 Export 단계에서 어떤 실행 구성을 사용할지 선택해야 한다.

## 8. Lombok

Lombok은 반복적으로 작성하는 코드를 어노테이션으로 줄여주는 라이브러리이다.

```java
@NoArgsConstructor
@AllArgsConstructor
@ToString
@Getter
@Setter
public class Cup {
    private String model;
    private String size;
    private int price;
}
```

각 어노테이션의 역할은 다음과 같다.

| 어노테이션            | 역할                         |
| --------------------- | ---------------------------- |
| `@NoArgsConstructor`  | 기본 생성자 생성             |
| `@AllArgsConstructor` | 모든 필드를 받는 생성자 생성 |
| `@Getter`             | getter 생성                  |
| `@Setter`             | setter 생성                  |
| `@ToString`           | `toString()` 생성            |

Eclipse에서 사용하려면 Lombok을 설치하고 프로젝트 Build Path에 JAR를 추가해야 한다.

정리:

- Lombok은 getter, setter, 생성자, `toString()` 같은 반복 코드를 줄여준다.
- IDE에 Lombok 설정이 되어 있어야 정상적으로 인식된다.

## 9. 라이브러리 방식과 모듈 방식

다른 프로젝트의 코드를 사용하는 방법에는 라이브러리 방식과 모듈 방식이 있다.

라이브러리 방식은 JAR를 Build Path에 추가해서 사용하는 방식이다.

이 경우 public 클래스는 모듈의 `exports` 설정과 관계없이 접근할 수 있다.

```java
import pack1.A;
import pack2.B;
```

즉, 모듈 시스템을 사용하지 않고 classpath에 JAR를 추가하면 public 클래스 접근 범위를 모듈로 접근할 때처럼 세밀하게 제한하기 어렵다.

반면 모듈 방식은 `module-info.java`에서 어떤 패키지를 외부로 공개할지 정한다.

```java
module my_module_a {
    exports pack1;
    // exports pack2;
}
```

`pack2`를 export하지 않으면 다른 모듈에서 직접 사용할 수 없다.

```java
// import pack2.B; // export하지 않았기 때문에 사용 불가
```

정리:

- 라이브러리 방식은 JAR 파일을 classpath에 추가해서 사용한다.
- 모듈 방식은 `module-info.java`로 의존성과 공개 범위를 명시한다.
- 모듈은 필요한 패키지만 `exports`로 공개할 수 있다.
- public 클래스라도 모듈에서 export하지 않은 패키지는 다른 모듈에서 직접 접근할 수 없다.
- 라이브러리 방식보다 모듈 방식이 공개 범위를 더 명확하게 제어할 수 있다.

## 10. `module-info.java`

```java
module my_application_2 {
    requires my_module_a;
    requires my_module_b;
    requires java.sql;
}
```

`requires`는 다른 모듈에 의존한다는 의미이다.

```java
requires my_module_a;
```

`exports`는 현재 모듈의 특정 패키지를 외부에 공개한다는 의미이다.

```java
module my_module_b {
    exports pack3;
    exports pack4;
}
```

정리:

- `module-info.java`는 모듈 설정 파일이다.
- `requires`는 필요한 모듈을 지정한다.
- `exports`는 외부에 공개할 패키지를 지정한다.
- export하지 않은 패키지는 다른 모듈에서 직접 접근할 수 없다.

## 11. `import`, `requires`

Java는 기본적으로 `java.base` 모듈을 사용한다.

`java.lang` 패키지는 자동으로 import되기 때문에 따로 import하지 않아도 사용할 수 있다.

```java
String text = "Java";
System.out.println(text);
```

정리하면, `java.base` 모듈은 기본으로 사용 가능하지만 `java.base` 안의 모든 패키지가 자동 import되는 것은 아니다.  
자동 import되는 대표 패키지는 `java.lang`이다.

예를 들어 `java.util`은 `java.base`에 속하지만 import가 필요하다.

```java
import java.util.Date;
```

반면 `java.sql.Date`처럼 `java.base`가 아닌 모듈에 있는 클래스는 모듈 설정도 필요하다.

```java
requires java.sql;
```

그리고 코드에서는 import 후 사용한다.

```java
import java.sql.Date;
```

정리:

- 기본 모듈은 `java.base`이다.
- `java.lang`은 자동 import된다.
- `java.base`에 속한 패키지라도 `java.lang`이 아니면 import가 필요하다.
- `java.base`가 아닌 모듈은 `module-info.java`에서 `requires` 해야 한다.
- 패키지 사용을 위해서는 코드에서 `import`도 필요하다.

## 12. `requires transitive`

모듈 의존 관계가 여러 단계로 이어질 때 `requires transitive`를 사용할 수 있다.

예를 들어 `my_module_a`가 `my_module_b`를 전이 의존으로 공개할 수 있다.

```java
module my_module_a {
    exports pack1;
    requires transitive my_module_b;
}
```

이 경우 `my_application_4`가 `my_module_a`만 requires해도, `my_module_b`의 공개 패키지를 함께 사용할 수 있다.

```java
module my_application_4 {
    requires my_module_a;
}
```

중간 모듈이 `requires transitive`로 의존성을 전달하면, 사용하는 쪽에서 직접 모든 모듈을 requires하지 않아도 된다.

정리:

- `requires transitive`는 의존성을 다음 모듈로 전달한다.
- A가 B를 `requires transitive`하면, A를 requires하는 모듈도 B의 공개 패키지를 사용할 수 있다.
- 모듈 간 의존 관계를 단순화할 때 사용할 수 있다.
- 무분별하게 사용하면 의존 관계가 불명확해질 수 있으므로 필요한 경우에만 사용해야 한다.

## 13. 집합 모듈

집합 모듈은 자체 패키지를 가지지 않고, 여러 모듈 의존성을 모아 제공하는 모듈이다.

```java
module my_application_5 {
    requires transitive my_module_a;
    requires transitive my_module_b;
}
```

다른 모듈은 집합 모듈 하나만 requires해서 관련 모듈을 함께 사용할 수 있다.

```java
module my_application_6 {
    requires my_application_5;
}
```

정리:

- 집합 모듈은 여러 모듈 의존성을 묶는 역할을 한다.
- 자체 패키지 없이 의존성 설정만 담당할 수 있다.
- 사용하는 모듈은 집합 모듈 하나만 requires해서 여러 모듈을 간접적으로 사용할 수 있다.

## 15. 예외와 에러

예외는 프로그램 실행 중 발생할 수 있는 문제 상황이다.

```text
Exception:
  프로그래머의 노력으로 복구가 가능한 오류
  오류가 발생해도 계속 진행 가능

Error:
  프로그램이 종료될 수 있는 심각한 오류
  코드상에서 복구하기 어려운 심각한 오류
```

예외는 개발자가 처리해서 프로그램 흐름을 이어갈 수 있다.

```java
try {
    System.out.println(10 / 0);
} catch (ArithmeticException e) {
    System.err.println(e.getMessage());
}
```

예외 처리 방식을 두 가지로 나눌 수 있다.

```text
1. try-catch-finally로 직접 처리
2. throws로 호출한 쪽에 떠넘기기
```

정리:

- 예외는 처리 가능한 오류 상황이다.
- 에러는 일반적으로 프로그램이 직접 복구하기 어려운 심각한 문제이다.
- `try`에는 예외가 발생할 수 있는 코드를 작성한다.
- `catch`에는 예외가 발생했을 때 처리할 코드를 작성한다.
- `finally`는 예외 발생 여부와 관계없이 실행된다.
- `throws`는 예외 처리를 호출한 쪽으로 넘길 때 사용한다.

## 16. 다중 catch와 예외 처리 순서

여러 예외를 각각 다르게 처리할 수 있다.

```java
try {
    System.out.println(num1 / num2);
    System.out.println(Integer.parseInt(num3));
    System.out.println(arr[5]);
} catch (ArithmeticException | NumberFormatException e) {
    System.err.println(e.getMessage());
} catch (ArrayIndexOutOfBoundsException e) {
    System.err.println(e.getMessage());
} catch (RuntimeException e) {
    System.err.println(e.getMessage());
} catch (Exception e) {
    System.err.println(e.getMessage());
}
```

예외 처리는 구체적인 예외를 먼저 작성하고, 더 넓은 예외 타입을 뒤에 작성해야 한다.

```java
catch (RuntimeException e) {
}
catch (Exception e) {
}
```

정리:

- 여러 예외를 하나의 `catch`에서 함께 처리할 땐 `|`를 사용하여 함께 처리한다.
- 상속 관계가 있는 예외는 구체적인 타입을 먼저 처리해야 한다.
- `Exception`처럼 넓은 타입을 먼저 쓰면 뒤의 구체적인 예외 처리가 불가능해진다.

---

## 17. 예외 떠넘기기 `throws`

메서드 내부에서 직접 예외를 처리하지 않고 호출한 쪽으로 넘길 수 있다.

```java
private static void f2() throws ClassNotFoundException {
    Class.forName("com.shinhan.day10.Cup");
}
```

호출한 쪽에서는 `try-catch`로 처리한다.

```java
try {
    f2();
} catch (ClassNotFoundException e) {
    e.printStackTrace();
}
```

정리:

- `throws`는 예외 처리를 호출한 쪽으로 넘긴다.
- 예외를 어디에서 처리할지에 따라 코드 구조가 달라진다.
- checked exception은 직접 처리하거나 `throws`로 넘겨야 한다.
  - checked exception : 컴파일러가 예외 처리 여부를 강제하는 예외, 예외처리를 꼭 해줘야 한다.

---

## 18. try-with-resources

try-with-resources는 사용한 자원을 자동으로 닫아주는 문법이다.

```java
try (FileReader fr = new FileReader("src/com/shinhan/day10/ButtonExample.java")) {
    int data;

    while ((data = fr.read()) != -1) {
        System.out.print((char) data);
    }
} catch (IOException e) {
    System.err.println(e.getMessage());
}
```

기존 방식에서는 `finally`에서 직접 `close()`를 호출해야 했다.

```java
FileReader fr = null;

try {
    fr = new FileReader("src/com/shinhan/day10/ButtonExample.java");
} finally {
    if (fr != null) {
        fr.close();
    }
}
```

try-with-resources를 사용하려면 자원이 `AutoCloseable`을 구현하고 있어야 한다.

```java
public class CustomFileWriter  implements AutoCloseable {
    @Override
    public void close() throws IOException {
        System.out.println("파일 닫습니다.");
    }
}
```

정리:

- try-with-resources는 자원을 자동으로 닫아준다.
- `finally`에서 직접 `close()`를 호출하는 코드를 줄일 수 있다.
- try-with-resources에 들어가는 객체는 `AutoCloseable`을 구현해야 한다.

## 19. 사용자 정의 예외

직접 예외 클래스를 만들 수 있다.

```java
class ScoreException extends RuntimeException {
    ScoreException(String message) {
        super(message);
    }
}
```

필요한 조건이 맞지 않을 때 `throw`로 예외를 발생시킬 수 있다.

```java
if (score <= 90) {
    throw new ScoreException("90보다 크게하기");
}
```

발생한 예외는 `catch`에서 처리한다.

```java
try {
    if (score <= 90) {
        throw new ScoreException("90보다 크게하기");
    }
} catch (ScoreException e) {
    System.err.println(e.getMessage());
}
```

정리:

- 사용자 정의 예외는 직접 만든 예외 클래스이다.
- `throw`는 예외 객체를 직접 발생시킬 때 사용한다.
- `throws`는 예외 처리를 호출한 쪽으로 넘길 때 사용한다.
- `throw`와 `throws`는 역할을 확실히 구분지어 생각할 수 있어야한다.

## 20. DiceGame 예외 처리 실습

DiceGame 실습에서는 잘못된 매개변수가 들어왔을 때 예외를 발생시키는 구조를 확인했다.

```java
int countSameEye(int n) {
    if (n <= 0) {
        throw new IllegalArgumentException("매개변수 값이 잘못됐습니다.");
    }

    int result = 0;
    Dice dice = new Dice(8);

    for (int i = 0; i < n; i++) {
        int num1 = dice.play();
        int num2 = dice.play();

        if (num1 == num2) {
            result++;
        }
    }

    return result;
}
```

`n`이 0 이하이면 정상적인 반복 횟수가 아니므로 예외를 발생시킨다.

```java
int result = game.countSameEye(-10);
```

정리:

- 메서드 매개변수는 필요한 조건을 먼저 확인하는 것이 좋다.
- 잘못된 값이 들어왔을 때는 예외로 처리할 수 있다.
- `IllegalArgumentException`은 잘못된 인자가 전달되었을 때 사용할 수 있다.

## 21. 각 파트별 키워드

### 인터페이스

인터페이스에는 다음 요소들이 들어갈 수 있다.

```text
상수
추상 메서드
default method
static method
private method
private static method
```

### 람다식

같은 기능을 세 가지 방식으로 구현할 수 있다.

```text
1. 구현 클래스를 만들어 사용하는 방법
2. 익명 클래스를 사용하는 방법
3. 람다식을 사용하는 방법
```

람다식은 인터페이스에 추상 메서드가 하나만 있을 때 사용할 수 있다.
인터페이스에 `default`, `static`, `private` 메서드가 있더라도 추상 메서드가 하나라면 람다식 사용이 가능하다.

### Builder 패턴

Builder 패턴은 정적 중첩 클래스의 대표적인 사용 예시로 정리했다.

```text
정적 내부 클래스로 Builder
메서드 체이닝
```

### 모듈을 사용한 외부 프로젝트 접근 방법 사용시 주의 사항

```text
java.base는 기본 모듈
java.lang은 자동 import
java.base가 아닌 모듈은 module-info.java에 requires 필요
java.lang이 아닌 패키지는 import 필요
```

모듈 방식에서는 `exports` 여부가 정보 은닉과 연결된다.

```java
exports pack1;
// exports pack2;
```

### 예외

예외와 오류의 차이점

```text
Exception: 복구 가능한 오류
Error: 프로그램이 종료될 수 있는 심각한 오류
```

예외 처리 방식은 두 가지로 나눌 수 있다.

```text
try-catch-finally
throws
```

자원을 사용하는 경우에는 자원 반납을 고려해야 하며, try-with-resources를 사용하면 자동으로 닫을 수 있다.

## 22. 다시 볼 부분

- Builder 패턴은 객체 생성 과정을 별도 객체로 분리한다.
- 정적 중첩 클래스는 Builder 구현에 자주 사용된다.
- `java.lang` 패키지에 없는 클래스는 import가 필요하다.
- 구현 클래스, 익명 클래스, 람다식은 같은 인터페이스 구현을 다른 방식으로 표현한 것이다.
- 람다식은 추상 메서드가 하나인 인터페이스에서 사용할 수 있다.
- Runnable JAR는 터미널에서 `java -jar`로 실행할 수 있다.
- Lombok을 사용하려면 IDE와 Build Path 설정이 필요하다.
- 라이브러리 방식은 JAR를 classpath에 올려서 사용한다.
- 모듈 방식은 `module-info.java`로 의존성과 공개 범위를 관리한다.
- `requires`는 모듈 의존성을 지정한다.
- `exports`는 외부에 공개할 패키지를 지정한다.
- `requires transitive`는 의존성을 다음 모듈로 전달한다.
- 집합 모듈은 여러 모듈 의존성을 묶는 역할을 한다.
- `java.base`는 기본 모듈이고, `java.lang`은 자동 import된다.
- `java.base`가 아닌 모듈은 `requires`가 필요하다.
- 예외 처리는 `try-catch-finally` 또는 `throws`로 처리할 수 있다.
- try-with-resources는 `AutoCloseable` 자원을 자동으로 닫는다. ex) `Scanner`, `FileWriter`
- `throw`와 `throws`의 역할을 명확하게 구분지을 수 있어야 한다.

## 정리

- `Entry`는 key-value 한 쌍을 의미한다.
- Builder 패턴은 객체 생성 과정을 분리하고, 메서드 체이닝으로 값을 설정할 수 있다.
- 람다식은 추상 메서드가 하나인 인터페이스에서 사용할 수 있다.
- JAR는 Java 프로젝트를 하나로 묶은 파일이다.
- Lombok은 생성자, getter, setter, `toString()` 코드를 어노테이션을 사용하여 직접 작성할 내용을 줄여준다.
- 라이브러리 방식은 JAR를 Build Path에 추가해서 사용한다.
- 모듈 방식은 `module-info.java`를 통해 의존성과 공개 범위를 관리한다.
- `requires`는 필요한 모듈을 지정한다.
- `exports`는 외부에 공개할 패키지를 지정한다.
- `requires transitive`는 모듈 의존성을 다음 모듈로 전달한다.
- 집합 모듈은 여러 모듈 의존성을 묶는 역할을 한다.
- `java.base`는 기본 모듈이고, `java.lang`은 자동 import된다.
- 예외는 `try-catch-finally`로 직접 처리하거나 `throws`로 떠넘길 수 있다.
- try-with-resources는 자원을 자동으로 닫아준다.
- 직접 예외 클래스를 만들어 사용할 수 있다.
- `throw`는 예외를 직접 발생시키고, `throws`는 예외 처리를 호출한 쪽으로 넘긴다.
