## 2. 멀티스레드

멀티스레드는 하나의 프로그램 안에서 여러 실행 흐름이 동시에 동작하는 구조이다.

Java 프로그램은 기본적으로 `main()` 메서드를 실행하는 메인 스레드에서 시작한다.
여기에 작업 스레드를 추가로 만들면 여러 작업을 나누어 실행할 수 있다.

스레드를 만드는 방법은 크게 두 가지로 정리할 수 있다.

```text
1. Thread 클래스를 상속하고 run() 재정의
2. Runnable 인터페이스를 구현하고 Thread 객체에 전달
```

---

## 3. `Thread` 상속 방식

`Thread` 클래스를 상속받으면 직접 스레드 클래스를 만들 수 있다.

```java
class MyThread extends Thread {
    @Override
    public void run() {
        for (int i = 1; i <= 10; i++) {
            System.out.println(i);
        }
    }
}
```

실행할 때는 `run()`을 직접 호출하는 것이 아니라 `start()`를 호출해야 한다.

```java
MyThread t1 = new MyThread();
t1.start();
```

`start()`를 호출하면 새로운 실행 흐름이 만들어지고, 그 안에서 `run()`이 실행된다.

---

## 4. `Runnable` 구현 방식

이미 다른 클래스를 상속받고 있다면 `Thread`를 상속할 수 없다.
이 경우 `Runnable` 인터페이스를 구현해서 스레드 작업을 정의할 수 있다.

```java
class MyRunnableImpl implements Runnable {
    @Override
    public void run() {
        System.out.println("Runnable 실행");
    }
}
```

사용할 때는 `Thread` 객체에 `Runnable` 구현 객체를 전달한다.

```java
Runnable task = new MyRunnableImpl();
Thread t1 = new Thread(task);

t1.start();
```

정리하면, `Runnable`은 실행할 작업이고 `Thread`는 그 작업을 실제 스레드로 실행하는 객체라고 볼 수 있다.

---

## 5. 공유 객체와 동기화

여러 스레드가 같은 객체를 동시에 사용하면 실행 순서에 따라 결과가 달라질 수 있다.

예를 들어 여러 스레드가 같은 계좌 객체를 사용하면서 출금과 입금을 동시에 수행하면 잔액 계산이 꼬일 수 있다.

이런 공유 자원 문제를 막기 위해 `synchronized`를 사용할 수 있다.

```java
public synchronized void transfer() {
    int amount = lee.withdraw(100);
    sung.deposit(amount);
}
```

`synchronized`가 붙은 메서드는 한 스레드가 실행 중일 때 다른 스레드가 동시에 들어오지 못한다.

`synchronized`는 메서드 전체에 걸 수도 있고, 특정 블록에만 걸 수도 있다.

```java
synchronized (shareArea) {
    int total = shareArea.getTotalBalance();
    System.out.println(total);
}
```

정리:

- 여러 스레드가 같은 객체를 공유하면 데이터 불일치가 발생할 수 있다.
- `synchronized`는 공유 자원에 대한 동시 접근을 제한한다.
- 메서드 선언부 또는 블록에 사용할 수 있다.

---

## 6. `join()`

`join()`은 특정 스레드가 끝날 때까지 현재 스레드를 기다리게 한다.

예를 들어 합계를 계산하는 스레드가 끝나기 전에 결과를 출력하면 아직 계산이 끝나지 않은 값을 볼 수 있다.

```java
SumThread sumThread = new SumThread();
sumThread.start();

sumThread.join();

System.out.println(sumThread.getSum());
```

`join()`을 사용하면 `sumThread`가 끝난 뒤 결과를 출력할 수 있다.

정리:

- `join()`은 다른 스레드가 종료될 때까지 기다린다.
- 작업 스레드의 결과가 필요할 때 사용할 수 있다.

---

## 7. `yield()`

`yield()`는 현재 실행 중인 스레드가 실행 기회를 양보하고 실행 대기 상태로 돌아가게 한다.

```java
while (true) {
    if (work) {
        System.out.println(getName() + " 진행 중");
    } else {
        Thread.yield();
    }
}
```

`yield()`는 스레드를 종료하는 것이 아니라, 같은 우선순위의 다른 스레드에게 실행 기회를 넘기는 방식으로 이해하면 된다.

정리:

- `yield()`는 현재 스레드가 실행 기회를 양보한다.
- 스레드는 종료되지 않고 실행 대기 상태로 이동한다.

---

## 8. `wait()`와 `notify()`

`wait()`는 현재 스레드를 일시 정지 상태로 만든다.
`notify()`는 대기 중인 스레드 중 하나를 깨운다.

```java
public synchronized void use(String name) {
    try {
        wait();
    } catch (InterruptedException e) {
        e.printStackTrace();
    }

    notify();
}
```

`wait()`와 `notify()`는 동기화된 영역 안에서 사용해야 한다.

정리:

- `wait()`는 현재 스레드를 대기 상태로 만든다.
- `notify()`는 대기 중인 스레드 하나를 깨운다.
- 둘 다 `synchronized` 영역 안에서 사용해야 한다.
- 공유 자원의 사용 순서를 제어할 때 사용할 수 있다.

---

## 9. `interrupt()`를 이용한 안전 종료

스레드를 강제로 종료하는 방식은 권장되지 않는다.
대신 종료 플래그나 `interrupt()`를 이용해서 안전하게 종료 흐름을 만들 수 있다.

```java
Thread thread = new PrintThread();
thread.start();

Thread.sleep(1000);
thread.interrupt();
```

작업 스레드에서는 인터럽트 상태를 확인해서 반복을 종료할 수 있다.

```java
while (true) {
    if (Thread.interrupted()) {
        break;
    }
}
```

정리:

- 스레드는 강제로 끊기보다 종료 조건을 통해 안전하게 끝내는 것이 좋다.
- `interrupt()`는 스레드에 중단 요청을 보내는 방식이다.
- 작업 스레드는 인터럽트 여부를 확인하고 정리 작업 후 종료할 수 있다.

## 10. 데몬 스레드

데몬 스레드는 일반 스레드를 보조하는 스레드이다.

```java
AutoSaveThread thread = new AutoSaveThread();
thread.setDaemon(true);
thread.start();
```

데몬 스레드는 일반 스레드가 모두 종료되면 함께 종료된다.

자동 저장, 로그 처리처럼 메인 작업을 보조하는 기능에 사용할 수 있다.

정리:

- 데몬 스레드는 보조 작업을 수행한다.
- 일반 스레드가 모두 종료되면 데몬 스레드도 함께 종료된다.
- `setDaemon(true)`는 `start()` 전에 호출해야 한다.

---

## 11. 스레드 풀과 `ExecutorService`

스레드를 작업마다 계속 새로 만들면 비용이 커질 수 있다.
스레드 풀은 미리 정해진 개수의 스레드를 만들어두고 작업을 나누어 실행하는 방식이다.

```java
ExecutorService executorService = Executors.newFixedThreadPool(5);
```

작업은 `execute()`로 전달할 수 있다.

```java
executorService.execute(new Runnable() {
    @Override
    public void run() {
        System.out.println("작업 실행");
    }
});
```

작업 제출이 끝나면 `shutdown()`으로 스레드 풀을 종료한다.

```java
executorService.shutdown();
```

정리:

- 스레드 풀은 여러 작업을 제한된 수의 스레드로 처리한다.
- `Executors.newFixedThreadPool()`로 고정 크기 스레드 풀을 만들 수 있다.
- `execute()`는 반환값이 없는 작업을 실행할 때 사용한다.
- 사용 후에는 `shutdown()`을 호출한다.

## 12. `Callable`과 `Future`

`Runnable`은 반환값이 없다.
반환값이 필요한 작업은 `Callable`을 사용할 수 있다.

```java
Callable<Integer> task = new Callable<>() {
    @Override
    public Integer call() {
        return 100;
    }
};
```

`submit()`으로 작업을 제출하면 `Future`를 반환받는다.

```java
Future<Integer> result = executorService.submit(task);
Integer value = result.get();
```

`get()`은 작업이 끝날 때까지 기다린 뒤 결과를 가져온다.

정리:

- `Runnable`은 반환값이 없다.
- `Callable`은 작업 결과를 반환할 수 있다.
- `submit()`은 `Future`를 반환한다.
- `Future.get()`은 작업 결과를 받을 때 사용한다.

## 13. 컬렉션 프레임워크

컬렉션은 여러 데이터를 저장하고 처리하기 위한 자료구조이다.

대표 인터페이스는 `List`, `Set`, `Map`이다.

| 구분   | 특징                                 |
| ------ | ------------------------------------ |
| `List` | 순서 있음, 중복 가능                 |
| `Set`  | 순서 없음, 중복 불가                 |
| `Map`  | key-value 쌍으로 저장, key 중복 불가 |

---

## 14. `ArrayList`, `Vector`, `LinkedList`

`List` 계열은 순서가 있고 중복을 허용한다.

### `ArrayList`

`ArrayList`는 배열 기반 구조이다.

- 끝에 데이터를 추가하거나 인덱스로 조회할 때 유리하다.
- 중간 삽입과 삭제는 뒤의 요소를 이동해야 하므로 상대적으로 불리하다.
- 단일 스레드 환경에서 자주 사용한다.

### `Vector`

`Vector`는 `ArrayList`와 비슷하지만 주요 메서드에 동기화가 적용되어 있다.

- 멀티스레드 환경에서 상대적으로 안전하다.
- 동기화 비용 때문에 단일 스레드에서는 `ArrayList`보다 불리할 수 있다.

### `LinkedList`

`LinkedList`는 노드가 서로 연결된 구조이다.

- 중간 삽입과 삭제에 유리할 수 있다.
- 인덱스 기반 조회는 앞에서부터 탐색해야 하므로 불리하다.

정리:

| 구현체       | 특징                 |
| ------------ | -------------------- |
| `ArrayList`  | 끝 추가, 조회에 유리 |
| `Vector`     | 동기화 지원          |
| `LinkedList` | 삽입, 삭제에 유리    |

---

## 15. `HashSet`

`Set`은 중복을 허용하지 않는 자료구조이다.

```java
Set<String> set = new HashSet<>();

set.add("A");
set.add("A");
set.add("B");
```

위 코드에서 `"A"`를 두 번 넣어도 한 번만 저장된다.

직접 만든 객체의 중복 판단은 `equals()`와 `hashCode()` 기준으로 동작한다.

Lombok의 `@EqualsAndHashCode`를 사용하면 필드 값을 기준으로 두 객체가 같은지 판단하도록 만들 수 있다.

정리:

- `Set`은 중복을 허용하지 않는다.
- `HashSet`은 저장 순서를 보장하지 않는다.
- 객체 중복 판단에는 `equals()`와 `hashCode()`가 사용된다.

## 16. `Iterator`

컬렉션을 순회할 때 향상된 for문을 사용할 수도 있고, `Iterator`를 사용할 수도 있다.

```java
Iterator<Board> it = data.iterator();

while (it.hasNext()) {
    Board board = it.next();
    System.out.println(board);
}
```

`Iterator`는 컬렉션 내부 요소를 하나씩 꺼내는 반복자이다.

정리:

- `hasNext()`는 다음 요소가 있는지 확인한다.
- `next()`는 다음 요소를 꺼낸다.
- 컬렉션의 구현체와 관계없이 순회 방식을 통일할 수 있다.

---

## 17. `Map`, `HashMap`, `Hashtable`

`Map`은 key-value 쌍으로 데이터를 저장한다.

```java
Map<String, Integer> map = new HashMap<>();

map.put("홍길동", 100);
map.put("홍길동", 90);
```

같은 key를 다시 넣으면 기존 값이 새 값으로 덮어써진다.

`Map`을 순회하는 방법은 크게 두 가지이다.

```java
Set<String> keys = map.keySet();

for (String key : keys) {
    System.out.println(key);
}
```

또는 `entrySet()`을 사용할 수 있다.

```java
Set<Map.Entry<String, Integer>> entries = map.entrySet();

for (Map.Entry<String, Integer> entry : entries) {
    System.out.println(entry.getKey());
    System.out.println(entry.getValue());
}
```

`Hashtable`은 동기화가 적용된 오래된 Map 구현체이다.
멀티스레드 환경에서 동기화 특성이 있지만, 새 코드에서는 상황에 따라 `ConcurrentHashMap`도 고려할 수 있다.

정리:

- `Map`은 key-value 쌍으로 저장한다.
- key는 중복될 수 없다.
- 같은 key로 값을 넣으면 기존 값이 덮어써진다.
- `keySet()` 또는 `entrySet()`으로 순회할 수 있다.

## 18. `Properties`

`Properties`는 key와 value가 문자열로 구성된 설정 정보 저장용 컬렉션이다.

```java
Properties properties = new Properties();

InputStream is = CollectionExample.class.getResourceAsStream("oracle.properties");
properties.load(is);
```

파일에서 읽은 값은 `getProperty()`로 가져올 수 있다.

```java
String uid = properties.getProperty("userid");
String url = properties.getProperty("url");
```

정리:

- `Properties`는 문자열 기반 key-value 설정 정보를 다룬다.
- `.properties` 파일을 읽어 설정값을 가져올 수 있다.
- `load()`로 파일을 읽고, `getProperty()`로 값을 꺼낸다.

## 21. 수업 중 헷갈렸던 부분

### 21-1. `synchronized`를 어디에 걸어야 하는지

처음에는 공유 객체를 사용하는 모든 곳에 `synchronized`를 붙여야 하는지 헷갈렸다.

정리해보면 여러 스레드가 동시에 접근하면 안 되는 공유 자원 사용 구간에 동기화를 적용해야 한다.

메서드 전체가 공유 자원 처리라면 메서드에 붙일 수 있고, 일부 코드만 보호하면 된다면 `synchronized` 블록을 사용할 수 있다.

### 21-2. `wait()`와 `sleep()` 차이

둘 다 스레드를 멈추는 것처럼 보이지만 목적이 다르다.

`sleep()`은 지정한 시간 동안 현재 스레드를 멈춘다.  
`wait()`는 동기화된 공유 객체에서 다른 스레드의 `notify()`를 기다린다.

즉, `sleep()`은 시간 기준 대기이고 `wait()`는 다른 스레드의 알림을 기다리는 구조이다.

### 21-3. `Runnable`과 `Callable` 차이

`Runnable`은 반환값이 없고, `Callable`은 반환값이 있다.  
그래서 작업 결과가 필요하면 `Callable`과 `Future`를 사용한다.

### 21-4. `ArrayList`와 `LinkedList` 선택 기준

단순히 `LinkedList`가 삽입과 삭제에 무조건 좋다고 이해하면 안 된다.

앞이나 중간에 삽입하는 경우에는 `LinkedList`가 유리할 수 있지만, 인덱스 기반 조회나 끝 추가가 많으면 `ArrayList`가 더 적합할 수 있다.

## 22. 정리

13일차에는 멀티스레드와 컬렉션을 배웠다.

스레드에서는 여러 실행 흐름이 공유 객체를 사용할 때 생기는 문제를 확인했고, 이를 제어하기 위해 `synchronized`, `wait()`, `notify()`, `join()`, `yield()`, `interrupt()` 같은 메서드를 사용했다.

특히 공유 계좌 예제와 화장실 예제를 통해 동기화가 필요한 상황을 볼 수 있었다.

컬렉션에서는 `List`, `Set`, `Map`의 차이를 정리했다.
`ArrayList`, `Vector`, `LinkedList`는 모두 `List` 구현체이지만 내부 구조와 사용 상황이 다르다.

`HashSet`은 중복을 허용하지 않고, 직접 만든 객체를 중복 판단하려면 `equals()`와 `hashCode()`를 기준으로 판단한다.

`Map`은 key-value 형태로 데이터를 저장하며, key가 중복되면 기존 값이 덮어써진다.
