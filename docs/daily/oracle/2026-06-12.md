## 2. PL/SQL

PL/SQL은 Oracle에서 사용하는 절차형 SQL 언어이다.

SQL은 기본적으로 한 번에 하나의 명령을 실행하는 구조이다.
반면 PL/SQL은 SQL에 변수, 조건문, 반복문, 예외 처리를 추가해서 여러 로직을 하나의 블록으로 묶을 수 있다.

가장 기본적인 PL/SQL 블록은 다음과 같다.

```sql
BEGIN
    DBMS_OUTPUT.PUT_LINE('Hello, PL/SQL!');
END;
/
```

정리:

- PL/SQL은 Procedural Language/SQL의 약자이다.
- SQL에 절차형 프로그래밍 요소를 추가한 구조이다.
- 변수, 조건문, 반복문, 예외 처리를 사용할 수 있다.
- 저장 프로시저, 함수, 패키지, 트리거를 작성할 때 사용한다.
- SQL Developer에서 출력 결과를 보려면 `SET SERVEROUTPUT ON`이 필요하다.

## 3. PL/SQL 블록 구조

PL/SQL 블록은 크게 선언부, 실행부, 예외 처리부로 나눌 수 있다.

```sql
DECLARE
    -- 변수, 상수, 커서 선언
BEGIN
    -- 실행할 SQL과 PL/SQL 로직
EXCEPTION
    -- 예외 처리
END;
/
```

각 영역의 의미는 다음과 같다.

| 영역        | 필수 여부 | 역할                  |
| ----------- | --------: | --------------------- |
| `DECLARE`   |      선택 | 변수, 상수, 커서 선언 |
| `BEGIN`     |      필수 | 실행할 로직 작성      |
| `EXCEPTION` |      선택 | 예외 처리             |
| `END`       |      필수 | 블록 종료             |

정리:

- `BEGIN ~ END`는 필수이다.
- `DECLARE`는 선언할 변수가 있을 때 사용한다.
- `EXCEPTION`은 오류 처리 로직이 필요할 때 사용한다.
- `/`는 SQL Developer에서 PL/SQL 블록을 실행할 때 사용한다.

## 4. 변수와 상수

PL/SQL에서는 변수를 선언해서 값을 저장할 수 있다.

```sql
DECLARE
    v_emp_id NUMBER := 100;
    v_name VARCHAR2(100);
    v_salary employees.salary%TYPE;
    c_bonus_rate CONSTANT NUMBER := 0.1;
BEGIN
    DBMS_OUTPUT.PUT_LINE(v_emp_id);
END;
/
```

정리:

- 변수는 `변수명 타입` 형태로 선언한다.
- `:=`로 초기값을 지정할 수 있다.
- `CONSTANT`를 붙이면 상수가 된다.
- 상수는 선언 후 값을 변경할 수 없다.
- 변수명은 보통 `v_`, 상수명은 `c_` 접두어를 붙이면 구분하기 쉽다.

## 5. `%TYPE`

`%TYPE`은 테이블 컬럼의 타입을 그대로 참조할 때 사용한다.

```sql
DECLARE
    v_salary employees.salary%TYPE;
BEGIN
    SELECT salary
    INTO v_salary
    FROM employees
    WHERE employee_id = 100;

    DBMS_OUTPUT.PUT_LINE(v_salary);
END;
/
```

정리:

- `%TYPE`은 특정 컬럼의 데이터 타입을 그대로 가져온다.
- 컬럼 타입을 직접 하드코딩하지 않아도 된다.
- 테이블 컬럼 타입이 변경되면 PL/SQL 변수 타입도 자동으로 맞춰진다.
- 유지보수 측면에서 유리하다.

## 6. `SELECT INTO`

PL/SQL에서는 조회 결과를 변수에 저장할 때 `SELECT INTO`를 사용한다.

```sql
DECLARE
    v_name employees.first_name%TYPE;
    v_salary employees.salary%TYPE;
BEGIN
    SELECT first_name, salary
    INTO v_name, v_salary
    FROM employees
    WHERE employee_id = 100;

    DBMS_OUTPUT.PUT_LINE(v_name || ': ' || v_salary);
END;
/
```

정리:

- `SELECT INTO`는 조회 결과를 PL/SQL 변수에 저장한다.
- `SELECT` 컬럼 개수와 `INTO` 변수 개수가 맞아야 한다.
- 결과가 정확히 1행이어야 한다.
- 결과가 0행이면 `NO_DATA_FOUND` 예외가 발생한다.
- 결과가 2행 이상이면 `TOO_MANY_ROWS` 예외가 발생한다.
- 여러 행을 처리하려면 커서를 사용해야 한다.

## 7. `IF`, `ELSIF`, `ELSE`

조건에 따라 다른 로직을 실행할 때 `IF`문을 사용한다.

```sql
DECLARE
    v_salary employees.salary%TYPE;
    v_grade VARCHAR2(10);
BEGIN
    SELECT salary
    INTO v_salary
    FROM employees
    WHERE employee_id = 103;

    IF v_salary >= 15000 THEN
        v_grade := 'S등급';
    ELSIF v_salary >= 10000 THEN
        v_grade := 'A등급';
    ELSIF v_salary >= 5000 THEN
        v_grade := 'B등급';
    ELSE
        v_grade := 'C등급';
    END IF;

    DBMS_OUTPUT.PUT_LINE('급여: ' || v_salary || ' / 등급: ' || v_grade);
END;
/
```

정리:

- `IF`는 조건 분기이다.
- 여러 조건은 `ELSIF`로 이어서 작성한다.
- 마지막 기본 처리는 `ELSE`에 작성한다.
- PL/SQL에서는 `ELSIF`로 쓴다.
- 조건문은 `END IF;`로 닫는다.

## 8. `CASE`

`CASE`도 조건에 따라 값을 분기할 때 사용한다.

```sql
DECLARE
    v_dept_id NUMBER := 90;
    v_dept_name VARCHAR2(30);
BEGIN
    CASE v_dept_id
        WHEN 10 THEN v_dept_name := '총무';
        WHEN 60 THEN v_dept_name := 'IT';
        WHEN 80 THEN v_dept_name := '영업';
        WHEN 90 THEN v_dept_name := '경영진';
        ELSE v_dept_name := '기타';
    END CASE;

    DBMS_OUTPUT.PUT_LINE('부서: ' || v_dept_name);
END;
/
```

정리:

- `CASE`는 값에 따라 분기할 때 사용할 수 있다.
- 단순 값 비교에는 `CASE 변수 WHEN 값 THEN ...` 형태가 보기 좋다.
- 범위 조건처럼 복잡한 조건은 `IF`나 searched CASE를 쓰는 편이 자연스럽다.
- `CASE`문은 `END CASE;`로 닫는다.

## 9. 반복문

PL/SQL에는 여러 반복문이 있다.

기본 `LOOP`:

```sql
DECLARE
    v_cnt NUMBER := 1;
BEGIN
    LOOP
        DBMS_OUTPUT.PUT_LINE('반복: ' || v_cnt);
        v_cnt := v_cnt + 1;
        EXIT WHEN v_cnt > 5;
    END LOOP;
END;
/
```

`FOR LOOP`:

```sql
BEGIN
    FOR i IN 1..5 LOOP
        DBMS_OUTPUT.PUT_LINE(i || '번째 실행');
    END LOOP;
END;
/
```

`WHILE LOOP`:

```sql
DECLARE
    v_sum NUMBER := 0;
    v_i NUMBER := 1;
BEGIN
    WHILE v_i <= 100 LOOP
        v_sum := v_sum + v_i;
        v_i := v_i + 1;
    END LOOP;

    DBMS_OUTPUT.PUT_LINE('1~100 합계: ' || v_sum);
END;
/
```

정리:

- `LOOP`는 조건 없이 반복하고, `EXIT WHEN`으로 빠져나온다.
- `FOR LOOP`는 정해진 범위를 반복할 때 사용한다.
- `FOR i IN REVERSE 1..5 LOOP`처럼 역순 반복도 가능하다.
- `WHILE LOOP`는 조건이 참인 동안 반복한다.
- 단순 횟수 반복은 `FOR LOOP`가 가장 간단하다.

## 10. `%ROWTYPE`

`%ROWTYPE`은 테이블의 한 행 전체 구조를 변수로 받을 때 사용한다.

```sql
DECLARE
    v_emp employees%ROWTYPE;
BEGIN
    SELECT *
    INTO v_emp
    FROM employees
    WHERE employee_id = 101;

    DBMS_OUTPUT.PUT_LINE('이름: ' || v_emp.first_name || ' ' || v_emp.last_name);
    DBMS_OUTPUT.PUT_LINE('직무: ' || v_emp.job_id);
    DBMS_OUTPUT.PUT_LINE('급여: ' || v_emp.salary);
END;
/
```

정리:

- `%ROWTYPE`은 테이블의 전체 행 구조를 참조한다.
- 컬럼이 많을 때 각각 변수를 선언하지 않아도 된다.
- `v_emp.first_name`처럼 `변수명.컬럼명` 형태로 접근한다.
- `SELECT * INTO`와 함께 사용할 수 있다.
- 테이블 구조가 바뀌면 행 타입도 같이 반영된다.

## 11. 사용자 정의 `RECORD`

필요한 필드만 묶은 사용자 정의 레코드 타입도 만들 수 있다.

```sql
DECLARE
    TYPE t_emp_info IS RECORD (
        emp_id NUMBER,
        fullname VARCHAR2(100),
        dept VARCHAR2(30),
        salary NUMBER
    );

    v_info t_emp_info;
BEGIN
    SELECT e.employee_id,
           e.first_name || ' ' || e.last_name,
           d.department_name,
           e.salary
    INTO v_info
    FROM employees e
    JOIN departments d ON e.department_id = d.department_id
    WHERE e.employee_id = 100;

    DBMS_OUTPUT.PUT_LINE(
        v_info.emp_id || ' | ' ||
        v_info.fullname || ' | ' ||
        v_info.dept || ' | ' ||
        v_info.salary
    );
END;
/
```

정리:

- `RECORD`는 여러 필드를 하나로 묶은 타입이다.
- Java의 DTO와 비슷하게 볼 수 있다.
- `%ROWTYPE`이 테이블 전체 구조라면, 사용자 정의 `RECORD`는 필요한 필드만 직접 정의한다.
- 조인 결과처럼 여러 테이블의 컬럼을 묶어 담을 때 사용할 수 있다.

## 12. 컬렉션

PL/SQL 컬렉션은 여러 값을 담는 배열 또는 목록 구조이다.

수업에서는 세 가지 컬렉션을 확인했다.

| 종류              | 특징                                           |
| ----------------- | ---------------------------------------------- |
| Associative Array | 키-값 구조, 동적 크기, PL/SQL 블록 안에서 사용 |
| Nested Table      | 동적 배열, 생성자 초기화 필요                  |
| VARRAY            | 최대 크기가 정해진 배열                        |

정리:

- 컬렉션은 여러 값을 담을 때 사용한다.
- Java의 배열, List, Map과 비슷하게 볼 수 있다.
- 종류마다 초기화 방식과 사용 목적이 다르다.

---

## 13. Associative Array

Associative Array는 키를 기준으로 값을 저장하는 컬렉션이다.

```sql
DECLARE
    TYPE t_salary_list IS TABLE OF NUMBER INDEX BY PLS_INTEGER;
    v_salaries t_salary_list;

    TYPE t_dept_map IS TABLE OF VARCHAR2(50) INDEX BY VARCHAR2(10);
    v_dept t_dept_map;
BEGIN
    v_salaries(1) := 24000;
    v_salaries(2) := 17000;
    v_salaries(3) := 9000;

    v_dept('IT') := 'IT 개발팀';
    v_dept('FIN') := '재무팀';
    v_dept('SALES') := '영업팀';

    DBMS_OUTPUT.PUT_LINE('IT 부서: ' || v_dept('IT'));
END;
/
```

정리:

- Associative Array는 key-value 구조이다.
- 숫자 키나 문자열 키를 사용할 수 있다.
- 선언 시 크기를 정하지 않아도 된다.
- 동적으로 값이 추가된다.
- DB 컬럼에 직접 저장하는 용도보다는 PL/SQL 내부 임시 자료구조로 사용한다.

---

## 14. Nested Table

Nested Table은 순서 있는 동적 배열처럼 사용할 수 있다.

```sql
DECLARE
    TYPE t_name_list IS TABLE OF VARCHAR2(50);
    v_names t_name_list := t_name_list();
BEGIN
    v_names.EXTEND;
    v_names(1) := 'Steven King';

    v_names.EXTEND;
    v_names(2) := 'Neena Kochhar';

    DBMS_OUTPUT.PUT_LINE('총 ' || v_names.COUNT || '명');
END;
/
```

정리:

- Nested Table은 생성자로 초기화해야 한다.
- `EXTEND`로 공간을 늘릴 수 있다.
- `COUNT`로 요소 개수를 확인할 수 있다.
- `DELETE`로 요소를 삭제할 수 있다.
- 삭제 후 인덱스가 비어 있는 희소 배열 형태가 될 수 있다.

## 15. VARRAY

VARRAY는 최대 크기가 정해진 배열이다.

```sql
DECLARE
    TYPE t_dept_list IS VARRAY(5) OF VARCHAR2(30);
    v_depts t_dept_list := t_dept_list('IT', 'FIN', 'SALES');
BEGIN
    FOR i IN 1..v_depts.COUNT LOOP
        DBMS_OUTPUT.PUT_LINE(i || ': ' || v_depts(i));
    END LOOP;
END;
/
```

정리:

- VARRAY는 최대 크기를 지정한다.
- 순서가 있다.
- 생성자로 초기화해야 한다.
- 정해진 최대 개수를 넘을 수 없다.
- 고정된 크기의 목록을 다룰 때 사용할 수 있다.

## 16. `BULK COLLECT`

`BULK COLLECT`는 여러 행을 한 번에 컬렉션으로 가져올 때 사용한다.

```sql
DECLARE
    TYPE t_emp_ids IS TABLE OF employees.employee_id%TYPE;
    TYPE t_emp_names IS TABLE OF VARCHAR2(100);

    v_ids t_emp_ids;
    v_names t_emp_names;
BEGIN
    SELECT employee_id,
           first_name || ' ' || last_name
    BULK COLLECT INTO v_ids, v_names
    FROM employees
    WHERE department_id = 60;

    FOR i IN 1..v_ids.COUNT LOOP
        DBMS_OUTPUT.PUT_LINE(v_ids(i) || ' - ' || v_names(i));
    END LOOP;
END;
/
```

정리:

- `BULK COLLECT`는 여러 행을 한 번에 가져온다.
- 반복해서 한 행씩 가져오는 것보다 Context Switch를 줄일 수 있다.
- 조회 결과를 컬렉션 변수에 저장한다.
- 대량 데이터를 처리할 때 성능상 유리할 수 있다.
- 너무 많은 데이터를 한 번에 가져오면 메모리 사용량이 커질 수 있다.

## 17. 커서

커서는 SQL 실행 결과를 한 행씩 처리하기 위한 구조이다.

`SELECT INTO`는 정확히 1행만 처리할 수 있다.
여러 행을 순차적으로 처리하려면 커서를 사용한다.

정리:

- 커서는 여러 행의 결과를 하나씩 처리할 때 사용한다.
- 묵시적 커서와 명시적 커서가 있다.
- 명시적 커서는 개발자가 직접 선언한다.
- Cursor FOR LOOP를 사용하면 커서를 더 간단하게 처리할 수 있다.

---

## 18. 묵시적 커서

묵시적 커서는 Oracle이 자동으로 생성하는 커서이다.

DML이나 `SELECT INTO`를 실행할 때 내부적으로 생성된다.

대표 속성:

| 속성           | 의미                                         |
| -------------- | -------------------------------------------- |
| `SQL%FOUND`    | 처리된 행이 있으면 `TRUE`                    |
| `SQL%NOTFOUND` | 처리된 행이 없으면 `TRUE`                    |
| `SQL%ROWCOUNT` | 처리된 행 수                                 |
| `SQL%ISOPEN`   | 묵시적 커서는 자동으로 닫히므로 보통 `FALSE` |

예시:

```sql
BEGIN
    UPDATE emp_test
    SET salary = salary * 1.05
    WHERE department_id = 60;

    DBMS_OUTPUT.PUT_LINE(SQL%ROWCOUNT || '건 수정');
END;
/
```

정리:

- 묵시적 커서는 Oracle이 자동으로 관리한다.
- DML 실행 결과를 `SQL%ROWCOUNT`로 확인할 수 있다.
- `SQL%FOUND`, `SQL%NOTFOUND`로 처리 여부를 확인할 수 있다.

## 19. 명시적 커서

명시적 커서는 개발자가 직접 선언하고 여는 커서이다.

```sql
DECLARE
    CURSOR c_emp IS
        SELECT employee_id, first_name, salary
        FROM employees
        WHERE department_id = 90
        ORDER BY salary DESC;

    v_id employees.employee_id%TYPE;
    v_name employees.first_name%TYPE;
    v_sal employees.salary%TYPE;
BEGIN
    OPEN c_emp;

    LOOP
        FETCH c_emp INTO v_id, v_name, v_sal;
        EXIT WHEN c_emp%NOTFOUND;

        DBMS_OUTPUT.PUT_LINE(v_id || ' | ' || v_name || ' | ' || v_sal);
    END LOOP;

    CLOSE c_emp;
END;
/
```

정리:

- 명시적 커서는 `CURSOR`로 선언한다.
- `OPEN`으로 커서를 연다.
- `FETCH`로 한 행씩 가져온다.
- `EXIT WHEN 커서명%NOTFOUND`로 반복을 종료한다.
- `CLOSE`로 커서를 닫는다.
- `OPEN-FETCH-CLOSE` 흐름을 기억해야 한다.

## 20. Cursor FOR LOOP

Cursor FOR LOOP는 커서 처리 과정을 간단하게 만든다.

```sql
BEGIN
    FOR r IN (
        SELECT first_name, salary
        FROM employees
        WHERE department_id = 90
    ) LOOP
        DBMS_OUTPUT.PUT_LINE(r.first_name || ': ' || r.salary);
    END LOOP;
END;
/
```

정리:

- Cursor FOR LOOP는 커서 선언, OPEN, FETCH, CLOSE를 자동으로 처리한다.
- 코드가 짧고 실수할 부분이 적다.
- 여러 행 조회 결과를 반복 처리할 때 자주 사용한다.
- 실무에서는 명시적 커서를 직접 여닫는 것보다 Cursor FOR LOOP가 더 간결한 경우가 많다.

---

## 21. 예외 처리

PL/SQL에서는 `EXCEPTION` 영역에서 예외를 처리할 수 있다.

```sql
BEGIN
    -- 실행 로직
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('데이터 없음');
    WHEN TOO_MANY_ROWS THEN
        DBMS_OUTPUT.PUT_LINE('결과가 너무 많음');
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE(SQLERRM);
END;
/
```

정리:

- `NO_DATA_FOUND`는 조회 결과가 없을 때 발생한다.
- `TOO_MANY_ROWS`는 `SELECT INTO` 결과가 여러 행일 때 발생한다.
- `OTHERS`는 처리되지 않은 모든 예외를 잡는다.
- `OTHERS`만 쓰면 원인을 알기 어려우므로 `SQLCODE`, `SQLERRM`을 함께 확인하는 것이 좋다.
- 트랜잭션 오류가 발생하면 `ROLLBACK` 처리가 필요할 수 있다.

---

## 22. 사용자 정의 예외

직접 예외를 선언해서 사용할 수도 있다.

```sql
DECLARE
    e_insufficient_funds EXCEPTION;
    v_balance NUMBER := 10000;
    v_amount NUMBER := 20000;
BEGIN
    IF v_balance < v_amount THEN
        RAISE e_insufficient_funds;
    END IF;

EXCEPTION
    WHEN e_insufficient_funds THEN
        DBMS_OUTPUT.PUT_LINE('잔액 부족');
END;
/
```

정리:

- 사용자 정의 예외는 `EXCEPTION` 타입으로 선언한다.
- `RAISE`로 직접 예외를 발생시킨다.
- 업무 규칙 위반을 명확하게 표현할 수 있다.
- `RAISE_APPLICATION_ERROR`를 사용하면 사용자 정의 오류 번호와 메시지를 줄 수 있다.
- 사용자 정의 오류 번호는 보통 `-20000 ~ -20999` 범위를 사용한다.

## 23. 프로시저

프로시저는 DB에 저장되는 PL/SQL 서브프로그램이다.

반복적으로 수행하는 작업을 이름 있는 로직으로 저장해두고 호출할 수 있다.

```sql
CREATE OR REPLACE PROCEDURE raise_salary (
    p_emp_id IN emp_back.employee_id%TYPE,
    p_pct IN NUMBER DEFAULT 0.1
)
IS
    v_current_sal emp_back.salary%TYPE;
BEGIN
    SELECT salary
    INTO v_current_sal
    FROM emp_back
    WHERE employee_id = p_emp_id;

    UPDATE emp_back
    SET salary = salary * (1 + p_pct)
    WHERE employee_id = p_emp_id;

    DBMS_OUTPUT.PUT_LINE(
        '직원 ' || p_emp_id || ' 급여 인상: ' ||
        v_current_sal || ' → ' || ROUND(v_current_sal * (1 + p_pct))
    );

    COMMIT;
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('오류: ' || p_emp_id || '번 직원이 없습니다.');
        ROLLBACK;
END raise_salary;
/
```

실행:

```sql
EXEC raise_salary(103);
EXEC raise_salary(103, 0.15);
```

정리:

- 프로시저는 이름이 있는 PL/SQL 로직이다.
- DB에 저장되어 재사용할 수 있다.
- `CREATE OR REPLACE PROCEDURE`로 생성한다.
- `EXEC 프로시저명(...)`으로 실행할 수 있다.
- 반환값은 없지만 `OUT` 매개변수로 결과를 돌려줄 수 있다.
- 수업 예제에서는 프로시저 내부에서 `COMMIT`, `ROLLBACK`을 처리했다.
- 실무에서는 트랜잭션 경계를 호출하는 쪽에서 관리하는 경우도 많다.

---

## 24. 매개변수 모드

프로시저 매개변수에는 방향이 있다.

| 모드     | 방향              | 의미                       |
| -------- | ----------------- | -------------------------- |
| `IN`     | 호출자 → 프로시저 | 입력값 전달                |
| `OUT`    | 프로시저 → 호출자 | 결과값 반환                |
| `IN OUT` | 양방향            | 입력값을 받아 수정 후 반환 |

`OUT` 매개변수 예시:

```sql
CREATE OR REPLACE PROCEDURE get_emp_info (
    p_emp_id IN employees.employee_id%TYPE,
    p_name OUT VARCHAR2,
    p_salary OUT employees.salary%TYPE,
    p_dept OUT departments.department_name%TYPE
)
IS
BEGIN
    SELECT e.first_name || ' ' || e.last_name,
           e.salary,
           d.department_name
    INTO p_name, p_salary, p_dept
    FROM employees e
    JOIN departments d ON e.department_id = d.department_id
    WHERE e.employee_id = p_emp_id;
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        p_name := '미존재';
        p_salary := 0;
        p_dept := '미배정';
END get_emp_info;
/
```

정리:

- `IN`은 입력값이다.
- `OUT`은 결과를 호출자에게 돌려준다.
- `IN OUT`은 입력값을 받아 내부에서 수정한 뒤 다시 돌려준다.
- `OUT` 매개변수를 받을 때는 PL/SQL 변수에 담아야 한다.

---

## 25. 함수

함수는 반드시 하나의 값을 반환하는 서브프로그램이다.

```sql
CREATE OR REPLACE FUNCTION get_annual_sal (
    p_emp_id IN employees.employee_id%TYPE
)
RETURN NUMBER
IS
    v_monthly employees.salary%TYPE;
    v_comm employees.commission_pct%TYPE;
BEGIN
    SELECT salary, NVL(commission_pct, 0)
    INTO v_monthly, v_comm
    FROM employees
    WHERE employee_id = p_emp_id;

    RETURN (v_monthly + v_monthly * v_comm) * 12;
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        RETURN 0;
END get_annual_sal;
/
```

SQL에서 호출:

```sql
SELECT employee_id,
       first_name,
       salary,
       get_annual_sal(employee_id) AS 연봉
FROM employees
WHERE department_id = 80
  AND ROWNUM <= 5
ORDER BY 연봉 DESC;
```

정리:

- 함수는 `RETURN` 값을 가진다.
- `CREATE OR REPLACE FUNCTION`으로 생성한다.
- `RETURN 타입`을 명시해야 한다.
- 함수 내부에서는 `RETURN 값;`으로 결과를 반환한다.
- SQL의 `SELECT`절에서도 사용할 수 있다.
- 단순 계산 결과를 돌려주는 로직에 적합하다.

---

## 26. 프로시저와 함수 차이

프로시저와 함수는 둘 다 DB에 저장되는 PL/SQL 서브프로그램이다.

차이는 반환값과 사용 목적이다.

| 구분        | 프로시저              | 함수                           |
| ----------- | --------------------- | ------------------------------ |
| 반환값      | 직접 `RETURN` 없음    | 반드시 `RETURN` 있음           |
| 실행        | `EXEC`, `CALL`        | `SELECT 함수명(...) FROM dual` |
| 목적        | 작업 수행             | 값 계산 후 반환                |
| 결과 전달   | `OUT` 매개변수 가능   | `RETURN`으로 반환              |
| SQL 안 사용 | 보통 직접 사용 어려움 | `SELECT`절에서 사용 가능       |

정리:

- 프로시저는 작업을 수행하는 데 초점이 있다.
- 함수는 값을 계산해서 반환하는 데 초점이 있다.
- 프로시저는 `OUT` 매개변수로 값을 돌려줄 수 있다.
- 함수는 반드시 하나의 값을 `RETURN`해야 한다.

생성된 프로시저와 함수는 데이터 사전에서 확인할 수 있다.

```sql
SELECT object_name, object_type, status, last_ddl_time
```

소스 확인:

```sql
SELECT text
```

```sql
SHOW ERRORS PROCEDURE raise_salary;
```

정리:

- `USER_OBJECTS`에서 객체 상태를 확인할 수 있다.
- `USER_SOURCE`에서 저장된 소스를 확인할 수 있다.
- 컴파일 오류는 `SHOW ERRORS`나 `USER_ERRORS`에서 확인할 수 있다.
- 필요 없으면 `DROP PROCEDURE`, `DROP FUNCTION`으로 삭제한다.

## 28. 패키지

패키지는 관련된 프로시저, 함수, 변수, 커서, 타입을 하나로 묶는 객체이다.

패키지는 명세와 본문으로 나뉜다.

```text
PACKAGE       -> 명세, 공개 API 선언
PACKAGE BODY  -> 실제 구현
```

패키지 명세:

```sql
CREATE OR REPLACE PACKAGE pkg_emp_mgmt AS
    c_max_raise CONSTANT NUMBER := 0.3;

    PROCEDURE raise_salary(p_emp_id IN NUMBER, p_pct IN NUMBER DEFAULT 0.1);
    FUNCTION get_annual_sal(p_emp_id IN NUMBER) RETURN NUMBER;
    PROCEDURE print_dept_summary(p_dept_id IN NUMBER);
END pkg_emp_mgmt;
/
```

정리:

- 패키지는 관련 기능을 묶는 단위이다.
- 명세에는 외부에 공개할 프로시저, 함수, 상수 등을 선언한다.
- 본문에는 실제 구현을 작성한다.
- 명세에 없는 내부 로직은 외부에서 직접 호출할 수 없다.
- 기능을 모듈화하고 재사용하기 좋다.
- 패키지 변수는 세션 단위 전역 변수처럼 사용할 수 있다.

---

## 29. 패키지 본문

패키지 본문에는 명세에서 선언한 프로시저와 함수를 구현한다.

```sql
CREATE OR REPLACE PACKAGE BODY pkg_emp_mgmt AS

    PROCEDURE raise_salary(p_emp_id IN NUMBER, p_pct IN NUMBER DEFAULT 0.1) IS
    BEGIN
        IF p_pct > c_max_raise THEN
            RAISE_APPLICATION_ERROR(-20001, '인상률이 최대치를 초과합니다.');
        END IF;

        UPDATE employees
        SET salary = salary * (1 + p_pct)
        WHERE employee_id = p_emp_id;

        COMMIT;
    END raise_salary;

    FUNCTION get_annual_sal(p_emp_id IN NUMBER) RETURN NUMBER IS
        v_sal NUMBER;
    BEGIN
        SELECT salary * 12
        INTO v_sal
        FROM employees
        WHERE employee_id = p_emp_id;

        RETURN v_sal;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RETURN 0;
    END get_annual_sal;

    PROCEDURE print_dept_summary(p_dept_id IN NUMBER) IS
    BEGIN
        FOR r IN (
            SELECT first_name, salary
            FROM employees
            WHERE department_id = p_dept_id
            ORDER BY salary DESC
        ) LOOP
            DBMS_OUTPUT.PUT_LINE(r.first_name || ': ' || r.salary);
        END LOOP;
    END print_dept_summary;

END pkg_emp_mgmt;
/
```

정리:

- 패키지 본문은 명세에 선언한 기능을 구현한다.
- 명세와 본문의 프로시저·함수 이름과 매개변수가 맞아야 한다.
- 패키지 안의 프로시저는 `패키지명.프로시저명`으로 호출한다.
- 수업 예제의 `raise_salary`는 원본 `employees`를 직접 수정하고 `COMMIT`하므로 반복 실행 시 주의가 필요하다.

## 30. 트리거

트리거는 특정 테이블에 DML 이벤트가 발생했을 때 자동으로 실행되는 PL/SQL 객체이다.

```text
INSERT
UPDATE
DELETE
```

이런 이벤트가 발생하면 DB 엔진이 트리거를 자동으로 실행한다.

정리:

- 트리거는 사용자가 직접 호출하지 않는다.
- DML 이벤트가 발생하면 자동 실행된다.
- 데이터 무결성 유지, 연관 테이블 자동 동기화, 감사 로그 기록에 사용할 수 있다.
- 트리거 안에서는 일반적으로 `COMMIT`, `ROLLBACK`을 직접 실행할 수 없다.
- 트리거는 호출한 DML의 트랜잭션에 종속된다.

---

## 31. 트리거 기본 문법

```sql
CREATE OR REPLACE TRIGGER trigger_name
AFTER INSERT
ON table_name
BEGIN
    -- 실행할 로직
END;
/
```

행 레벨 트리거는 `FOR EACH ROW`를 붙인다.

```sql
CREATE OR REPLACE TRIGGER trigger_name
AFTER INSERT
ON table_name
FOR EACH ROW
BEGIN
    -- 변경된 각 행마다 실행할 로직
END;
/
```

정리:

- `BEFORE`는 DML 실행 전에 트리거를 실행한다.
- `AFTER`는 DML 실행 후에 트리거를 실행한다.
- `INSERT`, `UPDATE`, `DELETE` 이벤트에 반응할 수 있다.
- `FOR EACH ROW`가 없으면 문장 레벨 트리거이다.
- `FOR EACH ROW`가 있으면 행 레벨 트리거이다.

---

## 32. 문장 레벨 트리거

문장 레벨 트리거는 DML 문장 하나당 한 번 실행된다.

```sql
CREATE OR REPLACE TRIGGER trg_01
AFTER INSERT
ON emp01
BEGIN
    DBMS_OUTPUT.PUT_LINE('신입사원이 입사했습니다.');
END;
/
```

정리:

- 문장 레벨 트리거는 `FOR EACH ROW`를 쓰지 않는다.
- DML 문장 1회에 트리거가 1회 실행된다.
- 여러 행이 변경되어도 문장 기준으로 한 번 실행된다.
- `:NEW`, `:OLD`는 사용할 수 없다.
- 알림 메시지나 로그 기록 같은 작업에 사용할 수 있다.

---

## 33. 행 레벨 트리거

행 레벨 트리거는 변경되는 각 행마다 실행된다.

```sql
CREATE OR REPLACE TRIGGER trg_02
AFTER INSERT
ON emp01
FOR EACH ROW
BEGIN
    INSERT INTO sal01
    VALUES (
        sal01_salno_seq.NEXTVAL,
        100,
        :NEW.empno
    );
END;
/
```

정리:

- 행 레벨 트리거는 `FOR EACH ROW`를 사용한다.
- 변경된 행 수만큼 트리거가 반복 실행된다.
- `:NEW`, `:OLD`를 사용할 수 있다.
- 연관 테이블에 자동으로 데이터를 넣거나 수정할 때 사용할 수 있다.

---

## 34. `:NEW`와 `:OLD`

`:NEW`와 `:OLD`는 행 레벨 트리거에서 사용하는 의사 레코드이다.

| 이벤트   | `:NEW`         | `:OLD`      |
| -------- | -------------- | ----------- |
| `INSERT` | 새로 삽입될 값 | 사용 불가   |
| `UPDATE` | 변경 후 값     | 변경 전 값  |
| `DELETE` | 사용 불가      | 삭제되는 값 |

정리:

- `:NEW`는 INSERT, UPDATE에서 새 값을 참조한다.
- `:OLD`는 UPDATE, DELETE에서 이전 값을 참조한다.
- 문장 레벨 트리거에서는 사용할 수 없다.
- 행 레벨 트리거에서만 사용할 수 있다.

---

## 35. 연관 테이블 자동 처리 트리거

직원이 추가되면 급여 테이블에 기본 급여 데이터를 자동으로 넣을 수 있다.

```sql
CREATE OR REPLACE TRIGGER trg_02
AFTER INSERT
ON emp01
FOR EACH ROW
BEGIN
    INSERT INTO sal01
    VALUES (
        sal01_salno_seq.NEXTVAL,
        100,
        :NEW.empno
    );
END;
/
```

직원이 삭제되면 관련 급여 데이터도 삭제할 수 있다.

```sql
CREATE OR REPLACE TRIGGER trg_03
AFTER DELETE
ON emp01
FOR EACH ROW
BEGIN
    DELETE FROM sal01
    WHERE empno = :OLD.empno;
END;
/
```

정리:

- 트리거는 연관 테이블을 자동으로 동기화할 수 있다.
- INSERT 트리거에서는 `:NEW` 값을 사용한다.
- DELETE 트리거에서는 `:OLD` 값을 사용한다.
- 자동 처리 로직은 편하지만, 숨은 동작이 되기 쉬우므로 관리가 필요하다.

---

## 36. 재고 자동 관리 트리거

입고 테이블에 데이터가 들어오면 상품 재고를 자동으로 증가시킬 수 있다.

```sql
CREATE OR REPLACE TRIGGER trg_04
AFTER INSERT
ON 입고
FOR EACH ROW
BEGIN
    UPDATE 상품
    SET 재고수량 = 재고수량 + :NEW.입고수량
    WHERE 상품코드 = :NEW.상품코드;
END;
/
```

입고 수량이 변경되면 기존 수량을 빼고 새 수량을 더해야 한다.

```sql
CREATE OR REPLACE TRIGGER trg_05
AFTER UPDATE
ON 입고
FOR EACH ROW
BEGIN
    UPDATE 상품
    SET 재고수량 = 재고수량 + (-:OLD.입고수량 + :NEW.입고수량)
    WHERE 상품코드 = :NEW.상품코드;
END;
/
```

입고 데이터가 삭제되면 재고를 감소시킨다.

```sql
CREATE OR REPLACE TRIGGER trg_06
AFTER DELETE
ON 입고
FOR EACH ROW
BEGIN
    UPDATE 상품
    SET 재고수량 = 재고수량 - :OLD.입고수량
    WHERE 상품코드 = :OLD.상품코드;
END;
/
```

정리:

- 입고 INSERT → 상품 재고 증가
- 입고 UPDATE → 기존 입고수량을 빼고 새 입고수량을 더함
- 입고 DELETE → 상품 재고 감소
- 재고처럼 연관 값이 자동으로 맞춰져야 하는 경우 트리거를 사용할 수 있다.
- 다만 트리거가 많아지면 실제 데이터 변경 흐름을 추적하기 어려워질 수 있다.

## 37. 트리거 관리

생성된 트리거는 데이터 사전에서 확인할 수 있다.

```sql
SELECT trigger_name,
       trigger_type,
       triggering_event,
       table_name,
       status
FROM user_triggers
ORDER BY table_name;
```

트리거 삭제:

```sql
DROP TRIGGER trg_06;
```

트리거 비활성화:

```sql
ALTER TRIGGER trg_04 DISABLE;
```

트리거 활성화:

```sql
ALTER TRIGGER trg_04 ENABLE;
```

테이블의 모든 트리거 비활성화:

```sql
ALTER TABLE 입고 DISABLE ALL TRIGGERS;
```

정리:

- `USER_TRIGGERS`에서 트리거 목록과 상태를 확인할 수 있다.
- `DROP TRIGGER`로 트리거를 삭제한다.
- `ALTER TRIGGER ... DISABLE`로 일시 중지할 수 있다.
- `ALTER TRIGGER ... ENABLE`로 다시 활성화할 수 있다.
- 테이블 단위로 모든 트리거를 비활성화하거나 활성화할 수 있다.

## 39. 다시 볼 부분

- PL/SQL 블록은 `DECLARE`, `BEGIN`, `EXCEPTION`, `END` 구조이다.
- `BEGIN`과 `END`는 필수이고, `DECLARE`와 `EXCEPTION`은 선택이다.
- `SELECT INTO`는 반드시 정확히 1행을 반환해야 한다.
- 0행이면 `NO_DATA_FOUND`, 여러 행이면 `TOO_MANY_ROWS`가 발생한다.
- 여러 행을 처리하려면 커서를 사용한다.
- `%TYPE`은 컬럼 타입을 참조한다.
- `%ROWTYPE`은 테이블의 행 전체 구조를 참조한다.
- 사용자 정의 `RECORD`는 필요한 필드만 직접 묶을 수 있다.
- Associative Array는 key-value 구조이다.
- Nested Table과 VARRAY는 생성자 초기화가 필요하다.
- `BULK COLLECT`는 여러 행을 한 번에 컬렉션으로 가져온다.
- 명시적 커서는 `OPEN → FETCH → CLOSE` 흐름이다.
- Cursor FOR LOOP는 커서 열기, 가져오기, 닫기를 자동으로 처리한다.
- `SQL%ROWCOUNT`는 직전 DML의 처리 행 수를 확인할 때 사용한다.
- `OTHERS` 예외 처리에서는 `SQLCODE`, `SQLERRM`을 함께 확인하는 것이 좋다.
- 프로시저는 작업 수행에 초점이 있고, 함수는 값 반환에 초점이 있다.
- 함수는 반드시 `RETURN` 값을 가져야 한다.
- 패키지는 명세와 본문으로 나뉜다.
- 트리거는 직접 호출하지 않고 DML 이벤트에 의해 자동 실행된다.
- 문장 레벨 트리거는 DML 문장당 한 번 실행된다.
- 행 레벨 트리거는 변경된 행마다 실행된다.
- `:NEW`와 `:OLD`는 행 레벨 트리거에서만 사용할 수 있다.
- 트리거 안에서는 `COMMIT`, `ROLLBACK`을 직접 실행할 수 없다.
- 트리거는 편하지만 자동 실행되므로 데이터 변경 흐름이 숨겨질 수 있다.

## 40. 수업 진행 중 생겼던 의문

### `SELECT INTO`는 왜 여러 행을 처리하지 못할까?

`SELECT INTO`는 조회 결과를 변수에 직접 담는 문법이다.

```sql
SELECT first_name, salary
INTO v_name, v_salary
FROM employees
WHERE employee_id = 100;
```

변수 하나에는 한 행의 값만 담을 수 있다.
그래서 결과가 여러 행이면 어떤 행을 변수에 넣어야 하는지 결정할 수 없다.

정리하면 `SELECT INTO`는 단일 행 조회용이고, 여러 행을 처리하려면 커서를 사용해야 한다.

---

### `%TYPE`과 `%ROWTYPE`은 왜 사용할까?

처음에는 그냥 `NUMBER`, `VARCHAR2`로 직접 타입을 쓰면 된다고 볼 수 있다.

하지만 테이블 컬럼 타입이 바뀌면 PL/SQL 코드의 변수 타입도 같이 바꿔야 한다.

```sql
v_salary employees.salary%TYPE;
```

이렇게 작성하면 `employees.salary` 컬럼 타입을 그대로 참조한다.

`%ROWTYPE`은 한 행 전체를 가져올 때 편하다.

```sql
v_emp employees%ROWTYPE;
```

정리하면 `%TYPE`과 `%ROWTYPE`은 테이블 구조 변경에 덜 취약한 코드를 만들기 위해 사용한다.

---

### 커서 FOR LOOP가 있는데 명시적 커서를 왜 배울까?

Cursor FOR LOOP는 커서 선언, 열기, 가져오기, 닫기를 자동으로 처리한다.

그래서 단순 조회 반복에는 더 간단하다.

하지만 명시적 커서의 `OPEN`, `FETCH`, `CLOSE` 흐름을 알아야 커서가 내부적으로 어떻게 동작하는지 이해할 수 있다.

```text
OPEN  -> 쿼리 실행
FETCH -> 한 행씩 가져오기
CLOSE -> 커서 닫기
```

정리하면 실무에서는 Cursor FOR LOOP가 간결하지만, 커서의 기본 원리는 명시적 커서 흐름으로 이해해야 한다.

---

### 프로시저와 함수는 어떻게 구분해야 할까?

프로시저는 작업을 수행하는 로직에 적합하다.

예를 들어 급여를 인상하거나 계좌 이체를 처리하는 작업은 프로시저가 자연스럽다.

함수는 값을 계산해서 반환하는 로직에 적합하다.

예를 들어 직원의 연봉이나 세후 월급을 계산해서 반환하는 작업은 함수가 자연스럽다.

```text
프로시저 -> 작업 수행
함수     -> 값 반환
```

이 기준으로 구분하면 된다.

---

### 패키지는 왜 명세와 본문으로 나눌까?

패키지 명세는 외부에 공개할 기능을 선언한다.

패키지 본문은 실제 구현을 작성한다.

즉, 명세는 외부에서 볼 수 있는 API이고, 본문은 내부 구현이라고 볼 수 있다.

```text
PACKAGE      -> 공개 인터페이스
PACKAGE BODY -> 실제 구현
```

이 구조 덕분에 관련 기능을 하나로 묶으면서도, 외부에 공개할 것과 내부 구현을 구분할 수 있다.

---

### 트리거는 프로시저와 뭐가 다를까?

프로시저는 사용자가 직접 호출한다.

```sql
EXEC raise_salary(103);
```

트리거는 직접 호출하지 않는다.
테이블에 `INSERT`, `UPDATE`, `DELETE`가 발생하면 DB가 자동으로 실행한다.

```text
프로시저 -> 직접 호출
트리거   -> DML 이벤트 발생 시 자동 실행
```

또한 트리거는 호출한 DML의 트랜잭션에 묶인다.
그래서 트리거 내부에서 `COMMIT`, `ROLLBACK`을 직접 처리하지 않는다.

---

### 문장 레벨과 행 레벨 트리거는 어떻게 구분할까?

문장 레벨 트리거는 DML 문장 하나당 한 번 실행된다.

```sql
UPDATE employees
SET salary = salary * 1.1
WHERE department_id = 60;
```

이 문장이 5명의 직원을 수정하더라도 문장 레벨 트리거는 한 번만 실행된다.

반면 행 레벨 트리거는 변경된 행마다 실행된다.
5명이 수정되면 트리거도 5번 실행된다.

정리하면 다음처럼 볼 수 있다.

```text
문장 레벨 트리거 -> SQL 문장당 1회
행 레벨 트리거   -> 변경된 행마다 1회
```

---

### `:NEW`와 `:OLD`는 언제 사용할까?

`:NEW`는 새 값이고, `:OLD`는 기존 값이다.

INSERT에서는 새로 들어오는 값만 있으므로 `:NEW`를 사용한다.

UPDATE에서는 변경 전 값과 변경 후 값이 모두 있으므로 `:OLD`, `:NEW`를 모두 사용할 수 있다.

DELETE에서는 삭제되는 기존 값만 있으므로 `:OLD`를 사용한다.

```text
INSERT -> :NEW
UPDATE -> :OLD, :NEW
DELETE -> :OLD
```

그리고 `:NEW`, `:OLD`는 행 레벨 트리거에서만 사용할 수 있다.

## 정리

Oracle Day05에서는 PL/SQL, 커서, 예외 처리, 프로시저, 함수, 패키지, 트리거를 학습했다.

PL/SQL 기본 구조에서는 `DECLARE`, `BEGIN`, `EXCEPTION`, `END` 흐름을 확인했다.
SQL만 사용할 때와 달리 변수, 조건문, 반복문, 예외 처리를 함께 사용할 수 있어서 여러 SQL과 로직을 하나의 블록으로 묶을 수 있었다.

변수와 타입에서는 `%TYPE`, `%ROWTYPE`, 사용자 정의 `RECORD`를 정리했다.
`%TYPE`은 컬럼 타입을 참조하고, `%ROWTYPE`은 테이블의 한 행 전체 구조를 참조한다.
이 방식은 테이블 구조 변경에 덜 취약한 코드를 작성하는 데 도움이 된다.

컬렉션에서는 Associative Array, Nested Table, VARRAY를 확인했다.
여러 행을 한 번에 가져올 때는 `BULK COLLECT`를 사용할 수 있고, 반복 처리보다 Context Switch를 줄일 수 있다는 점이 중요했다.

커서에서는 묵시적 커서와 명시적 커서를 구분했다.
묵시적 커서는 Oracle이 자동으로 관리하고, 명시적 커서는 개발자가 직접 `OPEN`, `FETCH`, `CLOSE`를 제어한다.
Cursor FOR LOOP는 이 과정을 자동으로 처리해 주기 때문에 여러 행을 반복 조회할 때 간결하게 사용할 수 있다.

예외 처리에서는 `NO_DATA_FOUND`, `TOO_MANY_ROWS`, `OTHERS`, 사용자 정의 예외를 확인했다.
특히 `SELECT INTO`는 정확히 1행만 반환해야 하므로 예외 처리가 중요하다.

프로시저와 함수는 둘 다 DB에 저장되는 PL/SQL 서브프로그램이다.
프로시저는 작업 수행에 초점이 있고, 함수는 값을 반환하는 데 초점이 있다.
패키지는 관련된 프로시저와 함수를 명세와 본문으로 나누어 묶는 구조이다.

트리거는 DML 이벤트가 발생했을 때 자동으로 실행되는 객체이다.
문장 레벨 트리거는 DML 문장당 한 번 실행되고, 행 레벨 트리거는 변경된 행마다 실행된다.
행 레벨 트리거에서는 `:NEW`, `:OLD`를 사용해 변경 전후 값을 참조할 수 있다.

오늘 다시 볼 핵심은 `SELECT INTO`의 1행 조건, `%TYPE`과 `%ROWTYPE` 차이, 명시적 커서의 `OPEN-FETCH-CLOSE`, Cursor FOR LOOP, `BULK COLLECT`, 프로시저와 함수 차이, 패키지 명세와 본문 구조, 문장 레벨/행 레벨 트리거, `:NEW`와 `:OLD` 사용 기준이다.
