## 2. 식별자 오류

식별자 오류는 컬럼명, 별칭, 테이블명 같은 식별자를 잘못 사용했을 때 발생한다.

예를 들면 다음 상황에서 발생할 수 있다.

```text
존재하지 않는 컬럼명 사용
별칭 오타
테이블명 오타
큰따옴표로 만든 별칭을 잘못 참조
```

Oracle에서 큰따옴표로 별칭을 만들면 이후에도 정확히 같은 이름으로 참조해야 한다.

```sql
SELECT AVG(salary) AS "평균급여"
FROM employees;
```

위처럼 별칭을 만들면 바깥 쿼리에서 참조할 때도 `"평균급여"`처럼 써야 한다.

정리:

- 식별자 오류는 보통 컬럼명, 별칭, 테이블명 문제이다.
- 큰따옴표 별칭은 대소문자와 공백까지 그대로 맞춰야 한다.
- 공개용 SQL에서는 가능하면 영문 별칭이나 단순한 별칭을 쓰는 편이 안전하다.

## 3. `INITCAP()`

`INITCAP()`은 문자열의 각 단어 첫 글자를 대문자로, 나머지는 소문자로 변환한다.

```sql
SELECT INITCAP('neena')
FROM dual;
```

결과:

```text
Neena
```

직원 이름 검색에서도 사용할 수 있다.

```sql
SELECT *
FROM employees
WHERE first_name = INITCAP('neena');
```

정리:

- `INITCAP()`은 단어 첫 글자를 대문자로 바꾼다.
- 전체 문자열의 첫 글자만 바꾸는 함수가 아니라, 각 단어 단위로 처리한다.
- 대소문자 입력을 맞춰야 하는 조건 검색에서 사용할 수 있다.

## 4. 서브쿼리

서브쿼리는 SQL 문 안에 포함된 또 다른 SQL 문이다.

조회 조건을 고정값으로 쓰지 않고, 다른 조회 결과를 이용해서 동적으로 만들 때 사용한다.

```sql
SELECT first_name, salary
FROM employees
WHERE salary >= (
    SELECT AVG(salary)
    FROM employees
);
```

위 쿼리는 전체 평균 급여 이상을 받는 직원을 조회한다.

정리:

- 서브쿼리는 메인 쿼리 안에 들어가는 쿼리이다.
- 조건값을 직접 쓰지 않고 조회 결과로 대체할 수 있다.
- `WHERE`, `FROM`, `SELECT` 절에서 사용할 수 있다.

---

## 5. 단일행 서브쿼리

단일행 서브쿼리는 결과가 하나의 행만 나오는 서브쿼리이다.

예를 들어 전체 평균 급여는 하나의 값만 반환한다.

```sql
SELECT first_name,
       salary
FROM employees
WHERE salary >= (
    SELECT AVG(salary)
    FROM employees
);
```

급여를 가장 많이 받는 직원도 단일행 서브쿼리로 조회할 수 있다.

```sql
SELECT first_name,
       hire_date,
       department_id,
       salary
FROM employees
WHERE salary = (
    SELECT MAX(salary)
    FROM employees
);
```

정리:

- 단일행 서브쿼리는 결과가 하나여야 한다.
- `=`, `>`, `<`, `>=`, `<=` 같은 단일행 비교 연산자와 함께 사용할 수 있다.
- 결과가 여러 행이면 오류가 발생할 수 있다.

---

## 6. 다중행 서브쿼리

다중행 서브쿼리는 결과가 여러 행 나올 수 있는 서브쿼리이다.

예를 들어 이름이 `Alexander`인 직원이 여러 명이면 부서 번호도 여러 개 나올 수 있다.

```sql
SELECT *
FROM employees
WHERE department_id IN (
    SELECT department_id
    FROM employees
    WHERE first_name = INITCAP('alexander')
);
```

정리:

- 다중행 서브쿼리는 결과가 여러 개일 수 있다.
- `IN`, `ANY`, `ALL`, `EXISTS` 같은 다중행 연산자와 함께 사용한다.
- 단일행 연산자 `=`와 함께 쓰면 오류가 날 수 있다.

---

## 7. `IN`

`IN`은 여러 값 중 하나와 일치하면 참이다.

```sql
SELECT *
FROM employees
WHERE department_id IN (30, 50, 80);
```

의미는 다음과 같다.

```text
department_id = 30
OR department_id = 50
OR department_id = 80
```

서브쿼리와 함께 사용할 수도 있다.

```sql
SELECT *
FROM employees
WHERE employee_id IN (
    SELECT manager_id
    FROM employees
    WHERE manager_id IS NOT NULL
);
```

위 쿼리는 매니저 역할을 하는 직원을 조회한다.

정리:

- `IN`은 여러 값 중 하나라도 같으면 참이다.
- 내부적으로 `OR` 조건과 비슷하게 볼 수 있다.
- 서브쿼리 결과가 여러 행일 때 자주 사용한다.

---

## 8. `NOT IN`과 NULL

`NOT IN`은 모든 값과 일치하지 않아야 참이다.

```sql
SELECT *
FROM employees
WHERE employee_id NOT IN (
    SELECT manager_id
    FROM employees
    WHERE manager_id IS NOT NULL
);
```

주의할 점은 `NOT IN` 목록에 `NULL`이 포함되면 결과가 예상과 다르게 나올 수 있다는 것이다.

```sql
WHERE department_id NOT IN (10, NULL)
```

이 조건은 다음과 비슷하게 해석될 수 있다.

```text
department_id <> 10
AND department_id <> NULL
```

`NULL`과의 비교는 참이나 거짓이 아니라 UNKNOWN이 되므로, 결과가 나오지 않을 수 있다.

정리:

- `NOT IN`을 사용할 때는 `NULL` 포함 여부를 조심해야 한다.
- 서브쿼리에서 `NOT IN`을 쓸 때는 보통 `IS NOT NULL` 조건을 같이 둔다.
- `NOT EXISTS`로 바꾸는 것도 방법이다.

---

## 9. `ANY`

`ANY`는 서브쿼리 결과 중 하나라도 조건을 만족하면 참이다.

### `< ANY`

```sql
salary < ANY (
    SELECT salary
    FROM employees
    WHERE department_id = 30
)
```

의미:

```text
salary < val1
OR salary < val2
OR salary < val3
```

값들 중 하나보다만 작으면 되므로, 일반적으로 `< MAX(...)`와 비슷하게 볼 수 있다.

### `> ANY`

```sql
salary > ANY (
    SELECT salary
    FROM employees
    WHERE department_id = 30
)
```

의미:

```text
salary > val1
OR salary > val2
OR salary > val3
```

값들 중 하나보다만 크면 되므로, 일반적으로 `> MIN(...)`과 비슷하게 볼 수 있다.

정리:

- `ANY`는 하나라도 조건을 만족하면 참이다.
- `< ANY`는 `< MAX(...)`와 유사하다.
- `> ANY`는 `> MIN(...)`과 유사하다.

---

## 10. `ALL`

`ALL`은 서브쿼리 결과 전체에 대해 조건을 만족해야 참이다.

### `< ALL`

```sql
salary < ALL (
    SELECT salary
    FROM employees
    WHERE department_id = 30
)
```

의미:

```text
salary < val1
AND salary < val2
AND salary < val3
```

모든 값보다 작아야 하므로, 일반적으로 `< MIN(...)`과 비슷하다.

### `> ALL`

```sql
salary > ALL (
    SELECT salary
    FROM employees
    WHERE department_id = 30
)
```

의미:

```text
salary > val1
AND salary > val2
AND salary > val3
```

모든 값보다 커야 하므로, 일반적으로 `> MAX(...)`와 비슷하다.

정리:

- `ALL`은 모든 조건을 만족해야 참이다.
- `< ALL`은 `< MIN(...)`과 유사하다.
- `> ALL`은 `> MAX(...)`와 유사하다.
- `ANY`보다 조건이 더 엄격하다.

---

## 11. `EXISTS`

`EXISTS`는 서브쿼리 결과가 존재하는지 확인한다.

```sql
SELECT *
FROM departments d
WHERE EXISTS (
    SELECT 1
    FROM employees e
    WHERE e.department_id = d.department_id
);
```

위 쿼리는 직원이 한 명 이상 있는 부서를 조회한다.

반대로 직원이 없는 부서를 찾을 때는 `NOT EXISTS`를 사용한다.

```sql
SELECT *
FROM departments d
WHERE NOT EXISTS (
    SELECT 1
    FROM employees e
    WHERE e.department_id = d.department_id
);
```

정리:

- `EXISTS`는 값 자체보다 행의 존재 여부를 확인한다.
- 상관 서브쿼리에서 자주 사용된다.
- 데이터 구조와 실행 계획에 따라 `IN`보다 유리할 수 있지만, 항상 더 빠른 것은 아니다.
- `NOT EXISTS`는 조건에 맞는 행이 없는 경우를 찾는다.

## 12. 인라인 뷰

인라인 뷰는 `FROM`절에 사용하는 서브쿼리이다.

```sql
SELECT *
FROM (
    SELECT *
    FROM employees
    ORDER BY salary DESC
)
WHERE ROWNUM <= 10;
```

쿼리 실행 중 임시 결과 집합처럼 사용되며, 실제 테이블로 저장되는 것은 아니다.

정리:

- 인라인 뷰는 `FROM`절의 서브쿼리이다.
- 임시 테이블처럼 사용할 수 있다.
- 정렬 후 Top-N 조회에 자주 사용한다.
- 실제 테이블로 생성되는 것은 아니다.

## 13. Top-N Query와 `ROWNUM`

Oracle 11g 기준으로 정렬 후 상위 N개를 조회하려면 인라인 뷰와 `ROWNUM`을 함께 사용한다.

급여 상위 10명 조회:

```sql
SELECT *
FROM (
    SELECT *
    FROM employees
    ORDER BY salary DESC
)
WHERE ROWNUM <= 10;
```

급여 상위 5번째 직원을 조회할 때는 한 번 더 감싸서 `ROWNUM`을 별칭으로 만든 뒤 조건을 걸 수 있다.

```sql
SELECT tt.first_name,
       tt.salary
FROM (
    SELECT ROWNUM AS rn,
           t.first_name,
           t.salary
    FROM (
        SELECT first_name,
               salary
        FROM employees
        ORDER BY salary DESC
    ) t
    WHERE ROWNUM <= 5
) tt
WHERE tt.rn = 5;
```

정리:

- `ROWNUM`은 조회 과정에서 먼저 부여된다.
- 정렬 후 상위 N개를 구하려면 인라인 뷰 안에서 먼저 정렬한다.
- 바깥 쿼리에서 `ROWNUM <= N` 조건을 건다.
- N번째만 조회하려면 `ROWNUM` 별칭을 한 번 더 바깥에서 필터링한다.

## 14. 상관 서브쿼리

상관 서브쿼리는 내부 서브쿼리가 외부 쿼리의 컬럼을 참조하는 서브쿼리이다.

```sql
SELECT department_id,
       first_name,
       salary
FROM employees e
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
    WHERE department_id = e.department_id
);
```

위 쿼리는 각 직원의 급여가 자신이 속한 부서의 평균 급여보다 높은지 비교한다.

정리:

- 상관 서브쿼리는 외부 쿼리의 컬럼을 내부 쿼리에서 사용한다.
- 외부 쿼리의 각 행마다 서브쿼리가 실행될 수 있다.
- 대용량 데이터에서는 성능에 주의해야 한다.
- 조인이나 인라인 뷰로 바꿀 수 있는 경우도 있다.

## 15. 스칼라 서브쿼리

스칼라 서브쿼리는 `SELECT`절에서 하나의 값을 반환하는 서브쿼리이다.

예를 들어 직원 정보 옆에 해당 직원의 직무 평균 급여를 함께 출력할 수 있다.

```sql
SELECT e.first_name,
       e.job_id,
       e.salary,
       (
           SELECT AVG(salary)
           FROM employees
           WHERE job_id = e.job_id
       ) AS "직무 평균급여"
FROM employees e;
```

정리:

- 스칼라 서브쿼리는 하나의 값만 반환해야 한다.
- `SELECT`절에서 계산된 컬럼처럼 사용할 수 있다.
- 결과가 여러 행이면 오류가 발생한다.

## 16. 다중 컬럼 서브쿼리

다중 컬럼 서브쿼리는 여러 컬럼을 한 번에 비교하는 방식이다.

부서별 최저 급여를 받는 직원을 찾을 때 사용할 수 있다.

```sql
SELECT first_name,
       department_id,
       salary
FROM employees
WHERE (department_id, salary) IN (
    SELECT department_id,
           MIN(salary)
    FROM employees
    GROUP BY department_id
);
```

정리:

- 여러 컬럼 조합을 한 번에 비교할 수 있다.
- `(A, B) IN (...)` 형태로 작성한다.
- 부서별 최저급여자, 직무별 최고급여자 같은 문제에 활용할 수 있다.

## 17. DDL과 `CREATE TABLE AS SELECT`

DDL은 데이터베이스 객체를 정의하는 명령어이다.

수업에서는 기존 테이블 구조와 데이터를 이용해 테스트 테이블을 생성했다.

```sql
CREATE TABLE emp_test
AS
SELECT *
FROM employees;
```

구조만 복사하려면 항상 거짓인 조건을 사용할 수 있다.

```sql
CREATE TABLE emp_test2
AS
SELECT *
FROM employees
WHERE 1 = 0;
```

정리:

- `CREATE TABLE AS SELECT`는 조회 결과를 이용해 새 테이블을 만든다.
- 데이터와 구조를 함께 복사할 수 있다.
- `WHERE 1 = 0`을 사용하면 구조만 복사할 수 있다.
- 기본키, 외래키 같은 제약조건은 그대로 복사되지 않을 수 있다.

---

## 18. DML

DML은 테이블의 데이터를 추가, 수정, 삭제하는 명령어이다.

| 명령어   | 의미                           |
| -------- | ------------------------------ |
| `INSERT` | 새 행 추가                     |
| `UPDATE` | 기존 행 수정                   |
| `DELETE` | 기존 행 삭제                   |
| `MERGE`  | 조건에 따라 UPDATE 또는 INSERT |

정리:

- DML은 테이블 내부 데이터를 바꾼다.
- `WHERE` 조건을 잘못 작성하면 의도보다 많은 행이 변경될 수 있다.
- DML 실행 전후에는 `SELECT`로 결과를 확인하는 습관이 필요하다.

---

## 19. `INSERT`

`INSERT`는 테이블에 새 행을 추가한다.

```sql
INSERT INTO account_test (
    account_id,
    account_no,
    customer_name,
    balance,
    open_date
)
VALUES (
    100001,
    '11122233344455',
    '홍길동',
    1500000,
    SYSDATE
);
```

기존 테이블의 조회 결과를 다른 테이블에 넣는 다중행 INSERT도 가능하다.

```sql
INSERT INTO emp_test
SELECT *
FROM employees
WHERE salary >= 15000;
```

정리:

- 단일행 INSERT는 `VALUES`를 사용한다.
- 다중행 INSERT는 `INSERT INTO ... SELECT` 형태로 작성한다.
- 컬럼 목록을 명시하면 값의 의미가 명확해진다.
- 테이블 구조가 같아야 `SELECT *`를 그대로 사용할 수 있다.

---

## 20. `UPDATE`

`UPDATE`는 기존 행의 값을 수정한다.

```sql
UPDATE account_test
SET balance = 2000000
WHERE customer_name = '홍길동';
```

서브쿼리를 이용해 조건을 만들 수도 있다.

```sql
UPDATE emp_test
SET salary = salary * 1.1
WHERE salary < (
    SELECT AVG(salary)
    FROM employees
);
```

정리:

- `UPDATE`는 기존 데이터를 수정한다.
- `WHERE`가 없으면 모든 행이 수정될 수 있다.
- 변경 전후 결과를 `SELECT`로 확인해야 한다.

---

## 21. `DELETE`

`DELETE`는 조건에 맞는 행을 삭제한다.

```sql
DELETE FROM account_test
WHERE balance < 1000000;
```

삭제 전후 행 수를 확인하면 영향 범위를 확인할 수 있다.

```sql
SELECT COUNT(*)
FROM account_test;
```

정리:

- `DELETE`는 행 단위로 데이터를 삭제한다.
- `WHERE`가 없으면 전체 행이 삭제될 수 있다.
- 삭제 전후 `COUNT(*)`를 확인하는 것이 좋다.
- `ROLLBACK` 전이라면 되돌릴 수 있다.

---

## 22. `MERGE`

`MERGE`는 대상 테이블에 같은 데이터가 있으면 `UPDATE`, 없으면 `INSERT`를 수행하는 문법이다.

```sql
MERGE INTO emp_test t
USING emp_new s
ON (t.employee_id = s.employee_id)
WHEN MATCHED THEN
    UPDATE SET
        t.salary = s.salary,
        t.job_id = s.job_id
WHEN NOT MATCHED THEN
    INSERT (
        employee_id,
        first_name,
        last_name,
        email,
        phone_number,
        hire_date,
        job_id,
        salary,
        commission_pct,
        manager_id,
        department_id
    )
    VALUES (
        s.employee_id,
        s.first_name,
        s.last_name,
        s.email,
        s.phone_number,
        s.hire_date,
        s.job_id,
        s.salary,
        s.commission_pct,
        s.manager_id,
        s.department_id
    );
```

정리:

- `MERGE`는 `UPDATE`와 `INSERT`를 한 번에 처리한다.
- `ON` 조건으로 기존 데이터와 신규 데이터를 비교한다.
- 일치하면 `WHEN MATCHED THEN UPDATE`.
- 없으면 `WHEN NOT MATCHED THEN INSERT`.
- 배치 작업이나 데이터 적재 작업에서 자주 사용된다.

---

## 23. 트랜잭션

트랜잭션은 하나의 작업 단위이다.

예를 들어 은행 이체는 다음 두 작업이 모두 성공해야 한다.

```text
홍길동 계좌에서 50만원 차감
김영희 계좌에 50만원 증가
```

둘 중 하나만 성공하면 데이터가 깨진다.  
그래서 두 작업을 하나의 트랜잭션으로 묶어야 한다.

정리:

- 트랜잭션은 여러 DML을 하나의 작업 단위로 묶는다.
- 모두 성공하면 `COMMIT`.
- 문제가 있으면 `ROLLBACK`.
- 은행 이체처럼 데이터 일관성이 중요한 작업에 필수이다.

---

## 24. ACID

트랜잭션의 특징은 ACID로 정리한다.

| 특징        | 의미                                           |
| ----------- | ---------------------------------------------- |
| Atomicity   | 원자성. 모두 성공하거나 모두 실패              |
| Consistency | 일관성. 트랜잭션 전후 데이터 무결성 유지       |
| Isolation   | 고립성. 진행 중인 중간 상태는 다른 세션과 분리 |
| Durability  | 지속성. COMMIT된 결과는 장애 후에도 유지       |

정리:

- 원자성은 부분 완료를 막는다.
- 일관성은 데이터 무결성을 유지한다.
- 고립성은 동시에 실행되는 트랜잭션 간 영향을 제어한다.
- 지속성은 커밋된 결과가 보존됨을 의미한다.

---

## 25. `COMMIT`과 `ROLLBACK`

`COMMIT`은 변경사항을 확정한다.

```sql
COMMIT;
```

`ROLLBACK`은 아직 확정되지 않은 변경사항을 되돌린다.

```sql
ROLLBACK;
```

실습에서는 데이터를 넣고 `ROLLBACK`한 뒤 행 수가 원래대로 돌아오는지 확인했다.

```sql
SELECT COUNT(*)
FROM emp_test;
```

정리:

- `COMMIT` 전에는 `ROLLBACK`으로 되돌릴 수 있다.
- `COMMIT` 후에는 일반적인 `ROLLBACK`으로 되돌릴 수 없다.
- DML 실습에서는 커밋 시점을 명확히 확인해야 한다.

---

## 26. `SAVEPOINT`

`SAVEPOINT`는 트랜잭션 중간 지점을 저장한다.

```sql
SAVEPOINT sp1;
```

특정 지점까지만 되돌릴 수 있다.

```sql
ROLLBACK TO sp1;
```

실습 흐름은 다음과 같다.

```text
INSERT
SAVEPOINT sp1
UPDATE
SAVEPOINT sp2
DELETE
ROLLBACK TO sp2
ROLLBACK TO sp1
```

정리:

- `SAVEPOINT`는 트랜잭션 중간 저장 지점이다.
- `ROLLBACK TO 저장점`으로 일부 작업만 취소할 수 있다.
- 복잡한 트랜잭션 실습에서 변경 범위를 확인하기 좋다.

---

## 27. 은행 이체 트랜잭션

은행 이체는 트랜잭션 예제로 보기 좋다.

```sql
UPDATE account_test
SET balance = balance - 500000
WHERE customer_name = '홍길동';

UPDATE account_test
SET balance = balance + 500000
WHERE customer_name = '김영희';
```

이후 홍길동 잔액이 음수인지 확인한다.

```sql
SELECT CASE
           WHEN (
               SELECT balance
               FROM account_test
               WHERE customer_name = '홍길동'
           ) < 0 THEN 'ROLLBACK'
           ELSE 'COMMIT'
       END AS "결과"
FROM dual;
```

두 계좌의 잔액 합계도 확인할 수 있다.

```sql
SELECT SUM(balance) AS "두 계좌 잔액 합계"
FROM account_test
WHERE customer_name IN ('홍길동', '김영희');
```

정리:

- 이체는 차감과 증가가 함께 성공해야 한다.
- 한쪽만 성공하면 데이터 일관성이 깨진다.
- 실제 처리에서는 조건 확인 후 `COMMIT` 또는 `ROLLBACK`을 수행해야 한다.
- 단순 `CASE` 조회는 문자열만 보여줄 뿐 실제 트랜잭션을 제어하지는 않는다.

---

## 28. `SELECT FOR UPDATE`

`SELECT FOR UPDATE`는 조회와 동시에 해당 행에 잠금을 거는 문법이다.

```sql
SELECT employee_id,
       salary
FROM emp_test
WHERE department_id = 90
FOR UPDATE;
```

잠금을 얻지 못했을 때 바로 실패하게 할 수도 있다.

```sql
SELECT employee_id,
       salary
FROM emp_test
WHERE employee_id = 100
FOR UPDATE NOWAIT;
```

일정 시간 기다리게 할 수도 있다.

```sql
SELECT employee_id,
       salary
FROM emp_test
WHERE employee_id = 100
FOR UPDATE WAIT 5;
```

정리:

- `FOR UPDATE`는 조회한 행을 수정 대상으로 잠근다.
- `NOWAIT`는 잠금 실패 시 바로 오류를 반환한다.
- `WAIT n`은 n초 기다린 뒤 실패하면 오류를 반환한다.
- 동시에 같은 데이터를 수정하는 상황에서 중요하다.

## 30. 다시 볼 부분

- `INITCAP()`은 각 단어의 첫 글자를 대문자로 바꾼다.
- 단일행 서브쿼리는 결과가 하나여야 한다.
- 다중행 서브쿼리에는 `IN`, `ANY`, `ALL`, `EXISTS`를 사용한다.
- `IN`은 `OR` 조건과 비슷하다.
- `NOT IN`은 `NULL`이 포함되면 결과가 예상과 달라질 수 있다.
- `< ANY`는 `< MAX(...)`와 유사하다.
- `> ANY`는 `> MIN(...)`과 유사하다.
- `< ALL`은 `< MIN(...)`과 유사하다.
- `> ALL`은 `> MAX(...)`와 유사하다.
- `EXISTS`는 행의 존재 여부를 확인한다.
- 인라인 뷰는 `FROM`절의 서브쿼리이다.
- 상관 서브쿼리는 외부 쿼리의 컬럼을 내부 쿼리에서 참조한다.
- `CREATE TABLE AS SELECT`는 제약조건까지 모두 복사하지는 않는다.
- `UPDATE`, `DELETE`는 `WHERE` 조건을 반드시 확인해야 한다.
- `MERGE`는 있으면 `UPDATE`, 없으면 `INSERT`를 처리한다.
- `COMMIT` 후에는 일반적인 `ROLLBACK`으로 되돌릴 수 없다.
- `SAVEPOINT`는 트랜잭션 중간 지점을 저장한다.
- `SELECT FOR UPDATE`는 조회한 행에 잠금을 건다.

## 31. 수업 진행 중 생겼던 의문

### `ANY`와 `ALL`은 어떻게 구분해야 할까?

`ANY`는 여러 값 중 하나라도 조건을 만족하면 참이다.

```sql
salary > ANY (...)
```

이 조건은 여러 값 중 하나보다만 크면 된다.  
그래서 일반적으로 `> MIN(...)`과 비슷하게 볼 수 있다.

반대로 `ALL`은 모든 값에 대해 조건을 만족해야 한다.

```sql
salary > ALL (...)
```

이 조건은 모든 값보다 커야 한다.  
그래서 일반적으로 `> MAX(...)`와 비슷하게 볼 수 있다.

정리하면 다음처럼 기억하면 된다.

```text
ANY = 하나라도 만족
ALL = 전부 만족
```

---

### `IN`과 `EXISTS`는 어떻게 다르게 봐야 할까?

`IN`은 서브쿼리 결과 목록 안에 값이 포함되는지 비교한다.

```sql
WHERE employee_id IN (
    SELECT manager_id
    FROM employees
)
```

`EXISTS`는 서브쿼리 결과가 존재하는지만 확인한다.

```sql
WHERE EXISTS (
    SELECT 1
    FROM employees e
    WHERE e.manager_id = m.employee_id
)
```

`IN`은 값 목록 비교, `EXISTS`는 존재 여부 확인으로 보면 된다.

성능은 상황에 따라 달라질 수 있으므로, 무조건 `EXISTS`가 빠르다고 외우기보다는 실행 계획과 데이터 구조에 따라 달라질 수 있다고 보는 게 맞다.

---

### 인라인 뷰는 왜 필요할까?

Oracle 11g에서는 `ORDER BY` 후 바로 `ROWNUM`으로 상위 N개를 구하면 의도와 다를 수 있다.

```sql
SELECT *
FROM employees
WHERE ROWNUM <= 5
ORDER BY salary DESC;
```

이렇게 작성하면 먼저 5명을 뽑고 그 안에서 정렬될 수 있다.

그래서 정렬을 먼저 수행한 결과를 인라인 뷰로 만들고, 바깥에서 `ROWNUM`을 적용한다.

```sql
SELECT *
FROM (
    SELECT *
    FROM employees
    ORDER BY salary DESC
)
WHERE ROWNUM <= 5;
```

---

### `MERGE`는 언제 사용할까?

`MERGE`는 같은 키가 있으면 수정하고, 없으면 추가해야 할 때 사용한다.

예를 들어 `emp_new`에 변경 대상 직원과 신규 직원이 섞여 있을 때, `employee_id` 기준으로 비교할 수 있다.

```text
emp_test에 employee_id가 있음 -> UPDATE
emp_test에 employee_id가 없음 -> INSERT
```

이런 구조는 배치 작업이나 데이터 적재 작업에서 유용하다.

---

### 트랜잭션에서 왜 COMMIT 시점이 중요할까?

DML을 실행했다고 바로 영구 저장되는 것은 아니다.  
`COMMIT`을 해야 변경사항이 확정된다.

```sql
COMMIT;
```

확정 전에는 `ROLLBACK`으로 되돌릴 수 있다.

```sql
ROLLBACK;
```

하지만 `COMMIT` 이후에는 일반적인 `ROLLBACK`으로 되돌릴 수 없다.

그래서 계좌 이체처럼 중요한 작업은 모든 조건을 확인한 뒤 `COMMIT`해야 한다.

## 정리

Oracle Day03에서는 서브쿼리, DML, MERGE, 트랜잭션을 학습했다.

서브쿼리에서는 단일행 서브쿼리와 다중행 서브쿼리를 구분했다.  
단일행 서브쿼리는 결과가 하나일 때 사용하고, 다중행 서브쿼리는 `IN`, `ANY`, `ALL`, `EXISTS` 같은 연산자와 함께 사용한다.

`ANY`와 `ALL`은 조건 범위가 헷갈리기 쉬운 부분이었다.  
`ANY`는 하나라도 만족하면 참이고, `ALL`은 모든 값에 대해 만족해야 참이다.  
특히 `> ANY`는 `> MIN(...)`, `> ALL`은 `> MAX(...)`와 비슷하게 볼 수 있다는 점을 다시 봐야 한다.

인라인 뷰는 `FROM`절의 서브쿼리로, Oracle 11g 기준 Top-N Query에서 중요했다.  
정렬 후 상위 N개를 조회하려면 안쪽 쿼리에서 먼저 정렬하고, 바깥 쿼리에서 `ROWNUM` 조건을 적용해야 한다.

DML에서는 `INSERT`, `UPDATE`, `DELETE`, `MERGE`를 실습했다.  
특히 `UPDATE`와 `DELETE`는 `WHERE` 조건을 잘못 쓰면 전체 행이 변경될 수 있으므로 주의해야 한다.  
`MERGE`는 기존 데이터가 있으면 수정하고, 없으면 추가하는 구조라 데이터 적재 작업에서 활용할 수 있다.

트랜잭션에서는 `COMMIT`, `ROLLBACK`, `SAVEPOINT`를 확인했다.  
은행 이체 예제처럼 여러 DML이 하나의 작업 단위로 묶여야 하는 상황에서는 트랜잭션이 필수이다.  
`COMMIT` 전에는 `ROLLBACK`할 수 있지만, `COMMIT` 이후에는 일반적인 방식으로 되돌릴 수 없기 때문에 확정 시점을 신중하게 잡아야 한다.

오늘 다시 볼 핵심은 `ANY/ALL` 비교 방향, `NOT IN`과 `NULL`, 인라인 뷰와 `ROWNUM` 처리 순서, `MERGE` 구조, 트랜잭션의 `COMMIT/ROLLBACK/SAVEPOINT` 차이이다.
