## 2. Oracle 11g 수업 환경

Oracle은 여러 버전이 있지만, 기본 SQL 문법의 큰 흐름은 같다.  
다만 실무에서 사용하는 버전이나 DBMS에 따라 일부 함수, 자료형, 날짜 처리 방식은 달라질 수 있다.

HR 계정의 기본 테이블을 기준으로 조회 실습을 했다.

```sql
SELECT *
FROM employees;
```

테이블 구조를 확인할 때는 `DESC` 명령어를 사용할 수 있다.

```sql
DESC employees;
```

정리:

- Oracle 11g 기준으로 진행
- HR 계정의 `EMPLOYEES` 테이블을 중심으로 한다.
- 테이블 전체 조회는 `SELECT * FROM 테이블명` 형태로 작성한다.
- 테이블 구조 확인은 `DESC 테이블명`으로 할 수 있다.

## 3. `SELECT` 기본 구조

SQL에서 데이터를 조회할 때는 `SELECT` 문을 사용한다.

기본 구조는 다음과 같다.

```sql
SELECT 컬럼명
FROM 테이블명;
```

예시:

```sql
SELECT employee_id, first_name, salary
FROM employees;
```

모든 컬럼을 조회할 때는 `*`를 사용할 수 있다.

```sql
SELECT *
FROM employees;
```

정리:

- `SELECT`는 조회할 컬럼을 지정한다.
- `FROM`은 조회할 테이블을 지정한다.
- `*`는 모든 컬럼을 의미한다.
- 필요한 컬럼만 명시하는 것이 더 좋다.

## 4. `DUAL` 테이블과 `SYSDATE`

Oracle에서는 실제 테이블이 없어도 값을 조회해야 할 때 `DUAL` 테이블을 사용할 수 있다.

현재 날짜와 시간을 조회할 때는 `SYSDATE`를 사용한다.

```sql
SELECT SYSDATE
FROM dual;
```

별칭을 붙이면 결과 컬럼명을 보기 좋게 만들 수 있다.

```sql
SELECT SYSDATE AS "오늘 날짜"
FROM dual;
```

정리:

- `DUAL`은 Oracle에서 제공하는 더미 테이블이다.
- 계산식, 함수 결과, 현재 날짜 등을 확인할 때 사용할 수 있다.
- `SYSDATE`는 현재 날짜와 시간을 반환한다.

## 5. 의사 컬럼과 `ROWNUM`

`ROWNUM`은 Oracle에서 조회 결과에 순번을 붙일 때 사용할 수 있는 의사 컬럼이다.

의사 컬럼은 실제 테이블에 저장된 컬럼은 아니지만, SQL에서 컬럼처럼 사용할 수 있는 값이다.

```sql
SELECT ROWNUM, employee_id, first_name
FROM employees;
```

상위 몇 개 행만 조회할 때 사용할 수 있다.

```sql
SELECT ROWNUM, employee_id, first_name
FROM employees
WHERE ROWNUM <= 5;
```

정리:

- `ROWNUM`은 실제 테이블 컬럼이 아니다.
- Oracle이 조회 결과에 임시로 붙여주는 의사 컬럼이다.
- `DESC employees`를 해도 `ROWNUM`은 나오지 않는다.
- 단순히 앞에서부터 N개 행을 조회할 때 사용할 수 있다.

---

## 6. `ROWNUM` 사용 시 주의점

`ROWNUM`은 정렬 후에 붙는 값이 아니다.  
조회되는 과정에서 먼저 번호가 붙는다.

따라서 급여가 높은 직원 상위 5명을 조회하려고 아래처럼 작성하면 의도와 다를 수 있다.

```sql
SELECT ROWNUM, employee_id, first_name, salary
FROM employees
WHERE ROWNUM <= 5
ORDER BY salary DESC;
```

위 쿼리는 먼저 5명을 뽑고, 그 5명 안에서 급여를 정렬하는 구조가 될 수 있다.

정렬 후 상위 N개를 조회하려면 서브쿼리를 사용해야 한다.

```sql
SELECT ROWNUM, employee_id, first_name, salary
FROM (
    SELECT employee_id, first_name, salary
    FROM employees
    ORDER BY salary DESC
)
WHERE ROWNUM <= 5;
```

정리:

- `ROWNUM`은 조회 과정에서 먼저 부여된다.
- `ORDER BY` 이후 순위를 매기는 용도로 바로 쓰면 안 된다.
- 정렬 후 상위 N개가 필요하면 서브쿼리로 먼저 정렬해야 한다.

## 7. 무결성 제약조건

데이터베이스에서는 데이터의 정확성과 일관성을 지키기 위해 무결성 제약조건을 사용한다.

오늘 정리한 무결성은 다음과 같다.

```sql
-- 개체 무결성(PK): NOT NULL + UNIQUE
-- ORA-00001: unique constraint (HR.EMP_EMP_ID_PK) violated

-- 참조 무결성(FK)
-- ORA-02291: integrity constraint (HR.EMP_JOB_FK) violated - parent key not found

-- 도메인 무결성(CHECK)
-- ORA-02290: check constraint (HR.EMP_SALARY_MIN) violated

-- 고유 무결성(UNIQUE)
-- ORA-00001: unique constraint (HR.EMP_EMAIL_UK) violated
```

정리:

- 제약조건은 잘못된 데이터가 들어가는 것을 막는다.
- 오류 메시지의 제약조건 이름을 보면 어떤 조건을 위반했는지 추적할 수 있다.

---

## 8. 개체 무결성

개체 무결성은 각 행을 유일하게 식별할 수 있어야 한다는 규칙이다.

보통 `PRIMARY KEY`가 개체 무결성을 담당한다.

```text
PRIMARY KEY = NOT NULL + UNIQUE
```

예를 들어 `EMPLOYEE_ID`가 기본키라면 같은 직원 번호가 두 번 들어갈 수 없다.

```sql
-- 같은 employee_id를 중복으로 넣으면 PK 제약조건 위반
-- ORA-00001 발생 가능
```

정리:

- 개체 무결성은 각 행의 식별 가능성을 보장한다.
- 기본키는 중복될 수 없다.
- 기본키는 `NULL`이 될 수 없다.

---

## 9. 참조 무결성

참조 무결성은 외래키가 부모 테이블에 존재하는 값을 참조해야 한다는 규칙이다.

예를 들어 직원 테이블의 `JOB_ID`가 직무 테이블을 참조한다면, 직무 테이블에 없는 `JOB_ID`는 직원 테이블에 넣을 수 없다.

```sql
-- 부모 테이블에 없는 값을 FK로 넣으면 참조 무결성 위반
-- ORA-02291 발생 가능
```

정리:

- 참조 무결성은 테이블 간 관계를 유지한다.
- 외래키는 부모 테이블의 존재하는 값을 참조해야 한다.
- 없는 부모 키를 참조하면 `parent key not found` 오류가 발생할 수 있다.

---

## 10. 도메인 무결성

도메인 무결성은 컬럼에 들어갈 수 있는 값의 범위를 제한하는 규칙이다.

예를 들어 급여 컬럼에 최소 급여 조건이 있다면, 그 조건보다 작은 값은 저장할 수 없다.

```sql
-- CHECK 조건에 맞지 않는 값을 넣으면 도메인 무결성 위반
-- ORA-02290 발생 가능
```

정리:

- 도메인 무결성은 컬럼 값의 범위를 제한한다.
- `CHECK` 제약조건과 관련이 있다.
- 값의 형식, 범위, 조건을 제한할 수 있다.

---

## 11. 고유 무결성

고유 무결성은 특정 컬럼의 값이 중복되지 않도록 보장하는 규칙이다.

대표적으로 이메일 같은 값에 `UNIQUE` 제약조건을 걸 수 있다.

```sql
-- 같은 email 값을 중복으로 넣으면 UNIQUE 제약조건 위반
-- ORA-00001 발생 가능
```

정리:

- 고유 무결성은 중복 값을 막는다.
- `UNIQUE` 제약조건과 관련이 있다.
- 기본키가 아니더라도 중복되면 안 되는 컬럼에 사용할 수 있다.

## 12. Oracle 메모리 구조

Oracle의 메모리 구조는 크게 SGA와 PGA로 나누어 볼 수 있다.

```text
SGA: 여러 프로세스가 공유하는 메모리 영역
PGA: 개별 프로세스가 사용하는 메모리 영역
```

SGA 안에는 대표적으로 다음 영역이 있다.

```text
Shared Pool
Database Buffer Cache
Redo Log Buffer
```

정리:

- SGA는 공유 메모리 영역이다.
- PGA는 세션 또는 프로세스별 작업 공간이다.
- SQL 실행과 데이터 변경 과정에서 여러 메모리 영역이 사용된다.

---

## 13. Shared Pool

Shared Pool은 SQL 문장과 실행 계획을 관리하는 영역이다.

SQL이 들어오면 Oracle은 SQL을 파싱하고, 실행 가능한 형태로 분석한다.  
이미 같은 SQL이 Shared Pool에 있다면 재사용할 수 있다.

```sql
SELECT *
FROM employees
WHERE employee_id = 100;
```

바인딩 변수를 사용하면 SQL 재사용에 유리하다.

```sql
SELECT *
FROM employees
WHERE employee_id = ?;
```

정리:

- Shared Pool은 SGA 내부 영역이다.
- SQL 파싱 정보와 실행 계획을 저장한다.
- 같은 SQL을 재사용하면 파싱 비용을 줄일 수 있다.
- 바인딩 변수는 SQL 재사용성을 높이는 데 도움이 된다.

---

## 14. Database Buffer Cache

Database Buffer Cache는 데이터 파일에서 읽은 블록을 메모리에 저장하는 영역이다.

디스크에서 매번 데이터를 읽는 것은 비용이 크기 때문에, Oracle은 자주 사용하는 데이터를 메모리에 올려두고 재사용한다.

정리:

- Database Buffer Cache는 SGA 내부 영역이다.
- 데이터 블록을 메모리에 임시 저장한다.
- 디스크 접근을 줄여 조회 성능을 높일 수 있다.

---

## 15. Redo Log Buffer

Redo Log Buffer는 변경 내역을 임시로 저장하는 영역이다.

`INSERT`, `UPDATE`, `DELETE` 같은 변경 작업이 발생하면 변경 내역이 redo 정보로 기록된다.

정리:

- Redo Log Buffer는 SGA 내부 영역이다.
- 데이터 변경 내역을 임시 저장한다.
- 장애 복구와 관련된 중요한 영역이다.

---

## 16. PGA

PGA는 개별 프로세스가 사용하는 작업 공간이다.

정렬, 해시 작업, 세션별 처리에 사용될 수 있다.

정리:

- PGA는 공유 영역이 아니라 개별 프로세스 영역이다.
- 각 세션의 작업 공간으로 볼 수 있다.
- SGA와 PGA의 차이를 구분해야 한다.

## 17. Oracle 자료형

Oracle 자료형엔 문자, 숫자, 날짜 타입이 있다.

### 문자 타입

```sql
VARCHAR2(n)
CLOB
```

`VARCHAR2(n)`은 가변 길이 문자열을 저장한다.  
`CLOB`은 긴 문자열을 저장할 때 사용한다.

### 숫자 타입

```sql
NUMBER
NUMBER(n)
NUMBER(n, m)
```

`NUMBER(n, m)`에서 `n`은 전체 자리 수, `m`은 소수점 이하 자리 수이다.

예를 들어 `NUMBER(5, 2)`는 전체 5자리 중 소수점 이하 2자리를 의미한다.  
따라서 정수부는 3자리까지 가능하다.

### 날짜 타입

```sql
DATE
```

Oracle의 `DATE`는 날짜뿐 아니라 시, 분, 초까지 포함한다.

정리:

- Oracle 문자열 타입은 보통 `VARCHAR2`를 사용한다.
- 긴 문자열은 `CLOB`을 사용할 수 있다.
- 숫자는 `NUMBER` 타입으로 다룬다.
- Oracle의 `DATE`는 날짜와 시간 정보를 포함한다.

## 18. 날짜 출력과 `TO_CHAR`

Oracle의 `DATE`는 시간까지 포함하지만, 화면에 보이는 형식은 설정에 따라 다를 수 있다.

날짜를 원하는 형식으로 출력하려면 `TO_CHAR`를 사용할 수 있다.

```sql
SELECT first_name,
       TO_CHAR(hire_date, 'YYYY-MM-DD HH24:MI:SS') AS hire_date_text
FROM employees;
```

정리:

- Oracle `DATE`는 시, 분, 초까지 포함한다.
- 기본 출력 형식은 NLS 설정에 따라 달라질 수 있다.
- 날짜를 원하는 문자열 형식으로 보고 싶으면 `TO_CHAR`를 사용한다.
- 24시간 표기는 `HH24`를 사용한다.

## 19. 컬럼 별칭

조회 결과의 컬럼명을 바꾸고 싶을 때 별칭을 사용할 수 있다.

```sql
SELECT employee_id AS "사번",
       first_name AS "이름",
       salary AS "급여"
FROM employees;
```

한글 별칭이나 공백, 특수문자가 들어간 별칭은 큰따옴표로 감싸는 것이 안전하다.

```sql
SELECT salary * 12 AS "직원의 연봉"
FROM employees;
```

정리:

- 별칭은 조회 결과 컬럼명을 보기 좋게 바꾼다.
- `AS`를 사용할 수 있다.
- 한글 또는 공백이 포함된 별칭은 큰따옴표를 사용한다.

## 20. 문자열 연결 연산자

Oracle에서는 문자열을 연결할 때 `||` 연산자를 사용할 수 있다.

```sql
SELECT first_name || ' ' || last_name AS "이름"
FROM employees;
```

Oracle에서도 `CONCAT()` 함수를 사용할 수 있지만, 두 개씩만 연결하는 구조라 여러 값을 연결할 때는 중첩해서 사용해야 한다.

```sql
SELECT CONCAT(CONCAT(first_name, ' '), last_name) AS "함수이용"
FROM employees;
```

정리:

- Oracle 문자열 연결은 `||`를 주로 사용한다.
- `CONCAT()`도 가능하지만 여러 값을 연결할 때는 중첩이 필요하다.
- MySQL에서는 `CONCAT(a, b)` 형식을 자주 사용한다.

## 21. 산술 연산과 `NVL`

급여, 연봉, 세금처럼 숫자 컬럼을 이용해 계산할 수 있다.

```sql
SELECT employee_id,
       salary,
       salary * 12 AS "연봉",
       salary * 12 * 0.1 AS "세금"
FROM employees;
```

커미션처럼 `NULL`이 들어갈 수 있는 컬럼은 계산 시 주의해야 한다.

```sql
SELECT employee_id,
       salary,
       commission_pct,
       salary + (salary * NVL(commission_pct, 0)) AS "커미션 포함 급여"
FROM employees;
```

`NVL(commission_pct, 0)`은 `commission_pct`가 `NULL`이면 0으로 바꿔 계산한다.

정리:

- 숫자 컬럼은 산술 연산에 사용할 수 있다.
- `NULL`이 포함된 산술 연산 결과는 `NULL`이 될 수 있다.
- Oracle에서는 `NVL(컬럼, 대체값)`으로 `NULL`을 대체할 수 있다.

## 22. `DISTINCT`

`DISTINCT`는 중복된 조회 결과를 제거할 때 사용한다.

```sql
SELECT DISTINCT department_id
FROM employees;
```

여러 컬럼을 함께 조회하면, 각 컬럼 하나만 기준으로 중복을 제거하는 것이 아니라 조회된 컬럼 조합 전체를 기준으로 중복을 제거한다.

```sql
SELECT DISTINCT department_id, job_id
FROM employees;
```

정리:

- `DISTINCT`는 중복 행을 제거한다.
- 여러 컬럼을 조회하면 컬럼 조합 전체가 중복 판단 기준이 된다.

## 23. `NULL` 특징

`NULL`은 값이 없거나 알 수 없다는 의미이다.

따라서 `=` 연산자로 비교하지 않는다.

```sql
-- 잘못된 방식
SELECT *
FROM employees
WHERE commission_pct = NULL;
```

`NULL` 여부를 확인하려면 `IS NULL` 또는 `IS NOT NULL`을 사용해야 한다.

```sql
SELECT *
FROM employees
WHERE commission_pct IS NULL;
```

```sql
SELECT *
FROM employees
WHERE commission_pct IS NOT NULL;
```

정리:

- `NULL`은 특정 값이 아니다.
- `NULL`은 `=` 또는 `<>`로 비교하지 않는다.
- `IS NULL`, `IS NOT NULL`을 사용한다.
- `NULL`이 포함된 계산과 조건식은 결과가 예상과 다를 수 있다.

## 24. `ORDER BY`와 `NULL` 정렬

조회 결과를 정렬할 때는 `ORDER BY`를 사용한다.

```sql
SELECT employee_id, first_name, salary
FROM employees
ORDER BY salary DESC;
```

`NULL`이 포함된 컬럼을 정렬할 때는 `NULLS FIRST`, `NULLS LAST`를 사용할 수 있다.

```sql
SELECT employee_id, first_name, salary, commission_pct
FROM employees
ORDER BY commission_pct NULLS FIRST;
```

```sql
SELECT employee_id, first_name, salary, commission_pct
FROM employees
ORDER BY commission_pct NULLS LAST;
```

정리:

- `ORDER BY`는 조회 결과를 정렬한다.
- `ASC`는 오름차순, `DESC`는 내림차순이다.
- `NULLS FIRST`는 `NULL`을 앞에 둔다.
- `NULLS LAST`는 `NULL`을 뒤에 둔다.
- `NULL` 정렬 위치는 직접 명시하는 것이 가장 명확하다.

## 25. `WHERE` 조건 검색

조건에 맞는 행만 조회하려면 `WHERE`절을 사용한다.

```sql
SELECT employee_id, first_name, salary
FROM employees
WHERE salary >= 10000;
```

비교 연산자는 다음과 같다.

| 연산자 | 의미        |
| ------ | ----------- |
| `=`    | 같다        |
| `<>`   | 다르다      |
| `>`    | 크다        |
| `>=`   | 크거나 같다 |
| `<`    | 작다        |
| `<=`   | 작거나 같다 |

숫자 컬럼을 비교할 때는 숫자를 문자열로 쓰지 않는 것이 좋다.

```sql
-- 권장하지 않음
WHERE salary >= '10000'

-- 권장
WHERE salary >= 10000
```

정리:

- `WHERE`는 조건에 맞는 행만 조회한다.
- 숫자 컬럼은 숫자 값으로 비교하는 것이 좋다.
- Oracle이 암묵 변환을 해줄 수는 있지만, 학습 기록에는 명확하게 작성하는 편이 좋다.

## 26. `BETWEEN`

`BETWEEN A AND B`는 A 이상 B 이하를 의미한다.

```sql
SELECT *
FROM employees
WHERE salary BETWEEN 8000 AND 15000;
```

같은 조건은 비교 연산자로도 작성할 수 있다.

```sql
SELECT *
FROM employees
WHERE salary >= 8000
  AND salary <= 15000;
```

정리:

- `BETWEEN A AND B`는 A와 B를 포함한다.
- 숫자 범위 조건을 표현할 때 사용할 수 있다.
- 비교 연산자로 풀어 쓰면 의미를 더 명확히 확인할 수 있다.

---

## 27. 날짜 조건 검색

Oracle의 `DATE`는 시간까지 포함한다.

입사일 조건을 조회할 때는 날짜 리터럴을 사용할 수 있다.

```sql
SELECT employee_id, first_name, hire_date
FROM employees
WHERE hire_date >= DATE '2000-01-01';
```

특정 기간을 조회할 때는 다음처럼 작성할 수 있다.

```sql
SELECT employee_id, first_name, hire_date
FROM employees
WHERE hire_date >= DATE '2000-01-01'
  AND hire_date < DATE '2004-01-01';
```

정리:

- Oracle의 `DATE`는 날짜와 시간 정보를 포함한다.
- `DATE 'YYYY-MM-DD'` 형식으로 날짜 리터럴을 사용할 수 있다.
- 기간 조건은 `>= 시작일`과 `< 다음날 또는 다음기간 시작일` 형태가 안전하다.

## 28. `IN`

`IN`은 여러 값 중 하나에 해당하는 데이터를 조회할 때 사용한다.

```sql
SELECT *
FROM employees
WHERE department_id IN (20, 50, 80);
```

같은 조건은 `OR`로도 작성할 수 있다.

```sql
SELECT *
FROM employees
WHERE department_id = 20
   OR department_id = 50
   OR department_id = 80;
```

정리:

- `IN`은 여러 값 중 하나와 일치하는지 확인한다.
- `OR` 조건을 간단하게 표현할 수 있다.
- 값 목록이 명확할 때 사용하기 좋다.

---

## 29. `NOT IN`과 `NULL`

`NOT IN` 조건에 `NULL`이 들어가면 결과가 예상과 다르게 나올 수 있다.

```sql
SELECT *
FROM employees
WHERE department_id NOT IN (10, NULL);
```

위 조건은 내부적으로 다음과 비슷하게 해석될 수 있다.

```text
department_id <> 10
AND department_id <> NULL
```

그런데 `NULL`과의 비교는 참이나 거짓이 아니라 UNKNOWN이 된다.  
그래서 결과가 나오지 않을 수 있다.

정리:

- `NOT IN` 목록에 `NULL`이 들어가면 주의해야 한다.
- `NULL` 비교는 `=` 또는 `<>`로 처리되지 않는다.
- `NOT IN`을 사용할 때는 비교 목록에서 `NULL`을 제거하는 것이 안전하다.
- 필요하면 `IS NOT NULL` 조건을 별도로 사용한다.

---

## 30. `LIKE`

문자열 패턴 검색에는 `LIKE`를 사용한다.

```sql
SELECT *
FROM employees
WHERE first_name LIKE 'S%';
```

패턴 의미는 다음과 같다.

| 패턴     | 의미                            |
| -------- | ------------------------------- |
| `'S%'`   | S로 시작하는 값                 |
| `'%a%'`  | 문자열 중간에 a가 포함된 값     |
| `'_ING'` | 앞 한 글자 + ING로 끝나는 4글자 |
| `'A___'` | A로 시작하는 4글자              |

예시:

```sql
SELECT *
FROM employees
WHERE first_name LIKE '%a%';
```

정리:

- `%`는 0개 이상의 문자를 의미한다.
- `_`는 한 글자를 의미한다.
- 문자열 검색 조건에 자주 사용된다.

---

## 31. `ESCAPE`

`LIKE`에서 `%`나 `_`는 와일드카드로 해석된다.

따라서 `%` 문자 자체를 검색하려면 `ESCAPE`를 사용할 수 있다.

```sql
SELECT *
FROM employees
WHERE job_id LIKE 'IT\_%' ESCAPE '\';
```

위 쿼리는 `IT_`로 시작하는 `JOB_ID`를 찾는 조건이다.

정리:

- `%`와 `_`는 `LIKE`에서 특수한 의미를 가진다.
- 문자 자체로 검색하려면 `ESCAPE`를 사용한다.
- `LIKE 'IT\_%' ESCAPE '\'`는 `IT_`를 실제 문자로 본다.

## 32. 논리 연산자 우선순위

조건식에서는 연산자 우선순위를 조심해야 한다.

우선순위는 대략 다음 순서로 볼 수 있다.

```text
괄호
산술 연산
비교 연산
BETWEEN, IN, LIKE, IS NULL
NOT
AND
OR
```

`AND`가 `OR`보다 먼저 처리된다.

아래처럼 작성하면 의도와 다르게 해석될 수 있다.

```sql
WHERE department_id IN (60, 80, 100)
  AND salary BETWEEN 5000 AND 15000
  AND job_id LIKE 'IT\_%' ESCAPE '\'
   OR job_id LIKE 'SA\_%' ESCAPE '\'
```

의도한 조건이 `IT_` 또는 `SA_`라면 괄호로 묶어야 한다.

```sql
SELECT employee_id AS "사번",
       first_name || ' ' || last_name AS "이름",
       job_id AS "직무 ID",
       salary AS "급여",
       commission_pct AS "커미션",
       salary * 12 AS "연봉",
       department_id AS "부서번호"
FROM employees
WHERE department_id IN (60, 80, 100)
  AND salary BETWEEN 5000 AND 15000
  AND (
        job_id LIKE 'IT\_%' ESCAPE '\'
        OR job_id LIKE 'SA\_%' ESCAPE '\'
      )
  AND commission_pct IS NOT NULL
ORDER BY "연봉" DESC;
```

정리:

- `AND`는 `OR`보다 우선순위가 높다.
- 복합 조건에서는 괄호를 명시하는 것이 안전하다.
- 조건이 많을수록 의도한 범위를 괄호로 분리해야 한다.

## 34. 다시 볼 부분

- `DISTINCT`는 조회한 컬럼 조합 전체를 기준으로 중복을 제거한다.

- `LIKE`에서 `%`는 여러 글자, `_`는 한 글자를 의미한다.
- `%`나 `_` 자체를 검색하려면 `ESCAPE`가 필요하다.
- `AND`가 `OR`보다 먼저 처리된다.
- 복합 조건에서는 괄호를 명확히 써야 한다.

## 35. 수업 진행 중 생겼던 의문

### `ROWNUM`은 실제 컬럼인가?

처음에는 `ROWNUM`이 테이블에 있는 컬럼처럼 느껴졌다.

하지만 `ROWNUM`은 실제 저장된 컬럼이 아니라 Oracle이 조회 결과에 임시로 붙이는 의사 컬럼이다.

그래서 테이블 구조를 확인하는 `DESC employees` 결과에는 `ROWNUM`이 나오지 않는다.

```sql
DESC employees;
```

하지만 조회할 때는 컬럼처럼 사용할 수 있다.

```sql
SELECT ROWNUM, employee_id, first_name
FROM employees;
```

정리하면 `ROWNUM`은 저장된 데이터가 아니라 조회 과정에서 만들어지는 값으로 봐야 한다.

---

### `ROWNUM`으로 급여 상위 5명을 바로 구할 수 있을까?

단순히 아래처럼 작성하면 의도와 다를 수 있다.

```sql
SELECT ROWNUM, employee_id, first_name, salary
FROM employees
WHERE ROWNUM <= 5
ORDER BY salary DESC;
```

이 쿼리는 급여 기준으로 먼저 정렬한 뒤 5명을 뽑는 것이 아니라, 먼저 일부 행을 뽑고 그 결과를 정렬하는 식으로 동작할 수 있다.

그래서 정렬 후 상위 5명을 구하려면 서브쿼리를 사용해야 한다.

```sql
SELECT ROWNUM, employee_id, first_name, salary
FROM (
    SELECT employee_id, first_name, salary
    FROM employees
    ORDER BY salary DESC
)
WHERE ROWNUM <= 5;
```

즉, `ROWNUM`은 처리 순서를 같이 생각해야 한다.

---

### `NULL`은 왜 `=`로 비교하지 않을까?

`NULL`은 값이 없거나 알 수 없다는 의미이다.

그래서 아래 조건은 원하는 결과를 보장하지 않는다.

```sql
WHERE commission_pct = NULL
```

`NULL` 여부를 확인하려면 다음처럼 작성해야 한다.

```sql
WHERE commission_pct IS NULL
```

반대로 `NULL`이 아닌 값을 찾으려면 다음처럼 작성한다.

```sql
WHERE commission_pct IS NOT NULL
```

정리하면 `NULL`은 일반 값처럼 비교하지 않고, 전용 연산자인 `IS NULL`, `IS NOT NULL`로 확인해야 한다.

---

### `NOT IN`에 `NULL`이 있으면 왜 결과가 안 나올까?

아래 쿼리는 직관적으로는 10번 부서가 아닌 직원을 찾는 것처럼 보인다.

```sql
SELECT *
FROM employees
WHERE department_id NOT IN (10, NULL);
```

하지만 `NULL`이 포함되면 조건식이 예상과 다르게 처리된다.

```text
department_id <> 10
AND department_id <> NULL
```

`department_id <> NULL`은 참이나 거짓이 아니라 UNKNOWN이 된다.  
그래서 전체 조건이 원하는 대로 참이 되지 않을 수 있다.

정리하면 `NOT IN` 목록에는 `NULL`이 들어가지 않도록 주의해야 한다.

---

### `AND`와 `OR`를 같이 쓰면 왜 괄호가 필요할까?

SQL에서는 `AND`가 `OR`보다 먼저 처리된다.

그래서 아래 조건은 사람이 읽은 의도와 다르게 해석될 수 있다.

```sql
WHERE department_id IN (60, 80, 100)
  AND salary BETWEEN 5000 AND 15000
  AND job_id LIKE 'IT\_%' ESCAPE '\'
   OR job_id LIKE 'SA\_%' ESCAPE '\'
```

의도한 조건이 `IT_` 또는 `SA_` 직무라면 다음처럼 괄호를 사용해야 한다.

```sql
WHERE department_id IN (60, 80, 100)
  AND salary BETWEEN 5000 AND 15000
  AND (
        job_id LIKE 'IT\_%' ESCAPE '\'
        OR job_id LIKE 'SA\_%' ESCAPE '\'
      )
```

조건이 많아질수록 괄호를 생략하면 결과가 크게 달라질 수 있다.

---

### Oracle의 `DATE`는 날짜만 저장할까?

Oracle의 `DATE`는 날짜만 저장하는 타입이 아니다.  
시, 분, 초까지 포함한다.

다만 화면에 보이는 형식은 설정에 따라 날짜만 보일 수 있다.

날짜와 시간을 명확히 보고 싶으면 `TO_CHAR`를 사용할 수 있다.

```sql
SELECT first_name,
       TO_CHAR(hire_date, 'YYYY-MM-DD HH24:MI:SS') AS hire_date_text
FROM employees;
```

정리하면 Oracle의 `DATE`는 날짜와 시간을 모두 가진 타입으로 봐야 한다.

## 정리

Oracle 첫 수업에서는 기본 조회 문법과 데이터베이스 기초 개념을 정리했다.

SQL 문법에서는 `SELECT`, `FROM`, `WHERE`, `ORDER BY`를 중심으로 데이터를 조회하는 방법을 실습했다.  
또한 `DISTINCT`, `NVL`, 문자열 연결 연산자 `||`, `LIKE`, `BETWEEN`, `IN` 같은 기본 문법을 확인했다.

데이터베이스 개념에서는 개체 무결성, 참조 무결성, 도메인 무결성, 고유 무결성을 정리했다.  
각 제약조건은 잘못된 데이터가 테이블에 들어가는 것을 막기 위한 규칙으로 볼 수 있다.

Oracle 구조에서는 SGA와 PGA를 구분했고, SGA 내부의 Shared Pool, Database Buffer Cache, Redo Log Buffer 역할을 확인했다.  
아직 깊게 다루지는 않았지만, SQL이 실행될 때 단순히 문장만 실행되는 것이 아니라 파싱, 캐시, 로그 기록 같은 내부 과정이 있다는 점을 알 수 있었다.

오늘 가장 다시 봐야 할 부분은 `NULL`, `ROWNUM`, `NOT IN`, `AND/OR 우선순위`, `DATE` 타입이다.  
이 부분들은 문법 자체는 짧지만 결과가 예상과 다르게 나올 수 있어서 따로 복습이 필요하다.
