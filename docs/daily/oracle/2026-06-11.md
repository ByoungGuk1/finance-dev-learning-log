## 2. DDL

DDL은 데이터베이스 객체의 구조를 정의하거나 변경하는 명령어이다.

대표적으로 테이블을 만들거나, 컬럼을 추가하거나, 테이블을 삭제할 때 사용한다.

```sql
CREATE TABLE accounts (
    account_id NUMBER(10),
    account_no CHAR(14),
    customer_name VARCHAR2(50),
    balance NUMBER(18, 2)
);
```

정리:

- DDL은 테이블이나 객체의 구조를 다룬다.
- `CREATE`, `ALTER`, `DROP`, `TRUNCATE` 등이 있다.
- DML이 데이터를 변경하는 명령어라면, DDL은 구조를 변경하는 명령어이다.
- Oracle에서는 DDL 실행 시 자동 `COMMIT`이 발생한다.

---

## 3. `CREATE TABLE`

`CREATE TABLE`은 새 테이블을 만들 때 사용한다.

```sql
CREATE TABLE accounts (
    account_id NUMBER(10) NOT NULL,
    account_no CHAR(14) NOT NULL,
    customer_name VARCHAR2(50) NOT NULL,
    account_type VARCHAR2(10) DEFAULT 'SAVINGS',
    balance NUMBER(18, 2) DEFAULT 0,
    open_date DATE DEFAULT SYSDATE,
    status CHAR(1) DEFAULT 'A',
    created_at TIMESTAMP DEFAULT SYSTIMESTAMP
);
```

컬럼을 만들 때는 자료형과 기본값, 필수 입력 여부를 같이 지정할 수 있다.

정리:

- `NUMBER`는 숫자 타입이다.
- `CHAR`는 고정 길이 문자열이다.
- `VARCHAR2`는 가변 길이 문자열이다.
- `DATE`는 날짜와 시간을 저장한다.
- `TIMESTAMP`는 더 정밀한 시간 정보를 저장한다.
- `DEFAULT`는 값을 넣지 않았을 때 사용할 기본값이다.
- `NOT NULL`은 반드시 값이 들어가야 한다는 의미이다.

## 4. 제약조건

제약조건은 잘못된 데이터가 들어가지 않도록 막는 규칙이다.

테이블을 만들 때 같이 작성할 수도 있고, 나중에 `ALTER TABLE`로 추가할 수도 있다.

```sql
CREATE TABLE accounts (
    account_id NUMBER(10) NOT NULL,
    account_no CHAR(14) NOT NULL,
    customer_name VARCHAR2(50) NOT NULL,
    account_type VARCHAR2(10) DEFAULT 'SAVINGS',
    balance NUMBER(18, 2) DEFAULT 0,
    status CHAR(1) DEFAULT 'A',
    CONSTRAINT pk_accounts PRIMARY KEY (account_id),
    CONSTRAINT uq_account_no UNIQUE (account_no),
    CONSTRAINT ck_balance CHECK (balance >= 0),
    CONSTRAINT ck_status CHECK (status IN ('A', 'C', 'F')),
    CONSTRAINT ck_type CHECK (account_type IN ('SAVINGS', 'CHECKING', 'LOAN'))
);
```

정리:

| 제약조건      | 의미                      |
| ------------- | ------------------------- |
| `PRIMARY KEY` | 행을 유일하게 식별        |
| `FOREIGN KEY` | 다른 테이블의 값을 참조   |
| `UNIQUE`      | 중복 값 방지              |
| `CHECK`       | 지정한 조건을 만족해야 함 |
| `NOT NULL`    | NULL 허용 안 함           |

---

## 5. `PRIMARY KEY`

`PRIMARY KEY`는 테이블의 각 행을 유일하게 구분하기 위한 제약조건이다.

```sql
CONSTRAINT pk_accounts PRIMARY KEY (account_id)
```

정리:

- 기본키는 중복될 수 없다.
- 기본키는 `NULL`이 될 수 없다.
- 한 테이블에는 기본키를 하나만 만들 수 있다.
- 기본키를 만들면 인덱스도 자동으로 생성된다.

---

## 6. `UNIQUE`

`UNIQUE`는 특정 컬럼의 중복을 막는 제약조건이다.

```sql
CONSTRAINT uq_account_no UNIQUE (account_no)
```

계좌번호처럼 중복되면 안 되는 값에 사용할 수 있다.

정리:

- `UNIQUE`는 중복 값을 막는다.
- 기본키와 달리 `NULL`은 허용될 수 있다.
- 하나의 테이블에 여러 개 만들 수 있다.
- `UNIQUE` 제약조건을 만들면 인덱스가 자동으로 생성된다.

---

## 7. `CHECK`

`CHECK`는 컬럼에 들어갈 수 있는 값의 범위를 제한한다.

```sql
CONSTRAINT ck_balance CHECK (balance >= 0)
```

```sql
CONSTRAINT ck_type CHECK (account_type IN ('SAVINGS', 'CHECKING', 'LOAN'))
```

정리:

- `CHECK`는 값의 범위나 목록을 제한한다.
- 잔액이 음수가 되면 안 되는 경우 사용할 수 있다.
- 계좌 상태나 계좌 유형처럼 정해진 값만 허용할 때도 사용할 수 있다.

---

## 8. `FOREIGN KEY`

`FOREIGN KEY`는 다른 테이블의 값을 참조하는 제약조건이다.

```sql
CREATE TABLE transactions (
    txn_id NUMBER(10),
    account_id NUMBER(10),
    amount NUMBER(18, 2),
    CONSTRAINT pk_transactions PRIMARY KEY (txn_id),
    CONSTRAINT fk_txn_account FOREIGN KEY (account_id)
        REFERENCES accounts(account_id)
);
```

정리:

- 외래키는 참조 무결성을 지키기 위해 사용한다.
- 부모 테이블에 없는 값을 자식 테이블에 넣을 수 없다.
- 부모 데이터 삭제 시 자식 데이터가 있으면 삭제가 막힐 수 있다.
- `ON DELETE CASCADE`, `ON DELETE SET NULL` 같은 옵션도 있다.

---

## 9. `CREATE TABLE AS SELECT`

기존 테이블을 이용해서 새 테이블을 만들 수 있다.

```sql
CREATE TABLE emp_backup AS
SELECT *
FROM employees;
```

데이터 없이 구조만 복사하려면 항상 거짓인 조건을 사용한다.

```sql
CREATE TABLE emp_empty AS
SELECT *
FROM employees
WHERE 1 = 0;
```

정리:

- `CREATE TABLE AS SELECT`는 조회 결과를 이용해 새 테이블을 만든다.
- 구조와 데이터를 함께 복사할 수 있다.
- `WHERE 1 = 0`을 쓰면 구조만 복사된다.
- 기본키, 외래키 같은 제약조건은 그대로 복사되지 않을 수 있다.

---

## 10. `ALTER TABLE`

`ALTER TABLE`은 기존 테이블 구조를 변경할 때 사용한다.

컬럼 추가:

```sql
ALTER TABLE accounts ADD memo VARCHAR2(200);
```

컬럼 수정:

```sql
ALTER TABLE accounts MODIFY customer_name VARCHAR2(100);
```

컬럼 삭제:

```sql
ALTER TABLE accounts DROP COLUMN memo;
```

컬럼명 변경:

```sql
ALTER TABLE accounts RENAME COLUMN account_no TO acct_number;
```

정리:

- `ADD`는 컬럼 추가이다.
- `MODIFY`는 컬럼 타입, 크기, 기본값 등을 변경한다.
- `DROP COLUMN`은 컬럼 삭제이다.
- `RENAME COLUMN`은 컬럼명을 변경한다.
- 기존 데이터가 있는 컬럼을 수정할 때는 데이터 손상 여부를 먼저 생각해야 한다.

---

## 11. `DROP`과 `TRUNCATE`

`DROP TABLE`은 테이블 자체를 삭제한다.

```sql
DROP TABLE emp_backup;
```

`TRUNCATE`는 테이블 구조는 유지하고 데이터만 전체 삭제한다.

```sql
TRUNCATE TABLE accounts;
```

정리:

| 구분     | DROP            | TRUNCATE        |
| -------- | --------------- | --------------- |
| 구조     | 삭제됨          | 유지됨          |
| 데이터   | 삭제됨          | 삭제됨          |
| ROLLBACK | 일반적으로 불가 | 일반적으로 불가 |
| 용도     | 객체 삭제       | 데이터 초기화   |

DDL은 자동 `COMMIT`이 발생하므로 실행 전에 조심해야 한다.

---

## 12. `COMMENT`

`COMMENT`는 테이블이나 컬럼에 설명을 남길 때 사용한다.

```sql
COMMENT ON TABLE accounts IS '금융 계좌 마스터 테이블';

COMMENT ON COLUMN accounts.account_type
IS '계좌유형: SAVINGS, CHECKING, LOAN';
```

주석은 데이터 사전에서 확인할 수 있다.

```sql
SELECT table_name, comments
FROM user_tab_comments
WHERE table_name = 'ACCOUNTS';
```

```sql
SELECT column_name, comments
FROM user_col_comments
WHERE table_name = 'ACCOUNTS';
```

정리:

- `COMMENT`는 테이블이나 컬럼 설명을 남긴다.
- 컬럼 의미를 문서처럼 DB 안에 기록할 수 있다.
- 협업이나 유지보수에서 도움이 된다.

## 13. INDEX

인덱스는 조회 속도를 높이기 위해 사용하는 객체이다.

```sql
CREATE INDEX idx_emp_dept
ON employees(department_id);
```

인덱스는 직접 만들 수도 있고, 제약조건에 의해 자동으로 만들어질 수도 있다.

정리:

- `PRIMARY KEY`, `UNIQUE` 제약조건 생성 시 인덱스가 자동 생성된다.
- 자주 `WHERE`, `JOIN`, `ORDER BY`에 사용되는 컬럼은 인덱스 후보가 될 수 있다.
- 인덱스는 조회 성능을 높일 수 있다.
- 하지만 항상 빠른 것은 아니다.

---

## 14. 인덱스가 항상 빠른 것은 아니다

인덱스는 데이터를 빠르게 찾는 데 도움이 되지만, 모든 상황에서 좋은 것은 아니다.

예를 들어 많은 행을 조회해야 한다면 인덱스를 타고 여러 번 접근하는 것보다 전체 테이블을 읽는 것이 더 빠를 수 있다.

```sql
SELECT *
FROM employees
WHERE salary BETWEEN 10000 AND 20000;
```

정리:

- 반환 행이 많으면 Full Table Scan이 더 유리할 수 있다.
- 테이블이 작으면 인덱스 효과가 크지 않을 수 있다.
- `INSERT`, `UPDATE`, `DELETE`가 발생하면 인덱스도 같이 갱신된다.
- 인덱스가 많으면 DML 비용이 커질 수 있다.
- Oracle 옵티마이저가 통계 정보를 기준으로 실행 계획을 선택한다.

---

## 15. 인덱스 종류

인덱스 종류는 여러 가지가 있다.

| 인덱스 종류          | 설명                                  |
| -------------------- | ------------------------------------- |
| B-Tree Index         | 가장 일반적인 인덱스                  |
| Unique Index         | 중복을 허용하지 않는 인덱스           |
| 복합 Index           | 여러 컬럼을 묶은 인덱스               |
| Function-based Index | 함수 적용 결과를 기준으로 만든 인덱스 |

예시:

```sql
CREATE INDEX idx_salary
ON employees(salary);
```

```sql
CREATE INDEX idx_dept_sal
ON employees(department_id, salary);
```

```sql
CREATE INDEX idx_upper_last_name
ON employees(UPPER(last_name));
```

정리:

- B-Tree 인덱스는 가장 일반적인 형태이다.
- 복합 인덱스는 컬럼 순서가 중요하다.
- 함수 기반 인덱스는 `UPPER(last_name)`처럼 함수가 적용된 검색에 사용할 수 있다.

## 16. 실행 계획

인덱스를 사용하는지 확인하려면 실행 계획을 볼 수 있다.

```sql
EXPLAIN PLAN FOR
SELECT *
FROM employees
WHERE department_id = 50;
```

```sql
SELECT *
FROM TABLE(DBMS_XPLAN.DISPLAY);
```

힌트를 사용해서 옵티마이저에게 특정 인덱스 사용을 유도할 수도 있다.

```sql
EXPLAIN PLAN FOR
SELECT /*+ INDEX(emp_test idx_emptest_job) */ *
FROM emp_test
WHERE job_id = 'IT_PROG';
```

정리:

- 실행 계획은 SQL이 어떻게 실행될지 보여준다.
- 인덱스 사용 여부를 확인할 수 있다.
- 힌트는 옵티마이저에게 실행 방향을 제안하는 문법이다.
- 힌트를 써도 상황에 따라 그대로 반영되지 않을 수 있다.

## 17. SEQUENCE

시퀀스는 자동 번호를 생성하는 객체이다.

```sql
CREATE SEQUENCE seq_number
START WITH 1
INCREMENT BY 1;
```

다음 값을 가져올 때는 `NEXTVAL`을 사용한다.

```sql
SELECT seq_number.NEXTVAL
FROM dual;
```

현재 값을 확인할 때는 `CURRVAL`을 사용한다.

```sql
SELECT seq_number.CURRVAL
FROM dual;
```

정리:

- 시퀀스는 자동 증가 번호를 만들 때 사용한다.
- `NEXTVAL`은 다음 번호를 가져온다.
- `CURRVAL`은 현재 세션에서 마지막으로 가져온 번호를 확인한다.
- `CURRVAL`은 `NEXTVAL`을 먼저 실행한 뒤 사용할 수 있다.
- 기본키 값을 자동으로 넣을 때 자주 사용한다.

## 18. VIEW

뷰는 `SELECT` 문을 저장한 논리적 객체이다.

```sql
CREATE VIEW vw_emp_dept AS
SELECT e.employee_id,
       e.first_name,
       d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id;
```

조회할 때는 테이블처럼 사용할 수 있다.

```sql
SELECT *
FROM vw_emp_dept;
```

정리:

- 뷰는 실제 데이터를 직접 저장하는 일반 테이블은 아니다.
- 저장된 `SELECT` 문을 테이블처럼 조회할 수 있게 한다.
- 복잡한 SQL을 단순하게 사용할 수 있다.
- 특정 컬럼만 공개해서 보안 목적으로 사용할 수 있다.
- `WITH READ ONLY`를 사용하면 조회 전용 뷰로 만들 수 있다.

---

## 19. SYNONYM

시노님은 다른 객체에 대한 별칭이다.

```sql
CREATE SYNONYM emp
FOR hr.employees;
```

이후에는 아래처럼 조회할 수 있다.

```sql
SELECT *
FROM emp;
```

정리:

- 시노님은 테이블, 뷰, 시퀀스 등에 붙이는 별칭이다.
- 긴 객체명을 짧게 줄일 수 있다.
- 다른 스키마 객체를 편하게 접근할 때 사용할 수 있다.
- Private Synonym은 생성한 사용자만 사용할 수 있다.
- Public Synonym은 모든 사용자가 사용할 수 있으며 DBA 권한이 필요하다.
- 대표적인 예시는 `DUAL`이다.

## 20. 사용자 생성

Oracle에서는 계정을 만들어 DB에 접속할 수 있게 한다.

```sql
CREATE USER db_student
IDENTIFIED BY student123
DEFAULT TABLESPACE users
TEMPORARY TABLESPACE temp
QUOTA UNLIMITED ON users;
```

사용자 생성만으로는 접속할 수 없다.
접속 권한을 따로 부여해야 한다.

```sql
GRANT CREATE SESSION TO db_student;
```

정리:

- 사용자는 DB에 접속하는 계정이다.
- `CREATE USER`로 계정을 만든다.
- `CREATE SESSION` 권한이 있어야 접속할 수 있다.
- 테이블을 만들려면 `CREATE TABLE` 권한도 필요하다.
- `QUOTA`는 테이블스페이스 사용 가능 용량이다.

---

## 21. 권한

Oracle 권한은 크게 시스템 권한과 객체 권한으로 나눌 수 있다.

### 시스템 권한

DB 전체 수준에서 어떤 작업을 할 수 있는 권한이다.

```sql
GRANT CREATE SESSION TO db_student;
GRANT CREATE TABLE TO db_student;
GRANT CREATE VIEW TO db_student;
GRANT CREATE SEQUENCE TO db_student;
```

### 객체 권한

특정 테이블이나 뷰 같은 객체에 대한 권한이다.

```sql
GRANT SELECT ON hr.employees TO db_student;
```

권한 회수는 `REVOKE`를 사용한다.

```sql
REVOKE SELECT ON hr.employees FROM db_student;
```

정리:

- 시스템 권한은 DB 작업 자체에 대한 권한이다.
- 객체 권한은 특정 객체에 대한 권한이다.
- `GRANT`는 권한 부여이다.
- `REVOKE`는 권한 회수이다.

---

## 22. ROLE

롤은 여러 권한을 묶어둔 권한 그룹이다.

```sql
CREATE ROLE role_fin_read;
```

롤에 권한을 부여한다.

```sql
GRANT SELECT ON accounts TO role_fin_read;
```

사용자에게 롤을 부여한다.

```sql
GRANT role_fin_read TO db_student;
```

정리:

- 롤은 권한 묶음이다.
- 사용자마다 권한을 하나씩 주는 것보다 관리하기 쉽다.
- 읽기 전용, 쓰기 가능, 관리자 권한처럼 역할별로 나눌 수 있다.
- 실무에서는 최소 권한 원칙을 지키는 것이 중요하다.

## 24. 다시 볼 부분

- DDL은 실행 시 자동 `COMMIT`이 발생한다.
- `DROP`과 `TRUNCATE`는 일반적인 `ROLLBACK`으로 되돌릴 수 없다.
- `CREATE TABLE AS SELECT`는 제약조건까지 그대로 복사하지 않을 수 있다.
- `ALTER TABLE MODIFY`로 컬럼 크기를 줄일 때는 기존 데이터를 확인해야 한다.
- `PRIMARY KEY`는 `NOT NULL`과 `UNIQUE` 성격을 가진다.
- `UNIQUE`는 중복을 막지만 `NULL`은 허용될 수 있다.
- 외래키는 부모 테이블에 존재하는 값을 참조해야 한다.
- `ON DELETE CASCADE`는 부모 삭제 시 자식 데이터도 삭제되므로 주의해야 한다.
- 인덱스는 조회를 빠르게 할 수 있지만 항상 좋은 것은 아니다.
- DML이 많은 테이블은 인덱스 유지 비용이 발생한다.
- 옵티마이저가 통계 정보를 기준으로 인덱스 사용 여부를 결정한다.
- 시퀀스의 `CURRVAL`은 `NEXTVAL` 실행 후 사용할 수 있다.
- 뷰는 저장된 `SELECT` 문이다.
- 시노님은 다른 객체에 대한 별칭이다.
- 시스템 권한과 객체 권한을 구분해야 한다.
- 롤은 여러 권한을 묶어서 관리하는 객체이다.

## 25. 수업 진행 중 생겼던 의문

### DDL은 왜 ROLLBACK이 안 될까?

DDL은 테이블이나 인덱스 같은 객체 구조를 바꾸는 명령어이다.

Oracle에서는 DDL 실행 시 자동 `COMMIT`이 발생한다.
그래서 DDL 실행 전의 미완료 DML도 같이 확정될 수 있다.

즉, `CREATE TABLE`, `DROP TABLE`, `TRUNCATE` 같은 명령어는 실행 전에 신중하게 확인해야 한다.

---

### 인덱스는 왜 항상 빠르지 않을까?

인덱스는 원하는 데이터를 빠르게 찾게 도와준다.

하지만 조회해야 하는 행이 많으면 인덱스를 타고 여러 번 접근하는 것보다 테이블 전체를 읽는 것이 더 빠를 수 있다.

또한 `INSERT`, `UPDATE`, `DELETE`가 발생하면 인덱스도 함께 수정되어야 한다.

그래서 인덱스는 조회 성능에는 도움이 될 수 있지만, 쓰기 작업에는 비용이 생길 수 있다.

---

### `PRIMARY KEY`와 `UNIQUE`는 어떻게 다를까?

둘 다 중복을 막는다는 점은 비슷하다.

하지만 `PRIMARY KEY`는 행을 식별하는 대표 컬럼이므로 `NULL`을 허용하지 않는다.

반면 `UNIQUE`는 중복을 막지만 `NULL`은 허용될 수 있다.

```text
PRIMARY KEY -> 중복 불가 + NULL 불가
UNIQUE      -> 중복 불가 + NULL 가능
```

---

### 뷰는 테이블인가?

뷰는 테이블처럼 조회할 수 있지만 실제 데이터를 저장하는 일반 테이블은 아니다.

뷰는 `SELECT` 문을 저장한 논리적 객체이다.

```sql
CREATE VIEW vw_emp_dept AS
SELECT e.employee_id,
       e.first_name,
       d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id;
```

이후에는 테이블처럼 조회할 수 있다.

```sql
SELECT *
FROM vw_emp_dept;
```

정리하면 뷰는 테이블처럼 사용하지만, 실제로는 저장된 조회문으로 보는 것이 맞다.

---

### 권한은 왜 롤로 관리할까?

사용자마다 권한을 하나씩 주면 관리가 복잡해진다.

예를 들어 조회 담당자에게는 조회 권한만, 입력 담당자에게는 입력과 수정 권한을 줘야 한다.

이때 권한을 롤로 묶어두면 사용자에게 롤만 부여하면 된다.

```text
role_read  -> SELECT
role_write -> INSERT, UPDATE
role_admin -> DELETE, DDL
```

정리하면 롤은 권한을 역할별로 묶어서 관리하기 위한 객체이다.

---

## 정리

Oracle Day04에서는 DDL, 데이터베이스 객체, 제약조건, 권한 관리를 학습했다.

DDL에서는 `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`, `TRUNCATE`, `COMMENT`를 확인했다.
DDL은 테이블 구조를 다루는 명령어이고, 실행 시 자동 `COMMIT`이 발생한다는 점이 중요하다.

데이터베이스 객체에서는 인덱스, 시퀀스, 뷰, 시노님을 정리했다.
인덱스는 조회 속도를 높일 수 있지만 항상 빠른 것은 아니고, DML이 많은 테이블에서는 유지 비용이 발생한다.
시퀀스는 자동 번호를 만들 때 사용하고, 뷰는 복잡한 조회를 단순하게 만들거나 특정 컬럼만 공개할 때 사용할 수 있다.
시노님은 다른 객체에 대한 별칭이다.

제약조건에서는 `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `CHECK`, `NOT NULL`을 확인했다.
제약조건은 잘못된 데이터가 들어가는 것을 막기 위한 규칙이다.
금융 계좌처럼 데이터 정확성이 중요한 테이블에서는 제약조건이 특히 중요하다.

권한 관리에서는 사용자 생성, 시스템 권한, 객체 권한, 롤을 정리했다.
사용자는 권한이 있어야 접속하거나 객체를 사용할 수 있고, 여러 권한은 롤로 묶어서 관리할 수 있다.

오늘 다시 볼 핵심은 DDL의 자동 커밋, `CREATE TABLE AS SELECT`의 제약조건 복사 여부, 인덱스의 장단점, 시퀀스의 `NEXTVAL/CURRVAL`, 뷰와 시노님의 차이, 제약조건별 역할, 시스템 권한과 객체 권한의 차이이다.
