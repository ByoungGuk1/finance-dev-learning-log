## 2. 단일행 함수

단일행 함수는 한 행을 입력받아 한 행의 결과를 반환하는 함수이다.

예를 들어 직원 이름을 대문자로 바꾸거나, 급여를 반올림하거나, 입사일에서 연도를 추출하는 작업이 단일행 함수에 해당한다.

```sql
SELECT employee_id,
       first_name,
       UPPER(first_name),
       LOWER(first_name)
FROM employees;
```

정리:

- 단일행 함수는 각 행마다 개별적으로 적용된다.
- 문자, 숫자, 날짜, 변환, NULL 처리 함수 등이 있다.
- 조회 결과를 보기 좋게 가공할 때 자주 사용한다.

## 3. 문자 함수

문자 함수는 문자열을 변환하거나 일부만 추출할 때 사용한다.

수업에서 확인한 문자 함수는 다음과 같다.

```sql
SELECT employee_id,
       first_name,
       UPPER(first_name) AS "대문자",
       LOWER(first_name) AS "소문자",
       SUBSTR(first_name, 1, 3) AS "앞 3글자",
       INSTR(first_name, 'E') AS "E 위치",
       LENGTH(first_name) AS "길이",
       REPLACE(first_name, 'A', 'AAA') AS "문자 변경",
       TRIM(first_name) AS "앞뒤 공백 제거",
       LPAD(employee_id, 5, '0') AS "왼쪽 채우기",
       RPAD(first_name, 9, '*') AS "오른쪽 채우기"
FROM employees;
```

정리:

| 함수        | 의미                          |
| ----------- | ----------------------------- |
| `UPPER()`   | 대문자로 변환                 |
| `LOWER()`   | 소문자로 변환                 |
| `SUBSTR()`  | 문자열 일부 추출              |
| `INSTR()`   | 특정 문자의 위치 반환         |
| `LENGTH()`  | 문자열 길이 반환              |
| `REPLACE()` | 문자열 치환                   |
| `TRIM()`    | 앞뒤 공백 또는 특정 문자 제거 |
| `LPAD()`    | 왼쪽에 문자 채우기            |
| `RPAD()`    | 오른쪽에 문자 채우기          |

## 4. `TRIM`, `LTRIM`, `RTRIM`

공백 제거 함수도 확인했다.

```sql
SELECT TRIM('             STEVEN               ') || '*'
FROM dual;
```

```sql
SELECT LTRIM('             STEVEN               ') || '*'
FROM dual;
```

```sql
SELECT RTRIM('             STEVEN               ') || '*'
FROM dual;
```

정리:

- `TRIM()`은 양쪽 공백을 제거한다.
- `LTRIM()`은 왼쪽 공백을 제거한다.
- `RTRIM()`은 오른쪽 공백을 제거한다.
- 결과를 눈으로 확인하기 위해 문자열 뒤에 `'*'`를 붙여 확인했다.

## 5. 숫자 함수

숫자 함수는 반올림, 버림, 올림 같은 숫자 처리를 할 때 사용한다.

```sql
SELECT employee_id,
       salary,
       ROUND(salary * 1.08) AS "반올림",
       ROUND(salary * 1.08, -2) AS "백 단위 반올림",
       ROUND(salary * 1.08, 1) AS "소수 1자리 반올림",
       TRUNC(salary * 1.08) AS "버림"
FROM employees;
```

정리:

| 함수      | 의미   |
| --------- | ------ |
| `ROUND()` | 반올림 |
| `TRUNC()` | 버림   |
| `CEIL()`  | 올림   |
| `FLOOR()` | 내림   |

`ROUND(값, -2)`처럼 음수 자릿수를 주면 정수부 기준으로 반올림할 수 있다.

## 6. 날짜 함수

Oracle의 `DATE`는 날짜뿐 아니라 시, 분, 초까지 포함한다.

입사일과 현재 날짜를 이용해 근무일수, 개월 수, 년차를 계산할 수 있다.

```sql
SELECT employee_id,
       first_name,
       hire_date,
       TRUNC(SYSDATE - hire_date) AS "근무일수",
       TRUNC(MONTHS_BETWEEN(SYSDATE, hire_date), 1) AS "개월수",
       CEIL(MONTHS_BETWEEN(SYSDATE, hire_date) / 12) AS "년차",
       ADD_MONTHS(hire_date, 6) AS "입사 6개월 후",
       LAST_DAY(hire_date) AS "입사월 말일",
       EXTRACT(YEAR FROM hire_date) AS "입사년도"
FROM employees;
```

정리:

| 함수                | 의미                       |
| ------------------- | -------------------------- |
| `SYSDATE`           | 현재 날짜와 시간           |
| `MONTHS_BETWEEN()`  | 두 날짜 사이의 개월 수     |
| `ADD_MONTHS()`      | 날짜에 개월 수 더하기      |
| `LAST_DAY()`        | 해당 월의 마지막 날짜      |
| `EXTRACT()`         | 날짜에서 연도, 월, 일 추출 |
| `TRUNC(date, 'MM')` | 월 기준 절사               |
| `ROUND(date, 'MM')` | 월 기준 반올림             |

## 7. 근무년차 계산

오늘 헷갈렸던 부분 중 하나는 근무년차 계산이었다.

문제는 다음처럼 접근하면 된다.

```text
근무년차 = 현재 날짜와 입사일 사이의 개월 수 / 12
```

Oracle에서는 두 날짜 사이의 개월 수를 `MONTHS_BETWEEN()`으로 구한다.

```sql
SELECT first_name,
       hire_date,
       salary,
       TRUNC(MONTHS_BETWEEN(SYSDATE, hire_date) / 12) AS "근무년차"
FROM employees
WHERE TRUNC(MONTHS_BETWEEN(SYSDATE, hire_date) / 12) >= 7;
```

정리:

- 현재 날짜는 `SYSDATE`이다.
- `DATE`는 함수가 아니라 자료형 이름이다.
- `MONTHS_BETWEEN(SYSDATE, hire_date)`는 현재 날짜와 입사일 사이의 개월 수를 구한다.
- `/ 12`를 하면 년 단위가 된다.
- `TRUNC()`로 소수점을 버리면 정수 근무년차가 된다.

## 8. 변환 함수

Oracle에서는 문자, 숫자, 날짜 사이의 형식을 바꿀 때 변환 함수를 사용한다.

```sql
SELECT employee_id,
       hire_date,
       TO_CHAR(hire_date, 'YY"년" MM"월" DD"일"') AS "입사일",
       salary,
       TO_CHAR(salary, '999,999,999') AS "급여 포맷",
       TO_NUMBER('1,234,567', '9,999,999') AS "문자에서 숫자"
FROM employees;
```

정리:

| 함수          | 의미                      |
| ------------- | ------------------------- |
| `TO_CHAR()`   | 날짜나 숫자를 문자로 변환 |
| `TO_NUMBER()` | 문자를 숫자로 변환        |
| `TO_DATE()`   | 문자를 날짜로 변환        |

날짜 컬럼을 원하는 형식으로 출력할 때는 `TO_DATE()`가 아니라 `TO_CHAR()`를 사용해야 한다.

## 9. 날짜 출력 형식

입사일을 문장 안에 넣을 때는 날짜 형식을 명확히 지정해야 한다.

```sql
SELECT first_name || '의 입사일은 '
       || TO_CHAR(hire_date, 'RR/MM/DD')
       || ' 이고, 급여는 '
       || salary
       || ' 입니다.' AS "직원정보"
FROM employees;
```

정리:

- `hire_date`는 이미 날짜 타입이다.
- 날짜를 문자열로 출력하려면 `TO_CHAR(hire_date, 포맷)`을 사용한다.
- `TO_DATE(hire_date, 포맷)`처럼 날짜 타입에 다시 `TO_DATE()`를 쓰는 것은 적절하지 않다.

## 10. NULL 처리 함수

NULL은 산술 연산이나 조건식에서 결과를 예상과 다르게 만들 수 있다.

Oracle에서는 `NVL`, `NVL2`, `COALESCE`를 사용해 NULL을 처리할 수 있다.

```sql
SELECT first_name,
       salary,
       commission_pct,
       salary + salary * NVL(commission_pct, 0) AS "총수입",
       COALESCE(commission_pct, department_id, salary) AS "NULL이 아닌 첫 값"
FROM employees;
```

정리:

| 함수                | 의미                                 |
| ------------------- | ------------------------------------ |
| `NVL(a, b)`         | a가 NULL이면 b 반환                  |
| `NVL2(a, b, c)`     | a가 NULL이 아니면 b, NULL이면 c 반환 |
| `COALESCE(a, b, c)` | NULL이 아닌 첫 번째 값 반환          |
| `NULLIF(a, b)`      | a와 b가 같으면 NULL, 다르면 a 반환   |

## 11. `CASE WHEN`

`CASE WHEN`은 조건에 따라 다른 값을 반환할 때 사용한다.

```sql
SELECT employee_id,
       salary,
       CASE
           WHEN salary >= 15000 THEN 'S등급'
           WHEN salary >= 10000 THEN 'A등급'
           WHEN salary >= 5000 THEN 'B등급'
           ELSE 'C등급'
       END AS "급여등급"
FROM employees
ORDER BY salary DESC;
```

정리:

- `CASE WHEN`은 Java의 `if` 또는 `switch`와 비슷하게 볼 수 있다.
- 조건은 위에서부터 순서대로 검사된다.
- 먼저 만족한 조건이 있으면 그 결과가 반환된다.
- 범위 조건에는 `CASE WHEN`이 자연스럽다.

## 12. `DECODE`

`DECODE`는 Oracle 전용 조건 함수이다.

```sql
SELECT employee_id,
       job_id,
       salary,
       DECODE(job_id,
              'AD_PRES', salary * 1.2,
              'AD_VP', salary * 1.15,
              'IT_PROG', salary * 1.1,
              salary * 1.05) AS "인상후급여"
FROM employees;
```

정리:

- `DECODE`는 Oracle 전용 함수이다.
- 단순 비교에는 사용할 수 있다.
- `LIKE`, 범위 조건처럼 복잡한 조건은 `CASE WHEN`이 더 자연스럽다.
- 수업 문제에서 `DECODE`를 요구하면 `INSTR()` 같은 함수와 조합할 수 있다.

예시:

```sql
SELECT e.first_name,
       j.job_title,
       e.salary,
       DECODE(
           SIGN(INSTR(LOWER(j.job_title), 'manager')),
           1, e.salary * 0.5,
           e.salary
       ) AS "지급급여"
FROM employees e
JOIN jobs j ON e.job_id = j.job_id;
```

## 13. 그룹 함수

그룹 함수는 여러 행을 입력받아 하나의 결과를 반환한다.

```sql
SELECT COUNT(*),
       COUNT(department_id),
       COUNT(commission_pct),
       SUM(salary),
       AVG(salary),
       MIN(salary),
       MAX(salary)
FROM employees;
```

정리:

| 함수          | 의미                |
| ------------- | ------------------- |
| `COUNT(*)`    | 전체 행 수          |
| `COUNT(컬럼)` | NULL이 아닌 값의 수 |
| `SUM()`       | 합계                |
| `AVG()`       | 평균                |
| `MIN()`       | 최솟값              |
| `MAX()`       | 최댓값              |

중요한 점은 `COUNT(*)`와 `COUNT(컬럼)`이 다르다는 것이다.  
`COUNT(컬럼)`은 해당 컬럼이 NULL인 행을 제외한다.

## 14. `GROUP BY`

`GROUP BY`는 특정 기준으로 행을 묶은 뒤 그룹 함수 결과를 계산할 때 사용한다.

```sql
SELECT department_id,
       COUNT(*) AS "직원수",
       SUM(salary) AS "급여합계"
FROM employees
GROUP BY department_id;
```

정리:

- 부서별, 직무별, 연도별 통계처럼 기준이 있는 집계에 사용한다.
- `SELECT`절에 그룹 함수가 아닌 컬럼이 있으면 `GROUP BY`에 포함해야 한다.
- 그룹화 전 조건은 `WHERE`, 그룹화 후 조건은 `HAVING`에 작성한다.

---

## 15. `HAVING`

`HAVING`은 그룹화된 결과에 조건을 걸 때 사용한다.

```sql
SELECT job_id,
       SUM(salary),
       COUNT(*) AS "인원"
FROM employees
WHERE salary > 0
GROUP BY job_id
HAVING COUNT(*) >= 5
ORDER BY COUNT(*) DESC;
```

실행 흐름은 다음 순서로 이해하면 된다.

```text
FROM
WHERE
GROUP BY
HAVING
SELECT
ORDER BY
```

정리:

- `WHERE`는 행 단위 필터이다.
- `HAVING`은 그룹 단위 필터이다.
- 집계 함수 조건은 `HAVING`에 작성한다.

---

## 16. `ROLLUP`과 `GROUPING`

`ROLLUP`은 그룹별 집계와 소계를 함께 출력할 때 사용한다.

```sql
SELECT department_id,
       COUNT(*),
       SUM(salary)
FROM employees
GROUP BY ROLLUP(department_id)
ORDER BY department_id NULLS FIRST;
```

부서별, 직무별 급여 합계처럼 여러 기준의 소계를 출력할 수도 있다.

```sql
SELECT department_id AS "부서ID",
       CASE GROUPING(job_id)
           WHEN 1 THEN
               CASE GROUPING(department_id)
                   WHEN 1 THEN '총합'
                   ELSE '부서별 합계'
               END
           ELSE job_id
       END AS "JOB_ID",
       SUM(salary),
       COUNT(*)
FROM employees
WHERE department_id IS NOT NULL
GROUP BY ROLLUP(department_id, job_id)
ORDER BY 1, 2;
```

정리:

- `ROLLUP`은 소계와 총계를 함께 구할 때 사용한다.
- `GROUPING()`은 해당 행이 일반 그룹인지 소계/총계인지 구분할 때 사용한다.

---

## 17. `LISTAGG`

`LISTAGG`는 여러 행의 값을 하나의 문자열로 모을 때 사용한다.

```sql
SELECT department_id,
       COUNT(*),
       LISTAGG(first_name, ',') WITHIN GROUP (ORDER BY salary) AS "직원목록"
FROM employees
GROUP BY department_id;
```

정리:

- 여러 행의 문자열을 한 줄로 합칠 수 있다.
- `WITHIN GROUP (ORDER BY ...)`로 합치는 순서를 정할 수 있다.
- 부서별 직원명 목록 같은 결과를 만들 때 사용할 수 있다.

## 18. JOIN

JOIN은 두 개 이상의 테이블을 연결해서 조회하는 문법이다.

데이터베이스 설계에서는 중복을 줄이기 위해 테이블을 나누고, 조회할 때 JOIN으로 다시 연결한다.

```sql
SELECT e.first_name,
       d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id;
```

정리:

- JOIN은 테이블 간 관계를 이용해 데이터를 연결한다.
- `employees.department_id`와 `departments.department_id`처럼 공통 관계 컬럼을 기준으로 연결한다.
- 컬럼명이 여러 테이블에 같이 있으면 테이블 별칭을 붙여 명확히 해야 한다.

---

## 19. INNER JOIN

`INNER JOIN`은 양쪽 테이블에 모두 매칭되는 데이터만 출력한다.

```sql
SELECT e.first_name,
       d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id;
```

정리:

- 직원이 부서를 참조하고 있어야 결과에 나온다.
- 부서가 없는 직원은 제외된다.
- 가장 기본적인 조인 형태이다.

---

## 20. OUTER JOIN

`OUTER JOIN`은 한쪽 테이블의 데이터를 기준으로 매칭되지 않는 데이터도 포함한다.

### LEFT JOIN

```sql
SELECT e.first_name,
       e.hire_date,
       NVL(d.department_name, '<부서없음>') AS "부서명"
FROM employees e
LEFT JOIN departments d ON e.department_id = d.department_id;
```

### RIGHT JOIN

```sql
SELECT d.*
FROM employees e
RIGHT JOIN departments d ON e.department_id = d.department_id
WHERE e.employee_id IS NULL;
```

### FULL OUTER JOIN

```sql
SELECT e.email,
       d.department_name
FROM employees e
FULL JOIN departments d ON e.department_id = d.department_id;
```

정리:

- `LEFT JOIN`은 왼쪽 테이블을 기준으로 모두 출력한다.
- `RIGHT JOIN`은 오른쪽 테이블을 기준으로 모두 출력한다.
- `FULL OUTER JOIN`은 양쪽 모두에서 매칭되지 않는 데이터까지 출력한다.
- 부서가 없는 직원, 직원이 없는 부서처럼 누락된 관계를 찾을 때 사용한다.

---

## 21. SELF JOIN

`SELF JOIN`은 같은 테이블을 두 번 사용해 자기 자신과 조인하는 방식이다.

직원과 관리자 관계처럼 같은 `employees` 테이블 안에서 관계가 있는 경우 사용할 수 있다.

```sql
SELECT e.first_name || ' ' || e.last_name AS "직원명",
       m.first_name || ' ' || m.last_name AS "관리자명"
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.employee_id;
```

매니저보다 급여가 높은 직원을 찾을 수도 있다.

```sql
SELECT e.first_name || ' ' || e.last_name AS "직원명",
       m.first_name || ' ' || m.last_name AS "관리자명"
FROM employees e
JOIN employees m ON e.manager_id = m.employee_id
WHERE e.salary > m.salary;
```

정리:

- SELF JOIN은 같은 테이블에 서로 다른 별칭을 붙여 사용한다.
- 직원과 관리자 관계를 조회할 때 유용하다.
- 관리자 없는 직원까지 포함하려면 `LEFT JOIN`을 사용한다.

## 22. SubQuery

서브쿼리는 SQL 안에 포함된 또 다른 SQL이다.

예를 들어 특정 부서의 평균 급여보다 많이 받는 직원을 조회할 수 있다.

```sql
SELECT first_name,
       department_id,
       salary
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
    WHERE department_id = 80
);
```

정리:

- 서브쿼리는 조건값을 동적으로 구할 때 사용한다.
- `WHERE`, `FROM`, `SELECT` 등 여러 위치에서 사용할 수 있다.
- 단일행 서브쿼리와 다중행 서브쿼리를 구분해야 한다.

## 23. 부서별 최저급여 직원 조회

각 부서별 최저급여를 받는 직원을 찾으려면 먼저 부서별 최저급여를 구하고, 다시 직원 테이블과 조인하면 된다.

```sql
SELECT e.first_name,
       e.department_id,
       e.salary
FROM employees e
JOIN (
    SELECT department_id,
           MIN(salary) AS min_salary
    FROM employees
    GROUP BY department_id
) m ON e.department_id = m.department_id
   AND e.salary = m.min_salary;
```

정리:

- 그룹 함수만으로는 직원 이름을 바로 가져오기 어렵다.
- 먼저 부서별 최저급여를 구한다.
- 원본 테이블과 다시 조인해서 해당 급여를 받는 직원을 찾는다.

---

## 24. 부서별 최대급여 직원 조회

부서별 최대급여 직원도 같은 방식으로 조회할 수 있다.

```sql
SELECT e.first_name,
       d.department_name,
       e.salary
FROM employees e
JOIN departments d ON e.department_id = d.department_id
JOIN (
    SELECT department_id,
           MAX(salary) AS max_salary
    FROM employees
    GROUP BY department_id
) m ON e.department_id = m.department_id
   AND e.salary = m.max_salary;
```

정리:

- 부서별 최대급여를 먼저 구한다.
- 직원 테이블과 다시 조인한다.
- 동점자가 있으면 여러 명이 출력될 수 있다.

## 25. Inline View와 Top-N Query

인라인 뷰는 `FROM`절 안에 들어가는 서브쿼리이다.

Oracle 11g 기준으로 정렬 후 상위 N개를 가져올 때는 인라인 뷰와 `ROWNUM`을 함께 사용한다.

```sql
SELECT *
FROM (
    SELECT *
    FROM employees
    ORDER BY salary DESC
)
WHERE ROWNUM <= 5;
```

커미션 상위 3명도 같은 방식으로 구할 수 있다.

```sql
SELECT *
FROM (
    SELECT *
    FROM employees
    WHERE commission_pct IS NOT NULL
    ORDER BY commission_pct DESC
)
WHERE ROWNUM <= 3;
```

정리:

- `ROWNUM`은 조회 과정에서 먼저 붙는다.
- 정렬 후 상위 N개를 구하려면 안쪽 쿼리에서 먼저 정렬해야 한다.
- 바깥 쿼리에서 `ROWNUM <= N` 조건을 건다.

## 26. 월별, 연도별 입사자 수

날짜를 월 또는 연도 기준으로 묶을 때는 `TO_CHAR()`를 사용할 수 있다.

```sql
SELECT TO_CHAR(hire_date, 'MM') AS "월",
       COUNT(*) AS "입사자 수"
FROM employees
GROUP BY TO_CHAR(hire_date, 'MM')
HAVING COUNT(*) >= 5
ORDER BY TO_CHAR(hire_date, 'MM');
```

연도별 입사자 수는 다음처럼 조회할 수 있다.

```sql
SELECT TO_CHAR(hire_date, 'YYYY') AS "년도",
       COUNT(*) AS "입사자 수"
FROM employees
GROUP BY TO_CHAR(hire_date, 'YYYY')
ORDER BY COUNT(*) DESC;
```

정리:

- 월별 집계는 `TO_CHAR(hire_date, 'MM')`을 사용한다.
- 연도별 집계는 `TO_CHAR(hire_date, 'YYYY')`를 사용한다.
- `YY`보다 `YYYY`가 공개용 학습 기록에는 더 명확하다.
- 입사자 수가 많은 순으로 보려면 `ORDER BY COUNT(*) DESC`를 사용한다.

## 28. 다시 볼 부분

- `DATE`는 현재 날짜가 아니라 자료형 이름이다.
- 현재 날짜는 `SYSDATE`를 사용한다.
- 근무년차는 `TRUNC(MONTHS_BETWEEN(SYSDATE, hire_date) / 12)`로 계산할 수 있다.
- 날짜를 출력 형식에 맞게 바꿀 때는 `TO_CHAR()`를 사용한다.
- 문자 값을 날짜로 바꿀 때만 `TO_DATE()`를 사용한다.
- `COUNT(*)`는 전체 행 수를 센다.
- `COUNT(컬럼)`은 해당 컬럼이 NULL인 행을 제외한다.
- 그룹 함수 외 컬럼을 `SELECT`에 쓰면 `GROUP BY`에 포함해야 한다.
- 집계 조건은 `WHERE`가 아니라 `HAVING`에 작성한다.
- `ROLLUP`은 소계와 총계를 만들 때 사용한다.
- `GROUPING()`은 소계 행인지 일반 행인지 구분할 때 사용한다.
- `LEFT JOIN`은 왼쪽 테이블 기준으로 모두 출력한다.
- `RIGHT JOIN`은 오른쪽 테이블 기준으로 모두 출력한다.
- `SELF JOIN`은 같은 테이블에 별칭을 다르게 붙여 조인한다.
- `LIKE 'manager'`는 정확히 manager와 같은 문자열만 찾는다.
- 직책명 안에 Manager가 포함된 값을 찾으려면 `LIKE '%Manager%'` 또는 `LOWER(job_title) LIKE '%manager%'`를 사용한다.
- `ROWNUM`은 정렬 후 순번이 아니라 조회 과정에서 먼저 부여된다.
- 정렬 후 상위 N개는 인라인 뷰 안에서 정렬하고 바깥에서 `ROWNUM` 조건을 건다.

## 29. 수업 진행 중 생겼던 의문

### 근무년차는 어떻게 계산해야 할까?

처음에는 현재 날짜에서 입사일을 빼면 된다고 생각할 수 있다.

```sql
SYSDATE - hire_date
```

이 방식은 두 날짜 사이의 일수를 구하는 데는 사용할 수 있다.

하지만 문제에서 원하는 것은 근무일수가 아니라 근무년차이다.  
그래서 개월 수를 구한 뒤 12로 나누는 방식이 더 적절하다.

```sql
TRUNC(MONTHS_BETWEEN(SYSDATE, hire_date) / 12)
```

정리하면 다음처럼 기억하면 된다.

```text
근무년차 = 현재까지 지난 개월 수 / 12
현재까지 지난 개월 수 = MONTHS_BETWEEN(SYSDATE, hire_date)
```

---

### `TO_DATE()`와 `TO_CHAR()`는 언제 구분해야 할까?

`TO_DATE()`는 문자를 날짜로 바꿀 때 사용한다.

```sql
TO_DATE('2006-01-01', 'YYYY-MM-DD')
```

반대로 이미 날짜 타입인 `hire_date`를 원하는 문자열 형식으로 출력하려면 `TO_CHAR()`를 사용해야 한다.

```sql
TO_CHAR(hire_date, 'RR/MM/DD')
```

입사일을 문장으로 출력하는 문제에서 `hire_date`는 이미 날짜 타입이므로 `TO_CHAR()`가 맞다.

---

### `COUNT(*)`와 `COUNT(department_id)`는 왜 다를까?

`COUNT(*)`는 행 자체를 센다.

```sql
COUNT(*)
```

반면 `COUNT(department_id)`는 `department_id`가 NULL이 아닌 행만 센다.

```sql
COUNT(department_id)
```

직원 수를 구하는 문제라면 보통 `COUNT(*)`가 더 안전하다.  
부서가 없는 직원도 직원 수에는 포함될 수 있기 때문이다.

---

### `WHERE`와 `HAVING`은 어떻게 나눠야 할까?

`WHERE`는 그룹화 전 개별 행을 필터링한다.

```sql
WHERE salary BETWEEN 5000 AND 24000
```

`HAVING`은 그룹화 후 집계 결과를 필터링한다.

```sql
HAVING AVG(salary) >= 8000
```

즉, 급여 범위처럼 행마다 판단할 수 있는 조건은 `WHERE`, 평균 급여처럼 그룹 결과를 보고 판단해야 하는 조건은 `HAVING`에 작성한다.

---

### 사용되지 않은 직급까지 포함하려면 왜 OUTER JOIN이 필요할까?

직원 테이블과 직무 테이블을 `INNER JOIN`하면 실제 직원이 사용하는 직무만 조회된다.

하지만 문제에서 사용되지 않은 직급도 포함하라고 하면 `JOBS` 테이블을 기준으로 모든 직급을 살려야 한다.

```sql
SELECT j.job_title,
       COUNT(e.employee_id) AS "인원수"
FROM jobs j
LEFT JOIN employees e ON j.job_id = e.job_id
GROUP BY j.job_title;
```

이때 인원수를 셀 때는 `COUNT(*)`가 아니라 `COUNT(e.employee_id)`를 사용해야 한다.  
그래야 직원이 없는 직급은 0명으로 계산된다.

---

### `ROWNUM`으로 상위 5명을 바로 구하면 왜 위험할까?

아래처럼 작성하면 먼저 5명을 뽑고 그 안에서 정렬될 수 있다.

```sql
SELECT *
FROM employees
WHERE ROWNUM <= 5
ORDER BY salary DESC;
```

급여 상위 5명을 구하려면 먼저 정렬을 끝낸 뒤, 바깥에서 `ROWNUM`을 걸어야 한다.

```sql
SELECT *
FROM (
    SELECT *
    FROM employees
    ORDER BY salary DESC
)
WHERE ROWNUM <= 5;
```

Oracle 11g 기준에서는 이 방식이 Top-N Query의 기본 형태로 볼 수 있다.

## 정리

Oracle Day02에서는 단순 조회에서 한 단계 더 나아가 데이터를 가공하고, 묶고, 여러 테이블을 연결하는 방법을 학습했다.

단일행 함수에서는 문자, 숫자, 날짜 함수를 사용해 각 행의 값을 변환했다.  
특히 날짜 함수에서는 `SYSDATE`, `MONTHS_BETWEEN`, `ADD_MONTHS`, `LAST_DAY`, `EXTRACT`를 확인했고, 근무년차 계산에서는 `MONTHS_BETWEEN(SYSDATE, hire_date) / 12` 구조를 다시 봐야 한다.

변환 함수에서는 `TO_CHAR`, `TO_NUMBER`, `TO_DATE`를 구분했다.  
날짜를 출력 형식에 맞게 보여줄 때는 `TO_CHAR`, 문자열을 날짜로 변환할 때는 `TO_DATE`를 사용한다.

그룹 함수에서는 `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`를 사용했고, `GROUP BY`와 `HAVING`의 역할을 구분했다.  
`COUNT(*)`와 `COUNT(컬럼)`의 차이도 중요했다.

JOIN에서는 `INNER JOIN`, `LEFT JOIN`, `RIGHT JOIN`, `FULL OUTER JOIN`, `SELF JOIN`을 확인했다.  
특히 부서가 없는 직원, 직원이 없는 부서, 직원과 관리자 관계처럼 누락되거나 자기 자신을 참조하는 데이터를 조회하는 방식이 중요했다.

서브쿼리와 인라인 뷰에서는 집계 결과를 다시 원본 테이블과 연결하거나, 정렬 후 상위 N개 행을 조회하는 방법을 실습했다.  
Oracle 11g 기준에서는 Top-N 조회를 할 때 인라인 뷰 안에서 먼저 정렬하고, 바깥에서 `ROWNUM` 조건을 거는 방식이 필요하다.

오늘 다시 볼 핵심은 `MONTHS_BETWEEN`, `TO_CHAR`와 `TO_DATE` 구분, `COUNT(*)`와 `COUNT(컬럼)` 차이, `WHERE`와 `HAVING` 차이, OUTER JOIN의 기준 테이블, `ROWNUM` 처리 순서이다.
