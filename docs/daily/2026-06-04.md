## 2. 컬렉션 프레임워크

컬렉션은 여러 데이터를 효율적으로 저장하고 처리하기 위한 자료구조이다.

Java 컬렉션은 크게 `Collection` 계열과 `Map` 계열로 나눌 수 있다.

```text
Collection
├─ List
│  ├─ ArrayList
│  ├─ Vector
│  └─ LinkedList
└─ Set
   ├─ HashSet
   └─ TreeSet

Map
├─ HashMap
├─ Hashtable
├─ Properties
└─ TreeMap
```

`List`와 `Set`은 `Collection`을 상속받지만, `Map`은 key-value 구조를 가지므로 별도 계열로 분리된다.

```java
List<Integer> data1 = new ArrayList<>();
List<Integer> data2 = new Vector<>();
List<Integer> data3 = new LinkedList<>();

Set<Integer> data4 = new HashSet<>();

Map<String, Integer> data5 = new HashMap<>();
Map<String, Integer> data6 = new Hashtable<>();
Properties data7 = new Properties();
```

정리:

- `List`는 순서가 있고 중복을 허용한다.
- `Set`은 중복을 허용하지 않는다.
- `Map`은 key와 value를 한 쌍으로 저장한다.
- `Map`은 `Collection`의 하위 타입이 아니다.
- 컬렉션 종류에 따라 데이터 저장 방식과 중복 판단 기준이 달라진다.

## 3. `List`

`List`는 순서가 있는 자료구조이다.  
같은 값을 여러 번 저장할 수 있고, 인덱스를 통해 요소에 접근할 수 있다.

```java
List<Integer> data = new ArrayList<>();

data.add(100);
data.add(200);

System.out.println(data.get(0));
```

대표 구현체:

| 구현체       | 특징                                            |
| ------------ | ----------------------------------------------- |
| `ArrayList`  | 배열 기반, 조회가 빠름                          |
| `Vector`     | 오래된 동기화 지원 리스트                       |
| `LinkedList` | 노드 연결 구조, 중간 삽입/삭제에 유리할 수 있음 |

수업에서는 `ArrayList`, `Vector`, `LinkedList`를 생성하고 `add()`, `get()`을 사용해 기본 동작을 확인했다.

정리:

- `List`는 순서를 유지한다.
- 중복 값을 허용한다.
- 인덱스로 요소를 조회할 수 있다.
- 구현체에 따라 내부 저장 구조와 성능 특성이 다르다.
  - `ArrayList`: 배열 기반 구조이다. 인덱스 조회와 맨 뒤 추가에 유리하다.
  - `Vector`: 주요 메서드에 동기화가 적용된 `List` 구현체이다. 멀티스레드 환경에서 `ArrayList`보다 안전할 수 있지만, 동기화 비용이 있다.
  - `LinkedList`: 각각의 노드가 연결된 구조이다. 중간 삽입과 삭제에 유리할 수 있지만, 인덱스 기반 조회에는 상대적으로 불리하다.

## 4. `Set`, `HashSet`, `TreeSet`

`Set`은 중복을 허용하지 않는 자료구조이다.

```java
Set<Integer> datas = new HashSet<>();

datas.add(100);
datas.add(100);
datas.add(100);
```

위처럼 같은 값을 여러 번 넣어도 `Set`에는 하나만 저장된다.

`HashSet`은 저장 순서를 보장하지 않는다.

```java
Set<Integer> datas = new HashSet<>();
```

반면 `TreeSet`은 정렬된 상태로 데이터를 관리한다.

```java
Set<Integer> datas = new TreeSet<>();

datas.add(100);
datas.add(200);
datas.add(400);
datas.add(500);
datas.add(300);
```

`Integer`, `String`처럼 기본적으로 비교 기준을 가진 타입은 `TreeSet`에 바로 저장할 수 있다.

사용자 정의 객체를 `TreeSet`에 저장하려면 객체가 비교 기준을 제공해야 한다.  
보통 `Comparable`을 구현하거나, `Comparator`를 별도로 전달한다.

정리:

- `HashSet`은 중복을 제거하지만 순서를 보장하지 않는다.
- `TreeSet`은 중복을 제거하면서 정렬된 상태를 유지한다.
- `TreeSet`은 요소 간 비교 기준이 필요하다.
- 사용자 정의 객체를 `TreeSet`에 넣으려면 `Comparable` 또는 `Comparator`가 필요하다.
- 사용자 정의 객체를 `HashSet`에서 중복 비교하려면 `hashCode()`와 `equals()`를 재정의해야 한다.

## 5. `HashSet`과 `TreeSet`의 중복 판단 기준

`HashSet`과 `TreeSet`은 모두 중복을 허용하지 않는다.  
하지만 중복을 판단하는 기준이 다르다.

`HashSet`은 `equals()`와 `hashCode()`를 기준으로 중복을 판단한다.

```java
@EqualsAndHashCode(of = "number")
public class Student implements Comparable<Student> {
    private String number;
    private String name;
    private int score;
}
```

위 구조에서는 `HashSet<Student>`가 `number`를 기준으로 같은 학생인지 판단한다.

반면 `TreeSet`은 정렬 기준을 이용해서 중복을 판단한다.  
`Comparable`을 구현했다면 `compareTo()`의 결과가 `0`일 때 같은 객체로 본다.

```java
@Override
public int compareTo(Student o) {
    int numberResult = this.number.compareTo(o.getNumber());

    if (numberResult != 0) {
        return numberResult;
    }

    int nameResult = this.name.compareTo(o.getName());

    if (nameResult != 0) {
        return nameResult;
    }

    return o.getScore() - this.score;
}
```

따라서 `equals/hashCode` 기준과 `compareTo()` 기준이 다르면 `HashSet`과 `TreeSet`에서 중복 판단 결과가 달라질 수 있다.

정리:

- `HashSet`은 `equals()`와 `hashCode()`를 기준으로 중복을 판단한다.
- `TreeSet`은 정렬 기준인 `compareTo()` 또는 `Comparator`를 기준으로 중복을 판단한다.
- `compareTo()`가 `0`을 반환하면 `TreeSet`에서는 같은 요소로 취급된다.
- 수업 예제처럼 두 기준이 다르면 컬렉션 종류에 따라 결과가 달라질 수 있다.

## 6. `Comparable`

`Comparable`은 객체 자신의 기본 정렬 기준을 정의할 때 사용한다.

```java
public class Student implements Comparable<Student> {
    private String number;
    private String name;
    private int score;

    @Override
    public int compareTo(Student o) {
        return this.number.compareTo(o.getNumber());
    }
}
```

`compareTo()`는 다음 기준으로 이해할 수 있다.

| 반환값 | 의미                |
| ------ | ------------------- |
| 음수   | 현재 객체가 앞에 옴 |
| 0      | 같은 값으로 판단    |
| 양수   | 현재 객체가 뒤에 옴 |

수업에서는 `Student`와 `Account`에서 `Comparable`을 구현했다.

`Student`는 학번, 이름, 점수 순서로 비교했고, `Account`는 잔액, 예금주 이름, 계좌번호 순서로 비교했다.

정리:

- `Comparable`은 객체의 기본 정렬 기준을 정의한다.
- `compareTo()`의 반환값으로 정렬 순서를 결정한다.
- `TreeSet`, `TreeMap`, `Arrays.sort()`에서 사용할 수 있다.
- 중복 제거 기준으로도 사용될 수 있으므로 `equals/hashCode` 기준과의 차이를 주의해야 한다.

---

## 7. `Comparator`

`Comparator`는 외부에서 별도의 정렬 기준을 제공할 때 사용한다.

```java
Arrays.sort(intArr, new ComparatorImplA());
```

예를 들어 정수 배열을 내림차순으로 정렬하려면 다음처럼 작성할 수 있다.

```java
class ComparatorImplA implements Comparator<Integer> {
    @Override
    public int compare(Integer o1, Integer o2) {
        return o2 - o1;
    }
}
```

문자열도 별도 `Comparator`를 만들어 내림차순 정렬할 수 있다.

```java
class ComparatorImplB implements Comparator<String> {
    @Override
    public int compare(String o1, String o2) {
        return o2.compareTo(o1);
    }
}
```

익명 구현 객체로도 정렬 기준을 전달할 수 있다.

```java
Arrays.sort(accountArr, new Comparator<Account>() {
    @Override
    public int compare(Account o1, Account o2) {
        return o2.getBalance() - o1.getBalance();
    }
});
```

정리:

- `Comparable`은 객체 내부의 기본 정렬 기준이다.
- `Comparator`는 외부에서 제공하는 정렬 기준이다.
- 같은 객체라도 상황에 따라 다른 정렬 기준이 필요하면 `Comparator`가 적합하다.
- 수업 예제처럼 뺄셈으로 비교할 수 있지만, 값 범위가 크면 `Integer.compare()`를 사용하는 것이 더 안전하다.

## 8. `TreeSet`과 `TreeMap`

`TreeSet`은 정렬된 `Set`이다.  
정렬된 상태를 이용해서 첫 번째 값, 마지막 값, 기준보다 작은 값, 크거나 같은 값 등을 찾을 수 있다.

```java
TreeSet<Integer> treeSet = new TreeSet<>();

treeSet.add(100);
treeSet.add(200);
treeSet.add(300);
treeSet.add(400);
treeSet.add(500);

System.out.println(treeSet.first());
System.out.println(treeSet.last());
System.out.println(treeSet.lower(250));
System.out.println(treeSet.ceiling(330));
```

`descendingSet()`을 사용하면 내림차순으로 볼 수 있다.

```java
NavigableSet<Integer> descTreeSet = treeSet.descendingSet();
```

`TreeMap`은 key를 기준으로 정렬된 `Map`이다.

```java
Map<String, Integer> mapDatas = new TreeMap<>();

mapDatas.put("E", 20);
mapDatas.put("f", 30);
mapDatas.put("D", 40);
```

`firstEntry()`로 첫 번째 entry를 가져올 수 있고, `descendingKeySet()`으로 key를 역순 조회할 수 있다.

```java
TreeMap<String, Integer> treeMapDatas = (TreeMap<String, Integer>) mapDatas;

Map.Entry<String, Integer> entry = treeMapDatas.firstEntry();
NavigableSet<String> descMap = treeMapDatas.descendingKeySet();
```

정리:

- `TreeSet`은 정렬된 `Set`이다.
- `TreeMap`은 key를 기준으로 정렬되는 `Map`이다.
- `TreeSet`과 `TreeMap`은 비교 기준이 필요하다.
- `first()`, `last()`, `lower()`, `ceiling()` 같은 탐색 메서드를 사용할 수 있다.
- `descendingSet()`, `descendingKeySet()`으로 역순 조회가 가능하다.

## 9. `Map.Entry`

`Map.Entry`는 `Map`의 key-value 한 쌍을 표현하는 타입이다.

```java
Map<String, Integer> mapDatas = new TreeMap<>();

mapDatas.put("E", 20);
mapDatas.put("f", 30);
mapDatas.put("D", 40);

for (Map.Entry<String, Integer> entry : mapDatas.entrySet()) {
    System.out.println(entry.getKey() + " : " + entry.getValue());
}
```

`entrySet()`을 사용하면 key와 value를 함께 순회할 수 있다.

정리:

- `Map`은 key-value 구조이다.
- `Map.Entry`는 key-value 한 쌍이다.
- `entrySet()`은 `Map.Entry`의 집합을 반환한다.
- key와 value를 함께 사용할 때 `entrySet()` 순회가 적합하다.

## 10. 불변 리스트와 고정 크기 리스트

Java에서는 리스트를 만드는 방식에 따라 수정 가능 여부가 달라질 수 있다.

```java
List<Integer> data1 = List.of(1, 2, 3);
List<Integer> data2 = List.copyOf(data1);
List<Integer> data3 = Arrays.asList(1, 2, 3);
```

`List.of()`와 `List.copyOf()`는 불변 리스트를 만든다.  
요소 추가, 삭제, 변경이 불가능하다.

`Arrays.asList()`는 고정 크기 리스트를 만든다.  
`add()`나 `remove()`는 불가능하지만, 기존 인덱스의 값을 바꾸는 `set()`은 가능하다.

정리:

- `List.of()`는 불변 리스트를 만든다.
- `List.copyOf()`는 기존 컬렉션을 바탕으로 불변 리스트를 만든다.
- `Arrays.asList()`는 고정 크기 리스트를 만든다.
- `Arrays.asList()`는 `add/remove`는 불가능하지만 `set()`은 가능하다.

## 11. 스택

스택은 나중에 들어온 데이터가 먼저 나가는 구조이다.

```text
LIFO: Last In First Out
```

```java
Stack<String> stack = new Stack<>();

stack.push("A");
stack.push("B");
stack.push("C");

System.out.println(stack.pop()); // C
System.out.println(stack.pop()); // B
```

정리:

- 스택은 LIFO 구조이다.
- `push()`로 값을 넣는다.
- `pop()`으로 마지막에 넣은 값을 꺼낸다.
- 되돌리기, 괄호 검사, 호출 스택 같은 구조를 이해할 때 사용할 수 있다.

## 12. 큐

큐는 먼저 들어온 데이터가 먼저 나가는 구조이다.

```text
FIFO: First In First Out
```

스택이 나중에 들어온 값을 먼저 꺼내는 LIFO 구조라면, 큐는 먼저 들어온 값을 먼저 꺼내는 FIFO 구조이다.

```java
Queue<String> queue = new LinkedList<>();

queue.offer("A");
queue.offer("B");
queue.offer("C");

System.out.println(queue.poll()); // A
System.out.println(queue.poll()); // B
```

`offer()`는 큐에 값을 추가할 때 사용한다.
`poll()`은 큐에서 값을 꺼내면서 제거한다.
`peek()`은 값을 제거하지 않고 맨 앞의 값을 확인한다.

```java
Queue<String> queue = new LinkedList<>();

queue.offer("A");
queue.offer("B");

System.out.println(queue.peek()); // A
System.out.println(queue.poll()); // A
System.out.println(queue.poll()); // B
```

정리:

- 큐는 FIFO 구조이다.
- `offer()`로 값을 넣는다.
- `poll()`로 가장 먼저 들어온 값을 꺼낸다.
- `peek()`은 값을 제거하지 않고 맨 앞의 값을 확인한다.
- 작업 대기열, 요청 처리, 메시지 처리 같은 구조를 이해할 때 사용할 수 있다.

## 13. 함수형 인터페이스와 람다식

함수형 인터페이스는 구현해야 할 추상 메서드가 하나인 인터페이스이다.

```java
@FunctionalInterface
interface Calculable {
    double calc(double a, double b);
}
```

람다식은 함수형 인터페이스의 구현 객체를 간단하게 표현하는 문법이다.

```java
Calculable add = (a, b) -> a + b;
```

익명 구현 객체로 작성하면 다음과 같다.

```java
Calculable add = new Calculable() {
    @Override
    public double calc(double a, double b) {
        return a + b;
    }
};
```

람다식은 추상 메서드가 하나인 인터페이스에서만 사용할 수 있다.  
`@FunctionalInterface`를 붙이면 컴파일러가 함수형 인터페이스 조건을 확인해준다.

정리:

- 함수형 인터페이스는 추상 메서드가 하나인 인터페이스이다.
- 람다식은 함수형 인터페이스의 구현을 간단히 표현한다.
- `@FunctionalInterface`는 함수형 인터페이스 조건을 컴파일 시점에 확인해준다.
- 람다식은 익명 구현 객체와 비슷하게 사용할 수 있지만, 완전히 같은 구조는 아니다.

## 14. 제네릭 함수형 인터페이스

람다식에서 제네릭을 사용할 때는 메서드 자체를 제네릭으로 만들기보다, 인터페이스 자체를 제네릭으로 선언하는 방식이 자연스럽다.

```java
@FunctionalInterface
interface MyInterface1<T> {
    void print(T t);
}
```

사용할 때 타입을 지정한다.

```java
MyInterface1<String> my1 = a -> System.out.println(a);
my1.print("hello");
```

반면 아래처럼 추상 메서드 자체를 제네릭 메서드로 만들면 타입이 메서드 호출 시점마다 달라지는 구조가 된다.

```java
@FunctionalInterface
interface MyInterface1 {
    <T> void print(T t);
}
```

람다식으로 단순하게 사용하려는 목적이라면 인터페이스 자체에 타입 매개변수를 두는 편이 더 이해하기 쉽다.

정리:

- 제네릭 타입을 함수형 인터페이스에 적용할 수 있다.
- 람다식에서 사용하려면 인터페이스 자체를 제네릭으로 선언하는 방식이 이해하기 쉽다.
- 추상 메서드 자체를 제네릭 메서드로 만들면 람다식의 대상 메서드 형태를 이해하기 어려워질 수 있다.

## 15. 익명 구현 객체와 람다식의 `this`

익명 구현 객체와 람다식은 `this`가 가리키는 대상이 다르다.

익명 구현 객체에서는 `this`가 익명 구현 객체 자신을 의미한다.

```java
Calculable c = new Calculable() {
    String field = "구현체 필드";

    @Override
    public double calc(double a, double b) {
        System.out.println(this.field);
        return a + b;
    }
};
```

바깥 클래스의 필드에 접근하려면 `외부클래스명.this.field`처럼 접근할 수 있다.

```java
System.out.println(LambdaExample2.this.field);
```

람다식에서는 별도의 객체 스코프를 만들지 않는다.  
그래서 람다식 내부의 `this`는 람다식을 감싼 외부 객체를 가리킨다.

정리:

- 익명 구현 객체의 `this`는 익명 객체 자신을 의미한다.
- 람다식의 `this`는 람다식을 감싼 외부 객체를 의미한다.
- 익명 구현 객체는 자체 필드를 가질 수 있다.
- 람다식은 더 간단하지만, 별도 객체 스코프를 만들지 않는다는 점을 구분해야 한다.

## 16. 메서드 참조

메서드 참조는 람다식이 기존 메서드를 그대로 호출하는 경우 더 짧게 표현하는 문법이다.

```java
double result = action((a, b) -> Math.max(a, b), 10, 20);
```

위 코드는 다음처럼 바꿀 수 있다.

```java
double result = action(Math::max, 10, 20);
```

정적 메서드 참조:

```java
p.action(Computer::staticMethod);
```

인스턴스 메서드 참조:

```java
Computer c = new Computer();
p.action(c::instanceMethod);
```

정리:

- 메서드 참조는 기존 메서드를 람다식 대신 전달하는 문법이다.
- 정적 메서드는 `클래스명::메서드명` 형태로 참조한다.
- 인스턴스 메서드는 `객체참조변수::메서드명` 형태로 참조한다.
- 함수형 인터페이스의 추상 메서드 매개변수와 반환 타입이 참조 메서드와 맞아야 한다.

---

## 17. 생성자 참조

생성자 참조는 객체 생성 람다식을 더 짧게 표현하는 문법이다.

```java
@FunctionalInterface
interface Accountable {
    Account makeAccount(String accNo, String ownerName, int balance);
}
```

람다식으로 작성하면 다음과 같다.

```java
Accountable acc = (accNo, ownerName, balance) ->
        new Account(accNo, ownerName, balance);
```

생성자 참조를 사용하면 더 간단히 표현할 수 있다.

```java
Accountable acc = Account::new;
```

이때 `Account` 클래스에는 함수형 인터페이스의 추상 메서드 매개변수와 일치하는 생성자가 있어야 한다.

```java
public Account(String accNo, String ownerName, int balance) {
    this.accNo = accNo;
    this.ownerName = ownerName;
    this.balance = balance;
}
```

정리:

- 생성자 참조는 `클래스명::new` 형태로 작성한다.
- 함수형 인터페이스의 추상 메서드 매개변수와 생성자 매개변수가 맞아야 한다.
- `Account::new`는 `new Account(...)`를 대신하는 표현이다.

## 18. 스트림과 반복자

반복자는 컬렉션의 요소를 외부에서 하나씩 꺼내 처리하는 방식이다.

```java
for (Integer data : arrList) {
    System.out.println(data);
}
```

스트림은 내부 반복자를 사용한다.

```java
arrList.stream().forEach(System.out::println);
```

스트림은 내부 반복 방식을 사용하며, 람다식과 함께 중간 처리와 최종 처리를 파이프라인 형태로 구성할 수 있다.  
또한 `parallelStream()`을 사용하면 병렬 처리를 적용할 수 있다.

다음은 중간 처리와 최종처리를 연결해서 파이프라인 형태로 구성한 예시이다.

```java
strArr.stream()
      .filter(data -> data.contains("2") || data.contains("3"))
      .distinct()
      .sorted()
      .map(data -> "이름은 " + data)
      .forEach(System.out::println);
```

정리:

- 반복자는 외부 반복 방식이다.
- 스트림은 내부 반복 방식을 사용한다.
- 스트림은 람다식과 함께 사용하기 좋다.
- 스트림은 중간 처리와 최종 처리를 파이프라인으로 연결한다.
- `parallelStream()`을 사용하면 병렬 처리도 가능하다.

## 19. 스트림 생성

배열, 컬렉션, 숫자 범위, 파일 등에서 스트림을 만들 수 있다.

컬렉션 스트림:

```java
List<Integer> arrList = List.of(100, 200, 300);
arrList.stream().forEach(System.out::println);
```

배열 스트림:

```java
int[] intArr = {1, 2, 3, 4, 5};
Arrays.stream(intArr).forEach(System.out::println);
```

숫자 범위 스트림:

```java
IntStream.rangeClosed(1, 10).forEach(System.out::println);
```

파일 라인 스트림:

```java
Path path = Paths.get(uri);
Files.lines(path).forEach(System.out::println);
```

정리:

- 컬렉션은 `.stream()`으로 스트림을 만들 수 있다.
- 배열은 `Arrays.stream()`으로 스트림을 만들 수 있다.
- `IntStream.rangeClosed()`로 숫자 범위 스트림을 만들 수 있다.
- `Files.lines()`로 파일의 각 줄을 스트림으로 처리할 수 있다.

## 20. 스트림 중간 처리

중간 처리는 스트림을 다시 스트림으로 반환한다.  
그래서 여러 중간 처리를 연결할 수 있다.

대표 중간 처리:

| 메서드          | 역할                                   |
| --------------- | -------------------------------------- |
| `filter()`      | 조건에 맞는 요소만 통과                |
| `distinct()`    | 중복 제거                              |
| `sorted()`      | 정렬                                   |
| `map()`         | 요소를 다른 형태로 변환                |
| `mapToInt()`    | 요소를 int 값으로 변환                 |
| `mapToDouble()` | 요소를 double 값으로 변환              |
| `boxed()`       | 기본형 스트림을 참조형 스트림으로 변환 |
| `flatMap()`     | 중첩된 구조를 펼침                     |

예시:

```java
List<String> strArr = List.of("이름3", "이름2", "이름3", "이름1");

strArr.stream()
      .filter(data -> data.contains("2") || data.contains("3"))
      .distinct()
      .sorted()
      .map(data -> "이름은 " + data)
      .forEach(System.out::println);
```

`map()`은 요소의 구조를 바꾼다.

```java
productList.stream()
        .map(data -> data.getPrice())
        .forEach(System.out::println);
```

`flatMap()`은 여러 스트림으로 나뉜 데이터를 하나의 흐름으로 펼칠 때 사용한다.

```java
List<String> strList = List.of("This is Java", "I'm a best developer");

strList.stream()
       .flatMap(statement -> Arrays.stream(statement.split(" ")))
       .forEach(System.out::println);
```

정리:

- 중간 처리는 최종 처리 전까지 실행을 준비한다.
- `filter()`는 조건 필터링에 사용한다.
- `distinct()`는 중복 제거에 사용한다.
- `sorted()`는 정렬에 사용한다.
- `map()`은 요소 변환에 사용한다.
- `flatMap()`은 중첩 구조를 펼칠 때 사용한다.

---

## 21. 스트림 최종 처리와 `Optional`

최종 처리는 스트림을 소비하고 결과를 만든다.

대표 최종 처리:

| 메서드      | 역할               |
| ----------- | ------------------ |
| `forEach()` | 요소를 하나씩 처리 |
| `sum()`     | 합계               |
| `average()` | 평균               |
| `count()`   | 개수               |
| `collect()` | 결과 수집          |

점수 합계:

```java
int total = studentList.stream()
        .mapToInt(data -> data.getScore())
        .sum();
```

점수 평균:

```java
double average = studentList.stream()
        .mapToDouble(data -> data.getScore())
        .average()
        .orElse(0);
```

비어 있는 스트림에서 평균을 구하면 값이 없을 수 있다.  
이때 `average()`의 반환 값 타입인 `OptionalDouble`을 사용해서 값이 있는 경우와 없는 경우를 나눌 수 있다.

```java
emptyList.stream()
        .mapToDouble(data -> data.getScore())
        .average()
        .ifPresentOrElse(
                System.out::println,
                () -> System.err.println("null")
        );
```

정리:

- 최종 처리는 스트림을 소비한다.
- 최종 처리를 한 스트림은 다시 사용할 수 없다.
- `sum()`, `average()` 같은 메서드로 집계할 수 있다.
- `average()` 결과는 값이 없을 수 있으므로 `Optional` 계열로 처리한다.
- `orElse()`는 값이 없을 때 기본값을 제공한다.
- `ifPresentOrElse()`는 값이 있을 때와 없을 때의 처리를 나눌 수 있다.

## 22. `Predicate`

`Predicate`는 조건 판단에 사용하는 함수형 인터페이스이다.

```java
@FunctionalInterface
public interface Predicate<T> {
    boolean test(T t);
}
```

스트림의 `filter()`는 조건에 맞는 요소만 통과시키므로 `Predicate`와 연결된다.

```java
strArr.stream()
      .filter(data -> data.contains("2") || data.contains("3"))
      .forEach(System.out::println);
```

위 람다식은 각 요소가 조건을 만족하는지 확인하고, 결과로 `true` 또는 `false`를 반환한다.

정리:

- `Predicate`는 조건 검사에 사용하는 함수형 인터페이스이다.
- `test()` 메서드는 boolean 값을 반환한다.
- 스트림의 `filter()`는 `Predicate` 조건을 사용한다.
- 조건에 맞는 요소만 다음 단계로 전달된다.

## 25. 수업 진행 중 생겼던 의문

### 제네릭 함수형 인터페이스는 어떻게 람다식으로 구현할까?

처음에는 함수형 인터페이스 안의 메서드에 직접 제네릭을 붙이면 람다식으로 구현할 수 있을 것 같았다.

```java
@FunctionalInterface
interface MyInterface1 {
    <T> void print(T t);
}
```

하지만 이 방식은 추상 메서드 자체가 제네릭 메서드가 된다.
수업을 정리하면서 제네릭 타입을 사용하려면 인터페이스 자체에 타입 매개변수를 두는 편이 더 자연스럽다는 것을 알았다.

```java
@FunctionalInterface
interface MyInterface1<T> {
    void print(T t);
}

MyInterface1<String> my1 = a -> System.out.println(a);
my1.print("hello");
```

즉, 람다식으로 사용할 함수형 인터페이스는 추상 메서드의 형태가 명확하게 하나로 정해져 있어야 이해하기 쉽다.

---

### `Account::new`는 어떻게 생성자를 호출하는 걸까?

처음에는 `Account::new`가 실제로 어떤 값을 받아서 생성자를 호출하는지 헷갈렸다.

```java
@FunctionalInterface
interface Accountable {
    Account makeAccount(String accNo, String ownerName, int balance);
}
```

`Accountable`의 추상 메서드는 문자열 2개와 정수 1개를 받아 `Account`를 반환한다.

```java
Accountable acc = Account::new;
```

이 생성자 참조는 아래 람다식과 같은 의미로 볼 수 있다.

```java
Accountable acc = (accNo, ownerName, balance) ->
        new Account(accNo, ownerName, balance);
```

즉, 함수형 인터페이스의 추상 메서드 매개변수 모양과 `Account` 생성자의 매개변수 모양이 맞기 때문에 `Account::new`로 연결될 수 있다.

---

### `Arrays.asList(intArr)`는 왜 원하는 결과가 아니었을까?

`int[]`는 기본형 배열이다.

```java
int[] intArr = {1, 2, 3, 4, 5};
```

이 배열을 `Arrays.asList(intArr)`에 넣으면 `1, 2, 3, 4, 5`가 각각 리스트 요소가 되는 것이 아니라, `int[]` 배열 하나가 리스트의 요소가 된다.

그래서 기본형 배열을 스트림으로 처리하려면 다음처럼 작성하는 것이 맞다.

```java
Arrays.stream(intArr).forEach(System.out::println);
```

참조형 배열과 기본형 배열을 다룰 때 차이가 있다는 점을 다시 확인했다.

## 정리

14일차에는 컬렉션의 정렬 기준, 스택과 큐, 람다식, 메서드 참조, 스트림 처리 흐름을 정리했다.

컬렉션에서는 `HashSet`과 `TreeSet`의 중복 판단 기준이 다르다는 점이 중요했다.

스택과 큐에서는 데이터가 들어가고 나오는 순서가 다르다는 점을 확인했다. `Stack`은 LIFO 구조이고, `Queue`는 FIFO 구조이다.  
`Stack`은 클래스로 직접 객체를 만들 수 있지만,  
`Queue`는 인터페이스이기 때문에 보통 `LinkedList`나 `ArrayDeque` 같은 구현체를 `Queue` 타입으로 참조해서 사용한다.

람다식에서는 함수형 인터페이스의 추상 메서드 형태가 람다식과 메서드 참조의 기준이 된다는 점을 확인했다.  
특히 `Account::new`처럼 생성자 참조가 함수형 인터페이스의 매개변수 구조와 연결된다는 점을 다시 볼 필요가 있다.

스트림에서는 `filter`, `map`, `flatMap` 같은 중간 처리와 `forEach`, `sum`, `average` 같은 최종 처리를 파이프라인으로 연결하는 구조를 가지고 있다.
