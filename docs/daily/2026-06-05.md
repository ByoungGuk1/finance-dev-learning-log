## 2. 스트림 후속 처리

이전 수업에서 스트림의 기본 구조를 배웠고, 오늘은 스트림을 조금 더 다양하게 사용하는 방법을 배웠다.

스트림은 크게 다음 흐름으로 볼 수 있다.

```text
원본 데이터
→ stream()
→ 중간 처리
→ 최종 처리
```

예시:

```java
int stdSum = stdList.stream()
        .filter(stdData -> stdData.getName().length() >= 2)
        .flatMap(s -> s.getScore().stream())
        .mapToInt(Integer::intValue)
        .sum();
```

위 코드는 학생 목록에서 조건에 맞는 학생을 고른 뒤, 각 학생의 점수 리스트를 하나의 흐름으로 펼치고, `int` 값으로 변환한 뒤 합계를 구한다.

정리:

- `filter()`는 조건에 맞는 요소만 통과시킨다.
- `flatMap()`은 중첩된 구조를 하나의 스트림으로 펼친다.
- `mapToInt()`는 값을 `int` 스트림으로 변환한다.
- `sum()`은 최종 처리로 합계를 구한다.

## 3. `peek()`과 `forEach()`

```text
결과가 필요 없는 반복 -> forEach
중간 과정에서 확인이 필요한 반복 -> peek
```

`forEach()`는 최종 처리이다.

```java
stdList.stream()
       .forEach(System.out::println);
```

`forEach()`가 실행되면 스트림이 소비된다.
따라서 그 뒤에 다른 스트림 연산을 이어 붙일 수 없다.

반면 `peek()`은 중간 처리이다.

```java
List<String> stdNameList = stdList.stream()
        .sorted((a, b) -> b.getName().compareTo(a.getName()))
        .peek(System.out::println)
        .map(Student::getName)
        .toList();
```

`peek()`은 중간에 데이터를 확인할 때 사용할 수 있다.
위 코드에서는 정렬된 `Student` 객체를 중간에 출력한 뒤, 이름만 뽑아서 리스트로 만든다.

정리:

| 메서드      | 구분      | 목적               |
| ----------- | --------- | ------------------ |
| `peek()`    | 중간 처리 | 중간 데이터 확인   |
| `forEach()` | 최종 처리 | 요소를 하나씩 소비 |

주의할 점은 `peek()`을 실제 로직 처리용으로 남발하면 코드 의도가 흐려질 수 있다는 점이다.
보통 디버깅이나 중간 확인 용도로 보는 것이 좋다.

## 4. 조건 검사: `allMatch()`, `anyMatch()`, `noneMatch()`

스트림에서는 모든 요소가 조건을 만족하는지, 하나라도 만족하는지, 모두 만족하지 않는지를 검사할 수 있다.

```java
int[] intArr = { 2, 4, 6 };

boolean result1 = Arrays.stream(intArr)
        .allMatch(a -> a % 2 == 0);

boolean result2 = Arrays.stream(intArr)
        .anyMatch(a -> a % 2 == 0);

boolean result3 = Arrays.stream(intArr)
        .noneMatch(a -> a % 2 == 0);
```

의미는 다음과 같다.

| 메서드        | 의미                                      |
| ------------- | ----------------------------------------- |
| `allMatch()`  | 모든 요소가 조건을 만족하면 `true`        |
| `anyMatch()`  | 하나라도 조건을 만족하면 `true`           |
| `noneMatch()` | 모든 요소가 조건을 만족하지 않으면 `true` |

위 배열은 모두 짝수이기 때문에 다음처럼 볼 수 있다.

```text
allMatch(a -> a % 2 == 0)  -> true
anyMatch(a -> a % 2 == 0)  -> true
noneMatch(a -> a % 2 == 0) -> false
```

조건 검사 결과가 필요한 경우에는 이런 메서드를 사용하면 반복문을 직접 작성하지 않아도 된다.

## 5. `OptionalDouble`

`average()`는 평균을 구하는 최종 처리이다.
하지만 스트림에 값이 없으면 평균을 계산할 수 없다.

그래서 `average()`의 반환 타입은 `double`이 아니라 `OptionalDouble`이다.

```java
List<Integer> list = new ArrayList<>();

OptionalDouble opd = list.stream()
        .mapToInt(Integer::valueOf)
        .average();

System.out.println(opd);
opd.ifPresent(System.out::println);
```

값이 있을 때만 출력하려면 `ifPresent()`를 사용할 수 있다.

값이 있는 경우와 없는 경우를 나누려면 `ifPresentOrElse()`를 사용할 수 있다.

```java
OptionalDouble opd = Arrays.stream(intArr).average();

opd.ifPresentOrElse(
        System.out::println,
        () -> System.out.println("값이 없습니다.")
);
```

정리:

- `average()` 결과는 값이 없을 수 있다.
- 그래서 `OptionalDouble`로 반환된다.
- `ifPresent()`는 값이 있을 때만 실행한다.
- `ifPresentOrElse()`는 값이 있을 때와 없을 때의 처리를 나눈다.
- `orElse()`는 값이 없을 때 기본값을 지정한다.

## 6. 리스트를 `Map`으로 변환하기

스트림 결과를 `Map` 자료구조로 바꿀 수 있다.

```java
Map<String, Integer> newMap = memList.stream()
        .collect(Collectors.toMap(Member::getName, Member::getScore));

System.out.println(newMap);
```

위 코드는 `Member` 리스트를 다음 형태의 `Map`으로 바꾼다.

```text
key   -> Member의 name
value -> Member의 score
```

즉, 이름을 key로 하고 점수를 value로 가지는 `Map<String, Integer>`가 만들어진다.

주의할 점은 key가 중복되면 `Collectors.toMap()`에서 예외가 발생할 수 있다.

정리:

- `Collectors.toMap()`은 스트림 요소를 `Map`으로 수집한다.
- 첫 번째 인자는 key를 만드는 함수이다.
- 두 번째 인자는 value를 만드는 함수이다.
- key 중복 가능성이 있으면 병합 규칙을 따로 지정해야 한다.

## 7. `groupingBy()`

`Collectors.groupingBy()`를 사용하면 특정 기준으로 데이터를 그룹화할 수 있다.

```java
Map<String, List<Member>> groupMember = memList.stream()
        .collect(Collectors.groupingBy(Member::getGender));
```

위 코드는 성별을 기준으로 `Member`를 그룹화한다.

결과 구조는 다음과 같다.

```text
남자 -> [Member, Member, ...]
여자 -> [Member, Member, ...]
```

출력 예시:

```java
groupMember.keySet().forEach(data -> {
    System.out.println(data);
    groupMember.get(data).stream().forEach(System.out::println);
});
```

정리:

- `groupingBy()`는 특정 기준으로 데이터를 묶는다.
- 결과는 보통 `Map<기준, List<요소>>` 형태이다.
- SQL의 `GROUP BY`와 비슷한 느낌으로 이해할 수 있다.
- 같은 성별, 같은 부서, 같은 카테고리처럼 데이터를 묶을 때 사용할 수 있다.

## 8. `Comparator.comparingInt()`

개인 실습에서는 `Num` 객체를 숫자 기준으로 정렬했다.

```java
@AllArgsConstructor
@Getter
@Setter
@ToString
class Num {
    int number;
}
```

```java
List<Num> numList = List.of(
        new Num(1),
        new Num(51),
        new Num(12)
);

numList.stream()
       .sorted(Comparator.comparingInt(Num::getNumber))
       .forEach(System.out::println);
```

`Comparator.comparingInt(Num::getNumber)`는 `Num` 객체의 `number` 값을 기준으로 오름차순 정렬한다.

직접 람다식으로 쓰면 다음과 비슷하다.

```java
.sorted((a, b) -> Integer.compare(a.getNumber(), b.getNumber()))
```

정리:

- `Comparator.comparingInt()`는 `int` 값을 기준으로 정렬 기준을 만든다.
- 메서드 참조와 함께 쓰면 코드가 짧아진다.
- 숫자 비교를 뺄셈으로 처리하는 것보다 `Integer.compare()` 계열이 더 안전하다.

## 9. 파일 데이터 읽기 실습

`Lab1`에서는 파일을 읽어서 점수 객체로 변환하는 실습을 했다.

```java
interface MakeStudent {
    Score make(String name, int korScore, int engScore, int mathScore);
}
```

```java
@AllArgsConstructor
@Getter
@Setter
@ToString
class Score implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
    private int korScore;
    private int engScore;
    private int mathScore;
}
```

`Score::new`를 사용해서 생성자 참조로 객체를 만들었다.

```java
MakeStudent maker = Score::new;
```

파일에서 한 줄씩 읽은 뒤 `/` 기준으로 자르고, 각 값을 `Score` 객체로 만들었다.

```java
try (FileReader fr = new FileReader("src/com/shinhan/day15/lab/data.txt");

    title = br.readLine();

    String data = null;
    while ((data = br.readLine()) != null) {

                Integer.parseInt(dataArr[1]),
                Integer.parseInt(dataArr[2]),
                Integer.parseInt(dataArr[3])

        stdList.add(student);

}
```

확인한 부분:

- `FileReader`로 파일을 읽는다.
- `BufferedReader`로 한 줄씩 읽는다.
- `split()`으로 문자열을 나눈다.
- `Integer.parseInt()`로 문자열을 정수로 바꾼다.
- 생성자 참조로 `Score` 객체를 만든다.

List<String> dataList = Arrays.stream(inputdata.split(":|\\s+"))

Score student = new Score(

Vector<Score> stdVector = new Vector<>();

## 12. 바이트 기반 입력: `FileInputStream`

`FileInputStream`은 파일을 바이트 단위로 읽는다.

```java
try (FileInputStream fis = new FileInputStream("src/com/shinhan/day15/Day14Review.java")) {
    int i = 0;

    while ((i = fis.read()) != -1) {
        System.out.print((char) i);
    }
}
```

`read()`는 더 이상 읽을 데이터가 없으면 `-1`을 반환한다.

정리:

- `FileInputStream`은 바이트 기반 입력 스트림이다.
- `read()`는 한 바이트씩 읽는다.
- EOF에 도달하면 `-1`을 반환한다.
- 텍스트 파일도 읽을 수 있지만, 문자 처리에는 `FileReader`가 더 적합하다.

- 텍스트 파일을 읽을 때 사용할 수 있다.

## 14. 보조 스트림: `BufferedReader`

`BufferedReader`는 문자 입력 스트림에 버퍼 기능을 추가하는 보조 스트림이다.

```java
try (FileReader fr = new FileReader("src/com/shinhan/day15/Day14Review.java");

    String str = null;

    while ((str = br.readLine()) != null) {
        System.out.println(str);
    }
}
```

`readLine()`을 사용하면 한 줄씩 읽을 수 있다.
파일을 줄 단위로 처리할 때 `BufferedReader`를 자주 사용한다.

정리:

- `BufferedReader`는 보조 스트림이다.
- 기존 `Reader`에 버퍼 기능을 추가한다.
- `readLine()`으로 한 줄씩 읽을 수 있다.
- 파일 데이터를 줄 단위로 처리할 때 편하다.

## 16. 기본형 데이터 입출력

`DataOutputStream`은 Java 기본 타입 값을 그대로 기록할 때 사용할 수 있다.

```java
try (FileOutputStream fos = new FileOutputStream("DataOutput.txt");
     DataOutputStream dos = new DataOutputStream(fos)) {

    dos.writeInt(100);
    dos.writeChar('김');
    dos.writeFloat(3.14f);
    dos.writeUTF("문자열 utf");
}
```

읽을 때는 같은 순서로 읽어야 한다.

```java
try (FileInputStream fis = new FileInputStream("DataOutput.txt");
     DataInputStream dis = new DataInputStream(fis)) {

    int intData = dis.readInt();
    char charData = dis.readChar();
    float floatData = dis.readFloat();
    String strData = dis.readUTF();
}
```

중요한 점은 쓴 순서와 읽는 순서가 같아야 한다는 것이다.

정리:

- `DataOutputStream`은 기본형 데이터를 출력한다.
- `DataInputStream`은 기본형 데이터를 읽는다.
- `writeInt()`로 썼으면 `readInt()`로 읽어야 한다.
- 기록 순서와 읽는 순서가 다르면 데이터가 깨질 수 있다.

## 17. 객체 직렬화

객체를 파일에 저장하려면 직렬화가 필요하다.

```java
class Member implements Serializable {
    private static final long serialVersionUID = 1L;

    String name;
    String gender;
    int score;
    transient String password;
}
```

객체 직렬화를 위해서는 클래스가 `Serializable`을 구현해야 한다.

```java
try (FileOutputStream fos = new FileOutputStream("Member.dat");
     ObjectOutputStream oos = new ObjectOutputStream(fos)) {

    oos.writeObject(member);
}
```

수업에서는 `Member` 객체 리스트를 순회하면서 하나씩 파일에 기록했다.

```java
memList.stream().forEach(data -> {
    try {
        oos.writeObject(data);
    } catch (IOException e) {
        System.err.println(e.getMessage());
    }
});
```

정리:

- 객체를 파일로 저장하려면 직렬화가 필요하다.
- 직렬화 대상 클래스는 `Serializable`을 구현해야 한다.
- `ObjectOutputStream`으로 객체를 쓸 수 있다.
- `serialVersionUID`는 직렬화 버전 관리를 위한 값이다.

## 18. 객체 역직렬화

파일에 저장된 객체를 다시 읽으려면 `ObjectInputStream`을 사용한다.

```java
try (FileInputStream fis = new FileInputStream("Member.dat");
     ObjectInputStream ois = new ObjectInputStream(fis)) {

    Object obj = null;

    while ((obj = ois.readObject()) != null) {
        if (obj instanceof Member m) {
            memList.add(m);
        }
    }
}
```

파일 끝까지 읽으면 `EOFException`이 발생할 수 있다.
수업 코드에서는 이 예외를 이용해 반복 읽기를 종료했다.

```java
catch (java.io.EOFException e) {
}
```

정리:

- `ObjectInputStream`은 직렬화된 객체를 다시 읽는다.
- 읽은 객체는 `Object` 타입으로 반환된다.
- 필요한 타입으로 확인한 뒤 사용해야 한다.
- 파일 끝까지 읽으면 `EOFException`이 발생할 수 있다.

---

## 19. `transient`

`transient`는 직렬화에서 제외할 필드에 사용한다.

```java
transient String password;
```

위 필드는 객체를 직렬화할 때 파일에 저장되지 않는다.

민감한 값이나 저장할 필요가 없는 값은 `transient`로 제외할 수 있다.

정리:

- `transient` 필드는 직렬화 대상에서 제외된다.
- 비밀번호, 임시 값, 계산 결과처럼 저장하지 않을 값에 사용할 수 있다.
- 역직렬화 후에는 해당 필드가 기본값으로 들어간다.

---

## 20. 파일 정보 확인

`File`과 `Path`를 사용해서 파일 정보를 확인할 수 있다.

```java
File f1 = new File("Member.dat");

System.out.println("읽을 수 있는지 : " + f1.canRead());
System.out.println("실행 가능한지 : " + f1.exists());
System.out.println("파일 절대 경로 : " + f1.getAbsolutePath());
```

경로 구분자도 확인할 수 있다.

```java
System.out.println("현재 파일 경로의 구분자 : " + File.separator);
```

`Path`를 사용하면 URI 형태로도 확인할 수 있다.

```java
Path path = Paths.get("Member.dat");
System.out.println(path.toUri().toString());
```

정리:

- `File`은 파일이나 디렉터리 정보를 다룬다.
- `canRead()`로 읽기 가능 여부를 확인할 수 있다.
- `exists()`로 존재 여부를 확인할 수 있다.
- `getAbsolutePath()`로 절대 경로를 확인할 수 있다.
- `Path`는 경로를 더 현대적인 방식으로 다룰 수 있다.

## 21. JSON 데이터 처리

JSON은 key-value 형태의 데이터 표현 방식이다.

```java
String s = """
        {"name":"홍길동","age":20}
        """;
```

`JSONObject`를 사용하면 Java 코드에서 JSON 객체를 만들 수 있다.

```java
JSONObject jo = new JSONObject();

jo.put("id", "winter");
jo.put("name", "홍길동");
jo.put("age", 25);
jo.put("student", true);
```

배열 구조는 `JSONArray`로 만들 수 있다.

```java
JSONArray skill = new JSONArray();

skill.put("Java");
skill.put("c");
skill.put("python");

jo.put("skill", skill);
```

문자열 JSON을 다시 `JSONObject`로 파싱할 수도 있다.

```java
JSONObject data = new JSONObject(jsonData);
System.out.println(data);
```

`toMap()`을 사용하면 JSON 객체를 `Map` 형태로 다룰 수 있다.

```java
jsonData.toMap().entrySet().stream().forEach(data -> {
    System.out.print(data.getKey() + " => " + data.getValue() + "\n");
});
```

정리:

- JSON은 key-value 형태의 데이터 표현 방식이다.
- `JSONObject`는 JSON 객체를 표현한다.
- `JSONArray`는 JSON 배열을 표현한다.
- 문자열 JSON을 파싱해서 객체처럼 다룰 수 있다.
- `toMap()`으로 `Map` 형태로 변환할 수 있다.
- `org.json` 라이브러리가 필요하다.

## 22. 네트워크 입출력

네트워크 입출력은 다른 컴퓨터 또는 프로세스와 데이터를 주고받는 구조이다.

수업에서는 TCP와 UDP를 비교했다.

```text
TCP: 연결 기반, 신뢰성 높음
UDP: 비연결 기반, 속도 중심, 신뢰성 낮음
```

정리:

- TCP는 연결을 맺고 데이터를 주고받는다.
- UDP는 연결 없이 데이터를 패킷 단위로 보낸다.
- TCP는 신뢰성이 높지만 상대적으로 무겁다.
- UDP는 빠르고 단순하지만 데이터 손실 가능성이 있다.

---

## 23. TCP 통신

TCP는 `Socket`과 `ServerSocket`을 사용한다.

클라이언트는 서버에 연결한다.

```java
try (Socket socket = new Socket()) {
    socket.connect(new InetSocketAddress("localhost", 50001));
}
```

서버는 특정 포트에서 클라이언트 연결을 기다린다.

```java
ServerSocket serverSocket = new ServerSocket(50001);
Socket socket = serverSocket.accept();
```

TCP에서는 연결이 된 뒤 입출력 스트림을 통해 데이터를 주고받는다.

```java
OutputStream os = socket.getOutputStream();
os.write(message.getBytes("UTF-8"));
os.flush();
```

```java
InputStream is = socket.getInputStream();
```

정리:

- TCP는 연결 기반 통신이다.
- 서버는 `ServerSocket`으로 포트를 열고 대기한다.
- 클라이언트는 `Socket`으로 서버에 접속한다.
- 연결 후에는 스트림을 통해 데이터를 주고받는다.
- 연결 실패나 서버 종료에 대한 예외 처리가 필요하다.

---

## 24. UDP 통신

UDP는 `DatagramSocket`과 `DatagramPacket`을 사용한다.

```java
try (DatagramSocket socket = new DatagramSocket()) {
    InetAddress serverAddress = InetAddress.getByName("localhost");
    int serverPort = 50002;

    String sendData = "클라이언트가 보내는 데이터 (UDP)";
    byte[] sendBuffer = sendData.getBytes("UTF-8");

    DatagramPacket sendPacket = new DatagramPacket(
            sendBuffer,
            sendBuffer.length,
            serverAddress,
            serverPort
    );

    socket.send(sendPacket);
}
```

UDP는 TCP처럼 연결을 맺지 않는다.
데이터, 목적지 IP, 목적지 포트를 패킷에 담아 보낸다.

수신할 때는 받을 버퍼를 준비한다.

```java
byte[] receiveBuffer = new byte[1024];

DatagramPacket receivePacket = new DatagramPacket(
        receiveBuffer,
        receiveBuffer.length
);

socket.receive(receivePacket);
```

정리:

- UDP는 비연결 기반 통신이다.
- `DatagramSocket`으로 송수신한다.
- `DatagramPacket`에 데이터와 목적지 정보를 담는다.
- 서버가 응답하지 않으면 `receive()`에서 계속 대기할 수 있다.
- 필요한 경우 `setSoTimeout()`으로 대기 시간을 제한할 수 있다.

---

## 25. UDP 데이터 손실

UDP는 신뢰성을 보장하지 않는다.

즉, 데이터를 보냈다고 해서 반드시 도착하는 것은 아니다.
순서가 보장되지 않을 수도 있고, 중간에 유실될 수도 있다.

정리:

- UDP는 데이터 도착을 보장하지 않는다.
- 데이터 순서도 보장하지 않는다.
- 대신 연결 과정이 없어서 단순하고 빠르다.
- 실시간성이 중요한 경우에 사용할 수 있다.
- 신뢰성이 필요하면 애플리케이션 레벨에서 별도 처리해야 한다.

## 26. 멀티 채팅 구조

채팅 프로그램은 송신과 수신을 동시에 처리해야 한다.

문제는 사용자가 키보드 입력을 하는 동안에도 서버에서 메시지가 올 수 있다는 점이다.

그래서 클라이언트에서는 보통 다음처럼 역할을 나눈다.

```text
메인 스레드: 키보드 입력을 읽고 서버로 전송
수신 스레드: 서버 메시지를 계속 읽어서 콘솔에 출력
```

수신 전용 작업은 `Runnable`로 분리할 수 있다.

```java
Thread receiverThread = new Thread(new ReceiverTask(reader, socket));
receiverThread.setDaemon(true);
receiverThread.start();
```

수신 스레드는 서버에서 오는 메시지를 계속 읽는다.

```java
while ((line = reader.readLine()) != null) {
    System.out.println(line);
}
```

정리:

- 채팅은 송신과 수신이 동시에 필요하다.
- 메인 스레드가 입력만 담당하면 서버 메시지를 놓칠 수 있다.
- 수신 전용 스레드를 분리하면 서버 메시지를 계속 받을 수 있다.
- 데몬 스레드는 메인 스레드가 끝나면 같이 종료될 수 있다.

## 29. 수업 진행 중 생겼던 의문

### `peek()`과 `forEach()`는 둘 다 출력할 수 있는데 왜 구분할까?

처음에는 `peek(System.out::println)`과 `forEach(System.out::println)`이 둘 다 출력이 가능해서 비슷하게 느껴졌다.

하지만 정리해보면 `peek()`은 중간 처리이고, `forEach()`는 최종 처리이다.

`peek()`은 뒤에 `map()`, `toList()` 같은 다른 처리를 이어갈 수 있다.

```java
List<String> names = stdList.stream()
        .peek(System.out::println)
        .map(Student::getName)
        .toList();
```

반면 `forEach()`는 최종 처리이기 때문에 그 뒤에 다른 스트림 연산을 이어갈 수 없다.

```java
stdList.stream()
       .forEach(System.out::println);
```

즉, 중간 확인이 필요하면 `peek()`, 결과를 소비하는 것이 목적이면 `forEach()`로 구분해서 보는 것이 좋다.

---

### `DataOutputStream`으로 쓴 데이터는 왜 같은 순서로 읽어야 할까?

`DataOutputStream`은 `int`, `char`, `float`, `UTF 문자열` 같은 값을 정해진 형식으로 파일에 기록한다.

```java
dos.writeInt(100);
dos.writeChar('김');
dos.writeFloat(3.14f);
dos.writeUTF("문자열 utf");
```

이렇게 썼다면 읽을 때도 같은 순서로 읽어야 한다.

```java
int intData = dis.readInt();
char charData = dis.readChar();
float floatData = dis.readFloat();
String strData = dis.readUTF();
```

파일 안에 타입 정보가 자동으로 이름표처럼 붙어 있는 것이 아니기 때문에, 읽는 쪽에서 순서를 맞춰야 한다.

---

### `transient`는 왜 필요한가?

객체를 직렬화하면 객체의 필드 값이 파일에 저장된다.

하지만 모든 값을 저장해야 하는 것은 아니다.  
비밀번호처럼 저장하면 안 되는 값이나, 실행 중에만 필요한 값은 제외해야 한다.

이때 `transient`를 사용할 수 있다.

```java
transient String password;
```

이 필드는 직렬화 대상에서 제외된다.

이번 실습에서는 `Member`의 `password` 필드를 `transient`로 두고, 직렬화 과정에서 제외되는 필드를 확인했다.

---

### TCP와 UDP는 언제 다르게 봐야 할까?

TCP는 연결을 맺고 데이터를 주고받는다.  
그래서 신뢰성이 중요할 때 사용한다.

반면 UDP는 연결 없이 데이터를 패킷으로 보낸다.  
도착 보장이 없지만 구조가 단순하고 빠르다.

정리하면 다음처럼 볼 수 있다.

```text
신뢰성이 중요함 -> TCP
속도와 실시간성이 중요함 -> UDP
```

채팅, 파일 전송, 웹 요청처럼 데이터가 정확히 도착해야 하는 경우는 TCP가 더 자연스럽다.  
반면 실시간 영상, 음성, 게임처럼 일부 손실보다 지연 시간이 더 중요한 경우에는 UDP가 사용될 수 있다.

---

## 정리

15일차에는 스트림 후속 처리, 데이터 입출력, 네트워크 입출력을 학습했다.

스트림에서는 `peek()`, `allMatch()`, `anyMatch()`, `noneMatch()`, `Collectors.toMap()`, `Collectors.groupingBy()`를 확인했다.  
특히 `peek()`은 중간 처리이고 `forEach()`는 최종 처리라는 점을 구분해야 한다.

입출력에서는 바이트 기반 스트림, 문자 기반 스트림, 보조 스트림을 사용했다.  
`DataOutputStream`과 `DataInputStream`으로 기본형 데이터를 쓰고 읽었고,  
`ObjectOutputStream`과 `ObjectInputStream`으로 객체 직렬화와 역직렬화를 확인했다.

객체를 파일에 저장하려면 `Serializable`이 필요하고, 저장하지 않을 필드는 `transient`로 제외할 수 있다.

네트워크에서는 TCP와 UDP의 차이를 확인했다.  
TCP는 연결 기반이라 신뢰성이 높고, UDP는 비연결 기반이라 빠르지만 데이터 손실 가능성이 있다.

마지막으로 채팅 예제를 메인 스레드는 키보드 입력과 송신을 담당하고, 별도의 수신 스레드는 서버 메시지를 계속 읽는 구조로 확인했다.
