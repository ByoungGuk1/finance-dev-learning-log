## 2. 상속 복습

상속은 이미 작성된 클래스를 재사용해서 새로운 클래스를 만드는 방법이다.

```java
public class Student extends Person {
}
```

`extends` 키워드를 사용하면 자식 클래스가 부모 클래스의 필드와 메서드를 물려받을 수 있다.

정리:

- 부모 클래스는 슈퍼 클래스라고도 부른다.
- 자식 클래스는 서브 클래스라고도 부른다.
- 자식 클래스는 부모 클래스의 기능을 재사용하고 확장할 수 있다.
- `private` 멤버는 상속되더라도 자식 클래스에서 직접 접근할 수 없다.
- Java 클래스는 하나의 부모 클래스만 상속할 수 있다.

---

## 3. 부모 생성자 호출과 `super()`

자식 객체를 생성하면 부모 객체가 먼저 생성된 뒤 자식 객체가 생성된다.

부모 생성자는 자식 생성자의 첫 줄에서 `super()`를 통해 호출된다.

```java
public class Student extends Person {
    private int studentNo;

    public Student(String name, int age, int studentNo) {
        super(name, age);
        this.studentNo = studentNo;
    }
}
```

부모 클래스에 기본 생성자가 없다면 자식 생성자에서 부모 생성자를 명시적으로 직접 호출해야 한다.

```java
super(name, age);
```

정리:

- 자식 객체를 만들 때 부모 생성자가 먼저 실행된다.
- `super()`는 부모 생성자를 호출한다.
- `super()`는 생성자의 첫 줄에 와야 한다.
- 부모 클래스에 기본 생성자가 없으면 `super(값...)`을 명시해야 한다.
- 같은 생성자 안에서 `this()`와 `super()`를 동시에 사용할 수 없다.

## 4. 메서드 오버라이딩

오버라이딩은 부모 클래스에서 상속받은 메서드를 자식 클래스에서 다시 정의하는 것이다.

```java
public class Teacher extends Person {
    @Override
    public void introduce() {
        System.out.println("교사입니다.");
    }
}
```

오버라이딩을 사용하면 같은 메서드 이름을 호출하더라도 실제 객체 타입에 따라 다른 동작을 실행할 수 있다.

오버라이딩 조건:

- 부모 메서드와 이름이 같아야 한다.
- 매개변수 목록이 같아야 한다.
- 리턴 타입이 같거나 호환 가능해야 한다.
- 접근 제한자는 부모 메서드보다 더 좁게 만들 수 없다.
- `final` 메서드는 오버라이딩할 수 없다.
- `@Override`를 붙이면 컴파일러가 오버라이딩 여부를 확인해준다.

---

## 5. `super.메서드()` 사용

자식 클래스에서 오버라이딩한 메서드 안에서 부모 메서드를 다시 호출할 수 있다.

```java
@Override
public void introduce() {
    super.introduce();
    System.out.println("추가 정보 출력");
}
```

`super.메서드()`를 사용하면 부모의 공통 기능은 그대로 사용하고, 자식 클래스에서 필요한 기능만 추가할 수 있다.

정리:

- `super.메서드()`는 부모 클래스의 메서드를 호출한다.
- 부모 기능을 재사용하면서 자식 기능을 추가할 때 사용한다.
- 중복 코드를 줄일 수 있다.

## 6. `final` 클래스와 `final` 메서드

`final`은 더 이상 변경하거나 확장하지 못하도록 제한할 때 사용한다.

```java
final class MyClass {
}
```

`final` 클래스는 상속할 수 없다.

```java
class Child extends MyClass { // 컴파일 오류
}
```

메서드에 `final`을 붙이면 자식 클래스에서 오버라이딩할 수 없다.

```java
class Parent {
    final void print() {
    }
}
```

정리:

| 사용 위치      | 의미            |
| -------------- | --------------- |
| `final class`  | 상속 불가       |
| `final method` | 오버라이딩 불가 |
| `final field`  | 값 변경 불가    |

## 7. 추상 클래스와 추상 메서드

추상 클래스는 직접 객체를 만들 수 없다.

```java
public abstract class Account {
}
```

추상 메서드는 선언만 있고 구현부가 없는 메서드이다.

```java
public abstract int calculateInterest();
```

추상 메서드를 가진 클래스는 반드시 추상 클래스로 선언해야 한다.

```java
public abstract class Account {
    public abstract int calculateInterest();
}
```

자식 클래스는 상속받은 추상 메서드를 구현해야 한다.

```java
public class SavingsAccount extends Account {
    @Override
    public int calculateInterest() {
        return 0;
    }
}
```

정리:

- 추상 클래스는 `abstract` 키워드로 선언한다.
- 추상 클래스는 `new`로 직접 객체를 만들 수 없다.
- 추상 메서드는 구현부 `{}`가 없다.
- 추상 메서드를 상속받은 자식 클래스는 해당 메서드를 구현해야 한다.
- 자식 클래스도 추상 클래스라면 구현을 미룰 수 있다.
- 공통 구조는 부모 추상 클래스에 두고, 세부 동작은 자식 클래스에서 구현할 때 사용한다.

## 8. 다형성과 타입 변환

다형성은 같은 사용 방법으로 여러 실행 결과가 나오는 성질이다.

```java
Person p1 = new Student();
Person p2 = new Teacher();
```

부모 타입 변수에 자식 객체를 대입하는 것을 자동 타입 변환, 즉 업캐스팅이라고 한다.

```java
Person person = new Student();
```

업캐스팅된 상태에서는 부모 타입에 선언된 멤버만 직접 사용할 수 있다.

```java
person.introduce();
// person.study(); // Person 타입에는 study()가 없으므로 호출 불가
```

하지만 오버라이딩된 메서드는 실제 객체 타입의 메서드가 실행된다.

정리:

- 부모 타입 변수에 자식 객체를 대입할 수 있다.
- 부모 타입으로 변환되면 부모 타입에 선언된 멤버만 바로 사용할 수 있다.
- 오버라이딩된 메서드는 실제 객체 타입 기준으로 실행된다.
- 여러 자식 객체를 부모 타입 하나로 처리할 수 있다.

---

## 9. 다운캐스팅과 `instanceof`

부모 타입으로 변환된 객체를 다시 자식 타입으로 사용할 때는 강제 타입 변환이 필요하다.

```java
Person person = new Student();
Student student = (Student) person;
```

잘못된 타입으로 강제 변환하면 런타임 오류가 발생할 수 있다.

```java
Person person = new Teacher();
// Student student = (Student) person; // ClassCastException 발생
```

안전하게 다운캐스팅하려면 `instanceof`로 실제 객체 타입을 확인한다.

```java
if (person instanceof Student student) {
    student.study();
}
```

정리:

- 다운캐스팅은 부모 타입 참조를 자식 타입으로 다시 변환하는 것이다.
- 실제 객체 타입과 맞지 않으면 `ClassCastException`이 발생할 수 있다.
- `instanceof`를 사용하면 변환 가능한 타입인지 확인할 수 있다.

## 10. `protected` 접근 제한자

`protected`는 같은 패키지에서는 default처럼 접근할 수 있고, 다른 패키지에서는 상속 관계의 자식 클래스에서만 접근할 수 있다.

```java
public class Person {
    protected String name;
}
```

```java
public class Student extends Person {
    public void printName() {
        System.out.println(name);
    }
}
```

정리:

| 접근 제한자 | 같은 클래스 | 같은 패키지 | 다른 패키지의 자식 클래스 | 다른 패키지 |
| ----------- | ----------: | ----------: | ------------------------: | ----------: |
| `public`    |        가능 |        가능 |                      가능 |        가능 |
| `protected` |        가능 |        가능 |                      가능 |      불가능 |
| default     |        가능 |        가능 |                    불가능 |      불가능 |
| `private`   |        가능 |      불가능 |                    불가능 |      불가능 |

`protected`는 다른 패키지에서도 자식 클래스라면 접근할 수 있지만, 상속 관계를 통한 접근이라는 조건이 있다.

---

## 11. `sealed` 클래스

`sealed` 클래스는 상속 가능한 자식 클래스를 제한할 때 사용한다.

```java
public sealed class Person permits Student, Teacher {
}
```

`permits` 뒤에는 상속을 허용할 자식 클래스를 작성한다.

```java
public final class Student extends Person {
}
```

`sealed` 클래스를 상속받은 자식 클래스는 다음 중 하나로 선언해야 한다.

| 키워드       | 의미                  |
| ------------ | --------------------- |
| `final`      | 더 이상 상속 불가     |
| `sealed`     | 다시 상속 대상을 제한 |
| `non-sealed` | 상속 제한을 해제      |

정리:

- `sealed`는 상속 가능한 클래스를 제한한다.
- `permits`로 허용할 자식 클래스를 지정한다.
- 자식 클래스는 `final`, `sealed`, `non-sealed` 중 하나를 선택해야 한다.
- 무분별한 상속을 막고 계층 구조를 명확히 할 때 사용할 수 있다.

## 12. 사용자 역할 상속 실습

실습에서는 `Person`을 부모 클래스로 두고 `Student`, `Teacher`를 자식 클래스로 구성했다.

```text
Person
├─ Student
└─ Teacher
```

공통 정보는 부모 클래스에 두고, 역할별 정보는 자식 클래스에서 추가했다.

```java
public class Person {
    protected String name;
    protected int age;

    public void introduce() {
        System.out.println(name + "입니다.");
    }
}
```

```java
public class Student extends Person {
    private int studentNo;

    @Override
    public void introduce() {
        super.introduce();
        System.out.println("학번: " + studentNo);
    }
}
```

실습 포인트:

- 공통 필드와 메서드는 부모 클래스에 둔다.
- 역할별 추가 정보는 자식 클래스에 둔다.
- 부모 메서드를 재사용하려면 `super.메서드()`를 사용한다.
- 자식 클래스에서 필요한 출력 형식을 오버라이딩할 수 있다.

## 13. 금융 계좌 상속 실습

금융 계좌 실습에서는 `Account`를 추상 부모 클래스로 두고 여러 계좌 타입을 만들었다.

```text
Account
├─ SavingsAccount
├─ FixedDeposit
└─ LoanAccount
```

각 클래스 역할:

| 클래스           | 역할                            |
| ---------------- | ------------------------------- |
| `Account`        | 계좌 공통 정보와 입금/출금 기능 |
| `SavingsAccount` | 일반 예금 계좌, 이자 계산 구현  |
| `FixedDeposit`   | 정기 예금 계좌, 만기 이자 계산  |
| `LoanAccount`    | 대출 계좌, 월 이자와 상환 기능  |

추상 부모 클래스는 공통 필드와 공통 메서드를 제공하고, 이자 계산은 자식 클래스에서 구현했다.

```java
public abstract int calculateInterest();
```

주요 정리:

- 공통 필드와 기능은 추상 부모 클래스에 둔다.
- 계좌별 계산 방식은 자식 클래스에서 구현한다.
- 추상 메서드를 통해 자식 클래스의 구현을 강제할 수 있다.
- 부모 타입 배열을 사용하면 여러 계좌 객체를 함께 처리할 수 있다.

## 14. 템플릿 메서드 패턴 실습

알림 시스템 실습에서는 `Notification` 추상 클래스를 만들고, 발송 흐름을 `send()` 메서드로 고정했다.

```text
Notification
├─ SmsNotification
├─ EmailNotification
└─ PushNotification
```

부모 클래스는 발송 프로세스의 순서를 정한다.

```java
public final void send() {
    isDelivered = false;

    if (!validate()) {
        System.out.println("발송 실패: 유효성 검사 오류");
        return;
    }

    String formatted = formatMessage();
    deliver(formatted);
    isDelivered = true;
    logDelivery();
}
```

`send()`는 `final`로 선언해서 자식 클래스에서 발송 순서를 바꿀 수 없게 했다.

자식 클래스는 실제 발송 방식만 구현한다.

```java
protected abstract void deliver(String formattedMessage);
```

템플릿 메서드 패턴 흐름:

```text
1. validate()
2. formatMessage()
3. deliver()
4. logDelivery()
```

실습 포인트:

- 부모 클래스가 전체 프로세스 순서를 정한다.
- 자식 클래스는 세부 구현만 담당한다.
- `final` 메서드로 프로세스 변경을 막을 수 있다.
- `protected` 메서드로 자식 클래스가 공통 로직을 재사용할 수 있다.
- `NotificationService`는 부모 타입 `Notification`으로 여러 알림 객체를 처리한다.

## 15. 매개변수 다형성

매개변수 다형성은 메서드의 매개변수를 부모 타입으로 선언하고, 다양한 자식 객체를 전달받는 방식이다.

```java
public class NotificationService {
    public boolean sendNotification(Notification notification) {
        notification.send();
        return notification.isDelivered();
    }
}
```

호출할 때는 `SmsNotification`, `EmailNotification`, `PushNotification`을 모두 전달할 수 있다.

```java
service.sendNotification(new SmsNotification(...));
service.sendNotification(new EmailNotification(...));
service.sendNotification(new PushNotification(...));
```

부모 타입인 `Notification`으로 받기 때문에 같은 메서드로 여러 알림 객체를 처리할 수 있다.

정리:

- 매개변수 타입을 부모 타입으로 선언하면 여러 자식 객체를 받을 수 있다.
- 실제 실행되는 메서드는 자식 클래스에서 오버라이딩한 메서드이다.
- 중복 메서드를 줄이고 확장성을 높일 수 있다.

## 16. 금융 상품 상속 계층 실습

금융 상품 실습에서는 `FinancialAsset`을 추상 부모 클래스로 두고 예금 상품과 투자 상품을 나누었다.

```text
FinancialAsset
├─ DepositProduct
│  ├─ SavingsDeposit
│  └─ TermDeposit
└─ InvestmentProduct
   ├─ StockFund
   └─ BondFund
```

각 클래스 역할:

| 클래스              | 역할                  |
| ------------------- | --------------------- |
| `FinancialAsset`    | 금융 상품 공통 정보   |
| `DepositProduct`    | 예금 상품 공통 기능   |
| `InvestmentProduct` | 투자 상품 공통 기능   |
| `SavingsDeposit`    | 자유 입출금 예금 상품 |
| `TermDeposit`       | 정기 예금 상품        |
| `StockFund`         | 주식형 펀드 상품      |
| `BondFund`          | 채권형 펀드 상품      |

공통 기능은 부모 클래스에 두고, 상품별 수익 계산은 자식 클래스에서 구현했다.

```java
public abstract int calculateProfit();
```

포트폴리오에서는 부모 타입 배열로 여러 금융 상품을 함께 관리했다.

```java
FinancialAsset[] assets = new FinancialAsset[10];
```

실습 포인트:

- 추상 클래스를 여러 단계로 상속할 수 있다.
- 예금 상품과 투자 상품처럼 큰 분류를 중간 추상 클래스로 나눌 수 있다.
- 상품별 수익 계산 방식은 자식 클래스에서 구현한다.
- 부모 타입 배열을 사용하면 여러 상품을 하나의 컬렉션처럼 처리할 수 있다.
- `instanceof`를 사용하면 실제 상품 타입에 따라 추가 정보를 출력할 수 있다.

---

## 17. 다시 볼 부분

- 부모 생성자는 자식 생성자보다 먼저 실행된다.
- 부모 클래스에 기본 생성자가 없으면 자식 생성자에서 `super(값...)`을 명시해야 한다.
- 오버라이딩은 부모 메서드와 매개변수 목록이 같아야 한다.
- `final class`는 상속할 수 없고, `final method`는 오버라이딩할 수 없다.
- 추상 클래스는 직접 객체를 생성할 수 없다.
- 추상 메서드를 상속받은 자식 클래스는 구현해야 한다.
- 부모 타입 변수에 자식 객체를 대입하면 부모 타입에 선언된 멤버만 바로 사용할 수 있다.
- 필드는 오버라이딩 되지 않고 참조 변수 타입을 기준으로 따라간다. (필드 하이딩)
- 오버라이딩된 메서드는 실제 객체 타입 기준으로 실행된다.
- 다운캐스팅 전에는 `instanceof`로 실제 객체 타입을 확인해야 한다.
- `sealed` 클래스는 상속 가능한 자식 클래스를 제한한다.
- 템플릿 메서드 패턴에서는 부모가 프로세스 순서를 정하고 자식이 세부 구현을 담당한다.
- 매개변수 다형성을 사용하면 하나의 메서드로 여러 자식 객체를 처리할 수 있다.

---

## 18. 수업 진행 중 생겼던 의문

### 템플릿 메서드 패턴에서 `final`을 사용하는 이유

알림 시스템 실습에서는 부모 클래스인 `Notification`에서 `send()` 메서드를 `final`로 선언했다.

처음에는 자식 클래스에서 필요한 방식으로 `send()`를 바꾸는 것이 더 자유로워 보였다.

하지만 `send()`는 유효성 검사, 메시지 포맷, 실제 발송, 발송 기록이라는 공통 순서를 가지고 있었다.

이 순서가 자식 클래스마다 달라지면 알림 발송 흐름이 일관되지 않을 수 있다.

그래서 부모 클래스에서 `send()`를 `final`로 고정하고, 자식 클래스는 `deliver()`만 구현하도록 하는 구조가 더 안전하다는 것을 확인했다.

정리하면, `final`은 단순히 변경을 막는 키워드가 아니라 공통 프로세스의 흐름을 보호하는 역할도 할 수 있다.

---

## 정리

- 상속은 기존 클래스를 확장해서 새로운 클래스를 만드는 방법이다.
- 자식 객체가 생성될 때 부모 생성자가 먼저 실행된다.
- `super()`는 부모 생성자를 호출하고, `super.메서드()`는 부모 메서드를 호출한다.
- 오버라이딩은 부모 메서드를 자식 클래스에서 다시 정의하는 것이다.
- `final` 클래스는 상속할 수 없고, `final` 메서드는 오버라이딩할 수 없다.
- 추상 클래스는 공통 구조를 정의하지만 직접 객체를 생성할 수 없다.
- 추상 메서드는 자식 클래스가 반드시 구현해야 할 동작을 강제한다.
- 부모 타입 변수에 자식 객체를 대입하면 다형성을 사용할 수 있다.
- 업캐스팅 후에는 부모 타입에 선언된 멤버만 바로 사용할 수 있다.
- 오버라이딩된 메서드는 실제 객체 타입 기준으로 실행된다.
- 다운캐스팅 전에는 `instanceof`로 타입을 확인하는 것이 안전하다.
- `protected`는 같은 패키지 또는 상속 관계에서 접근할 수 있다.
- `sealed`는 상속 가능한 자식 클래스를 제한할 때 사용한다.
- 템플릿 메서드 패턴은 부모 클래스가 처리 순서를 고정하고 자식 클래스가 세부 구현을 담당하는 구조이다.
- 매개변수 다형성을 사용하면 하나의 메서드로 여러 자식 객체를 처리할 수 있다.
