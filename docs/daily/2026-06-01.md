## 2. `Integer` 참조형 변수 비교

`Integer`는 기본 타입 `int`를 객체처럼 사용할 수 있게 해주는 Wrapper Class이다.

```java
Integer a = 100;
Integer b = 100;

System.out.println(a == b); // true
```

`Integer`는 오토박싱될 때 내부적으로 `Integer.valueOf()`를 사용한다.
Java는 기본적으로 `-128 ~ 127` 범위의 `Integer` 값을 캐싱한다.

그래서 위 범위 안의 값은 같은 객체가 재사용될 수 있다.

```java
Integer a = 300;
Integer b = 300;

System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true
```

`300`처럼 캐시 범위를 벗어난 값은 서로 다른 객체로 만들어질 수 있다.
이때 `==`은 참조값을 비교하므로 `false`가 나올 수 있다.

정리:

| 비교 방식  | 의미        |
| ---------- | ----------- |
| `==`       | 참조값 비교 |
| `equals()` | 값 비교     |

`Integer` 값을 비교할 때는 `==`이 아니라 `equals()`를 사용하는 것이 안전하다.

## 3. 라벨이 붙은 반복문과 `continue`

반복문에는 라벨을 붙일 수 있다.

```java
aa: while (true) {
    if (true) {
        continue aa;
    }

    start();
}
```

`continue aa`를 만나면 `aa` 라벨이 붙은 반복문의 다음 반복으로 넘어간다.

위 코드에서는 `continue aa`가 실행되면 아래의 `start()`는 실행되지 않는다.

정리:

- 라벨은 특정 반복문을 지정할 때 사용한다.
- `continue 라벨명`은 해당 반복문의 다음 반복으로 넘어간다.
- 중첩 반복문에서 바깥 반복문을 제어할 때 사용할 수 있다.

## 4. 제네릭을 사용하는 이유

제네릭은 클래스나 메서드에서 사용할 타입을 미리 고정하지 않고, 사용하는 시점에 타입을 정하는 문법이다.

제네릭을 사용하지 않으면 `Object` 타입으로 여러 값을 담을 수 있다.

```java
class OldBox {
    Object content;
}
```

이 방식은 어떤 타입이든 저장할 수 있지만, 값을 꺼낼 때 직접 형 변환이 필요하다.

```java
OldBox box = new OldBox();

box.setContent(100);
int data1 = (Integer) box.getContent();

box.setContent("신한");
String data2 = (String) box.getContent();
```

잘못된 타입으로 형 변환하면 실행 중 오류가 발생할 수 있다.

제네릭을 사용하면 타입을 사용하는 시점에 정할 수 있다.

```java
class NewBox<T> {
    T content;
}
```

```java
NewBox<String> box1 = new NewBox<>();
box1.setContent("문자열");

String data = box1.getContent();
```

제네릭을 사용하면 형 변환을 줄일 수 있고, 컴파일 시점에 타입 오류를 더 빨리 확인할 수 있다.

정리:

- 제네릭은 사용할 타입을 외부에서 정할 수 있게 한다.
- `Object` 기반 코드보다 타입 안정성이 높다.
- 값을 꺼낼 때 불필요한 형 변환을 줄일 수 있다.
- 컬렉션, DTO, 공통 유틸 클래스에서 자주 사용된다.

## 5. 제네릭 클래스

제네릭 클래스는 클래스 선언부에 타입 파라미터를 선언한다.

```java
public class Product<K, M> {
    private K kind;
    private M model;
}
```

사용할 때 타입을 지정한다.

```java
Product<TV, String> p1 = new Product<>();
p1.setKind(new TV());
p1.setModel("ABC_MODEL");

Product<Car, String> p2 = new Product<>();
p2.setKind(new Car());
p2.setModel("ABC_MODEL");
```

`K`, `M`은 실제 타입이 아니라 타입을 받을 자리이다.
실제 타입은 객체를 생성할 때 결정된다.

자주 쓰는 타입 파라미터 이름:

| 이름 | 의미                      |
| ---- | ------------------------- |
| `T`  | Type                      |
| `K`  | Key                       |
| `V`  | Value                     |
| `E`  | Element                   |
| `M`  | Model 등 상황에 맞게 사용 |

정리:

- 제네릭 클래스는 클래스 단위로 타입을 외부에서 받는다.
- 하나의 클래스 구조를 여러 타입에 재사용할 수 있다.
- 타입 파라미터 이름은 보통 대문자 한 글자를 사용한다.

---

## 6. 제네릭 인터페이스

인터페이스에도 제네릭을 사용할 수 있다.

```java
public interface Rentable<P> {
    P rent();
}
```

구현 클래스에서 실제 반환 타입을 정한다.

```java
public class HomeAgent implements Rentable<Home> {
    @Override
    public Home rent() {
        return new Home();
    }
}
```

```java
public class CarAgent implements Rentable<Car> {
    @Override
    public Car rent() {
        return new Car();
    }
}
```

사용 예시:

```java
HomeAgent homeAgent = new HomeAgent();
Home home = homeAgent.rent();
home.turnOnLight();

CarAgent carAgent = new CarAgent();
Car car = carAgent.rent();
car.run();
```

`Rentable<P>`는 대여 가능한 객체를 반환한다는 규칙만 정의하고, 실제로 무엇을 반환할지는 구현 클래스가 결정한다.

정리:

- 인터페이스도 제네릭 타입을 가질 수 있다.
- 구현 클래스가 실제 타입을 지정한다.
- 같은 인터페이스 구조를 여러 타입에 재사용할 수 있다.

## 7. 제네릭 메서드

제네릭 메서드는 메서드 선언부에 타입 파라미터를 선언한다.

```java
public <T> void swap(T[] arr, int i, int j) {
    T temp = arr[i];
    arr[i] = arr[j];
    arr[j] = temp;
}
```

`<T>`는 반환 타입 앞에 작성한다.

```java
Integer[] arr = {10, 20, 30, 40, 50};

swap(arr, 1, 2);
```

이 메서드는 `Integer[]`, `String[]`, `Person[]`처럼 여러 타입의 배열에 사용할 수 있다.

배열 출력도 제네릭 메서드로 만들 수 있다.

```java
public <T> void printArray(String label, T[] arr) {
    System.out.println("[" + label + "]");

    for (T data : arr) {
        System.out.print(data + " ");
    }

    System.out.println();
}
```

정리:

- 제네릭 클래스는 클래스 전체에서 타입을 사용한다.
- 제네릭 메서드는 특정 메서드 안에서만 타입 파라미터를 사용한다.
- 제네릭 메서드의 타입 파라미터는 반환 타입 앞에 선언한다.
- 여러 타입에 같은 로직을 적용할 때 사용할 수 있다.

## 8. 제네릭 클래스와 제네릭 메서드 차이

제네릭 클래스는 객체를 만들 때 타입이 결정된다.

```java
Box<String, Integer> box = new Box<>("A", 100);
```

제네릭 메서드는 메서드를 호출할 때 타입이 결정된다.

```java
public <K, S> Box<K, S> make1(K k, S s) {
    return new Box<>(k, s);
}
```

```java
Box<String, Integer> result = make1("문자열", 1234);
```

비교하면 다음과 같다.

| 구분          | 타입 결정 시점   | 사용 범위   |
| ------------- | ---------------- | ----------- |
| 제네릭 클래스 | 객체 생성 시점   | 클래스 전체 |
| 제네릭 메서드 | 메서드 호출 시점 | 메서드 내부 |

## 9. 제네릭 타입 제한

제네릭 타입을 아무 타입이나 받게 하지 않고, 특정 타입의 하위 타입으로 제한할 수 있다.

```java
private static <T extends Number> boolean compare(T i, T j) {
    System.out.println(i.getClass().getSimpleName());

    boolean result = i.equals(j);

    double d1 = i.doubleValue();
    double d2 = j.doubleValue();

    int num1 = i.intValue();
    int num2 = j.intValue();

    return result;
}
```

`<T extends Number>`는 `Number` 또는 `Number`를 상속받은 타입만 사용할 수 있다는 뜻이다.

가능한 예:

```java
compare(10, 10);
compare(2.3, 3.1);
```

`Integer`, `Double`은 모두 `Number`의 하위 타입이기 때문에 사용할 수 있다.

타입을 제한하면 `doubleValue()`, `intValue()`처럼 `Number`가 가진 메서드를 사용할 수 있다.

정리:

- `<T extends Number>`는 `Number` 계열 타입만 허용한다.
- 타입을 제한하면 제한한 상위 타입의 메서드를 사용할 수 있다.
- 숫자 계산처럼 특정 계열 타입만 받아야 할 때 유용하다.

## 10. 와일드카드 `?`

제네릭에서 `?`는 알 수 없는 타입을 의미한다.

```java
public static void registerCourse1(Applicant<?> applicant) {
    System.out.println(applicant.kind.getClass().getSimpleName() + "이(가) Course1을 등록함");
}
```

`Applicant<?>`는 `Applicant<Person>`, `Applicant<Student>`, `Applicant<Worker>` 등 어떤 타입의 지원자도 받을 수 있다.

```java
Applicant<Person> personType = new Applicant<>(new Person());
Applicant<Worker> workerType = new Applicant<>(new Worker());
Applicant<Student> studentType = new Applicant<>(new Student());

Course.registerCourse1(personType);
Course.registerCourse1(workerType);
Course.registerCourse1(studentType);
```

정리:

- `?`는 타입을 특정하지 않는 와일드카드이다.
- 어떤 타입이든 받을 수 있다.
- 읽기 중심으로 사용할 때 적합하다.

---

## 11. `? extends`

`? extends Student`는 `Student` 또는 `Student`의 하위 타입을 허용한다.

```java
public static void registerCourse2(Applicant<? extends Student> applicant) {
    System.out.println(applicant.kind.getClass().getSimpleName() + "이(가) Course2을 등록함");
}
```

가능한 타입:

```java
Applicant<Student>
Applicant<HighStudent>
Applicant<MiddleStudent>
```

불가능한 타입:

```java
Applicant<Person>
Applicant<Worker>
```

즉, 학생 계열만 등록할 수 있는 구조이다.

정리:

- `? extends Student`는 `Student`와 그 하위 타입을 허용한다.
- 상위 타입인 `Person`은 허용되지 않는다.
- 특정 하위 계층만 받을 때 사용한다.

---

## 12. `? super`

`? super Worker`는 `Worker` 또는 `Worker`의 상위 타입을 허용한다.

```java
public static void registerCourse3(Applicant<? super Worker> applicant) {
    System.out.println(applicant.kind.getClass().getSimpleName() + "이(가) Course3을 등록함");
}
```

가능한 타입:

```java
Applicant<Worker>
Applicant<Person>
Applicant<Object>
```

불가능한 타입:

```java
Applicant<Student>
Applicant<HighStudent>
Applicant<MiddleStudent>
```

수업 예제에서는 `Worker`와 일반 사람 계열을 받을 수 있는 구조로 이해하면 된다.

정리:

- `? super Worker`는 `Worker`와 그 상위 타입을 허용한다.
- 하위 타입 제한인 `extends`와 방향이 반대이다.
- 특정 타입을 기준으로 상위 타입까지 허용할 때 사용한다.

## 13. 프로세스와 스레드

프로세스는 실행 중인 프로그램이다.

```text
프로세스 = 실행 중인 프로그램
```

스레드는 프로세스 안에서 실제 코드를 실행하는 흐름이다.

```text
스레드 = 코드의 실행 흐름
```

Java 프로그램은 `main()` 메서드를 실행하는 메인 스레드로 시작한다.

작업 스레드를 추가로 실행하면 메인 스레드와 작업 스레드가 별도의 실행 흐름으로 동작한다.

정리:

- 프로세스는 실행 중인 프로그램이다.
- 스레드는 프로세스 안에서 코드를 실행하는 흐름이다.
- 하나의 프로세스 안에 여러 스레드가 있을 수 있다.
- Java 프로그램은 메인 스레드에서 시작한다.

## 14. 스레드를 만드는 방법

Java에서 스레드를 만드는 방법은 크게 세 가지로 정리할 수 있다.

## 14-1. `Thread` 클래스를 상속받는 방법

```java
public class DigitThread extends Thread {
    @Override
    public void run() {
        for (int i = 0; i < 27; i++) {
            System.out.println(Thread.currentThread().getName() + " - " + i);
        }
    }
}
```

사용할 때는 `start()`를 호출한다.

```java
DigitThread t1 = new DigitThread();
t1.setName("상속으로 스레드 생성");
t1.start();
```

`start()`를 호출해야 새로운 스레드가 생성되고, 그 안에서 `run()`이 실행된다.

---

## 14-2. `Runnable` 인터페이스를 구현하는 방법

```java
public class AlphabetRunnableImpl implements Runnable {
    @Override
    public void run() {
        for (char ch = 'A'; ch <= 'Z'; ch++) {
            System.out.println(Thread.currentThread().getName() + " - " + ch);
        }
    }
}
```

`Runnable` 구현 객체는 직접 실행하는 것이 아니라 `Thread` 객체에 전달해서 사용한다.

```java
Runnable impl = new AlphabetRunnableImpl();
Thread t2 = new Thread(impl);

t2.setName("구현체로 만든 스레드");
t2.start();
```

`Runnable` 방식은 이미 다른 클래스를 상속받고 있는 경우에도 사용할 수 있다.
Java는 클래스 다중 상속을 허용하지 않지만, 인터페이스는 구현할 수 있기 때문이다.

---

## 14-3. 익명 객체를 사용하는 방법

간단한 스레드 작업은 익명 객체로 만들 수도 있다.

```java
Thread t3 = new Thread() {
    @Override
    public void run() {
        for (int i = 0; i < 3; i++) {
            System.out.println(Thread.currentThread().getName() + " - " + i);
        }
    }
};

t3.setName("익명 객체로 정의");
t3.start();
```

별도의 클래스를 만들 필요가 없을 때 사용할 수 있다.

정리:

| 방식            | 특징                                  |
| --------------- | ------------------------------------- |
| `Thread` 상속   | `run()`을 재정의하고 `start()`로 실행 |
| `Runnable` 구현 | 구현 객체를 `Thread`에 전달           |
| 익명 객체       | 간단한 작업을 즉석에서 정의           |

## 15. `start()`와 `run()`의 차이

스레드를 사용할 때 가장 주의할 부분은 `start()`와 `run()`의 차이이다.

```java
DigitThread t1 = new DigitThread();

t1.run();
```

`run()`을 직접 호출하면 새로운 스레드가 만들어지지 않는다.
그냥 현재 스레드에서 일반 메서드처럼 실행된다.

```java
DigitThread t1 = new DigitThread();

t1.start();
```

`start()`를 호출해야 새로운 스레드가 생성되고, 그 스레드 안에서 `run()`이 실행된다.

정리:

| 호출      | 결과                                   |
| --------- | -------------------------------------- |
| `run()`   | 현재 스레드에서 일반 메서드처럼 실행   |
| `start()` | 새로운 스레드를 생성한 뒤 `run()` 실행 |

멀티 스레드로 실행하려면 `run()`이 아니라 `start()`를 호출해야 한다.

## 16. 오늘 실습 정리

```text
제네릭을 사용하면 타입을 사용하는 시점에 정할 수 있다.
제네릭 클래스와 제네릭 메서드는 타입 결정 위치가 다르다.
extends와 super는 제네릭 허용 범위의 방향이 다르다.
스레드는 코드 실행 흐름이다.
멀티 스레드 실행에는 start()가 필요하다.
```

- `Thread` 상속 방식과 `Runnable` 구현 방식 차이
- `start()`와 `run()`의 실행 방식 차이

## 18. 수업 중 헷갈렸던 부분

### 18-1. 제네릭 메서드와 제네릭 클래스 차이

처음에는 `Box<K, S>`처럼 클래스에 타입을 붙이는 것과, 메서드 앞에 `<T>`를 붙이는 것이 비슷해 보였다.

정리해보면 제네릭 클래스는 객체 전체에서 사용할 타입을 정하는 것이고, 제네릭 메서드는 특정 메서드 안에서만 사용할 타입을 정하는 것이다.

### 18-2. `extends`와 `super` 방향

`? extends Student`는 학생과 학생 하위 타입을 받는다.

```text
Student
HighStudent
MiddleStudent
```

반대로 `? super Worker`는 Worker와 Worker의 상위 타입을 받는다.

```text
Worker
Person
Object
```

둘 다 타입 제한이지만 허용 방향이 다르다.

### 18-3. `run()`을 호출해도 왜 멀티 스레드가 아닌지

`run()`은 오버라이딩한 메서드일 뿐이다.
직접 호출하면 현재 실행 중인 스레드에서 일반 메서드처럼 실행된다.

새로운 실행 흐름을 만들려면 `start()`를 호출해야 한다.

## 19. 정리

12일차에는 제네릭과 스레드의 기본 구조를 배웠다.

제네릭은 타입을 나중에 정할 수 있게 해서 코드 재사용성과 타입 안정성을 높인다.
특히 `Object`를 사용하는 방식과 비교하면, 제네릭을 사용할 때 형 변환이 줄어들고 타입 오류를 더 빨리 확인할 수 있다.

스레드는 코드의 실행 흐름이다.
Java에서는 `Thread`를 상속하거나 `Runnable`을 구현해서 작업 스레드를 만들 수 있다.

가장 중요한 부분은 `start()`와 `run()`의 차이였다.
`run()`을 직접 호출하면 멀티 스레드가 아니라 일반 메서드 실행이고, `start()`를 호출해야 새로운 스레드가 만들어진다.
