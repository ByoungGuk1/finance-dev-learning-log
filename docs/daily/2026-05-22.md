## 2. 상속

상속은 이미 작성된 클래스를 재사용해서 새로운 클래스를 만드는 방법이다.

```java
public class CheckingAccount extends Account {
}
```

`extends` 키워드를 사용하면 부모 클래스의 필드와 메서드를 자식 클래스에서 사용할 수 있다.

정리:

- 부모 클래스는 상위 클래스 또는 슈퍼 클래스라고 부른다.
- 자식 클래스는 하위 클래스 또는 서브 클래스라고 부른다.
- 자식 클래스는 부모 클래스의 필드와 메서드를 물려받을 수 있다.
- 단, `private` 멤버는 직접 접근할 수 없다.
- Java 클래스는 다중 상속을 허용하지 않는다.

## 3. 부모 클래스와 자식 클래스

부모 클래스는 공통 기능을 가지고, 자식 클래스는 부모 기능을 확장한다.

```java
public class Account {
    private String accNo;
    protected String owner;
    private int balance;

    public void deposit(int amount) {
        balance += amount;
    }

    public int withdraw(int amount) {
        if (balance < amount) {
            System.err.println("잔액 부족");
            return 0;
        }

        balance -= amount;
        return amount;
    }
}
```

```java
public class CheckingAccount extends Account {
    private String cardNo;

    int pay(String cardNo, int amount) {
        if (!cardNo.equals(this.cardNo)) {
            System.err.println("카드번호 불일치");
            return 0;
        }

        return super.withdraw(amount);
    }
}
```

`CheckingAccount`는 `Account`를 상속받았기 때문에 입금, 출금 기능을 재사용할 수 있다. 여기에 카드번호와 결제 기능을 추가해서 직불 계좌 역할로 확장했다.

## 4. 부모 생성자 호출과 `super()`

자식 객체를 생성하면 부모 객체가 먼저 생성된 뒤 자식 객체가 생성된다.

자식 생성자 첫 줄에는 부모 생성자를 호출하는 `super()`가 자동으로 들어간다.

```java
public CheckingAccount() {
    super();
    System.out.println("CheckingAccount default constructor");
}
```

부모 클래스에 기본 생성자가 없고 매개변수가 있는 생성자만 있다면, 자식 생성자에서 부모 생성자를 명시적으로 호출해야 한다.

```java
public CheckingAccount(String accNo, String owner, int balance, String cardNo) {
    super(accNo, owner, balance);
    this.cardNo = cardNo;
}
```

정리:

- 자식 객체 생성 시 부모 생성자가 먼저 실행된다.
- `super()`는 부모 생성자를 호출한다.
- `super()`는 생성자의 첫 줄에 와야 한다.
- 부모 클래스에 기본 생성자가 없으면 자식 생성자에서 명시적으로 직접 작성해야 한다.
- `this()`와 `super()`는 둘 다 생성자 첫 줄에 와야 하므로 같은 생성자에서 동시에 사용할 수 없다.
- 부모 클래스에 기본 생성자가 있으면 `super()`를 작성하지 않아도 컴파일러가 자동으로 추가한다.

## 5. 메서드 오버라이딩

오버라이딩은 부모에게 상속받은 메서드를 자식 클래스에서 다시 정의하는 것이다.

```java
public class CreditLineAccount extends Account {
    private int creditLine;

    @Override
    public int withdraw(int amount) {
        if (getBalance() + creditLine < amount) {
            System.err.println("잔액 부족");
            return 0;
        }

        setBalance(getBalance() - amount);
        return amount;
    }
}
```

`CreditLineAccount`는 부모의 `withdraw()`를 그대로 사용하지 않고, 마이너스 한도를 포함해서 출금 가능 여부를 판단하도록 재정의했다.

오버라이딩 조건:

- 부모 메서드와 이름이 같아야 한다.
- 매개변수 목록이 같아야 한다.
- 리턴 타입이 같거나, 허용되는 범위 안에서 호환되어야 한다.
- 접근 제한자는 부모 메서드보다 더 좁게 만들 수 없다.
- `@Override`를 붙이면 컴파일러가 오버라이딩 여부를 확인해준다.

## 6. 부모 메서드 호출 `super.메서드()`

자식 클래스 내부에 오버라이딩한 메서드 안에서 부모 메서드를 재사용할 수 있다.

```java
public class BonusPointAccount extends Account {
    private int bonusPoint;

    @Override
    public void deposit(int amount) {
        super.deposit(amount);
        bonusPoint += (int)(amount * 0.001);
    }
}
```

`super.deposit(amount)`는 부모 클래스의 입금 로직을 먼저 실행한다. 그 후 자식 클래스에서 포인트 적립 로직을 추가한다.

정리:

- `super.메서드()`는 부모 클래스의 메서드를 호출한다.
- 부모 기능을 유지하면서 자식 기능을 추가할 때 사용한다.
- 중복 코드를 줄일 수 있다.

## 7. `final` 클래스와 `final` 메서드

`final`은 더 이상 변경하거나 확장하지 못하게 제한할 때 사용한다.

```java
final class MyClass {
}
```

`final` 클래스는 상속할 수 없다.

```java
class MyClassChild extends MyClass { // 컴파일 오류
}
```

메서드에 `final`을 붙이면 자식 클래스에서 오버라이딩할 수 없다.

```java
class Parent {
    final void f2() {
    }
}

class Child extends Parent {
    // void f2() {} // 컴파일 오류
}
```

정리:

| 사용 위치      | 의미            |
| -------------- | --------------- |
| `final class`  | 상속 불가       |
| `final method` | 오버라이딩 불가 |
| `final field`  | 값 변경 불가    |

## 8. 추상 클래스와 추상 메서드

추상 클래스는 직접 객체를 만들 수 없는 클래스이다.

```java
public abstract class Vehicle {
    public abstract void run();
}
```

추상 메서드는 선언만 있고 구현이 없는 메서드이다.

```java
public abstract void run();
```

추상 메서드를 가진 클래스는 반드시 추상 클래스로 선언해야 한다. 자식 클래스는 추상 메서드를 반드시 구현해야 한다.

```java
public class Bus extends Vehicle {
    @Override
    public void run() {
        System.out.println("Bus가 달립니다.");
    }
}
```

정리:

- 추상 클래스는 `abstract` 키워드로 선언한다.
- 추상 클래스는 `new`로 직접 객체를 만들 수 없다.
- 추상 메서드는 구현부 `{}`가 없다.
- 추상 메서드를 상속받은 자식 클래스는 해당 메서드를 구현해야 한다. (단, 자식 클래스도 추상 클래스라면 구현을 미룰 수 있다.)
- 공통 구조는 부모 추상 클래스에 두고, 세부 동작은 자식 클래스에서 구현할 때 사용한다.

## 9. 다형성

다형성은 같은 사용 방법으로 여러 실행 결과가 나오는 성질이다.

```java
Vehicle v1 = new Bus();
Vehicle v2 = new Taxi();

Driver driver = new Driver();
driver.drive(v1);
driver.drive(v2);
```

```java
public class Driver {
    public void drive(Vehicle vehicle) {
        vehicle.run();
    }
}
```

`Driver`는 `Vehicle` 타입만 알고 있지만, 실제로 전달된 객체가 `Bus`인지 `Taxi`인지에 따라 실행 결과가 달라진다.

정리:

- 부모 타입 변수에 자식 객체를 대입할 수 있다.
- 같은 메서드 호출이라도 실제 객체의 오버라이딩된 메서드가 실행된다.
- 매개변수 타입을 부모 타입으로 두면 여러 자식 객체를 받을 수 있다.
- 다형성은 코드 변경을 줄이고 확장성을 높이는 데 도움이 된다.

## 10. 참조형 변수의 자동 형 변환 (업캐스팅)

자식 객체는 부모 타입으로 자동 형 변환될 수 있다.

```java
Account acc = new CheckingAccount("112", "b", 1000, "999");
```

이 경우 참조 변수의 타입은 `Account`이지만, 실제 객체는 `CheckingAccount`이다.

주의할 점:

- 부모 타입으로 변환되면 부모 타입에 선언된 멤버만 직접 사용할 수 있다.
- 자식 클래스에만 있는 메서드는 바로 호출할 수 없다.
- 오버라이딩된 메서드는 실제 객체의 메서드가 실행된다.

```java
Account acc = new CheckingAccount("112", "b", 1000, "999");

acc.deposit(1000);
acc.withdraw(500);
// acc.pay("999", 500); // Account 타입에는 pay()가 없어서 호출 불가
```

## 11. 필드 하이딩과 메서드 오버라이딩

상속에서 필드와 메서드는 동작 방식이 다르다.

```java
class Parent {
    int a = 10;

    void f1() {
        System.out.println("Parent.f1()");
    }
}

class Child extends Parent {
    int a = 15;

    @Override
    void f1() {
        System.out.println("Child.f1()");
    }
}
```

```java
Parent parent = new Child();

System.out.println(parent.a); // Parent의 a
parent.f1();                  // Child의 f1()
```

필드는 오버라이딩되지 않고, 참조 변수의 타입을 기준으로 접근된다. 이를 필드 하이딩이라고 볼 수 있다.

반면 메서드는 오버라이딩되면 실제 객체 타입의 메서드가 실행된다.

정리:

| 구분                | 기준                |
| ------------------- | ------------------- |
| 필드                | 참조 변수 타입 기준 |
| 오버라이딩된 메서드 | 실제 객체 타입 기준 |

## 12. 강제 형 변환(다운캐스팅)과 `instanceof`

부모 타입으로 변환된 객체를 다시 자식 타입으로 사용할 때는 강제 형 변환이 필요하다.

```java
Parent parent = new Child();
Child child = (Child) parent;
```

하지만 실제 객체가 해당 자식 타입이 아니면 런타임 오류가 발생할 수 있다.

```java
Parent parent = new Child();
// Child3 child3 = (Child3) parent; // ClassCastException 가능
```

안전하게 형 변환하기 위해 `instanceof`로 확인한다.

```java
if (parent instanceof Child child) {
    child.f1();
    child.f2();
}
```

정리:

- 강제 형 변환은 실제 객체 타입으로 되돌릴 때 사용한다.
- 잘못된 타입으로 강제 변환하면 런타임 오류가 발생할 수 있다.
- `instanceof`를 사용하면 변환 가능한 타입인지 확인할 수 있다.

## 13. `protected` 접근 제한자

`protected`는 같은 패키지에서는 default처럼 접근할 수 있고, 다른 패키지에서는 상속 관계의 자식 클래스에서 접근할 수 있다.

```java
public class Computer {
    public String memory1 = "2G";
    protected String memory2 = "2G";
    String memory3 = "2G";
    private String memory4 = "2G";
}
```

정리:

| 접근 제한자 | 같은 클래스 | 같은 패키지 | 다른 패키지의 자식 클래스 | 다른 패키지 |
| ----------- | ----------: | ----------: | ------------------------: | ----------: |
| `public`    |        가능 |        가능 |                      가능 |        가능 |
| `protected` |        가능 |        가능 |                      가능 |      불가능 |
| default     |        가능 |        가능 |                    불가능 |      불가능 |
| `private`   |        가능 |      불가능 |                    불가능 |      불가능 |

`protected`는 다른 패키지에서도 자식 클래스라면 접근할 수 있지만, 상속 관계를 통한 접근이라는 조건이 있다.

## 14. 계좌 상속 실습

오늘 실습에서는 `Account`를 부모 클래스로 두고 여러 계좌 클래스를 만들었다.

```text
Account
├─ CheckingAccount
├─ CreditLineAccount
└─ BonusPointAccount
```

각 클래스 역할:

| 클래스              | 역할                                    |
| ------------------- | --------------------------------------- |
| `Account`           | 기본 계좌, 입금/출금 기능 제공          |
| `CheckingAccount`   | 카드번호를 이용한 결제 기능 추가        |
| `CreditLineAccount` | 마이너스 한도를 고려한 출금 기능 재정의 |
| `BonusPointAccount` | 입금 시 포인트 적립 기능 추가           |

실습 포인트:

- 공통 기능은 부모 클래스에 작성한다.
- 자식 클래스는 필요한 필드와 기능만 추가한다.
- 기존 메서드 동작을 바꿔야 하면 오버라이딩한다.
- 부모 메서드를 재사용하려면 `super.메서드()`를 사용한다.

## 15. Shape 실습

`Shape`를 추상 클래스로 두고, `Circle`과 `Rectangle`에서 넓이와 둘레 계산을 구현했다.

```text
Shape
├─ Circle
└─ Rectangle
```

`Shape`는 공통 필드와 추상 메서드를 가진다.

```java
public abstract class Shape {
    private String color;
    private String type;

    public abstract double calculateArea();
    public abstract double calculatePerimeter();
}
```

`Circle`은 반지름을 기준으로 넓이와 둘레를 계산한다.

```java
@Override
public double calculateArea() {
    return Math.PI * radius * radius;
}

@Override
public double calculatePerimeter() {
    return 2 * Math.PI * radius;
}
```

`Rectangle`은 가로와 세로를 기준으로 넓이와 둘레를 계산한다.

```java
@Override
public double calculateArea() {
    return length * width;
}

@Override
public double calculatePerimeter() {
    return (length + width) * 2;
}
```

실습 포인트:

- 공통 속성은 추상 부모 클래스에 둔다.
- 도형마다 계산 방식이 다르므로 추상 메서드로 선언한다.
- 자식 클래스는 각 도형에 맞게 계산 메서드를 구현한다.
- 배열 타입을 `Shape[]`로 두면 여러 자식 객체를 함께 저장할 수 있다.

## 16. Vehicle 실습

`Vehicle`을 부모 클래스로 두고 `Car`, `Bus`, `Truck`에서 정보를 추가했다.

```text
Vehicle
├─ Car
├─ Bus
└─ Truck
```

부모 클래스는 공통 속성과 기능을 가진다.

```java
public class Vehicle {
    private String name;
    private int speed;

    public void start() {
        System.out.println(name + " 출발합니다.");
    }

    public void stop() {
        System.out.println(name + " 멈춥니다.");
    }

    public void info() {
        System.out.println("차량명: " + name + ", 최고속도: " + speed + "km/h");
    }
}
```

자식 클래스는 각 차량만의 정보를 추가하고 `info()`를 재정의한다.

```java
@Override
public void info() {
    super.info();
    System.out.println("연비: " + gasMileage + "km/L");
}
```

실습 포인트:

- 공통 정보는 부모 클래스에 둔다.
- 차량별 추가 정보는 자식 클래스에 둔다.
- `info()`를 오버라이딩해서 차량별 출력 내용을 다르게 만들 수 있다.
- `Vehicle[]` 배열에 여러 자식 객체를 담아 반복 처리할 수 있다.

## 17. 다시 볼 부분

- 부모 타입 변수에 자식 객체를 대입하면 부모 타입에 선언된 멤버만 바로 사용 가능
- 오버라이딩된 메서드는 참조 변수 타입이 아니라 실제 객체 타입을 기준으로 실행
- 필드는 오버라이딩되지 않고 참조 변수 타입을 기준으로 접근
- 다운캐스팅은 값을 덮어쓰는 것이 아니라 참조 타입을 다시 자식 타입으로 변환하는 것
- 부모 생성자는 자식 생성자보다 먼저 실행
- 부모에 기본 생성자가 없으면 자식 생성자에서 `super(값...)`를 명시적으로 직접 작성해야 한다.
- `super()`와 `this()`는 둘 다 생성자 첫 줄에 와야 하므로 같은 생성자에서 동시에 사용 불가
- `final class`는 상속할 수 없고, `final method`는 오버라이딩 불가
- 추상 클래스는 직접 객체를 생성할 수 없다.
- 추상 메서드를 상속받은 자식 클래스는 반드시 해당 메서드를 구현해야 한다.
- 강제 형 변환(다운캐스팅) 전에는 `instanceof`로 실제 객체 타입을 확인하기

## 18. 수업 진행 중 생겼던 의문

### 필드 하이딩

1. 필드의 값과 메서드를 자식 클래스에서 상속을 받고 변경을 했다.
2. 자식 클래스를 부모 클래스로 업캐스팅해서 생성했다.
3. 생성한 객체에서 필드 값을 출력하고 메서드를 실행해봤다.
4. 예상으론 모두 자식 클래스의 값이 나올 것이라고 생각했지만 필드의 값은 부모 클래스에서 정의한 값이 나왔다.
5. 다운캐스팅해서 출력한 후 결과가 예상했던 대로 나오는지 확인했다.
6. 다시 업캐스팅을 한 후 출력을 해보니 필드의 값은 변하지 않았다.
7. 자료를 찾아본 결과, 메서드는 오버라이딩되어 실제 객체 타입의 메서드가 실행되지만 필드는 `필드 하이딩`으로 인해 참조 변수 타입을 기준으로 접근된다는 것을 알았다.

## 정리

- 상속은 기존 클래스를 확장해서 새로운 클래스를 만드는 방법이다.
- Java에서 클래스 상속은 `extends` 키워드를 사용한다.
- Java 클래스는 다중 상속을 허용하지 않는다.
- 자식 객체가 생성되기 직전, 부모 객체가 먼저 생성된다.
- `super()`는 부모 생성자를 호출한다.
- 오버라이딩은 부모 메서드를 자식 클래스에서 재정의하는 것이다.
- `super.메서드()`를 사용하면 부모 클래스의 메서드를 호출할 수 있다.
- `final` 클래스는 상속할 수 없고, `final` 메서드는 오버라이딩할 수 없다.
- 추상 클래스는 공통 구조를 정의하지만 직접 객체를 만들 수 없다.
- 추상 메서드는 선언만 있고 구현은 자식 클래스에서 담당한다.
- 부모 타입 변수에 자식 객체를 대입하는 것을 자동 형 변환(업캐스팅)이라고 한다.
- 다형성은 같은 사용 방법으로 다양한 실행 결과가 나오는 성질이다.
- 필드는 참조 변수 타입 기준으로 접근되고, 오버라이딩된 메서드는 실제 객체 타입 기준으로 실행된다.
- 잘못된 다운캐스팅은 런타임 오류를 발생시킬 수 있으므로 `instanceof`로 확인할 필요가 있다.
- `protected`는 같은 패키지 또는 상속 관계에서 접근할 수 있다.
