## 2. 웹 개발 환경

Web 수업 시작 전에는 Eclipse 기반 웹 프로젝트와 Tomcat 실행 환경을 준비한 것으로 정리할 수 있다.

메모 기준으로 중요한 점은 **작성한 코드 위치와 실제 배포 위치가 다르다**는 점이다.

정리된 위치는 다음과 같다.

```text
JSP 변환 위치:
.metadata/.plugins/org.eclipse.wst.server.core/tmp0/work/Catalina/localhost/appleproject/...

웹 배포 위치:
.metadata/.plugins/org.eclipse.wst.server.core/tmp0/wtpwebapps/appleproject

Java class 배포 위치:
.metadata/.plugins/org.eclipse.wst.server.core/tmp0/wtpwebapps/appleproject/WEB-INF/classes
```

즉, Eclipse에서 작성한 파일이 Tomcat 실행 시 별도 배포 폴더로 복사되어 동작한다.
그래서 파일을 수정했는데 반영되지 않으면 서버 재시작, 클린, 배포 위치 확인이 필요하다.

## 3. Servlet Mapping

메모에 따르면 Servlet Mapping 주소가 잘못되면 다음과 같은 오류가 발생한다.

```text
서블릿 매핑에서 유효하지 않은 <url-pattern> [second2]
```

Servlet Mapping은 클라이언트 요청 URL과 Java Servlet 클래스를 연결하는 설정이다.

예시 흐름:

```text
브라우저 요청 URL
→ Servlet Mapping
→ Servlet 클래스 실행
→ 응답 생성
```

## 4. HTML/CSS 시작

자료 기준으로 Web 첫 구간은 HTML과 CSS의 기본 역할을 정리한다.

| 구분 | 역할 |
|---|---|
| HTML | 웹 페이지의 구조 작성 |
| CSS | 웹 페이지의 스타일 지정 |
| JavaScript | 웹 페이지의 동작 처리 |

HTML은 문서의 구조를 만드는 역할이고, CSS는 화면에 어떻게 보일지를 담당한다.

---

## 5. HTML 기본 구조

HTML 문서는 기본적으로 다음 구조를 가진다.

```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>문서 제목</title>
</head>
<body>
    화면에 보이는 내용
</body>
</html>
```

`head`에는 문서 정보가 들어가고, `body`에는 실제 화면에 표시되는 내용이 들어간다.
